# 直接原因

小程序返回首页按钮的点击处理存在一次性状态或一次性绑定风险。第一次点击后，按钮后续可能因防重复点击标记、禁用状态、页面实例变量、节流锁或路由状态未重置，导致再次进入页面时点击事件无法继续触发有效的首页跳转。

# 根本原因

返回首页能力被作为各页面局部交互处理，而不是作为可重复调用、可恢复状态的全局导航能力治理：

- 返回首页按钮的可点击状态缺少页面进入、页面显示或跳转失败后的统一恢复机制。
- 防重复点击、节流、防抖或 loading 状态可能只在首次成功路径设置，未在 `navigateTo` / `switchTab` / `reLaunch` 成功、失败和完成回调中完整释放。
- 多页面复用的返回首页组件或方法缺少跨页面重复进入的回归测试。
- 页面栈清理与首页跳转 API 的选择可能不一致，导致部分页面首次跳转后遗留状态影响后续点击。

# 触发条件

1. 用户打开微信小程序并进入任一非首页页面。
2. 用户首次点击返回首页按钮，完成或尝试完成返回首页。
3. 用户再次进入同一页面或另一个带返回首页按钮的页面。
4. 返回首页按钮沿用上一次页面实例、组件状态、节流锁或禁用状态。
5. 用户再次点击返回首页按钮时，点击处理未恢复为可执行状态，导致跳转失效。

# 需验证线索

- 返回首页按钮是否存在 `disabled`、`loading`、`isNavigating`、`isReturningHome`、`clicked` 等一次性状态。
- 点击处理是否在跳转失败、跳转完成或页面重新显示时恢复状态。
- 返回首页逻辑是否散落在多个页面，且每个页面独立维护状态。
- 是否混用 `navigateTo`、`redirectTo`、`switchTab`、`reLaunch`，导致首页类型或页面栈不匹配。
- 快速重复点击是否触发节流锁后不再释放。

# 分类

- 类型：code / navigation / state-management
- 层级：微信小程序前端
- 数据风险：低，不涉及数据写入或数据库结构
- API 风险：低，预计不需要后端 API 变更
- 回归风险：中，需覆盖多个页面入口、同页重复进入、跨页重复进入和快速重复点击
