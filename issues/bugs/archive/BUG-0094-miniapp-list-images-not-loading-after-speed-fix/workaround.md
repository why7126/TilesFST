# 临时规避

在正式修复前，可采用以下临时手段降低体验版无图影响：

1. 对生产公开 SKU 主图执行缩略图缺失清单审计，重点覆盖 `images/default/tiles/pending/`。
2. 按确认策略补齐缩略图：缩略图与原图保存在同一路径下，仅通过文件名差异区分。
3. 对历史公开 SKU 主图批量回填缩略图，并记录回填数量、失败数量和失败 SKU。
4. 回填完成前，如需快速恢复体验版，可让列表接口对缺失缩略图的商品临时回退原图 URL。
5. 保留小程序 `lazy-load` 与媒体缓存优化，先修正不可访问的缩略图 URL。

# 不建议的规避

- 不建议让小程序直接访问未授权对象存储地址，避免绕过后端鉴权与 MinIO/COS 适配层。
- 不建议把所有失败图片都替换成占位图并视为修复；这会掩盖真实商品主图缺失或媒体链路失败。
- 不建议继续把本问题归因于“小程序没有发起图片请求”；真机证据已经显示请求发出。
- 不建议在未确认对象存在性前批量修改数据库 object key。
- 不建议继续沿用独立 `thumbnails/` 前缀作为最终缩略图存储路径；本次已确认缩略图应与原图同路径，仅文件名不同。

# 回滚建议

如果需要快速恢复体验版可用性，优先选择低风险回滚路径：

1. 列表接口对缺失缩略图的主图临时返回原图 `/media/{object_key}`，避免生成不可访问缩略图 URL。
2. 保留 `/media` 图片缓存头和媒体读取观测。
3. 后续再通过 OpenSpec 修复缩略图命名、同路径存储、历史回填、列表 URL 生成策略和回归测试。
