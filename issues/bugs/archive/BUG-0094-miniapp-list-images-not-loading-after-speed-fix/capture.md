# 现象

微信小程序首页和列表区域中，商品卡片图片全部没有加载出来，卡片图片区域统一显示“暂无图片”。用户反馈此前是为了解决图片加载速度慢的问题做过处理，但当前结果不是预期。

# 复现步骤

1. 打开微信小程序。
2. 进入首页，查看“新品推荐”“热销推荐”“全部产品”等商品列表区域。
3. 观察商品卡片图片区域是否展示真实商品图。
4. 进入其他复用商品卡片的列表页，如分类商品列表、品牌商品列表、搜索结果页，观察图片是否同样无法加载。

# 期望 vs 实际

- 期望：商品列表图片应能正常展示；加载速度优化应通过懒加载、缩略图、缓存、请求并发控制或后端媒体链路优化实现，不能让已有商品图片整体退化为“暂无图片”。
- 实际：截图中多个列表区域的商品卡片均显示“暂无图片”，包括“新品推荐”“热销推荐”和“全部产品”，用户无法通过图片识别商品。

# 影响范围

- 微信小程序首页商品卡片列表。
- 微信小程序分类商品列表、品牌商品列表、搜索结果页等复用商品卡片的页面。
- 商品卡片图片字段、图片懒加载/占位策略、列表数据接口中的图片 URL 返回策略。
- 历史修复 `BUG-0092-miniapp-card-images-slow-load` / `fix-miniapp-card-image-loading` 的回归验证范围。

# 初步线索

- 用户截图显示页面顶部品牌区域可展示 Logo，但商品卡片图片区域均为“暂无图片”，说明问题可能集中在商品列表图片字段或商品卡片图片加载策略，而非所有媒体资源完全不可用。
- 商品文字、SKU 编号、规格和参考价格均正常显示，说明列表数据主体加载成功；异常更可能出现在 `cover_image`、图片 URL 生成、懒加载条件、占位兜底判断或媒体代理访问上。
- 历史缺陷 `BUG-0092-miniapp-card-images-slow-load` 已归档，本次反馈明确指出“之前是为了解决速度慢的问题”，需重点检查该修复是否把慢加载误处理为不加载或过早判定失败。

# 建议验收或复现要点

- [ ] 首页“新品推荐”“热销推荐”“全部产品”中的商品卡片能展示真实商品图片，不再全部显示“暂无图片”。
- [ ] 分类商品列表、品牌商品列表、搜索结果页等复用商品卡片页面图片展示一致正常。
- [ ] 有真实主图的商品不得被误判为无图；确实无主图或对象缺失的商品才显示“暂无图片”。
- [ ] 图片加载速度优化仍保留，首屏不一次性加载过多非可见图片，但可见区域图片应在可接受时间内显示。
- [ ] 图片加载失败事件、媒体请求状态码和对象缺失情况可被排查，避免静默退化。
- [ ] 回归覆盖 `BUG-0092-miniapp-card-images-slow-load` 的核心场景，确认“加载更快”和“图片正常展示”同时满足。
