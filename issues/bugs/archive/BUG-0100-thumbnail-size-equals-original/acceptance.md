# 验收标准

## AC-001 新上传 SKU 图片生成真实缩略图

- GIVEN 管理端上传一张尺寸大于缩略图目标尺寸的 SKU 图片
- WHEN 上传接口成功返回原图 `object_key`
- THEN 后端应在同目录生成 `.thumb` 缩略图对象
- AND 缩略图像素宽高应小于或等于约定最大宽高
- AND 缩略图不得与原图 bytes 完全一致

## AC-002 缩略图体积有效下降

- GIVEN 原图尺寸大于缩略图目标尺寸且格式受支持
- WHEN 后端生成 `.thumb` 对象
- THEN 缩略图文件体积通常应小于原图
- AND 对明显异常增大的输出应有保护、回退或告警策略
- AND 验证不得仅以缩略图对象存在作为通过条件

## AC-003 小图和边界图片处理正确

- GIVEN 上传图片本身小于或等于缩略图目标尺寸
- WHEN 后端生成缩略图
- THEN 不应放大图片
- AND 可按约定保留原尺寸重编码、轻压缩或复用原图，但必须记录明确策略
- AND 不得因小图导致上传失败

## AC-004 多格式图片处理正确

- GIVEN 用户上传 JPG、PNG、WebP、横图、竖图和大尺寸图片
- WHEN 后端生成缩略图
- THEN 应保持图片可读取、方向正确、比例不变
- AND 透明 PNG/WebP 不应出现不符合约定的黑底、白底或透明丢失
- AND 不支持或损坏的图片应返回明确错误或按约定跳过缩略图生成

## AC-005 公开商品卡片继续优先使用缩略图

- GIVEN 商品已公开且有主图
- WHEN 小程序首页、商品列表、搜索结果、品牌详情商品区返回商品卡片数据
- THEN `cover_image` 应继续优先返回后端受控的同目录 `.thumb` URL
- AND 该 URL 对应对象应为真实缩略图
- AND 详情大图仍可使用原图或高清图

## AC-006 历史缩略图可审计和重生成

- GIVEN 存量公开 SKU 已存在原图和 `.thumb` 对象
- WHEN 执行历史缩略图审计 dry-run
- THEN 应输出原图存在、缩略图存在、疑似同 size、疑似同 bytes、需要重生成、失败原因等统计
- AND dry-run 不写数据库、不写对象存储
- WHEN 执行重生成 apply
- THEN 应为需要处理的对象生成真实缩略图
- AND 脚本应可重入，重复执行不会破坏已合格缩略图

## AC-007 对象存储与安全边界保持一致

- GIVEN 修复涉及对象读取、写入或历史重生成
- WHEN 后端处理媒体对象
- THEN 所有对象操作必须通过后端对象存储适配层
- AND 不得前端直连未授权对象存储
- AND 不得输出密钥、Authorization header、Cookie、`.env` 内容或本机路径
- AND 不得使用用户原始文件名生成最终对象 key

## AC-008 上传失败与缩略图失败边界明确

- GIVEN 原图上传成功但缩略图生成失败
- WHEN 后端处理上传响应
- THEN 行为应符合 Change 中约定的失败策略
- AND 不得出现数据库引用已保存但原图不可访问的半成功状态
- AND 失败日志或 Task Trace 应能定位到缩略图处理阶段，但不得泄露敏感信息

## AC-009 回归测试覆盖

- MUST 补充后端单元或集成测试，验证 `save_upload_file()` 或等价媒体处理函数生成的缩略图尺寸小于原图。
- MUST 补充测试验证缩略图 bytes 不再与原图完全一致。
- MUST 补充 JPG、PNG、WebP、横图、竖图、大图、小图和异常图片输入的测试。
- MUST 补充历史回填或重生成脚本测试，覆盖 dry-run、apply、幂等、对象缺失和已合格缩略图跳过。
- SHOULD 补充公开商品卡片接口测试，确认列表场景继续返回可访问 `.thumb` URL。
- SHOULD 更新或保留现有缩略图 key、缺失回退和媒体缓存测试，避免修复性能问题时引入无图回归。
