# 直接原因

管理端类目树节点右侧计数展示口径与用户预期不一致：当前展示的是类目关联商品数量或商品汇总数量，而不是节点的直接子类目数量。

从截图证据看，一级类目右侧的 `21`、`23`、`10`、`13` 等数值明显更符合商品数量特征；用户明确反馈这些位置应显示“下一层级类目数量”。因此直接原因应收敛为类目树计数字段选择或数据聚合口径错误。

# 根本原因

类目树计数的产品语义没有在数据契约和 UI 展示中被清晰区分，导致“商品数量”和“子类目数量”复用了同一个视觉位置或同一个字段。

结合补充验证信息，根因进一步收敛为前端字段绑定错误：

- 管理端类目树接口已返回直接子类目数量字段，后端具备表达下一层级类目数量的数据基础。
- 前端类目树组件当前绑定的是商品数量计数字段，而不是接口中的直接子类目数量字段；具体字段名由上一轮排查确定，后续修复 Change 需引用对应代码证据。
- “全部类目”入口的计数口径已明确：右侧数字应显示顶层类目数量，不应显示商品总数。
- 测试覆盖更关注商品筛选数量，没有覆盖类目树节点右侧数字必须等于直接子类目数量。

# 触发条件

1. 管理端页面渲染类目树。
2. 类目节点存在商品数量统计字段，且该字段被展示在节点右侧。
3. 用户把类目树右侧数字理解为下一层级类目数量。
4. 一级类目下商品数量大于直接子类目数量时，错误更明显。

# 已确认与待验证点

- 已确认：用户期望类目树右侧数字显示下一层级类目数量。
- 已确认：当前截图中右侧数字显示效果更像商品数量。
- 已确认：管理端类目树接口返回直接子类目数量字段。
- 已确认：前端类目树组件当前绑定的计数字段名称已由上一轮排查确定，问题集中在该字段未使用直接子类目数量。
- 已确认：“全部类目”入口右侧数字应显示顶层类目数量。
- 待验证：后续修复 Change 中需引用前端实际绑定字段名，并补充对应组件测试。
