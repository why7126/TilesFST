# 现象

管理端类目树中，一级类目右侧的数值当前显示为该类目下的商品数量。例如截图中“木纹砖产品”右侧显示 `21`、“莱姆石产品”显示 `23`、“地铺石产品”显示 `10`、“小地砖产品”显示 `13`，但这些数字应表达下一层级的类目数量。

# 复现步骤

1. 打开管理端类目管理或包含类目树筛选的页面。
2. 查看左侧“类目树”中一级类目列表。
3. 观察每个一级类目右侧的数值。
4. 展开对应一级类目，对比其下一层级子类目数量与右侧显示数值。

# 期望 vs 实际

- 期望：类目树节点右侧数值显示该节点的下一层级类目数量；没有子类目时显示 `0`。
- 实际：类目树节点右侧数值显示为该类目下商品数量，导致用户误以为下一层级类目很多或计数语义不清。

# 影响范围

- 管理端类目树组件。
- 类目管理、商品筛选或其他复用类目树的管理端页面。
- 类目树数据接口或前端计数字段映射逻辑。

# 初步线索

- 截图中面板标题显示“24 项”，全部类目入口显示 `67`，一级类目右侧显示的 `21`、`23`、`10`、`13` 等更像商品汇总数量，而不是下一层级类目数量。
- 需要确认后端类目树接口是否同时返回商品数量与子类目数量；若已有字段，优先修正前端映射；若接口只返回商品数量，则后续修复需通过 OpenSpec Change 明确接口返回口径。

# 建议验收或复现要点

- [ ] 一级类目右侧数字等于其直接子类目数量，不包含商品数量。
- [ ] 二级类目右侧数字等于其直接子类目数量；叶子类目显示 `0`。
- [ ] “全部类目”入口的数值口径明确，若作为树根节点，应显示顶层类目数量，而不是商品总数。
- [ ] 展开或折叠类目树后，计数不随商品筛选结果错误变化。
- [ ] 若页面另有商品数量提示，应与类目数量视觉语义区分，避免复用同一个数字位置造成误解。
