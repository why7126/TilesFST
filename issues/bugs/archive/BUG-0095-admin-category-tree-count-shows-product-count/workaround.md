# 临时规避

在正式修复前，管理人员可通过展开类目树实际查看下一层级类目，暂时不要把节点右侧数字作为子类目数量依据。

如果需要短期降低误解，可在不改变业务逻辑的前提下采用以下临时措施：

1. 在操作说明或验收备注中明确：当前类目树右侧数字临时代表商品数量，不代表下级类目数量。
2. 维护类目层级时，以展开后的直接子节点为准，不以右侧数字判断是否存在子类目。
3. 在正式修复前，避免基于该数字做批量类目清理、合并或下架决策。

# 不建议的规避

- 不建议直接隐藏所有节点计数并视为修复；这会丢失原本有价值的类目树摘要信息。
- 不建议把商品数量继续放在类目树节点右侧同一位置，除非 UI 明确标注该数字语义。
- 不建议只改文案不改计数口径；用户当前诉求是该位置应显示下一层级类目数量。
- 不建议绕过后端契约在前端用不可靠的嵌套数组长度临时计算，除非确认接口返回的是完整下一层级数据。

# 回滚建议

如果后续修复引入字段映射异常或类目树渲染异常，可回滚到当前展示逻辑以恢复页面可用性，但必须保留本 BUG，继续推进正确计数口径修复。
