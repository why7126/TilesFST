# 现象

管理端类目树节点右侧的数字当前显示为类目下商品数量，而不是该节点下一层级的类目数量。

从用户截图看，“类目树”面板中一级类目右侧显示 `21`、`23`、`10`、`13` 等数字，这些数值更像商品数量汇总；但用户明确期望该位置表达“下一层级类目数量”。例如某个一级类目下没有子类目时，应显示 `0`，而不应因为该类目下有商品而显示商品数量。

# 复现

1. 打开管理端类目管理页面，或打开任一复用类目树筛选的管理端页面。
2. 查看左侧“类目树”中一级类目列表。
3. 记录每个一级类目右侧的数字。
4. 展开对应一级类目，统计其直接子类目数量。
5. 对比右侧显示数字与直接子类目数量是否一致。

# 期望

- 类目树节点右侧数字应表示该节点的下一层级类目数量。
- 没有子类目的节点应显示 `0`。
- “全部类目”如果作为树根节点入口，应显示顶层类目数量；若产品另有定义，应在修复方案中明确口径。
- 商品数量不应复用类目树节点右侧的类目数量位置，避免用户把商品数误解为子类目数。

# 实际

- 一级类目右侧数字显示为商品数量。
- 截图中多个一级类目的右侧数字明显大于一般直接子类目数量，例如“木纹砖产品”显示 `21`、“莱姆石产品”显示 `23`。
- “全部类目”入口显示 `67`，也更像商品总数，而不是顶层类目数量。

# 影响范围

- 管理端类目树组件。
- 管理端类目管理页面。
- 管理端商品列表、商品筛选或其他复用类目树的页面。
- 类目树接口字段、数据聚合逻辑或前端计数字段映射逻辑。

# 严重等级说明

严重等级：`medium`。

该问题不会阻断类目浏览或商品管理主流程，但会让管理人员误判类目层级结构，尤其是在维护一级、二级、三级类目时，右侧数字的语义错误会干扰类目梳理、层级校验和数据排查。由于该数字位于类目树核心交互区域，属于高频可见的管理端体验偏差。

# 初步分析

- 类目树 UI 已存在节点右侧计数展示能力，但当前计数口径疑似绑定到商品数量字段。
- 需要检查管理端类目树数据源是否返回了 `product_count`、`children_count` 或等价字段。
- 若后端已返回直接子类目数量，修复重点应是前端 `CategoryTree` 的字段映射与展示文案。
- 若后端仅返回商品数量，则后续修复应通过 OpenSpec Change 明确接口响应新增或调整下一层级类目数量字段，并同步 OpenAPI、Orval 与测试。
