# 直接原因

管理后台瓷砖类目名称校验链路对可输入字符的定义不完整：英文括号 `(`、`)` 可以通过，但中文全角括号 `（`、`）` 未被纳入合法字符范围，导致包含中文括号的类目名称在新增或编辑保存时被拦截。

该拦截可能发生在以下任一层级，最终表现一致：

- 前端表单校验规则限制了名称字符集。
- 后端 Pydantic Schema 或服务层校验限制了名称字符集。
- 数据库或唯一性校验前的规范化逻辑未覆盖中文全角括号。

# 根本原因

类目名称能力缺少面向中文业务命名的字符集契约。既有规则验证了名称必填、长度、重复名等基础约束，但没有明确“中文全角标点中哪些应作为合法业务字符”，因此实现中容易只覆盖英文半角括号，遗漏中文括号。

# 触发条件

1. 用户进入管理后台瓷砖类目管理。
2. 用户新建或编辑类目。
3. 类目名称包含中文括号 `（`、`）`，例如 `墙砖（哑光）`。
4. 保存时命中前端、后端或持久化前的名称校验。

# 分类

- 类型：code / validation / i18n
- 层级：管理后台表单、后端输入校验、类目名称保存链路
- 数据风险：低，问题主要发生在保存前，不涉及已保存数据破坏
- API 风险：低，修复通常属于输入校验兼容性扩展
- 回归风险：中，需要确认修复不放宽空名称、超长名称、重复名称和其他非法字符限制
