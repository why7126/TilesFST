# 直接原因

小程序商品列表相关入口未统一复用品牌详情页现行排序策略。

品牌详情页商品列表已通过 `BUG-0087-miniapp-brand-detail-product-tab-sort-order` 修正排序规则，但搜索商品结果页、分类商品列表页仍可能沿用各自入口的默认查询顺序、接口参数或本地排序逻辑。由于不同入口面向的是同一类公开 SKU 集合，排序策略分散会导致用户从品牌、搜索、分类入口看到的商品顺序不一致。

# 根本原因

商品列表通用能力缺少跨入口排序契约：

- 未将品牌详情页修正后的排序规则抽象为小程序商品列表的公共排序标准。
- 搜索商品结果页、分类商品列表页与品牌详情页之间缺少统一的排序验收项。
- 关联需求 `REQ-0047-product-list-common-component-application` 更偏向列表组件复用，未显式沉淀“同类商品集合跨入口排序一致”的业务规则。
- 若搜索结果页存在相关性排序，当前缺陷记录尚未明确相关性排序与品牌详情页排序的优先级关系，容易造成实现阶段各入口解释不一致。

# 触发条件

1. 微信小程序中存在多条公开 SKU。
2. 这些 SKU 同时能通过品牌详情页、搜索商品结果页或分类商品列表页进入同一或相近商品集合。
3. SKU 在品牌详情页现行排序字段、发布时间、创建时间或其他排序依据上存在差异。
4. 搜索页或分类页没有复用品牌详情页排序策略，或分页加载时缺少稳定的次级排序。

# 分类

- 类型：design / consistency
- 层级：微信小程序商品列表体验、商品列表接口查询契约
- 数据风险：低，不改变 SKU 数据本身
- API 风险：中，若需要统一查询参数或后端默认排序，需要同步接口契约与 Orval
- 回归风险：中，需覆盖品牌详情页、搜索结果页、分类商品列表页及分页加载更多
