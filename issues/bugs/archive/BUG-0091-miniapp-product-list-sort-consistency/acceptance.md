# 验收标准

## AC-001 品牌详情页排序作为基准

- GIVEN 微信小程序中存在同一品牌下多条公开 SKU
- WHEN 用户进入品牌详情页商品列表
- THEN 商品列表应展示品牌详情页现行排序结果
- AND 该排序结果应作为搜索商品结果页、分类商品列表页一致性对比基准

## AC-002 搜索商品结果页排序一致

- GIVEN 搜索关键词可命中与品牌详情页相同或相近的公开 SKU 集合
- WHEN 用户进入搜索商品结果页
- THEN 搜索结果中同一商品集合的相对顺序应与品牌详情页现行排序方式一致
- AND 分页加载更多后不应出现重复、漏项或已加载商品顺序跳动

## AC-003 分类商品列表页排序一致

- GIVEN 分类商品列表页可展示与品牌详情页相同或相近的公开 SKU 集合
- WHEN 用户进入分类商品列表页
- THEN 分类列表中同一商品集合的相对顺序应与品牌详情页现行排序方式一致
- AND 分页加载更多后排序应稳定

## AC-004 首页全部产品列表不受影响

- GIVEN 用户进入小程序首页“全部产品”列表
- WHEN 本 BUG 修复上线后
- THEN 首页“全部产品”列表排序应保持修复前既有策略
- AND 不应因搜索页、分类页排序统一而产生额外排序变化

## AC-005 搜索相关性规则需明确

- GIVEN 搜索商品结果页存在关键词相关性排序或未来需要引入相关性排序
- WHEN 评审或实现本 BUG
- THEN 必须明确相关性排序与品牌详情页排序规则的优先级
- AND 若相关性排序覆盖品牌详情页排序，应在评审结论或 OpenSpec Change 中记录原因与验收口径

## AC-006 回归范围覆盖

- SHOULD 覆盖微信小程序品牌详情页商品列表、搜索商品结果页、分类商品列表页。
- SHOULD 覆盖关键词搜索、类目筛选、品牌筛选以及分页加载更多。
- SHOULD 覆盖排序字段相同值时的稳定次级排序，避免不同页或不同请求顺序跳动。
- SHOULD 补充或更新小程序端测试、后端商品列表查询测试或等价验收脚本。
