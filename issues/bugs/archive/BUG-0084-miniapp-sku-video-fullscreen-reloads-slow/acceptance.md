# Acceptance

## AC-001 全屏入口复用当前视频上下文

给定小程序 SKU 详情页存在可播放视频媒体，  
当用户先在内嵌轮播区域播放视频并确认视频已开始播放，随后点击全屏入口，  
则全屏播放应优先复用当前视频组件上下文或等价能力进入全屏态，避免打开会重新长时间加载的独立播放链路。

## AC-002 全屏切换首帧耗时可接受

给定同一个实际 SKU 视频，  
当用户从已播放的内嵌视频切换到全屏态，  
则全屏态应在可接受时间内出现首帧或可播放反馈，不应长时间停留在加载状态。

验收记录必须包含：

- SKU ID
- 视频 URL 类型或受控媒体路径
- 视频大小、格式、编码和时长
- 机型、微信版本和网络类型
- 内嵌播放首帧耗时
- 点击全屏到全屏首帧耗时

## AC-003 退出全屏上下文保持

给定用户从 SKU 详情页视频进入全屏播放，  
当用户退出全屏，  
则页面应回到当前 SKU 详情页和当前媒体上下文，不应跳错页面、重置到第一张媒体、触发异常 Toast 或丢失底部收藏/分享可用性。

## AC-004 加载反馈与失败兜底

给定平台或网络条件导致全屏态仍需重新加载，  
当用户点击全屏入口，  
则页面应提供明确加载反馈、失败提示或可理解降级路径，避免用户误以为页面卡死。

## AC-005 非回归

修复后应保持以下能力不回归：

- SKU 详情页图片轮播和图片预览可用。
- SKU 详情页内嵌视频仍由用户主动播放，不默认自动播放。
- 视频播放期间轮播不自动切换。
- 页面隐藏、锁屏、跳转或返回时暂停当前视频。
- 媒体 URL 继续来自后端安全可播放链路，不暴露原始 object key、对象存储 endpoint、bucket 或未授权素材路径。

## AC-006 测试与证据

修复实现时应补充或更新：

- 小程序静态测试，覆盖全屏入口使用的关键 API 或降级逻辑。
- 小程序真机证据，覆盖内嵌播放成功后进入全屏的耗时对比。
- 如修改媒体接口或响应字段，应同步 API / OpenAPI / Orval / 文档和后端契约测试。
