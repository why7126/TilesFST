# 缺陷描述

微信小程序 SKU 详情页中，商品视频在内嵌轮播区域已经可以正常播放；但用户点击视频右上角全屏入口后，全屏态重新进入较长加载等待，迟迟不能完成加载或出现首帧。

该问题影响的是“已可播放视频切换到全屏”的连续体验，不是视频在详情页内嵌态完全不可播放。

# 复现步骤

1. 打开微信小程序中包含商品视频的 SKU 详情页。
2. 在轮播媒体区点击视频播放控件，确认内嵌视频已开始播放。
3. 点击视频右上角全屏入口。
4. 观察全屏态从点击到首帧出现或可播放的等待时间。

# 期望结果

- 内嵌视频已可播放时，点击全屏入口后应尽快进入可播放全屏态。
- 全屏切换不应明显重新进入长时间加载。
- 用户退出全屏后应回到当前 SKU 详情页和当前媒体上下文。

# 实际结果

- 内嵌视频已经可以播放。
- 点击全屏入口后，全屏态仍重新加载很久，无法快速继续播放。
- 用户在商品视频查看过程中出现明显等待，打断浏览体验。

# 影响范围

- 微信小程序 SKU 详情页：`src/miniapp/pages/tile-detail/`
- 商品视频全屏入口与播放链路
- SKU 商品视频素材展示体验
- `REQ-0044-miniapp-sku-detail-page` 中的视频播放、全屏体验和真机验收

# 严重等级说明

严重等级建议为 `medium`：

- 主路径的内嵌视频播放仍可用，缺陷未完全阻断 SKU 详情浏览。
- 全屏播放是客户查看商品视频的重要体验入口，长时间重新加载会显著影响视频浏览连续性。
- 该问题和生产视频首播慢问题相关，但现象更聚焦于“内嵌态已播放成功后切换全屏仍重新加载”。

# 附件与证据

- 用户提供 2026-07-24 微信小程序真机录屏，显示视频内嵌态已播放后进入全屏加载较久。
- 初步线索：当前内嵌播放使用小程序 `<video>` 组件；全屏入口可能使用独立媒体预览链路，导致不复用已加载的视频上下文。
