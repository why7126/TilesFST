# 现象

小程序 SKU 详情页中，视频在内嵌轮播区域已经可以播放；但点击视频右上角全屏入口后，全屏态重新进入较长加载等待，迟迟不能完成加载或出现首帧。

# 复现步骤

1. 打开微信小程序中包含商品视频的 SKU 详情页。
2. 在轮播媒体区点击视频播放控件，确认内嵌视频已经可以播放。
3. 点击视频右上角全屏入口。
4. 观察全屏态从点击到首帧出现或可播放的等待时间。

# 期望 vs 实际

- 期望：内嵌视频已可播放时，点击全屏入口应尽快进入可播放全屏态，不应重新长时间加载；退出全屏后应回到当前 SKU 详情页和当前媒体上下文。
- 实际：内嵌视频已可播放，但进入全屏后仍出现长时间加载等待，影响客户查看商品视频的连续体验。

# 影响范围

- 微信小程序 SKU 详情页：`src/miniapp/pages/tile-detail/`
- 视频全屏入口与播放链路
- SKU 商品视频素材展示体验
- 与 `REQ-0044-miniapp-sku-detail-page` 的视频播放和全屏体验验收相关

# 初步线索

- 当前内嵌播放使用小程序 `<video>` 组件播放详情接口返回的安全媒体 URL。
- 当前自定义全屏入口调用 `wx.previewMedia` 打开媒体预览链路；该链路可能不复用已在 `<video>` 组件中完成的加载和缓冲状态，导致全屏态重新探测或重新拉流。
- 与 BUG-0082 的首播慢不同，本缺陷的核心差异是“内嵌态已播放成功后，切换全屏态仍重新长时间加载”。

# 建议验收或复现要点

- 使用同一实际 SKU 视频记录内嵌播放首帧耗时与点击全屏后的首帧耗时。
- 记录机型、微信版本、网络类型、视频大小、格式、编码和时长。
- 验证全屏入口是否复用当前 `<video>` 组件上下文，或是否打开独立媒体预览器。
- 验证 `/media/{object_key}` Range 响应正常时，全屏切换是否仍存在重新加载等待。

# 附件

用户提供 2026-07-24 微信小程序真机录屏，显示视频内嵌态已播放后进入全屏加载较久。
