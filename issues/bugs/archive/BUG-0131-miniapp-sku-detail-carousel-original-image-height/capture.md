# 现象

小程序商品详情页轮播图首屏使用 `.thumb` 缩略图作为大图区域展示资源，导致用户在详情页查看瓷砖图片时感觉清晰度不足；同时轮播图高度固定为 `680rpx`，视觉上不够符合瓷砖详情页的大图展示预期。

# 复现步骤

1. 打开微信小程序商品详情页。
2. 进入包含 SKU 图片媒体的商品详情。
3. 观察首屏轮播图展示效果，尤其是瓷砖纹理、边缘、表面质感等细节。
4. 对比点击图片进入预览后的高清原图效果，以及详情页首屏固定 `680rpx` 媒体区高度。

# 期望 vs 实际

- 期望：商品详情页轮播首屏应优先呈现足够清晰的瓷砖图片细节，建议详情页展示改用原图或详情级展示图；商品列表、卡片和推荐位仍保留 `.thumb` 缩略图以保证加载性能。轮播高度应更符合瓷砖详情展示比例，可基于视口宽度或安全区动态调整，同时避免首屏把商品名称完全挤出。
- 实际：详情页轮播首屏使用 `.thumb` 缩略图，缩略图在大图区域被放大后清晰度不足；媒体区高度固定 `680rpx`，用户反馈轮播图高度不够。

# 影响范围

- 微信小程序商品详情页 SKU 轮播首屏展示。
- SKU 图片媒体字段 `url`、`preview_url` 在详情页的展示与预览语义。
- 小程序商品详情页首屏布局、商品名称露出、底部操作栏安全区和推荐区滚动体验。
- 列表、卡片、推荐位仍应继续使用 `.thumb`，避免因修复详情页清晰度导致其他页面加载性能回退。

# 初步线索

- 探索阶段确认，当前小程序详情页 `<image>` 的 `src` 绑定 `item.url || imageFallback`，点击预览绑定 `item.preview_url || item.url`。
- 后端 SKU 详情图片媒体当前将 `url` 优先返回同目录 `.thumb`，`preview_url` 返回原图或等价高清预览 URL。
- 当前缩略图生成默认最大宽高为 `480x480`，详情页轮播区域固定 `680rpx`，在高 DPR 真机上可能出现缩略图被放大导致的清晰度不足。
- 该问题与 `BUG-0125-miniapp-sku-detail-media-original-load` 的媒体加载策略相关，但本次反馈重点从“加载慢”转为“详情首屏大图清晰度与高度体验不足”。

# 建议验收或复现要点

- [ ] 商品详情页轮播首屏图片不再优先使用小尺寸 `.thumb` 作为大图展示资源，可使用原图或详情级展示图。
- [ ] 点击图片预览仍使用原图或等价高清预览 URL。
- [ ] 商品列表、商品卡片、推荐位仍保留 `.thumb`，不引入列表加载性能回退。
- [ ] 轮播高度从固定 `680rpx` 调整为更适合瓷砖详情展示的比例，覆盖 320 到 430px 逻辑宽度视口。
- [ ] 首屏仍能露出商品名称或关键商品信息，不因媒体区变高导致首屏信息完全被挤出。
- [ ] 补充真机或开发者工具截图，对比修复前后图片清晰度、媒体区高度和首屏信息露出。
