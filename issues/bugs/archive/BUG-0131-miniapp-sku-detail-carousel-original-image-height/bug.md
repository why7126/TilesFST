# 现象

微信小程序商品详情页顶部轮播首屏使用 `.thumb` 缩略图作为大图区域展示资源，用户反馈瓷砖纹理、边缘和背景文字等细节不够清晰。用户补充截图显示 SKU `M612X07` 的详情页首屏图片存在明显发糊感，瓷砖表面花纹和展板文字细节难以辨认。

同一页面轮播图高度当前固定为 `680rpx`，用户反馈高度不够。截图中商品名称和价格仍能在首屏露出，因此后续调整高度时需要在“大图展示”和“首屏商品信息可见”之间保持平衡。

# 复现步骤

1. 打开微信小程序。
2. 进入任一包含 SKU 图片媒体的商品详情页，例如用户反馈截图中的 `M612X07`。
3. 查看商品详情页顶部轮播首屏图片。
4. 观察瓷砖纹理、图片边缘、展板文字等细节是否清晰。
5. 点击图片进入预览，对比预览图与首屏轮播图的清晰度。
6. 观察轮播图高度是否满足瓷砖详情大图展示预期，以及商品名称和价格是否仍在首屏可见。

# 期望 vs 实际

## 期望

- 商品详情页轮播首屏应展示足够清晰的瓷砖图片细节，适合用户查看纹理、花色、表面质感和规格信息。
- 详情页可优先使用原图或详情级展示图；商品列表、商品卡片和推荐位仍应使用 `.thumb` 缩略图以保证加载性能。
- 点击图片预览时继续使用原图或等价高清预览 URL。
- 轮播高度应更符合瓷砖详情展示比例，可基于视口宽度或安全区动态调整。
- 调整轮播高度后，首屏仍应露出商品名称或关键商品信息，不应被媒体区完全挤出。

## 实际

- 商品详情页轮播首屏使用 `.thumb` 缩略图，缩略图在大图区域内放大展示后清晰度不足。
- 当前详情页轮播高度固定为 `680rpx`，用户反馈高度不够。
- 现有媒体契约中，后端图片媒体 `url` 优先返回 `.thumb`，`preview_url` 才返回原图；小程序首屏 `<image>` 绑定 `item.url`，导致首屏展示沿用了小图策略。

# 影响范围

- 影响微信小程序商品详情页 SKU 顶部轮播首屏展示体验。
- 影响用户查看瓷砖纹理、花色、边缘、规格文字和展板细节的能力。
- 与 `BUG-0125-miniapp-sku-detail-media-original-load` 的修复策略相关：此前为解决详情页原图加载慢，将详情页首屏展示图切到 `.thumb`；本 BUG 表明该策略在详情页大图场景下带来清晰度回退。
- 修复时需要避免影响商品列表、商品卡片、推荐位和 Banner 的缩略图加载策略。
- 修复可能触及小程序详情页 WXML/WXSS、后端 SKU 详情媒体字段语义、OpenSpec 详情页媒体规格和相关测试断言。

# 严重等级说明

严重等级建议为 `medium`。

理由：

- 该问题影响商品详情页核心视觉体验，且商品详情页是客户查看瓷砖信息的关键页面。
- 问题不阻断页面打开、收藏、分享或继续浏览，也不涉及交易、权限、数据安全或接口不可用。
- 若后续真机证据显示大批 SKU 图片在主流设备上严重模糊，或影响客户选砖判断，可在评审阶段上调为 `high`。

# 初步判断

根因状态暂定为 `probable`，正式根因需在 `/bug-complete` 阶段补充。

当前证据指向：

- 详情页首屏图片展示链路复用了 `.thumb` 缩略图。
- 缩略图默认最大宽高较小，进入详情页大图展示区域后可能被放大。
- 详情页媒体区固定高度与商品详情视觉预期不完全匹配。

仍需补证：

- 具体 SKU 的原图与 `.thumb` 像素尺寸、文件体积和加载耗时对比。
- 微信开发者工具或真机截图，覆盖修复前后清晰度、轮播高度和首屏商品信息露出。
- 320 到 430px 逻辑宽度视口下的布局对比。
