# 现象

Web 端瓷砖 SKU 列表当前默认排序不符合业务预期：列表不应按更新时间排序。已发布 SKU 应优先体现最近发布的记录，未发布 SKU 应优先体现最近创建的草稿。

# 复现步骤

1. 在 Web 端打开瓷砖 SKU 列表。
2. 准备多条 SKU 数据，至少包含以下组合：
   - 已发布 SKU，且 `published_at` 不同。
   - 未发布 SKU，且 `created_at` 不同。
   - 更新时间与发布时间或创建时间不一致的记录。
3. 查看列表默认排序结果。
4. 对列表执行搜索、筛选或分页后，再次观察排序结果是否保持一致。

# 期望 / 实际

## 期望

- 已发布 SKU 按 `published_at` 降序排列。
- 未发布 SKU 按 `created_at` 降序排列。
- 搜索、筛选、分页后的列表仍遵循同一默认排序策略。
- 当主排序时间相同时，列表应使用稳定的兜底排序字段，避免刷新或翻页后顺序跳动。

## 实际

当前列表按更新时间或等价更新时间字段排序，导致：

- 已发布 SKU 的展示顺序可能偏离发布时间顺序。
- 未发布 SKU 的草稿展示顺序可能偏离创建时间顺序。
- 运营人员难以稳定查看最新发布或最新创建的 SKU。

# 影响范围

- Web 管理端瓷砖 SKU 列表默认排序。
- 可能涉及后端 SKU 列表查询排序逻辑，或前端列表请求参数与展示排序逻辑。
- 可能影响分页、搜索、筛选场景下的 SKU 浏览效率。
- 不应影响 SKU 新增、编辑、上下架、删除等操作行为。

# 严重等级说明

严重等级为 `medium`。该问题影响管理端运营人员浏览和定位 SKU 的效率，属于已交付列表行为与业务期望不一致；但未直接阻断 SKU 数据维护、发布或删除等核心写入流程，也未涉及数据丢失或权限绕过。

# 待确认事项

- 已发布和未发布 SKU 是否在同一列表中混排；若混排，需要确认两类记录的分组先后规则。
- `published_at` 为空、`created_at` 为空或主排序时间重复时，应使用哪个字段作为稳定兜底排序。
- 排序应由后端统一返回，还是由 Web 端显式传参并由后端执行。
