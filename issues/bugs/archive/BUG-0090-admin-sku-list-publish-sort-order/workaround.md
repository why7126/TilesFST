# 临时规避

正式修复前，可通过运营和验收方式降低影响：

1. 查找最近发布 SKU 时，不以当前列表默认首屏顺序作为唯一依据，应结合“发布时间”列人工确认。
2. 查找未发布草稿时，应结合 SKU 创建记录或业务记录人工确认，不以最近编辑时间推断草稿创建顺序。
3. 验收或演示时准备包含 `published_at`、`created_at`、`updated_at` 差异的数据样本，避免把更新时间排序误判为发布排序。
4. 若需要确认某个 SKU 是否为最新发布，可进入详情或通过后端数据查询核对 `published_at`。

# 注意事项

- 不建议通过无意义编辑 SKU 来调整列表顺序；这会进一步污染 `updated_at`，并影响问题复现。
- 不建议在前端本地临时排序当前页数据；分页场景下只排序当前页会导致跨页顺序不稳定。
- 不建议手动修改数据库时间字段；这会破坏历史审计和后续验收样本。
- 临时规避不改变最终修复方向：默认排序应由后端列表查询统一保证。
