# 临时规避方案

当前缺陷不阻断日志查询或详情打开，正式修复前可采用以下临时方式降低误读风险：

1. 使用日志列表中的复制按钮复制 `request_id`、`client_request_id`、`behavior_trace_id` 或 `task_trace_id`，避免仅凭重叠区域肉眼识别。
2. 在日志详情抽屉中选中字段值文本后复制到外部编辑器查看完整 ID。
3. 临时放大浏览器窗口宽度或使用桌面端查看，减少抽屉内字段列被压缩的概率。
4. 排障时优先使用可复制的链路 ID 作为筛选条件，避免从重叠位置手动抄录。

# 不建议的规避方式

- 不建议隐藏字段名或删除字段说明图标，因为这些字段对排障语义和可访问性仍有价值。
- 不建议修改后端返回字段名或日志采集字段，这会扩大影响到 API、Orval 和历史日志解释。
- 不建议临时关闭日志详情中的链路字段展示，否则会降低日志审计页面的排障能力。

# 正式修复前注意事项

- 修复应优先限定在 Web 管理端日志详情样式或展示组件内。
- 不应改变后端日志采集、数据库字段、API 响应或 OpenAPI / Orval 类型。
- 字段说明 tooltip 的键盘聚焦和悬浮说明能力应保留。
