# 直接原因

管理后台证书编辑弹窗在回显已有证书时，文件状态提示和图片信息展示的数据消费逻辑存在偏差：

- PDF/兼容文件区域把“已有文件可用”状态渲染成了面向上传流程的 `证书文件已就绪` 文案。
- 图片信息区域未正确消费已有证书的图片数组、主图标识、缩略图 URL 或原图 URL，导致编辑弹窗内图片信息无法正常展示。

# 根本原因

证书编辑弹窗对“新增上传态”和“编辑回显态”的展示边界不够清晰，文件与图片字段缺少统一的数据归一化与 UI 状态映射：

- 文件状态文案可能复用了上传完成后的提示，没有区分已有文件回显、待替换文件、上传成功文件和兼容文件缺失等场景。
- 图片列表可能依赖新增上传流程生成的临时结构，而已有证书接口返回的数据结构未被转换为弹窗组件期望的展示模型。
- 主图状态、缩略图 URL、原图 URL、图片排序或图片 ID 等字段可能在表单初始化阶段未完整传入图片组件。
- 既有 BUG `BUG-0089-admin-certificate-edit-image-filename-noise` 表明该弹窗已有图片文件名/对象 key 展示噪音，说明图片展示模型与面向运营人员的 UI 文案之间仍存在职责混杂。

# 触发条件

1. 管理员登录管理后台。
2. 进入证书列表。
3. 打开任一已有证书的编辑弹窗。
4. 该证书存在 PDF/兼容文件或图片信息。
5. 弹窗初始化文件与图片字段时，展示层未正确区分文件状态与图片展示模型。

# 需验证线索

- 编辑弹窗表单初始化时，证书文件字段是否被映射为“已有文件”而非“本次上传已就绪”。
- 图片组件是否收到已有图片数组，以及每张图片的 `id`、`url`、`thumbnail_url`、`is_primary`、排序字段和展示名称。
- 主图判断是否依赖字段名不一致、布尔值类型不一致或缺省值，导致全部图片信息被隐藏。
- PDF/兼容文件区域是否存在固定文案或根据文件字段 truthy 状态直接显示的提示。
- 修复时是否保留上传失败、文件缺失、格式不兼容等必要错误提示。

# 分类

- 类型：code / ui-state / data-mapping
- 层级：管理后台 Web 前端
- 数据风险：低，预计不涉及数据库结构变更
- API 风险：低到中，优先检查前端映射；若接口缺少必要图片字段，则需后续通过 OpenSpec Change 评估 API 变更
- 回归风险：中，需覆盖已有证书编辑、新增图片、替换/删除图片、主图状态和保存后再次回显
