# Workaround

## 临时规避方案

正式修复前，可先从素材、数据和运营侧降低影响：

1. 对高频访问品牌的图片类证书优先确认缩略图对象存在，避免卡片进入 `file_url` fallback。
2. 对暂时无法补齐缩略图的图片证书，优先替换为移动端可接受体积的 WebP、JPG 或 PNG 素材，降低误拉原文件时的流量影响。
3. 对 PDF/文档证书保持文件类型占位，不临时伪装为图片证书展示。
4. 在发布前抽查品牌详情页证书 Tab 的 Network，发现卡片直接请求原文件时优先下架或替换对应证书素材。

## 不足与风险

- 人工补缩略图不能保证后续新增或替换证书继续符合卡片展示策略。
- 压缩原文件会影响详情页预览、下载或管理端高清查看质量。
- 运营侧抽查无法覆盖所有品牌证书和历史对象。
- 如果前端模板仍保留 `thumbnail_url || file_url`，只要缩略图缺失，卡片仍可能再次退回原文件。

## 正式修复方向

- 小程序品牌详情证书卡图片展示只允许使用 `thumbnail_url`、卡片专用展示 URL 或占位资源，不直接使用 `file_url`。
- 后端品牌证书摘要接口如需继续返回 `file_url`，应明确其仅用于详情、预览或打开动作；卡片展示字段应与原文件字段分离。
- 图片证书使用 `images/default/brand-certificates/` 前缀；PDF/文档证书使用 `files/default/brand-certificates/` 前缀。
- 若发现历史图片证书仍落在文件前缀、缩略图缺失或对象漂移，修复 Change 中记录 dry-run、apply 和幂等摘要。
- 增加小程序静态检查、接口回归和 DevTools/真机 Network 验收，防止证书卡片再次回退原文件。
