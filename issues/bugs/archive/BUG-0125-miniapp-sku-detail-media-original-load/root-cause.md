# 根因分析

## 直接原因

微信小程序 SKU 详情接口组装媒体数据时，图片媒体项的展示 URL 与预览 URL 使用同一个原图地址；小程序详情页顶部媒体轮播又直接以 `item.url` 渲染图片。因此用户进入详情页后，首屏图库请求的是 SKU 原图，而不是已有 `.thumb` 缩略图。

## 根本原因

小程序媒体缩略图优化此前主要覆盖了首页、商品列表、搜索结果、Banner 和商品卡片等列表型入口，但没有同步扩展到商品详情页媒体契约。详情页仍沿用“媒体 `url` 即可展示和预览”的早期设计，没有区分：

- 首屏展示用轻量缩略图；
- 预览用原图；
- 视频播放用原视频；
- 视频封面用图片缩略图。

## 触发条件

- 用户进入微信小程序商品详情页。
- SKU 存在一张或多张图片，且原图体积明显大于缩略图。
- 弱网、真机、首次访问、缓存未命中或对象存储链路较慢时，体验更明显。
- 含视频的 SKU 还会受到视频封面仍引用原图的影响。

## 分类

- 缺陷类型：code / design
- 影响层级：后端接口契约 + 微信小程序渲染
- 媒体类型：SKU 图片、缩略图、视频封面
- 回归关系：与 `BUG-0110-miniapp-card-banner-thumbnail-usage` 相关，属于小程序媒体缩略图覆盖范围遗漏。

## 证据摘要

- 详情接口 `GET /api/v1/miniapp/skus/{sku_id}` 当前对详情卡片主图使用原图 URL。
- 后端媒体项中图片 `url` 与 `preview_url` 均指向原图。
- 小程序详情页 `<image>` 直接绑定 `item.url`。
- 商品列表与首页测试已断言 `.thumb` 缩略图契约，而详情页测试仍断言原图契约。
