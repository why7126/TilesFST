# 临时规避方案

## 可用规避

在正式修复前，可通过运营和素材侧降低影响：

1. 优先压缩新上传 SKU 原图，避免详情页首屏请求超大图片。
2. 对重点商品确认对象存储中存在同目录 `.thumb` 缩略图，并避免公开 SKU 长期引用 pending 主图。
3. 对含视频商品优先维护较轻的视频封面图，减少首屏 poster 拉取原图的等待。
4. 在真机验收或发布前检查中优先覆盖多图 SKU、弱网和首次进入详情页场景。

## 局限

以上规避不能从根本上解决问题。只要详情接口和详情页渲染仍使用原图字段，用户首屏进入详情页时仍可能请求大图；对象存储侧 `.thumb` 存在也不会自动带来详情页性能收益。

## 正式修复方向

正式修复应在后端 SKU 详情接口中区分展示 URL 与预览 URL，并在小程序详情页首屏使用缩略图字段。视频封面应优先使用主图缩略图，视频播放 URL 保持原视频。
