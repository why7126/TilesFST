# Root Cause - BUG-0085 管理后台视频上传长时间卡在 99%

## 结论摘要

当前证据显示，“上传中 99%”首先是前端进度表达的结果：管理端视频上传使用浏览器 `onUploadProgress` 事件计算请求体上传进度，并把进度封顶在 99%；只有上传接口成功返回后，前端才会设置 100 并进入“视频已添加”状态。

因此，99% 长时间停留不一定表示浏览器还在传输文件，更可能表示请求体已接近或已经发送完成，前端正在等待后端完成对象存储写入并返回响应。若该等待阶段被外层 HTTPS Nginx、容器内 Web Nginx、CDN/网关默认超时截断，或对象存储响应过慢，用户就会看到长时间停在 99%，最终可能失败。

## 直接原因

| 项 | 说明 |
|---|---|
| 前端进度封顶 | `uploadTileVideo()` 将浏览器上传进度限制为最大 99%，等待接口响应成功后才置为 100 |
| 后端同步写入 | 上传接口读取完整文件后同步调用对象存储 `put_object()`，对象写入完成前不会返回 `object_key` 与 `url` |
| UI 状态不足 | 99% 后仍显示“上传中 99%”，没有区分“请求体上传中”和“服务端保存/等待确认中” |
| 生产链路风险 | 若外层反代、容器内 Web Nginx 或网关未应用上传专用超时配置，可能在对象写入或响应返回阶段触发 60 秒级超时 |

## 根本原因

该问题的根本原因是上传链路缺少端到端阶段语义和生产部署生效验证：

1. 前端只暴露一个线性百分比，把客户端请求体上传进度与服务端对象存储保存阶段混在同一个“上传中”状态里。
2. 后端上传接口采用同步写入对象存储后再返回的闭环模式，这对大视频和云对象存储网络延迟敏感。
3. `BUG-0081` 已经为上传路径补充过专用 Nginx 超时与 `proxy_request_buffering` 配置，但当前生产现场仍需确认外层 HTTPS 反代、当前 Web 镜像和运行中容器是否都已应用同等配置。
4. 缺少面向生产的上传 smoke 记录，无法仅凭截图判断是“最终成功但等待久”、还是“对象已写入但响应链路超时”、或“对象存储写入失败”。

## 触发条件

- 视频文件较大或网络上传耗时较长。
- 对象存储写入耗时接近或超过反代、网关、CDN 默认 upstream 超时。
- 生产外层 Nginx 未对 `/api/v1/admin/uploads/` 配置上传专用 `proxy_send_timeout`、`proxy_read_timeout`、`send_timeout`。
- 容器内 Web Nginx 使用旧镜像或旧配置，未启用上传路径专用 location。
- 对象存储 endpoint、region、访问风格、权限或网络链路异常，导致后端迟迟无法完成 `put_object()`。
- 前端在 99% 等待阶段没有展示“正在保存视频/等待服务器确认”，用户误判为客户端上传卡死。

## 缺陷分类

| 分类 | 判断 |
|---|---|
| frontend | 进度状态表达不完整，99% 后缺少服务端保存阶段文案 |
| deployment | 生产外层反代、容器内 Web Nginx、网关超时配置可能未完全生效 |
| object-storage | 大视频写入云对象存储时对 endpoint、region、权限、网络和响应耗时敏感 |
| observability | 缺少现场 Network、对象存储对象、Nginx/backend 日志组合证据 |
| database | 暂未发现数据库结构或数据写入根因 |

## 与 BUG-0081 的关系

`BUG-0081-prod-cos-video-upload-fails` 已记录过同类模式：前端上传停在 99%，COS Bucket 中已出现对象，但浏览器最终拿到 504，Nginx 日志出现约 60 秒后的 499。该问题的修复方向是上传路径专用超时、`proxy_request_buffering off` 和部署文档同步。

BUG-0085 应优先判断是否为 BUG-0081 的部署回归或生产 smoke 未闭环。如果最终确认生产已应用相关超时配置且请求最终返回 200，则 BUG-0085 更偏向前端状态表达与长耗时提示缺陷。

## 待确认事实

| 事实 | 需要收集 |
|---|---|
| 请求最终状态 | 浏览器 Network 中上传请求最终是 200、504、499、502、pending 还是其他错误 |
| 对象是否写入 | 对象存储 Bucket 中是否出现与本次上传对应的 `videos/...` 对象 |
| 失败耗时 | 是否约 60 秒失败，若是则强指向反代/网关默认超时 |
| 运行中 Nginx 配置 | 外层 HTTPS Nginx 和容器内 Web Nginx 是否都包含上传专用 location 和 600 秒级超时 |
| 后端日志 | 是否存在对象存储不可用、权限错误、region mismatch、NoSuchBucket、签名错误或网络超时 |
