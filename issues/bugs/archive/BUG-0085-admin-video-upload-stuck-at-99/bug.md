# 现象

管理后台上传 SKU 视频时，上传进度长时间停留在 99%，页面持续显示“上传中 99%”，用户无法判断上传是否仍在进行、已经成功、失败，还是进入服务端处理阶段。

截图附件见 `screenshots/upload-stuck-at-99.png`。

# 复现步骤

1. 打开生产环境管理后台。
2. 进入 SKU 新增或编辑弹窗的视频上传区域。
3. 选择一个合法视频文件上传，例如 MP4，且文件大小不超过系统视频上传上限。
4. 观察上传进度条和“上传中 xx%”文案。
5. 当进度显示 99% 后继续等待，记录停留时长。
6. 在浏览器 Network 中检查 `POST /api/v1/admin/uploads/tile-videos` 的最终状态码、耗时和响应体。
7. 同步检查对象存储 Bucket 中是否已经出现 `videos/...` 对象，以及 Web Nginx、外层 HTTPS Nginx、backend 日志中是否存在 `504`、`499`、超时或对象存储异常。

# 期望结果

- 合法视频上传后，接口应在合理时间内返回 `200`。
- 响应体应包含 `object_key` 与 `/media/{object_key}` URL。
- 前端应把视频加入 SKU 表单的视频列表，并显示“视频已添加”。
- 若后端仍在保存对象或等待对象存储响应，前端应展示明确的处理中状态，而不是长期停留在“上传中 99%”。
- 若上传失败、超时或对象存储不可用，前端应展示明确错误，允许用户重试。

# 实际结果

- 前端上传进度长时间停留在 99%。
- 页面仍显示“上传中 99%”，没有进入“视频已添加”状态，也没有明确失败原因。
- 当前证据尚未确认最终请求状态码；需在 Network、对象存储和 Nginx/backend 日志中补充确认。

# 影响范围

- 影响端：管理后台 Web。
- 影响页面：SKU 新增/编辑弹窗的视频上传区域。
- 影响能力：SKU 视频素材上传、视频对象写入、上传结果确认与 SKU 表单保存闭环。
- 影响用户：管理员无法判断视频是否上传成功，可能反复重试。
- 潜在副作用：如果对象存储已写入但接口响应链路超时，可能产生未被 SKU 业务数据引用的孤儿视频对象。

# 严重等级说明

严重等级为 `high`。该问题发生在生产管理后台视频上传链路，直接影响商品视频资料维护。视频上传一旦无法闭环，管理员无法把素材可靠绑定到 SKU；如果重复上传，还可能造成对象存储冗余对象堆积。

# 初步分析

当前前端视频上传进度并不等价于端到端完成度。`uploadTileVideo()` 使用浏览器上传进度事件计算进度，并通过 `Math.min(99, ...)` 将上传阶段进度封顶到 99%。只有上传接口 Promise 成功返回后，`TileSkuFormModal` 才会把进度设置为 100 并切换为 `uploaded`。

因此，“卡在 99%”更可能表示浏览器请求体已经接近或已经上传完成，但前端仍在等待后端响应。后端上传链路会读取完整文件内容，再同步调用对象存储客户端 `put_object()`，对象存储写入完成后才返回 `object_key` 和 `url`。若对象存储写入耗时较长、外层 HTTPS Nginx 或容器内 Web Nginx 超时、CDN/网关默认 60 秒截断，前端就会长期停在 99%，最终可能返回 `504` 或请求失败。

该模式与 `BUG-0081-prod-cos-video-upload-fails` 高度相关：历史记录中同样出现“前端 99% 后等待、COS 中已出现对象、响应链路 504/499”的现象。当前仓库已存在上传路径专用 Nginx 模板配置，但生产现场仍需确认外层 HTTPS 反代、当前 Web 镜像和运行中容器是否已经应用该配置。

# 复现与排查要点

| 检查项 | 判断依据 |
|---|---|
| 浏览器请求 | `POST /api/v1/admin/uploads/tile-videos` 是否最终返回 `200`、`504`、`499` 或一直 pending |
| 对象存储 | Bucket 中是否已经出现符合前缀规范的 `videos/...` 对象 |
| 外层 HTTPS Nginx | `/api/v1/admin/uploads/` 是否配置 `proxy_send_timeout`、`proxy_read_timeout`、`send_timeout`，建议不低于 600 秒 |
| 容器内 Web Nginx | 运行中配置是否包含上传路径专用 location，且 `proxy_request_buffering off` 与上传超时已生效 |
| backend 日志 | 是否出现 `对象存储不可用`、COS/TOS/MinIO 超时、签名不匹配、AccessDenied、NoSuchBucket、region mismatch 等异常 |
| UI 状态 | 99% 后是否需要改为“正在保存视频，请稍候”，避免把服务端等待误导为客户端上传卡死 |

# 建议后续处理

1. 先用同一个视频做生产复现，补齐 Network 状态码、请求总耗时、对象存储对象是否存在、Nginx/backend 日志。
2. 若最终返回 `504` 或日志出现约 60 秒 `499/504`，优先按 `BUG-0081` 同类回归或部署未生效处理，检查外层与容器内 Nginx 上传专用超时。
3. 若请求最终返回 `200` 但等待时间很久，则应补充前端状态文案，将 99% 后的阶段区分为“正在保存视频”或“正在等待服务器确认”。
4. 若对象存储未出现对象且 backend 返回 `502` 或存储异常，则转向对象存储配置、权限、网络、endpoint、region 和访问风格排查。
