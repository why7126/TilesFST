# Root Cause

## 直接原因

管理后台瓷砖 SKU 列表的素材列基于 `has_main_image` 渲染了「主图已设 / 缺主图」标签；当 `has_main_image = true` 时，即使同列已经展示图片数量，也会额外展示「主图已设」。

## 根本原因

素材列的信息层级没有随业务规则收敛而调整。当前规则下，只要 SKU 有图片就会自动具备主图兜底，因此「主图已设」不是独立的维护判断项；列表仍把它作为正向状态标签展示，导致冗余信息进入主列表。

## 触发条件

- 管理后台进入「瓷砖 SKU」列表。
- SKU 至少存在一张图片。
- 列表项 `has_main_image` 为 `true`。
- 素材列同时展示主图状态标签和图片/视频数量。

## 缺陷分类

- 分类：`design`
- 端：管理后台 Web
- 模块：瓷砖 SKU 管理
- 性质：列表展示信息冗余，不涉及数据写入、接口契约或权限边界。

## 修复方向

- 素材列移除「主图已设」正向标签。
- 保留图片数量与视频数量展示。
- 对缺图或素材不完整状态，继续通过图片/视频数量展示表达，避免把正常状态当成标签噪音。
