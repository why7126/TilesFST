# 临时规避方案

## 可用规避

在正式修复前，可以采用以下低风险运维和内容侧缓解措施：

1. 优先压缩品牌列表 Banner、品牌 Logo、品牌证书图片和品牌下商品主图，避免上传超大原图作为高频展示素材。
2. 对已知访问慢的品牌素材，人工确认同目录 `.thumb` 对象存在且文件体积明显小于原图。
3. 临时减少品牌列表页上线 Banner 数量，优先保留首屏关键图。
4. 对生产媒体域名或 `/media/` 路径启用网关、Nginx 或 CDN 缓存策略时，先在测试环境验证缓存命中、权限边界和图片更新后的失效策略。
5. 在后端日志中抽查 `media_read` 的 `elapsed_ms` 与 `size_bytes`，优先处理高耗时、大体积图片。

## 不建议的规避

- 不建议关闭 `/media` 受控读取并让小程序直连未授权对象存储。
- 不建议只把接口字段改成 `.thumb` URL 后即认为性能问题解决；必须验证 `.thumb` 对象真实存在且足够轻量。
- 不建议删除 `.thumb` 缺失回退原图能力，因为这会把“慢图”变成“破图”。
- 不建议通过降低图片显示质量或移除品牌图来规避，这会影响品牌展示体验。

## 剩余风险

临时规避只能降低部分素材体积或减少首屏请求数量，无法系统性保证历史对象、端侧懒加载和生产缓存策略全部闭环。正式修复仍需要通过 OpenSpec Change 明确实现与验收范围。
