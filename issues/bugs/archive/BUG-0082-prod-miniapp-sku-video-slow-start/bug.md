# 现象

微信小程序切换到生产环境后，进入包含商品视频的商品详情页，点击轮播区视频播放控件后需要等待较久才开始播放。

等待期间可能出现首帧迟迟不出现、封面不稳定或用户误以为视频不可播放的体验问题。

# 复现步骤

1. 将微信小程序切换到生产环境。
2. 打开一个已配置商品视频的 SKU 商品详情页。
3. 在商品详情页轮播区域切换到视频项。
4. 点击视频播放控件。
5. 记录从点击播放到视频出现首帧并开始播放的耗时。

# 期望 vs 实际

## 期望

- 点击播放后，视频应较快出现首帧并开始播放。
- 视频封面应稳定展示，避免播放启动前长时间黑屏或空白。
- 弱网或视频加载较慢时，应有可理解的等待体验或降级策略。

## 实际

- 生产环境下视频播放启动耗时较长。
- 用户在商品详情页查看视频素材时需要明显等待，影响商品展示和客户演示体验。
- 当前仍缺少真实生产 SKU、机型、网络、视频大小和首帧耗时数据，需要在后续补齐复现证据。

# 影响范围

- 端：微信小程序。
- 页面：商品详情页 `src/miniapp/pages/tile-detail/`。
- 接口链路：`GET /api/v1/miniapp/skus/{sku_id}` 返回视频媒体 URL，视频播放读取 `/media/{object_key}`。
- 存储链路：生产对象存储或 S3 兼容存储视频对象读取。
- 用户体验：店主或客户在商品详情页查看商品介绍、铺贴效果、工艺视频时等待时间过长。

# 严重等级说明

严重等级为 `high`。

理由：

- 该问题发生在生产环境，影响小程序核心商品详情展示链路。
- 商品视频是 SKU 素材完整度和客户演示的重要组成部分，慢启动会直接降低展示效果。
- 已有相关历史缺陷 `BUG-0069-miniapp-sku-detail-carousel-video-not-playable`，说明该链路此前出现过播放可用性问题，本次属于同一能力的生产体验回归或残留风险。

# 初步排查方向

- 后端 `/media/{object_key}` 当前受控读取链路疑似整文件读取后返回普通响应，需确认是否支持视频 `Range` 请求、`206 Partial Content`、`Accept-Ranges` 与 `Content-Range`。
- 小程序商品详情页 `<video>` 已使用 `poster="{{item.cover_url || ''}}"`，但 SKU 详情媒体项当前可能没有有效视频封面 URL，需确认生产数据是否具备封面。
- 需排查生产 HTTPS 反代、Web 容器 Nginx、后端到对象存储链路、对象存储/CDN 回源、视频编码格式与文件大小。

# 待补充证据

- 生产 SKU ID 与视频对象 Key。
- 视频文件大小、格式、编码、时长。
- 机型、微信版本、网络类型。
- 点击播放到首帧的耗时。
- `/media/{object_key}` 使用 Range 请求时的响应状态码与响应头。
