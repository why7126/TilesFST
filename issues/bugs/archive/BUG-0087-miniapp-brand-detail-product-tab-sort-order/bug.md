# 现象

微信小程序品牌详情页的商品 Tab 用于展示当前品牌下的公开 SKU。该列表应由后端按默认排序稳定返回：发布时间升序、ID 升序；前端分页加载后应保持接口返回顺序展示。

当前品牌详情页商品 Tab 的排序规则与该期望不一致或尚未固化，导致同一品牌下多条商品的展示顺序可能不是发布时间从早到晚，且相同发布时间下缺少明确的 ID 升序兜底顺序。

# 复现步骤

1. 准备同一品牌下多条已公开 SKU。
2. 确保这些 SKU 存在可比较的发布时间，且至少包含发布时间不同的多条记录。
3. 打开微信小程序品牌详情页。
4. 查看商品 Tab 首屏商品顺序。
5. 继续上拉加载更多，观察分页追加后的整体顺序。

# 期望结果

- 品牌详情页商品 Tab 仅召回当前品牌下可公开 SKU。
- 后端默认排序为发布时间升序、ID 升序。
- 前端首屏和加载更多后的列表顺序与后端返回顺序一致。
- 同一发布时间下使用 ID 升序保证分页稳定性。

# 实际结果

- 品牌详情页商品 Tab 当前排序规则待修正或待确认，可能未按发布时间升序、ID 升序稳定返回。
- 分页场景下若排序不稳定，可能出现展示顺序与期望不一致，甚至产生跨页顺序漂移风险。

# 影响范围

- 微信小程序品牌详情页：`src/miniapp/pages/brand-detail/`
- 小程序公开商品列表接口：`GET /api/v1/miniapp/products`
- 后端品牌商品列表查询排序逻辑
- 关联需求：`REQ-0058-brand-detail-home-page`

# 严重等级说明

严重等级暂定为 `medium`。

该问题不阻断品牌详情页打开，也不影响商品详情页访问，但会影响品牌页商品展示顺序的可预期性和运营编排/验收一致性。若后续确认排序错误导致重点商品长期错位、分页重复或遗漏，可在评审阶段上调严重等级。

# 已确认点

- “发布时间”在当前数据模型中对应的事实字段为 `published_at`；历史空值使用 `created_at` 作为排序兜底。
- 排序修复应用于 `/api/v1/miniapp/products` 的 `brandId` 默认过滤场景，覆盖品牌详情页商品 Tab。
- 普通商品列表、搜索页、新品榜、热销榜保持既有排序策略不变。
