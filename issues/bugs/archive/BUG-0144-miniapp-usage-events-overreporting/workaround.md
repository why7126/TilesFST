# 临时规避方案

当前没有对用户侧可见功能的阻断性影响，不建议直接关闭 `/api/v1/usage-events` 或移除所有小程序埋点。

在正式修复前，可采用以下临时规避方式降低排查噪音：

1. 本地调试商品列表页或搜索页时，在微信开发者工具网络面板中过滤业务 API，临时隐藏 `/api/v1/usage-events`。
2. 分析商品曝光或搜索转化数据时，临时排除 `product_list_item_exposure`、`product_card_exposure`、`search_input` 等高频事件，避免把重复曝光或逐字符输入误读为真实行为规模。
3. 若后端写入量短时过高，可在运维层面临时降低 usage-events 日志详情采样，但不应影响接口可用性和主流程。

# 不建议的规避方式

- 不建议直接关闭 `/api/v1/usage-events` 接口，否则会影响其他页面真实行为采集。
- 不建议只在后端丢弃事件，因为前端请求数量和网络噪音仍然存在。
- 不建议仅删除某一个事件名而不定义新口径，否则会造成商品列表、搜索页和商品卡组件的报表口径断层。

# 正式修复前注意事项

- 埋点失败必须继续不阻断商品列表浏览、搜索输入、结果展示、商品点击或分享。
- 修复应保留必要的产品分析能力，只压缩重复、高频和无边界事件。
- 若需要短期验证，可以只在本地或测试环境记录 usage-events 数量对比，不写入真实客户数据或敏感请求内容。
