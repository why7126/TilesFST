# 小程序返回首页按钮第二次点击失效回归

## 现象

微信小程序中，带“返回首页”悬浮按钮的页面首次点击可以返回首页；再次进入同一页面或其他带该按钮的页面后，第二次点击返回首页按钮会失效，表现为不跳转或无明显反馈。

该问题与已归档的 `BUG-0109-miniapp-home-button-one-time-failure` 现象高度一致，当前按回归或仍可复现问题处理。

## 复现步骤

1. 打开微信小程序。
2. 进入任意带返回首页悬浮按钮的非首页页面，例如品牌列表页、分类页、商品详情页、搜索结果页或证书页。
3. 点击返回首页按钮，确认首次点击是否能正常回到首页。
4. 再次进入同一页面，或进入另一个带返回首页按钮的页面。
5. 再次点击返回首页按钮。
6. 观察第二次点击是否不再触发跳转、按钮无反馈，或需要依赖系统返回、TabBar、重新进入小程序等方式绕行。

## 期望结果

- 所有带返回首页按钮的小程序页面，每次点击都能稳定回到首页。
- 同一页面重复进入后，返回首页按钮状态不应被历史点击锁住。
- 跨页面进入后，返回首页按钮不应继承其他页面的失效状态。
- 快速重复点击时可以防重复导航，但防重复锁必须自动释放，不能导致后续正常点击失效。
- 当前已经在首页或导航失败时，应有明确且可恢复的兜底行为。

## 实际结果

- 首次点击返回首页按钮后，后续再次点击可能失效。
- 用户反馈为“目前每个页面点击一次后，再一次点击就失效了”。
- 现有静态测试只检查组件源码中存在导航锁释放逻辑，尚未覆盖真实的连续点击状态流，因此无法阻止此类回归。

## 影响范围

- 端：微信小程序
- 页面：使用 `home-floating-button` 的主要非首页页面，包括但不限于分类页、商品列表页、品牌列表页、品牌详情页、证书列表页、收藏页、搜索结果页、商品详情页。
- 组件：`src/miniapp/components/home-floating-button/`
- 行为：`wx.switchTab` 返回首页、`wx.reLaunch` 兜底、按钮 `navigating` 防重复状态、页面重新进入后的状态恢复。
- 用户影响：用户从深层页面回到首页的核心导航路径不稳定，容易误以为按钮不可用或页面卡住。

## 严重等级说明

- 严重等级：high
- 理由：返回首页按钮是小程序全局导航辅助能力，覆盖多个主要业务页面。二次点击失效会阻断用户从深层页面快速回到首页，且与已归档高严重度缺陷 `BUG-0109` 现象一致，具备回归风险。

## 初步分析

- 历史修复 `fix-miniapp-home-navigation-repeat-click` 已归档，当前组件仍保留 `navigating` 状态锁、800ms 延迟解锁、`pageLifetimes.show()` 重置和 `reLaunch` 兜底。
- 仍需通过真机或微信开发者工具确认：`switchTab` 成功后原页面组件是否按预期触发 `pageLifetimes.show()` 或延迟解锁；跨 TabBar 页面与非 TabBar 详情页是否一致。
- 当前测试应补充可执行的状态流验证，覆盖“首次点击成功、再次进入页面、第二次点击仍可触发返回首页”的场景，而不是仅检查字符串存在。

## 建议验证矩阵

| 场景 | 页面类型 | 验证点 |
|---|---|---|
| 同页重复进入 | 商品详情页 / 品牌详情页 | 第一次返回首页后，再次进入同页，第二次点击仍返回首页 |
| 跨页重复进入 | 分类页 → 品牌列表页 → 搜索结果页 | 不同页面的按钮状态互不污染 |
| TabBar 页面 | 分类页 / 品牌列表页 / 证书页 / 收藏页 | `switchTab` 返回首页后再次进入仍可点击 |
| 非 TabBar 页面 | 商品列表页 / 品牌详情页 / 商品详情页 | `switchTab` 或 `reLaunch` 兜底后状态可恢复 |
| 快速重复点击 | 任意带按钮页面 | 防重复点击不产生页面栈异常，且锁会释放 |
