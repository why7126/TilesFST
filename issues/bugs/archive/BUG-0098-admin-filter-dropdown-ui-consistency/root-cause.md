# Root Cause

## 直接原因

管理端多个页面的筛选条件下拉框未统一采用瓷砖类目页的筛选下拉交互和视觉样式，导致页面之间在触发位置、弹层对齐、控件尺寸、选项状态和样式细节上出现差异。

## 根本原因

管理端筛选控件缺少统一的页面级复用约束或验收基准。各页面在实现筛选区时可能分别处理 Select/Dropdown、筛选栏布局和局部样式，未将瓷砖类目页的下拉交互作为统一标准沉淀为可复用组件或明确规范。

由于本命令阶段禁止读取或修改 `src/`，以上根因为基于现象和缺陷描述的初步归因；后续进入 OpenSpec 修复阶段时，需要结合管理端页面实现和 Design System 组件进一步确认具体代码位置。

## 触发条件

- 管理员登录管理端。
- 进入包含筛选下拉框的后台页面。
- 对比瓷砖类目页与其他管理端页面的筛选下拉框。
- 操作筛选条件并观察下拉框展开位置、选项样式、状态反馈和重置表现。

## 缺陷分类

- 分类：`design`
- 端：管理后台 Web
- 模块：管理端筛选区 / 下拉控件 / Design System 应用
- 性质：跨页面 UI 一致性缺陷，不涉及数据写入、接口契约、数据库结构或权限边界。

## 修复方向

- 以瓷砖类目页的筛选下拉交互和样式作为基准。
- 梳理管理端所有筛选下拉框页面，优先复用统一筛选控件或统一筛选栏样式。
- 确保下拉位置、弹层对齐、宽度策略、悬停态、选中态、空态、加载态和重置后的表现一致。
- 使用管理端 Design System semantic token，避免页面级裸样式继续分化。
- 保持现有筛选参数、接口请求和查询结果语义不变。
