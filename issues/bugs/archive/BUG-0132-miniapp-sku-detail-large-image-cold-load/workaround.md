# Workaround

## 临时规避方案

在正式修复前，可通过运营和素材侧先降低用户可见影响：

1. 对已知商品详情页中的 1MB 以上普通展示图进行人工压缩，优先处理 PNG 大图。
2. 非透明 PNG 优先转换为 JPG 或 WebP 展示素材。
3. 对首屏关键图片控制到 100-300KB，普通详情图控制到 150-500KB。
4. 保留高清原图作为预览或后台素材，不作为详情页默认展示图。
5. 对已知慢商品优先减少首屏外详情图数量，避免进入详情页时一次性加载全部大图。

## 不足与风险

- 人工压缩只能处理已知商品，无法防止后续上传再次产生大图。
- 若接口和小程序仍绑定原图 URL，人工生成展示图后也可能不会被端侧使用。
- 若没有对象存储和媒体 URL 四联验收，容易出现展示图存在但页面仍请求原图的偏差。

## 正式修复方向

- BUG 修复侧：限制商品详情页冷加载大图，确保普通展示路径使用适配小程序的图片资源，并启用首屏外图片 lazy-load。
- 需求增强侧：推进 `REQ-0115-media-multi-variant-images`，建设 `thumbnail / display / original` 多规格媒体能力。
