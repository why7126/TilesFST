# Root Cause

## 直接原因

小程序品牌列表页类目区当前使用流式换行布局承载所有类目胶囊。类目胶囊作为连续节点进入同一个容器后，会按内容宽度和剩余空间自然排列；当不同类目名称长度不一致时，第二列的起始位置会受到前一枚胶囊宽度影响，无法形成稳定的右侧列左对齐线。

## 根本原因

实现层将“可换行胶囊列表”和“固定两列视觉布局”混为同一种布局处理。当前样式没有给类目区定义明确的两列轨道，也没有给胶囊建立受列宽约束的文本省略策略，因此在类目名称长度变化时，布局只能表现为流式折行，而不是两列网格。

## 触发条件

- 品牌列表页存在某个品牌拥有多个末级类目。
- 类目名称长度不一致，尤其左侧胶囊宽度变化较大时。
- 长类目名称接近或超过半列可用宽度时，容易进一步暴露文本撑开、溢出或列宽不稳定风险。

## 缺陷分类

- 分类：code
- 子类：miniapp frontend layout
- 影响层：微信小程序 `pages/brand-list/index.*`
- 数据层原因：无
- 接口层原因：无

## 修复约束

- 保持类目来源和去重逻辑不变。
- 保持类目点击跳转商品列表逻辑不变。
- 保持埋点字段不变。
- 类目区应使用固定两列布局或等效列约束。
- 胶囊文本应采用单行省略号，避免文字撑破边框或换行破坏卡片节奏。
