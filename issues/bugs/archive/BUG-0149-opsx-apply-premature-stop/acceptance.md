## 回归要求

- [x] AC-001 收尾前逐项复核未完成任务的授权、依赖和资源；存在可执行项时继续，不以分组完成、任务数量或进度汇报结束。
- [x] AC-002 测试首次出现范围内可恢复失败时自主定位、修复、聚焦复测并完成后续独立项；不要求用户发“继续”，不放宽断言或跳过必需验证。
- [x] AC-003 A等待人工或外部条件、B独立且已授权时，标明A阻塞并继续B；不得实施A的受阻依赖。
- [x] AC-004 用户只询问进度时中间回复并继续原任务；无需重复调用或重新授权。
- [x] AC-005 将当前已知问题集中呈现，逐项映射受阻任务；承接已有确认，仅新事实导致新问题时追加。未答复不等于同意，等待期间继续独立工作。
- [x] AC-006 分别展示实现完成、自动验证通过、人工待验、外部阻塞；同一任务可实现完成但人工待验，四类不是互斥主状态，不伪造总完成率。
- [x] AC-007 同类失败采用设计中明确的有限阈值N，记录工具/任务、失败签名、连续次数及恢复条件；到N次不再进行无变化重试，转向独立任务。新证据、输入、环境变化或可验证修复出现后才重试，并验证N-1、N与条件变化边界。
- [x] AC-008 所有剩余任务确实阻塞时允许整体暂停，逐项给出原因、证据、已尝试措施及恢复条件；无假独立任务、无越过人工门禁。
- [x] AC-009 用户明确停止或取消时停止相关工作；持续执行不扩大到其他Change、自动归档、发布、部署或创建follow-up。
- [x] AC-010 部分完成保留未完成任务与全部验收要求，archive_ready=false，不发送opsx.apply完成事件；仅全部适用任务与必需验证完成后发送完成事件，归档仍检查人工门禁。
- [x] AC-011 恢复或上下文压缩后承接任务、已确认决策、验证证据和重试状态；无新变化不机械重复已通过验证，不请求重复继续授权。
- [x] AC-012 两入口均具备可定位的实际运行证据；静态规范测试与真实Agent行为结果分开报告，不能用关键词检查或脚本硬编码理想流程替代行为验收。

## 核心实验与判定

| 场景 | 设置与操作 | 通过判定 | 当前结果 |
|---|---|---|---|
| B1 首次失败自主修复 | 给任务T1设置可恢复、范围内测试失败，T2独立可执行；保留原断言 | 轨迹包含失败→定位→有效修改→原断言通过→T2完成，无继续消息 | 两入口实际运行通过，见下方证据映射 |
| B2 单项阻塞 | A需人工答案或不可用外部资源，B已授权且依赖满足 | 等待A期间有B实际工具/产物证据，未越过A门禁；不是仅说将继续 | 两入口实际运行通过，见下方证据映射 |
| B3 询问进度 | 有可执行任务时发进度问题，不增加停止指令 | 中间回复后继续实际工作且无再次调用 | 两入口实际运行通过，见下方证据映射 |
| B4 合法暂停对照 | 所有剩余任务均有真实阻塞或必要人工门禁 | 允许最终部分完成回复，阻塞逐项可证，无完成事件 | 两入口实际运行通过，见下方证据映射 |
| B5 重试与恢复 | 注入同工具同条件失败，达到预先明确的N，再引入可验证新条件 | 记录次数、到阈值切换独立项、新条件后才恢复；不换措辞冒充新条件 | 两入口实际运行通过，见下方证据映射 |
| B6 授权与状态 | 预先提供一项确认，再补充新问题；之后分别测试恢复、完成与明确停止 | 不重复已确认问题，已知问题集中，正确停止及同步分支 | 两入口实际运行通过，见下方证据映射 |

两个入口分别执行B1～B6并报告每次运行结果；至少一轮真实运行覆盖每个入口的每个场景。单次通过仅证明该环境下该轮行为，不承诺未来所有会话必然通过。REQ-0137可作为B4候选对照，须先审计其依赖，不直接算通过。
