# 临时规避

尚无经过实际行为验证的永久规避方案。下列是当前规则下的临时操作建议，不表示BUG已修复。

- apply执行者在准备收尾时逐项核对未完成工作，继续已授权、依赖满足的任务；用中间消息汇报进度。
- 将当前已知人工问题按阻塞任务集中提出，沿用已有答复；等待期间处理独立工作。没有可执行项时明确列出阻塞和恢复条件。
- 若已错误结束，用户可用“继续当前Change中已授权且依赖满足的任务，承接已有确认；只对真正受阻项提问”恢复上下文。这是临时补救，仍增加用户负担，不能作为验收通过。
- 对REQ-0137样例，按实际需要回答Skeleton尺寸问题；不把该人工确认当作自动授权，也不因本BUG擅自修改范围外media-read.js。
- 连续同类工具失败时保留脱敏错误、尝试和恢复条件，转向独立任务；没有新输入、环境变化或可验证修复时不机械重试。后续设计需确定有限阈值。

## 边界与退出条件

不跳过测试、不降低验收、不伪造applied、不越过Skeleton确认、归档发布及不可逆动作授权。所有剩余工作真实受阻时允许暂停。

acceptance.md中的行为回归完成后再依据验证结果决定是否撤销临时补救；当前有效性未验证。
