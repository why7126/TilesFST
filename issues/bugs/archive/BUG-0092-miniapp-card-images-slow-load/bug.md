# 现象

微信小程序体验版页面加载速度较慢。进入首页或商品列表页后，商品卡片的文字内容先出现，卡片图片需要等待较久才逐步加载完成；部分图片可能加载失败并显示兜底图。

# 复现步骤

1. 打开微信小程序体验版。
2. 进入首页，观察 Banner、新品推荐、热销推荐和“全部产品”卡片图片的加载顺序与耗时。
3. 下滑到“全部产品”区域，或进入商品列表页、品牌商品列表页、搜索结果页。
4. 观察商品卡片图片是否长时间空白、逐张补齐或触发兜底图。
5. 使用微信开发者工具或真机调试网络面板筛选 `/media/` 请求，记录首屏请求数量、单张资源大小、P50/P95 耗时、失败状态和 HTTP 状态码。

# 期望结果

- 首屏核心商品卡片图片应在可接受时间内完成加载。
- 非首屏或滚动区域图片应按可见性逐步加载，避免一次性拉取过多不可见图片。
- 商品卡片应优先使用适合列表展示的轻量封面或缩略图，详情页仍可访问原图。
- 数据库中的公开 SKU 主图引用应能在对象存储中找到，不应出现 404、迁移残留 key 或长期空图。
- 媒体读取链路应具备必要缓存和可排障观测，能定位图片慢加载发生在小程序端、后端 `/media` 代理、对象存储读取还是对象缺失。

# 实际结果

- 首页加载时会同时拉取首页聚合数据和“全部产品”第一页，首屏可能渲染 Banner、新品 6 张、热销 6 张和全部产品 12 张，触发多张卡片图并发加载。
- 商品卡片组件当前直接渲染 `cover_image`，未见图片懒加载策略。
- 后端返回的 `cover_image` 是 `/media/{object_key}` 受控读取地址；该链路由后端从对象存储读取原始对象后返回，未见列表缩略图选择、图片缓存头或 `/media` 耗时日志。
- 本地行为事件中已有多条 `product_card_image_failed` 记录，集中在首页 `new_products`、`hot_products`、`all_products` 模块。
- 本地 SQLite 检查发现部分公开 SKU 主图对象引用缺失或无主图记录，体验版生产对象存储需进一步核对。

# 影响范围

- 微信小程序体验版首页。
- 微信小程序商品列表页、品牌商品列表页、搜索结果页中复用的商品卡片。
- 后端 `/api/v1/miniapp/home` 和 `/api/v1/miniapp/products` 返回的商品卡片 `cover_image`。
- 后端 `/media/{object_key}` 媒体读取链路。
- 对象存储中 SKU 主图对象与数据库 `tile_images.object_key` 的一致性。

# 严重等级说明

严重等级为 `high`。该问题影响小程序核心浏览路径，用户在首页和商品列表中首先感知到的是商品卡片图片；图片长时间空白、逐步补齐或失败会明显降低商品浏览效率和体验可信度。问题还可能叠加对象缺失、原图直出、后端代理读取、缺少缩略图和缺少媒体耗时观测等多处风险，需要优先进入复现和根因分析。
