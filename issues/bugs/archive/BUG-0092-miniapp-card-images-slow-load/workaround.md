# 临时规避

在正式修复前，可通过运营和配置手段降低体验版图片慢加载的影响：

1. 优先核对公开 SKU 主图对象是否存在，补传缺失图片或临时下架缺失主图的 SKU。
2. 控制首页新品、热销和全部产品首屏中带主图商品的数量，避免体验版首屏一次性触发过多 `/media/` 图片请求。
3. 管理端上传或替换 SKU 主图时，优先使用已经压缩过的 JPG / WebP 图片，避免使用大尺寸原图作为列表封面。
4. 对明显过大的 Banner、品牌 Logo、SKU 主图做人工压缩后重新上传。
5. 验收时使用微信开发者工具网络面板筛选 `/media/`，先确认是否存在 404/502；若存在缺失对象，应先修数据再判断性能。

# 注意事项

- 不建议让小程序绕过后端直接访问未授权对象存储。
- 不建议仅扩大上传图片大小上限；该问题主要在读取和展示链路，扩大上限会加重列表加载压力。
- 不建议用统一兜底图掩盖所有加载失败；兜底图只能降低破图感，不能解决卡片主图缺失或媒体链路慢的问题。
- 若引入 CDN、签名 URL、缩略图生成或对象存储直读，必须通过 OpenSpec Change 明确权限、安全、缓存和兼容策略。
