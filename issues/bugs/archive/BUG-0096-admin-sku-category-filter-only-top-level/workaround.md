# 临时规避

正式修复前，可采用以下方式降低管理后台维护成本：

1. 先选择目标一级类目，再结合关键词、品牌、状态或素材完整度筛选缩小 SKU 范围。
2. 对细分类目命名有稳定关键词的场景，可使用商品名称、SKU 编码或规格描述进行辅助查找。
3. 对需要批量巡检的细分类目，临时在类目管理或数据导出侧确认目标类目下的 SKU 清单，再回到 SKU 页逐条维护。
4. 如需要短期集中处理某一细分类目，可由后端或数据库只读查询生成待处理 SKU 列表，但不得直接修改生产数据绕过后台流程。

# 不建议的规避

- 不建议临时把所有二级类目提升为一级类目，这会破坏类目结构。
- 不建议通过修改 SKU 类目归属来适配当前筛选控件。
- 不建议让前端硬编码某些二级类目选项；这会造成类目变更后筛选项漂移。
- 不建议直接绕过后端接口查询或批量更新真实客户数据。

# 回滚建议

该问题当前处于记录与待修复阶段，没有代码改动可回滚。

后续修复如引入层级下拉或级联选择，应保留「全部类目」和现有一级类目筛选入口的等价能力；若修复后发现父类目筛选结果口径不符合预期，可先回滚为原一级类目筛选，再单独补充父子类目筛选语义设计。
