# 直接原因

管理后台「瓷砖 SKU」页面的类目筛选控件当前只渲染一级类目选项，没有把完整类目树中的二级、三级及更深层级类目纳入可选项。

从截图可见，类目下拉选项仅包含「高光产品」「金丝绒产品」「木纹砖产品」「莱姆石产品」「地铺石产品」「小地砖产品」等一级类目，未展示层级缩进、父子级结构或级联选择能力。

# 根本原因

当前 SKU 列表的类目筛选能力只满足了“按一级类目粗筛”的展示形态，没有与后台类目树和 SKU 真实归属层级建立一致的筛选契约：

- 类目管理能力已支持层级类目，SKU 维护场景也需要按细分类目定位商品。
- 代码确认：SKU 页筛选控件调用 `buildParentOptions(tree).filter((o) => o.id != null)` 构造类目选项，而 `buildParentOptions` 会跳过 `node.level >= 2` 的节点，因此列表筛选天然只会包含一级类目。
- 代码确认：SKU 新增/编辑弹窗内部已有递归 `buildCategoryOptions(tree)`，会将完整类目树按「父 / 子」路径扁平化，可证明后台已有可参考的全层级展示方式。
- 代码确认：后端 SKU 列表接口当前只接收单个 `category_id`；Repository 中过滤条件为 `t.category_id = :category_id`，属于精确匹配，不会自动包含子孙类目。
- 产品确认：父类目筛选语义采用“包含所有子孙类目 SKU”，不采用仅精确匹配父类目自身的口径。
- 产品确认：SKU 页类目筛选 UI 形态采用级联选择控件，而不是普通下拉加完整路径或缩进下拉。

# 触发条件

1. 管理后台存在多层级瓷砖类目。
2. SKU 数据归属到二级、三级或更深层级类目。
3. 管理员进入「瓷砖 SKU」页面。
4. 管理员打开「类目」筛选控件。
5. 筛选控件仅展示一级类目，导致无法选择目标细分类目。

# 分类

- 类型：ui-behavior / filtering-contract / admin-usability
- 层级：管理后台前端筛选控件、类目树数据取用、SKU 列表查询语义
- 直接影响端：管理后台 Web
- 关联能力：瓷砖 SKU 管理、瓷砖类目管理
- 数据风险：低，不涉及数据写入或迁移
- 回归风险：中，修复时需避免改变父类目筛选的既有结果口径

# 代码验证结论

- 已确认：用户截图中 SKU 页类目下拉仅展示一级类目。
- 已确认：用户明确期望可筛选各层级类目。
- 已代码确认：SKU 创建与更新只校验 `category_id` 是否存在，没有限制只能绑定一级类目；前端 SKU 表单也使用递归类目选项，支持选择完整类目树节点。
- 已代码确认：后台已有完整类目树数据源 `fetchCategoryTree()`，并已有 `flattenCategoryTree()` 与 SKU 表单内的递归 `buildCategoryOptions()` 可作为修复参考。
- 已代码确认：后端 SKU 查询接口对 `category_id` 是精确匹配，当前不会包含子孙类目 SKU。
- 已代码确认：关键词、品牌、类目、状态、素材完整度在 Repository 中作为 `AND` 条件组合，不存在参数互斥；修复需保证新增层级筛选后仍保持组合筛选能力。

# 产品确认结论

- 父类目筛选语义：选择父类目时，结果 MUST 包含该父类目下所有子孙类目的 SKU。
- UI 形态：SKU 页类目筛选 MUST 使用级联选择控件。
