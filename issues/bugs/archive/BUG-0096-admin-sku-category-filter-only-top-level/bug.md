# 现象

管理后台「瓷砖 SKU」页面筛选区提供了「类目」筛选项，但下拉选项仅展示一级类目，例如高光产品、金丝绒产品、木纹砖产品、莱姆石产品等。当前无法在 SKU 列表中直接选择二级、三级或更深层级类目进行筛选。

从用户截图看，「类目」下拉框打开后未展示层级缩进、父子级结构或级联选择能力，实际可选范围停留在一级类目。

# 复现

1. 登录管理后台。
2. 打开「瓷砖 SKU」页面。
3. 点击筛选区中的「类目」下拉框。
4. 查看下拉选项是否包含当前类目树中的二级、三级等各层级类目。
5. 尝试按某个非一级类目筛选 SKU。

# 期望

- 类目筛选应支持选择当前类目树中可用于 SKU 归属的各层级类目。
- 二级、三级及更深层级类目在选择控件中应有清晰的层级表达，避免同名类目混淆。
- 选择子类目后，SKU 列表应按该类目规则返回匹配结果。
- 选择父类目时，是否包含子孙类目 SKU 应有明确一致的筛选语义。
- 「全部类目」应保留，并在重置筛选后恢复完整 SKU 列表。

# 实际

- 类目下拉框只展示一级类目。
- 用户无法选择二级或更深层级类目。
- SKU 维护人员不能通过细分品类快速定位商品，只能通过一级类目、关键词、品牌或其他筛选条件间接查找。

# 影响范围

- 管理后台瓷砖 SKU 列表的类目筛选能力。
- SKU 资料维护、图片和视频素材完整度检查、上下架前核对等后台运营工作流。
- 可能涉及前端类目选项构造、类目树数据取用、SKU 列表查询参数，以及后端 SKU 类目筛选语义。

# 严重等级说明

严重等级：`medium`。

该问题不阻断 SKU 列表的基础浏览、新增、编辑、上下架或删除操作，但会明显降低后台按细分类目维护 SKU 的效率。对于类目层级较深、SKU 数量较多的业务场景，无法筛选各层级类目会增加人工查找成本，并影响素材完整度巡检和商品资料批量维护的准确性。

# 初步分析

- 当前管理后台 SKU 页已经存在「类目」筛选控件，因此这不是新增筛选能力，而是既有筛选能力覆盖范围不足。
- 截图中的选项表现更像基于一级类目列表渲染，而不是完整类目树扁平化或级联控件。
- 需确认 SKU 的类目归属字段是否允许绑定任意层级类目 ID。
- 需确认后端 SKU 查询接口收到父类目 ID 时，应按精确类目过滤，还是按该父类目的整棵子树过滤。
- 需确认前端是否已有可复用的类目树/层级选择组件，避免在 SKU 页另起一套层级展示逻辑。
