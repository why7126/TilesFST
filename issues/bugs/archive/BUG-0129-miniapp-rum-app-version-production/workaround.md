# 临时规避

正式修复前，可采用以下临时判断方式降低误判：

1. 性能观测表中小程序版本号显示 `production` 时，先按“小程序生产策略样本”理解，不要把它当作真实产品版本号。
2. 小程序性能样本 `request_id` 为空时，暂时无法通过性能样本直接串联请求日志；需要结合时间范围、页面或接口 path、端类型、网络和设备信息进行人工排查。
3. 指标名含义临时按以下口径解读：
   - `app_launch_ready`：小程序启动就绪耗时。
   - `api_duration`：小程序接口请求成功耗时。
   - `api_failed_duration`：小程序接口请求失败耗时。
4. 聚合列表出现页面、版本号、端类型、指标相同但数值不同的行时，先怀疑是隐藏的 `network_type` 或 `device_class` 不同，不要直接判定为重复数据。
5. 空态样式问题没有业务规避手段，只能在正式修复中调整 UI。

# 风险

- 临时规避依赖人工理解隐藏上下文，仍会影响排障效率。
- 无法补齐历史样本中的 `request_id`。
- 历史 `app_version=production` 样本需要在正式修复时决定是否仅兼容展示，还是做一次数据清理或迁移。

# 是否可接受

短期可接受，因为不阻断小程序和管理后台使用；但不适合长期保留。该问题会持续影响性能观测可信度，应进入正式修复流程。
