# Workaround

## 临时规避

无可靠产品内规避方案。

管理员或用户可以在个人资料页填写真实联系邮箱，这样个人资料页顶部身份栏会显示真实邮箱，但这不能解决用户菜单栏“不需要副标题”的产品期望，也不能消除前端在邮箱为空时拼接伪邮箱的错误逻辑。

## 不建议的规避

- 不建议批量给用户填入占位邮箱。
- 不建议把用户名约定成邮箱前缀来迎合当前展示。
- 不建议通过 CSS 仅隐藏伪邮箱而保留拼接逻辑，因为个人资料页顶部身份栏仍可能继续展示误导性邮箱。

## 正式修复方向

通过 Web 前端修复身份展示逻辑：

1. 用户菜单栏移除邮箱副标题展示。
2. 个人资料页顶部身份栏在邮箱为空时不拼接伪邮箱。
3. 相关测试改为断言不出现 `username@tilesfst.com` / `admin@tilesfst.com` 这类前端伪邮箱。
