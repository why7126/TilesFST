# 现象

小程序首页无跳转轮播图画面上显示 `internal-MINIAPP_HOME_NO_JUMP-1786622496149` 一类内部标题。该内部标识以大号白色文字覆盖在轮播图图片上，用户可直接看到后台内部命名、枚举和时间戳信息。

# 复现步骤

1. 在管理后台配置一张小程序首页轮播 Banner。
2. 将跳转类型设置为无跳转，并配置 Banner 图片。
3. 将该 Banner 上线，使其满足小程序首页轮播展示范围。
4. 打开微信小程序首页。
5. 观察首页轮播图画面是否出现 `internal-MINIAPP_HOME_NO_JUMP-...` 内部标题。

# 期望 vs 实际

- 期望：首页轮播图只展示运营配置的公开图片内容，不展示后台内部标题、内部枚举、时间戳或实现细节；无跳转 Banner 点击后也不应暴露内部标题。
- 实际：用户截图显示无跳转轮播图画面上出现 `internal-MINIAPP_HOME_NO_JUMP-1786622496149` 内部标题，影响首页视觉体验并暴露内部命名。

# 影响范围

- 影响微信小程序首页首屏 Banner 视觉质量。
- 暴露后台 Banner 内部识别信息和实现命名。
- 影响后台 Banner 无跳转配置生成内部标题后的公开展示链路。
- 品牌列表页等复用 Banner 轮播能力的页面存在同类回归风险，需要一并验证。
- 若内部标题已进入存量图片素材，还会影响已上线 Banner 数据，需要补充数据或素材清理。

# 严重等级说明

严重等级暂定 `medium`。该问题不阻断小程序启动、浏览或交易链路，但发生在首页首屏公开展示位置，用户可见且包含内部实现标识，属于明显体验缺陷和公开信息泄露风险。若确认线上所有用户稳定可见或多个 Banner 页面均受影响，可在评审时上调为 `high`。

# 初步分析

- 管理后台 Banner 表单会为新建 Banner 生成 `internal-*` 内部标题并保存到 `title` 字段。
- 后端小程序公开 Banner item 仍会返回数据库中的 `title` 字段。
- 当前仓库中的小程序首页 WXML 轮播块不直接渲染 `item.title`，因此画面叠字还需要继续确认是生产包、缓存包、图片素材生成链路，还是其他未覆盖展示路径导致。
- 正式修复应优先保证公开端不暴露内部标题，并回归无跳转 Banner、首页轮播、品牌列表页轮播和搜索/点击兜底链路。
