# 用户故事

| 编号 | 用户与目标 | 验收关联 |
|---|---|---|
| US-001 | 模型维护者希望分别维护本体语义与格式 Schema，确保结构正确的错误关系也会被拒绝。 | AC-001～AC-005 |
| US-002 | 研发人员希望 Change 归档自动提取有来源的增量，无需每个 PR 手动维护图谱。 | AC-006～AC-009 |
| US-003 | Sprint 负责人希望在关闭前发现覆盖范围内语义冲突和同步遗漏，同时看见范围外原因。 | AC-010～AC-012 |
| US-004 | 发布负责人希望版本知识由准备阶段构建、确认阶段绑定，可从 Git 离线追溯。 | AC-013～AC-015 |
| US-005 | 流程维护者希望失败不污染现有模型，重试只完成剩余步骤，能够定位原因。 | AC-016～AC-019 |
| US-006 | 验收人员希望通过真实 Change 验证全链路，并用隔离场景证明失败与安全边界。 | AC-020～AC-022 |

| US-007 | 模型维护者希望元本体与领域元素分离，能定位未定义、类型错误和跨层错误引用。 | AC-023～AC-025 |
| US-008 | 评审者希望业务补偿与同步恢复分离、示例与已确认事实分离，避免模型声明触发业务操作。 | AC-026～AC-027 |
| US-009 | 发布负责人希望分别锁定格式、本体、领域和快照版本，发现不兼容变化而不污染历史。 | AC-028～AC-029 |

所有故事共同支撑最小本体驱动同步闭环；Agent 动作仅作语义建模，不包含执行权限或问答接入。
