# 业务流程

## 本体与文件格式的职责

```text
ontology/ 元本体与产品研发本体：建模语言、通用语义
                  ↓ 限定领域模型的合法表达
domain-models/tilesfst/ 对象、行为、规则、场景、主体等
                  ↓ 定义具体业务语义
mappings/ 来源映射：资料定位、字段转换、提取配置
                  ↓
Change 归档成功 → 候选实体、关系、规则与证据
                  ↓
schema/ 格式约束 → validation/ 本体一致性与业务预期
                  ↓
generated/ 正式增量 → Sprint 一致性检查
                  ↓
release-prepare 候选完整快照 → release-publish 确认关联
```

schema/knowledge-model.schema.yaml 不能替代 ontology/；本体文件、实例和关系均须通过对应格式检查，生成实例还须满足本体定义。

## Change 同步

```text
确认覆盖范围与来源
  ├─ 范围外 → 记录 out_of_scope 与理由
  └─ 范围内 → 可选归档前预检
                → 原有 OpenSpec 归档
                → Workflow Sync → 必要 Issue 迁移
                → 固定正式输入与本体/映射版本
                → 临时生成 → 格式与语义校验
                → 互斥及来源复核 → 原子切换模型
                → 独立回执 → Change trace 摘要
```

源 Commit 不能代表未提交内容；输入不可信时保留旧模型，记录失败。重复事件按来源与配置摘要判断已完成阶段。Issue 的全部关联 Change 完成后才汇总闭环。

## 异常恢复

| 失败阶段 | 正式模型 | 恢复动作 |
|---|---|---|
| 归档失败 | 保持既有版本 | 修复原归档阻塞，尚不正式同步 |
| 提取或校验失败 | 保持既有版本 | 单 Change 重试，不重复已完成归档 |
| 并发锁或来源复核失败 | 不覆盖其他运行结果 | 重新获取锁并验证输入 |
| 模型提交后回执失败 | 保持已提交的新版本 | 依据提交标识补回执，不重复模型切换 |
| 冻结后补证或重建 | 不改旧交付事实 | 独立追加同步记录，引用冻结资料 |

## Sprint 与 Release

Sprint 检查覆盖范围、过期来源和跨 Change 本体一致性；高风险确定冲突阻断、低风险缺失警告。类型冲突必须考虑继承，权限冲突必须考虑版本及条件，不能只比较名称。

Release prepare 按真实范围构建候选快照和 manifest；Release publish 比较范围与摘要后仅确认关联。没有发布确认的快照不得显示为正式发布。发布历史不可覆盖；测试发布和真实发布证据分别记录。

## 与已有能力关系

独立需求，无父需求。复用 REQ-0089 的状态同步和既有归档冻结规则，复用 REQ-0026 的发布对象，不替代两者事实源。无 UI 页面与原型交付。

## 跨层引用与版本验证

```text
格式 Schema 校验
→ 元本体 model_type 与属性约束
→ 领域模型引用目标、参数和版本检查
→ 生成事实映射与证据检查
→ Sprint 跨 Change 一致性
→ 锁定所有依赖版本的发布快照
```

未定义模板、合法 ID 但目标类型错误、跨层把业务记录当类型、依赖版本不兼容分别产生可定位错误。业务补偿模型只描述业务语义，工具恢复流程只恢复知识生成与记录；不相互触发执行。
