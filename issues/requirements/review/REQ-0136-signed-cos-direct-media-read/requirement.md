# REQ-0136 Web 与小程序 COS 签名直读及过期恢复

## 1. 背景与目标

现有媒体读取部分经后端转发。用户提供的生产服务器出口约 3 Mbps，媒体多人访问容易受到服务器出口容量限制。存储适配层已有受控直读开关与签名能力，当前默认签名有效期为 300 秒，但视频地址仍使用 `/media/`；已核查的图片错误处理只切换已有地址，小程序媒体失败提示不包含自动续签。直接生成签名地址不会自动执行代理读取中的历史 Key 与缺失派生图候选回退。

事实依据见 `capture.md`、`src/backend/app/modules/media/storage.py`、`src/backend/app/services/tile_sku_admin_service.py`、`src/backend/app/services/miniapp_home_service.py`、`src/web/src/features/admin/components/FallbackListImage.tsx` 和 `src/miniapp/pages/tile-detail/index.ts`。现有 `tests/test_media_storage.py` 直读测试使用模拟存储，仅证明地址生成逻辑，不能代表线上 COS、视频播放或小程序真机已通过。

目标是在保留业务权限、稳定对象引用和历史兼容的前提下，让 Web 管理端、店主展示端及微信小程序的主要媒体文件流量直接到达 COS；页面停留、前后台切换和网络恢复后，媒体能够有限恢复或给出明确失败反馈。性能收益以同网络、同媒体的对比证据验证，不承诺所有用户网络下固定加载秒数。

## 2. 目标用户

| 用户 | 使用目标 |
|---|---|
| 企业管理人员 | 维护和预览商品、品牌、Banner、头像及证书媒体，视频可播放和拖动 |
| 店主 Web 与小程序访问者 | 查看允许公开的媒体，长时间浏览后仍可预览原图和播放视频 |
| 运维与维护人员 | 控制灰度和回滚，定位授权、直读、续签及历史回退失败，验证服务器流量变化 |

## 3. 范围与交付边界

### 3.1 纳入范围

覆盖三端现有媒体展示入口及字段，不借此新增业务页面或媒体种类。需求完善阶段按“端、页面、响应字段、媒体类别、权限、预览/下载行为、恢复方式”形成可逐项验收的覆盖矩阵；某端不存在的入口明确标记不适用。

| 媒体类别 | 覆盖场景 |
|---|---|
| 视频 | SKU/商品详情及现有管理预览，首播、暂停恢复、Range 拖动、重播和播放位置恢复 |
| 图片 | SKU/商品卡片及详情、品牌 Logo、Banner、头像、证书图片、视频封面；缩略图、展示图、原图预览 |
| 附件 | 现有证书 PDF 等附件的预览、下载或小程序文件打开路径，按实际支持能力验收 |
| 兼容与运维 | 旧 `/media/` 引用、历史对象 Key、缺失派生图、已存外部绝对 URL、灰度开关及受控代理回滚 |

按两个阶段交付：先三端视频完整读取与恢复闭环，再覆盖图片和附件；实际发布仍执行独立发布流程。无论如何拆分，只有全部纳入范围完成后才能关闭 REQ-0136。Sprint 与 Change 在评审后确定。

### 3.2 不纳入范围

不包含浏览器直传、上传确认与图片派生处理实现、新增小程序上传入口、视频转码、多清晰度、自动封面生成、CDN 建设、服务器或存储桶地域迁移、全量历史对象迁移。图片派生规格保持现状，读取兼容不负责补生成缺失对象。

## 4. 功能要求

### FR-001 稳定媒体引用与授权解析

数据库继续保存稳定对象 Key 或现有业务媒体引用，不将签名 URL 作为长期业务数据写入。端侧以业务对象、媒体标识及所需规格申请读取，不得通过任意 Key、bucket 或 endpoint 获取签名。后端验证媒体属于当前可访问业务对象，并统一解析实际对象及规格。

公开端按业务公开状态授权，管理端按当前身份与业务权限授权；公开访问不因签名能力被强制新增登录流程。草稿、下架、删除、未确认上传或其他不可公开媒体不得通过公开授权接口、批量请求或回退取得新授权。管理端对未发布媒体的合法预览保留独立权限判断。

### FR-002 短期地址与接口契约

所有纳入字段使用后端控制的读取地址，端侧不自行拼接 COS 域名、桶名和签名。建议业务响应或读取解析接口返回签名 URL、明确到期时间、稳定媒体标识、规格及读取模式；稳定入口鉴权跳转为兼容备选，具体接口形态在设计时确认。

| 能力 | 请求信息 | 响应信息 | 失败语义 |
|---|---|---|---|
| 读取解析/刷新 | 业务引用、媒体标识、规格、客户端上下文；批量请求限制数量 | 各媒体的可用读取地址、到期时间、规格、读取模式或逐项失败结果 | 输入无效、未认证、无权限/不可见、媒体不存在、存储不可用、限流 |
| 兼容入口 | 后端可识别的历史引用及当前访问上下文 | 受控跳转或符合权限的代理响应 | 不合法引用、无权限、无可用候选、服务不可用 |
| 媒体传输 | 受控地址及播放器/文件组件必要的 GET、HEAD、Range 请求 | 正确的内容类型、长度及平台需要的分段响应 | COS 或端侧错误转换为脱敏展示与可恢复分类 |

后端沿用统一 API 响应和错误码治理，精确路径、字段名与编号由 OpenSpec 设计定义；不可见资源的响应不得泄露其他业务对象存在性。批量解析需隔离单项失败，不因一个缺图导致整页不可用。COS 文件响应不强行包装成业务 JSON。

### FR-003 有效期、缓存与权限变更

有效期由后端受控配置，返回可计算剩余寿命的信息，并考虑端侧时钟偏差。签名有效期为300秒，提前30秒刷新，缓存规则与参数见第8节。授权结果不得跨用户、业务权限或媒体规格复用；退出登录、切换身份或业务引用变化后清理相关授权缓存。

商品下架、媒体删除或权限撤销后不得再次签发不再允许的读取授权。已签发链接允许在剩余有效期内继续访问，最长不超过签发后300秒；不承诺短期签名或跳转入口能立即撤销已发出的链接。已下载或本地缓存的内容不承诺远程收回。

签名轮换不得把旧授权结果写回业务字段。内容缓存和授权缓存分别定义，不通过无限延长签名有效期解决恢复问题。

### FR-004 端侧续签与有限恢复

在首次使用、页面恢复、原图预览、附件打开和视频重播等实际读取时检查授权剩余寿命；即将过期或已过期时获取新授权。不得仅在页面初次加载时获取一次地址，也不得把同批已过期的备用地址视为有效恢复。

同一媒体的并发刷新需合并，批量图片恢复限制并发并退避，防止同时过期造成请求集中。错误处理区分可恢复的网络/授权过期与权限拒绝、永久缺失等终止结果；图片组件无法直接取得 HTTP 状态时，不得把所有加载失败断言为签名过期，可进行有次数上限的重新解析。

自动重试次数、超时和退避参数按第8节执行；达到上限后显示失败占位或人工重试入口，不产生刷新、规格切换和代理之间的无限循环。异步返回需校验当前页面、媒体身份与请求版本，避免离开页面或切换资源后旧结果覆盖新内容。

### FR-005 视频播放与位置恢复

三端验证首播、暂停后继续、快进/回拖、重播及全屏播放。续签更换地址时记录媒体身份、播放位置和播放/暂停状态，在新资源可用后按平台能力恢复，避免重置为开头或擅自播放已暂停视频。保留用户手动播放动作要求，不绕过浏览器或小程序自动播放限制。

GET、HEAD 及 Range 行为分别验证，不能把 GET 签名直接假定为所有请求方法均可用。平台探测、跨域、跳转与签名适配应通过真实播放路径验证；Range 正常读取应有可定位的分段响应证据。续签接口成功不等于视频恢复成功，恢复位置允许误差不超过2秒。

### FR-006 图片规格与附件读取

列表、详情和原图预览保留现有规格选择及视觉行为。后端返回真实可用的规格或明确缺失，派生图缺失可按受控候选降级，不反复使用同一无效 URL。原图降级需记录原因和规格，避免大量列表图片静默改为原图传输。

预览相册在打开前确保当前图及必要预览地址可用；长时间浏览到下一张图的过期恢复也需覆盖。PDF 等文件不生成图片派生地址。附件下载与小程序文件打开应取得有效授权并处理到期/下载失败，不向用户展示签名参数或内部存储错误。

### FR-007 历史引用与候选回退

后端识别稳定 Key、旧 `/media/` 路径、自有存储地址和外部绝对 URL；自有引用仅按受信任域名及已知映射归一化，外部 URL 不得任意转换为桶内 Key、重新签名或由后端抓取。外部媒体不能声明为本系统 COS 直读成功。

复用已有受控历史 Key 映射及派生图/原图候选逻辑，候选均需属于同一已授权媒体。建议先使用所请求的可用规格，再按允许的替代规格/原图和历史映射查找；精确顺序、探测次数、结果缓存和原图降级条件在设计中固化为确定性规则。仅不存在的候选继续查找，权限拒绝和存储故障不得伪装成缺图后继续放宽访问。

不要求端侧识别历史目录结构，不在普通读取中迁移对象或修改数据库业务引用。无法解析或所有候选缺失时返回明确终止结果。

### FR-008 灰度、回滚与代理权限

提供可按端及媒体类别控制的灰度策略，并保留可操作回滚路径。关闭直读后的新读取走经过权限校验的兼容路径；已发出请求和已缓存签名的处理边界需明确，不声称切换开关会立即撤销旧链接。

代理回退必须执行与授权接口一致的业务权限，不能仅凭任意对象 Key 放行。现有 `src/backend/app/main.py` 的 `/media/` 路由本身未见业务鉴权依赖，实施前需核查完整访问链路并补齐本需求依赖的受控回退；不得直接视为安全授权入口。

默认不将所有直读失败自动转回服务器。回退预算及回滚指标按第8节执行，精确错误映射与流量限额在Change设计中固化；COS 自身不可用时代理访问同一存储不能被当成必然有效的恢复方式。回退需可统计、可停用且不掩盖直读故障。

### FR-009 部署与多存储兼容

核对 COS 读取最小权限、TLS、浏览器跨域、内容预览条件及小程序合法域名；配置只使用既有对象存储适配边界，不新增公开桶权限、不向端侧分发永久密钥。新增或调整变量同步 `.env.example` 与部署说明。

COS 为直读验收目标，本地 MinIO/S3 兼容环境继续可运行；不支持的直读模式应明确配置与受控代理行为，不能悄然破坏本地展示。部署验收包含 Docker Compose 配置与联调；线上域名、COS 和小程序真机证据单独记录。

### FR-010 产品数据采集与链路观测

采集媒体加载结果、预览/播放、续签、恢复结果、规格降级和代理回退等事件，使用统一行为事件 helper 和稳定事件字典，限制重复事件与高频播放噪音。授权请求透传合法链路 ID，后端记录请求日志；直接 API 调用允许无行为事件上下文，不伪造事件。

批量解析、历史候选探测和对象存储外部依赖按规范接入 Task Trace 与阶段 span；单纯本地签名计算若无需 Task Trace，应在设计声明原因。COS 直接读取不经过后端请求中间件，以端侧结果及可用 COS 访问证据补充，不制造后端文件读取日志。无法取得 COS 证据时注明可证明边界。

记录媒体稳定标识或 Key hash、规格、读取模式、耗时、重试次数及脱敏失败类型；不得采集完整签名 URL、签名查询参数、凭据或完整内部对象 Key。请求响应快照、错误摘要和缓存诊断也需执行同一脱敏规则。观测失败不阻断展示或覆盖主错误，沿用现有数据结构与保留周期，新增字段或周期另行声明并验证。

## 5. UI 约束

沿用现有页面布局、媒体尺寸、裁切方式、播放器和原图预览交互，不改变图片展示风格。补齐加载、恢复中、降级、失败和手动重试状态，文案不暴露 COS、签名算法或技术堆栈；恢复成功后清理旧错误提示。

Web 复用现有 Design System 组件和 semantic token，小程序遵循既有组件及样式规则。需求完善阶段确定状态矩阵与原型必要性；本命令不生成 prototype。如后续引入原型，执行对应 UI Contract、Skeleton、视觉验收与样式证据要求。

## 6. 验证目标与影响

正常路径由 Network 或等价证据证明文件主体直达 COS，服务器仅承担业务授权等控制请求；记录服务器出口流量、授权耗时、媒体加载 p95、失败率、续签恢复成功率、规格降级率和代理回退率。使用同媒体、同客户端网络及相同并发条件对比代理基线，样本规模、重复次数、指标阈值与回滚阈值按第8节执行。

功能验证覆盖三端、全部纳入字段与格式；异常覆盖过期、时钟偏差、断网恢复、前后台切换、并发刷新、旧请求晚到、下架/撤权、缺失派生图、历史 Key、外部 URL、存储故障、重试耗尽及灰度回滚。视频单独验证 HEAD/Range、全屏、重播和位置恢复；图片验证长停留后的相册与原图预览；附件验证下载及打开。

模拟存储单元测试、API 集成测试、Web/小程序组件测试、Compose 联调、开发工具 Network 和线上/真机验证分层记录来源，不相互替代。未取得证据的项目不得写为已通过。

| 影响面 | 后续交付要求 |
|---|---|
| 后端/API | 读取授权、批量解析、权限、历史兼容及回退；同步 OpenAPI、API 索引、错误码和测试 |
| 数据库 | 默认复用稳定引用，不预设新增表；若设计新增字段/映射持久化，同步 SQLite/MySQL schema、迁移、Pydantic 和文档 |
| Web 管理端/店主端 | 媒体响应消费、刷新与恢复、状态展示和事件采集；接口变化同步 Orval |
| 小程序 | 视频、图片预览和文件打开适配；验证平台域名及真机恢复行为 |
| 部署 | COS 权限、跨域、域名、配置与灰度回滚；需要 Compose 集成验证 |

正常COS可达的固定样本集要求媒体主体直读率100%、自动回退0、恢复位置误差≤2秒；服务器媒体出口字节数相较代理基线降低至少90%，无新增权限失败，加载p95不得劣于同条件代理基线超过10%。采用约20/60MB视频、超过TTL的长视频、图片各规格及PDF；并发1和3、同网络同缓存条件、每组至少20次。条件不可比时记录不可验证，不作性能改善结论。

连续5分钟媒体失败率高于5%且样本不少于100次时触发人工回滚评估；这是首期验收/运维评估基线，不是未经测量的线上SLO。测试样本、计时起止与指标分母在Change测试计划中固定。若实测无法达到基线，应修正实现或记录需求变更，不静默降低门槛。

原型采用prototype/web/media-states.html与context.md的局部状态策略；PNG为可选补充。原型不证明真实seek、COS读取或真机可用。条件通过项及责任阶段见review.md。
