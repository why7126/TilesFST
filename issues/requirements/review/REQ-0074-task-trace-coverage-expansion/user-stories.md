# 用户故事

## US-001 系统管理员追踪复杂任务

作为系统管理员，我希望保存 SKU、批量上下架、导入导出、媒体处理等复杂任务都能关联 `task_trace_id`，以便在日志审计中还原任务完整链路。

验收要点：

- 首批任务型接口清单覆盖保存 SKU、批量操作、导入导出、媒体处理、异步任务和复杂查询。
- 每个首批接口都能在响应、日志或错误反馈中获得 `task_trace_id`。
- 日志审计详情能通过 `task_trace_id` 查看任务时间线。

## US-002 运维定位慢节点和失败节点

作为开发 / 运维人员，我希望每个任务型接口都记录关键 span，以便快速判断慢点或失败点发生在校验、持久化、对象存储、异步处理还是响应阶段。

验收要点：

- 每个任务至少包含开始、核心业务处理、持久化或外部服务、响应或结束 span。
- 失败任务必须记录失败 span、统一错误码或失败摘要。
- 批量任务必须记录成功数、失败数和失败分类摘要。

## US-003 运营复制追踪标识

作为企业内部运营人员，我希望复杂任务执行失败或处理中时能看到可复制的追踪标识，以便向管理员或技术支持反馈时不用复述模糊现象。

验收要点：

- 管理端复杂任务成功、失败或处理中反馈中应展示 `task_trace_id` 或复制入口。
- 复制反馈不造成页面布局位移。
- 没有 Task Trace 的旧任务仍保持原交互，不出现空错误态。

## US-004 产品负责人识别高风险任务

作为产品负责人，我希望任务型接口接入情况有清单和优先级，以便判断哪些任务已可观测，哪些任务仍需后续排期。

验收要点：

- 候选接口清单标注任务类型、接入优先级、关键步骤、是否异步和是否批量。
- 未纳入首批的接口必须说明原因和后续排期建议。
- 后续 OpenSpec design 能基于清单拆分可执行 tasks。

## US-005 安全审计负责人控制敏感信息

作为安全 / 审计负责人，我希望任务链路记录能追踪操作者和资源摘要，同时不泄露认证信息、原始请求体或内部路径。

验收要点：

- metadata 不保存 Authorization、Cookie、AccessKey、SecretKey、数据库 DSN、`.env` 内容或完整敏感请求体。
- 不记录用户本地绝对路径、对象存储真实凭证或未授权直连地址。
- 管理端查询与详情查看复用系统管理员权限边界。
