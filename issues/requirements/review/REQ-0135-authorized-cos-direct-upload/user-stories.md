# 用户故事

范围与业务规则以 [requirement.md](requirement.md) 为准。本文件负责角色与验收映射；所有故事当前未实施。

| 编号 | 角色与目标 | 验收要点 | PRD / AC |
|---|---|---|---|
| US-001 | 管理员上传 SKU 视频，希望传输不受应用服务器出口限制 | 申请授权后文件主体直达 COS；传输、校验、可保存分开显示 | FR-001～004 / AC-001～006 |
| US-002 | 管理员遇到网络中断，希望保留当前页面内可恢复的上传 | 分片失败可重试，授权过期重新鉴权；取消后晚到结果不恢复文件 | FR-002、003、007 / AC-004、007、011 |
| US-003 | 管理员保存新建或现有业务，希望仅关联可信媒体 | 未确认不能绑定；重复确认幂等；保存失败不重复上传；已发布内容不可被临时凭证覆盖 | FR-004、005 / AC-005～009 |
| US-004 | 管理员上传图片，希望看到即时预览及明确处理结果 | 覆盖 SKU 图片、Logo、Banner、头像、证书图片；保留原图和既有派生规格；失败可重试 | FR-006 / AC-010、013、014 |
| US-005 | 管理员上传证书文档，希望保留现有类型和大小校验 | 现有证书文档入口也改用授权直传，按真实类型校验，不套用图片派生 | FR-001、004、008 / AC-002、005、014 |
| US-006 | 运维人员希望逐步上线并能追踪上传失败 | 按媒体类型切换，旧会话可继续；分阶段耗时、清理结果可追踪且不泄露凭证 | FR-007～009 / AC-011～017 |
| US-007 | 店主和小程序用户希望既有媒体仍能展示 | 新旧媒体四联证据闭环；保持原有读取能力，读取签名刷新由 REQ-0136 承担 | FR-005、006、008 / AC-013、018 |

## 交付顺序

第一阶段完成 US-001～003 的 SKU 视频闭环和 US-006 的必要观测、清理与灰度能力；第二阶段完成图片及证书文档入口，并复用前一阶段能力。US-007 两阶段都回归。阶段完成不等于本需求整体完成。
