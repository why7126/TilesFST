# REQ-0135 后端授权的 COS 媒体直传与上传确认

## 1. 背景与目标

当前管理端将图片、视频先上传后端，再由后端写入 COS；图片同时生成缩略图和展示图。生产部署为北京轻量服务器与广州 COS，用户提供的服务器公网带宽约 3 Mbps，宿主机解析 COS 域名返回公网地址。

2026-09-05 线上视频样本的请求体约 18.7、59.1、63.2 MB，存储完成阶段累计耗时约 52、166、177 秒，支持跨地域公网出口瓶颈的强推测（probable）。该阶段并非独立 COS 写入计时，宿主机解析也不能替代容器路径验证。事实来源和边界见 `capture.md`，不将推断作为性能验收通过证据。

目标是让文件主体直接从管理端传至 COS，后端保留鉴权、上传确认、内容校验、派生处理调度与业务关联；上传不再受后端公网出口转发完整文件的限制。速度仍取决于用户上行网络、COS链路和文件处理，不承诺所有网络下固定秒数。

## 2. 目标用户

| 用户 | 目标 |
|---|---|
| 企业管理端维护人员 | 大视频上传可见进度、可重试和取消，明确何时可以保存媒体 |
| 媒体与后端维护人员 | 可靠识别上传、处理、保存三个结果，避免越权、残留和重复关联 |
| 店主端及小程序访问者 | 已发布媒体保持可读，新增图片规格及视频内容不因上传方式改变而损坏 |

## 3. 范围与交付阶段

| 阶段 | 纳入内容 | 阶段完成标准 |
|---|---|---|
| 一：视频 | 现有 SKU 视频上传入口，授权直传、分片、当前页面内重试、取消、确认、正式对象保护及清理 | 视频可完整上传、确认、关联、保存，并完成权限和异常验证；不以原型直传成功代替闭环 |
| 二：图片与附件 | 现有 SKU 图片、品牌 Logo、Banner 图片、头像、证书图片及原有证书文件入口；图片派生、状态查询、降级和失败重试 | 全部纳入入口按实际允许类型通过覆盖矩阵，现有原图/派生规格与读取兼容通过 |

阶段一可独立评审验证和分批上线；REQ-0135 全部范围完成后才可标记交付完成，不能仅以视频阶段通过关闭需求。具体 Sprint/Change 拆分由评审后规划确定。

不包含：新建小程序上传入口、视频转码/封面自动生成、多清晰度、跨浏览器会话续传、CDN建设、服务器或存储桶地域迁移、全量历史对象迁移。展示端签名直读与读取签名刷新由 REQ-0136 承接；本需求仅处理上传授权续期与展示兼容回归。

## 4. 功能要求

### FR-001 上传申请与权限

后端按登录用户、角色及目标业务对象校验权限，创建唯一上传会话，生成受控临时对象 Key。申请输入包括媒体类别、业务对象引用（新建时可为空）、文件大小、声明类型及客户端幂等标识。类型与大小沿用生效的系统设置，不能仅信任前端校验。

授权只覆盖当前会话的临时对象及必要操作，限制有效期、允许大小/类型与前缀；不得给端侧正式对象覆盖、删除或整个桶/业务目录的写权限，不分发永久密钥。申请、续期、确认及取消均重新校验会话归属与权限，链路ID不得作为授权依据。

授权模式建议采用限定对象范围的临时凭证配合 COS SDK，简单预签名为可比较备选；最终选择需证明分片、续期与大小约束可实现，不将单次上传限制误用为分片聚合大小限制。

### FR-002 上传会话与持久化

会话需跨后端进程重启保留，可查询业务归属、预期大小/类型、传输方式、过期时间、对象确认结果、派生结果及业务绑定状态。不得将临时凭证或完整签名 URL 作为会话持久化内容。

建议生命周期为：已申请 → 传输中 → 待确认 → 校验中 → 待处理（图片） → 可关联 → 已绑定；失败、已取消、已过期为明确结果。客户端传输状态只表示进度线索，后端确认结果为可信状态。取消/确认/保存并发时需原子状态约束，禁止已取消任务再次绑定。

### FR-003 传输进度与恢复

视频支持分片上传、当前页面内失败重试、取消及临时授权续期；小文件可采用简单上传。网络重试不得生成重复业务媒体，会话状态与已完成分片应可协调恢复。授权已过期、权限被收回或会话取消时不得无条件续期。

进度按实际传输字节报告；传输达到100%后显示“校验中”或“处理中”，只有通过后端确认才可显示“可保存”。不得通过固定99%掩盖后端阶段。各类最大尺寸继续读取现有有效设置；当前代码默认图片20 MB、视频500 MB、文件25 MB仅作现状参考，不覆盖生产配置。

并发数、分片阈值、单片大小、退避次数和授权TTL在对应阶段实现前确定为可验证配置；关闭浏览器后不保证自动续传，但再次进入可以识别未绑定残留并清理或重新发起。

### FR-004 后端完成确认

完成请求以会话标识为主，后端从已授权记录定位对象，校验存在性、真实大小、类型、上传归属及完整性。声明的 Content-Type、客户端完成回调或 ETag 不得被单独作为真实内容正确性的证明；分片ETag不得按普通文件MD5解释。

内容校验应检查可信的文件格式证据，必要时采用受限读取或隔离解析，不执行文件内命令。视频校验不得以将完整文件经北京后端下载再上传作为常规路径；具体格式识别、解析资源上限与完整性方案在设计中明确。

重复确认幂等返回同一会话结果。对象超限、类型不符、对象缺失、归属不符或校验失败时不可作为有效业务引用；可重试与不可重试失败需区分。前端完成通知和未来可能的COS回调都只是触发确认，不能绕过后端校验。

### FR-005 确认后保护与正式归属

客户端可写的临时对象与业务正式引用隔离。确认后的内容必须形成端侧无写权限的稳定对象，旧授权即使尚未过期也不能改变已绑定媒体。实现需处理校验和复制之间的竞态，采用源版本/条件复制及正式副本校验等可证明的一致性方案。

优先使用 COS 侧复制完成归档，避免后端下载再上传完整文件。继续遵循同一Bucket、标准媒体前缀及业务id目录规则：新建对象可先进入受控pending阶段，保存后在业务id目录绑定；已有业务对象也不得为了少一次复制而给端侧已发布正式对象写权限。

正式归属与数据库绑定具有幂等及失败补偿规则。复制成功但数据库保存失败时可重试绑定，不能让业务引用不存在对象；数据库保存成功后的清理不能误删有效媒体。替换媒体先确保新对象可用，再切换引用，旧对象按引用与保留策略清理。

### FR-006 图片派生处理

保留原始格式、MIME及原图，派生图沿用现有缩略图/展示图尺寸、WebP格式、目标体积及类型允许规则。图片处理完成状态与上传确认分开，可查询、重试，并记录各派生结果。

候选方案为后端异步处理与COS数据万象。选型需比较现有编码/质量/体积目标一致性、费用、同地域处理条件、资源限额和重试策略；不预先开通收费服务。后端异步方案需明确北京服务器收取原图和上传派生图的带宽成本，不能宣称全部处理流量已脱离服务器。

派生失败保留通过校验的原图，显示失败或降级状态，不静默标记全部处理成功。正常绑定要求必要派生结果可用；原图降级发布条件、权限与端侧承接方式为第二阶段实现前决策，不能以缺少派生图造成空白展示。

### FR-007 取消、残留与清理

取消需停止端侧继续传输，并由后端尽力终止未完成分片；不能将取消API返回成功解释为临时凭证已立即撤销。晚到上传或回调仍受会话状态约束，禁止重新激活取消会话。

未确认对象、未绑定对象、失败副本及未完成分片按保留期清理。清理前检查状态、对象身份和有效引用；支持失败重试及脱敏审计，不影响已绑定对象。清理周期和保留期在对应阶段实现前确定，避免上传/确认与清理竞态。

### FR-008 接口与兼容契约

需提供申请、续期、状态查询、完成确认及取消能力；业务保存继续调用既有业务API，仅接受经后端确认并属于当前用户/业务的媒体引用。接口精确路径与错误码编号在OpenSpec设计阶段定义。

| 能力 | 请求信息 | 响应信息 | 失败语义 |
|---|---|---|---|
| 申请/续期 | 媒体类别、业务对象、声明大小类型或会话id | 会话id、授权范围与期限、传输参数、任务链路id | 未登录、无权限、超限、不支持类型、会话不可续期 |
| 状态/确认 | 会话id，必要上传完成信息 | 可信状态、稳定媒体标识、校验及派生结果、可重试原因 | 对象缺失、内容不符、状态冲突、归属不符、存储不可用 |
| 取消 | 会话id | 取消状态、清理处理状态 | 无权限、状态冲突、外部依赖失败 |
| 业务保存 | 业务字段与已确认媒体引用 | 保存结果及既有媒体展示字段 | 媒体未就绪、绑定冲突、业务校验失败 |

返回格式遵循现有统一响应和错误码规范，端侧不依赖内部SDK错误或原始COS错误串。新旧路径可按媒体类别配置灰度和回滚；回滚只影响新申请，已有直传会话仍可确认和清理，不因开关变化产生重复上传。不得默认静默回退后端代理造成耗时不可解释。

### FR-009 链路观测

申请、续期、查询、确认、取消、绑定均记录后端请求日志；直传和派生作为多阶段任务关联行为、请求与Task Trace。客户端传输字节/耗时标明客户端来源，后端校验、复制、派生、绑定耗时分别记录服务端来源，不伪造浏览器传输起止点。

端侧记录上传开始、失败、重试、取消、确认结果与业务保存行为，采集失败不阻断主流程。节点并发或嵌套时总耗时以任务起止/合理区间口径计算，不直接累加重叠阶段。安全摘要仅保留媒体类别、大小、状态、对象指纹等必要信息，不记录凭证、签名查询参数、原始文件内容和完整内部对象Key。

## 5. UI 与交互约束

复用现有管理端上传卡片、对话框、表单和Design System语义Token，不新增独立媒体管理产品。每个文件独立显示传输、校验、处理、可保存、失败、取消状态；传输进度与处理状态分开呈现。

可恢复失败提供重试，不可恢复失败明确重新选择文件；避免暴露COS内部参数和SDK堆栈。未就绪媒体不得通过保存动作被当作有效引用，已有业务内容保持可编辑。离开有未完成上传的页面需提示实际影响，取消文件不等于删除已发布媒体。

原型需求在 `/req-complete` 确认：至少形成上传中、校验中、处理失败、重试、取消、保存失败的状态与交互矩阵。已补齐 prototype/web/index.html 与 context.md；后续实现遵循UI Contract、Skeleton及视觉证据治理。

## 6. 验证目标与影响

使用相同视频、相同客户端网络对比旧代理与直传请求，记录申请、传输、确认和保存耗时、成功率及服务器出口流量；浏览器Network证明文件主体直达COS。以已观察到的约19/59/63 MB视频规模为代表，并覆盖有效上限和超限样本；具体p95目标及重复次数对应阶段实现前确定。

验证授权越权、类型伪装、分片总大小、过期续期、重复确认、确认后覆盖、取消后晚到请求、后端重启、数据库失败、清理竞态和图片处理失败。验证新建/编辑入口及历史媒体可读；小程序仅做展示真机兼容，不扩展写入口。静态测试、模拟存储、Compose联调与线上Network/真机证据分别标注，不相互替代。

| 影响面 | 后续要求 |
|---|---|
| 后端/API | 上传会话与确认流程、COS适配、权限、幂等及处理任务；同步API索引/OpenAPI/错误码 |
| 数据库 | 上传会话及状态持久化；SQLite/MySQL等价语义、schema/migration/Pydantic和数据库文档按设计同步 |
| Web/管理端 | COS上传客户端、状态UI、取消重试与业务保存适配；同步Orval及单元/集成测试 |
| 店主端/小程序 | 原图/派生及视频展示兼容回归；直读与读取签名刷新由REQ-0136负责 |
| 部署 | COS最小权限、跨域、配置注入、异步处理及清理入口；需要Docker Compose联调和生产授权验证 |
