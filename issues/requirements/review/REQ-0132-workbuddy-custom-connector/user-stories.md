# REQ-0132 用户故事

## US-001 销售人员查询商品资料

作为企业内部销售或导购，我希望在 WorkBuddy 中用自然语言查询瓷砖 SKU、规格、品牌和类目，以便在客户沟通时快速获得准确商品资料。

验收要点：

- 支持按关键词、品牌、类目、规格、状态等条件查询 SKU。
- 查询结果返回 SKU 名称、规格、品牌、类目、状态、媒体摘要和可追溯详情入口。
- 返回内容遵守公开展示和管理端权限边界，不泄露未授权字段。

## US-002 销售人员查看商品详情

作为销售或导购，我希望在 WorkBuddy 中查看某个 SKU 的完整详情和媒体摘要，以便回答客户关于规格、图片、视频和产品卖点的问题。

验收要点：

- 支持通过 SKU ID 或业务标识查询详情。
- 输出商品基础信息、规格、品牌、类目、上下架状态、图片/视频摘要和公开展示信息。
- 媒体 URL 或预览信息必须来自后端 API，不直接拼接对象存储地址。

## US-003 商品运营整理目录摘要

作为商品运营人员，我希望 WorkBuddy 能基于品牌、类目或搜索结果生成目录摘要和资料缺口提示，以便整理商品目录、选品话术和后续维护清单。

验收要点：

- 支持按查询条件生成目录摘要。
- 摘要包含覆盖范围、代表 SKU、缺失字段、媒体缺口和可人工复核的数据来源。
- 摘要不得保存完整 prompt、真实密钥、完整请求体或敏感客户数据。

## US-004 运营人员预览写操作草稿

作为商品运营人员，我希望第一阶段可以让 WorkBuddy 生成 SKU、品牌、类目或媒体上传的拟变更草稿，以便在真实提交前人工复核。

验收要点：

- dry-run 仅返回拟变更字段、差异、缺失项、权限要求和风险提示。
- dry-run 不写数据库、不上传对象存储、不改变上下架状态。
- dry-run 结果明确提示需进入第二阶段或管理端人工确认后才能真实提交。

## US-005 管理员控制真实写操作

作为管理员，我希望第二阶段远程 MCP 服务开放真实写操作时，能按工具级权限和操作确认控制范围，以便降低 AI 误操作风险。

验收要点：

- 首批真实写操作覆盖 SKU 创建/编辑、SKU 上下架、品牌/类目维护和媒体上传。
- 写操作必须鉴权、校验 scope、携带幂等键，并记录审计追踪。
- 高风险操作前需要 WorkBuddy 展示目标对象、变更摘要和确认动作。
- 删除操作不纳入 MVP。

## US-006 研发和运维排查连接器问题

作为研发或运维人员，我希望连接器调用可以在后端日志和 Task Trace 中追踪，以便排查超时、鉴权失败、越权、上传失败和数据写入失败。

验收要点：

- 连接器调用应能识别 `workbuddy_connector` 或等价来源。
- 后端请求日志记录 `request_id`、`client_request_id`、资源类型、结果和脱敏错误摘要。
- 写操作、上传、批量或长耗时工具记录 Task Trace 和流程节点。
- 日志不得保存 Authorization、Cookie、Token、真实密钥、完整 prompt 或完整 payload。

## US-007 实施人员部署远程 MCP 服务

作为实施或运维人员，我希望第二阶段提供 HTTPS 远程 MCP 服务部署说明和环境变量边界，以便在企业环境稳定接入 WorkBuddy。

验收要点：

- 支持 HTTPS 的 SSE 或 streamable HTTP MCP 连接方式。
- 提供健康检查、服务启动、超时、限流、凭据注入和日志配置。
- 新增环境变量使用示例值和安全注释，真实凭据不进入 Git。
