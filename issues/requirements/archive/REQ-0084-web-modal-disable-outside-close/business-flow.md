# 业务流程

## 1. 核心流程

```text
用户打开 Web 标准弹窗
  |
  v
弹窗展示内容、表单、确认信息或上传控件
  |
  +-- 用户点击弹窗外空白区域 / 遮罩
  |      |
  |      v
  |   弹窗保持打开，内容与输入状态不变
  |
  +-- 用户点击明确关闭入口
  |      |
  |      +-- 无未保存保护要求或用户确认放弃
  |      |      |
  |      |      v
  |      |   弹窗关闭
  |      |
  |      +-- 后续需求定义需二次确认
  |             |
  |             v
  |          按独立策略处理
  |
  +-- 用户点击保存 / 确认
         |
         +-- 操作成功
         |      |
         |      v
         |   沿用现有成功反馈并关闭弹窗
         |
         +-- 操作失败
                |
                v
             弹窗保持打开，展示错误，可继续修改或重试
```

## 2. 表单弹窗流程

```text
进入新增 / 编辑弹窗
  -> 输入或修改字段
  -> 误点遮罩
  -> 弹窗不关闭，字段值保留
  -> 继续填写
  -> 保存
  -> 成功关闭 / 失败留在弹窗内修正
```

适用示例：

- SKU 新增 / 编辑弹窗。
- 品牌新增 / 编辑弹窗。
- 类目新增 / 编辑弹窗。
- 证书新增 / 编辑弹窗。
- Banner 新增 / 编辑弹窗。

## 3. 确认弹窗流程

```text
触发删除 / 上下架 / 批量动作
  -> 展示 Design System 确认弹窗
  -> 误点外部空白区域
  -> 弹窗保持打开
  -> 用户明确点击取消或确认
  -> 按原业务流程结束
```

## 4. 上传弹窗流程

```text
打开含上传控件的弹窗
  -> 选择文件
  -> idle -> uploading
  -> 用户误点弹窗外空白区域
  -> 弹窗保持打开，上传状态不丢失
  -> done 后即时回显 / failed 后展示错误
  -> 用户保存、重试或取消
```

## 5. 与父需求差异

本需求没有父需求。它是跨 Web 端标准弹窗的交互策略 refinement，后续 OpenSpec Change 应评估是否沉淀为 Design System Dialog / Modal 默认行为，并回归管理端与展示端的历史弹窗。

## 6. 例外与待确认流程

| 项目 | 默认策略 | 待确认点 |
|---|---|---|
| 标准 Dialog / Modal | 点击外部不关闭 | 是否存在业务必须保留外部点击关闭的例外。 |
| Esc 键 | 待评审确认 | 可保持关闭，也可随外部点击一起禁用；需统一。 |
| Popover / Dropdown / Tooltip | 暂不纳入 | 轻量浮层通常依赖外部点击关闭，需单独评估。 |
| Select / 日期选择器 | 暂不纳入 | 属于字段选择控件，不默认按标准弹窗治理。 |
| 未保存改动二次确认 | 暂不纳入 | 可后续单独形成交互需求。 |
