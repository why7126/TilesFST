# 用户故事

## US-001 管理端表单弹窗防误关闭

作为后台管理员 / 内部员工，我希望在编辑 SKU、品牌、类目、证书、Banner 等资料时，误点弹窗外空白区域不会关闭弹窗，以便保持当前填写内容和操作上下文。

验收要点：

- 点击弹窗遮罩或弹窗外空白区域后，弹窗保持打开。
- 已填写的表单字段、已选择的上传文件和当前滚动位置不因外部点击丢失。
- 用户仍可通过取消按钮、关闭图标、保存成功等明确路径关闭弹窗。
- 保存失败时弹窗保持打开，并展示字段级或表单级错误反馈。

## US-002 确认弹窗操作不中断

作为运营与商品维护人员，我希望删除、上下架、批量操作等确认弹窗不会因误点外部区域而消失，以便我可以明确选择确认或取消。

验收要点：

- 确认弹窗点击外部空白区域不关闭。
- 取消按钮仍能关闭弹窗并放弃本次确认动作。
- 确认按钮仍能执行原业务动作，并沿用现有成功 / 失败反馈。
- 不使用浏览器原生 `window.confirm` 替代 Design System 确认弹窗。

## US-003 展示端预览弹窗保持可控

作为店主 Web 展示端访问者，我希望商品详情、品牌详情、图片预览等标准弹窗在点击页面空白区域时不会突然关闭，以便稳定查看内容。

验收要点：

- 展示端标准 Dialog / Modal 点击外部不关闭。
- 图片预览、详情滚动、链接点击等弹窗内交互保持可用。
- 详情或预览弹窗必须有可见关闭图标或等价关闭入口。
- 不影响弹窗内键盘焦点、滚动和图片切换。

## US-004 组件维护者统一默认策略

作为前端维护者，我希望在统一 Dialog / Modal 封装层设置默认关闭策略，以便后续新增弹窗天然继承“点击外部不关闭”规则。

验收要点：

- 优先通过共享组件默认配置实现外部点击禁用。
- 历史未复用共享组件的弹窗需在实现阶段盘点并补齐。
- 页面级例外必须在需求评审或 OpenSpec Change 中显式列出。
- 测试覆盖至少一个表单弹窗和一个确认弹窗。

## US-005 上传弹窗状态稳定

作为需要上传图片、证书或视频的运营人员，我希望上传过程不会因误点空白区域中断，以便等待上传、保存和回显状态完成。

验收要点：

- 上传弹窗点击外部不关闭。
- 上传控件状态覆盖 `idle → uploading → done/failed`。
- 上传成功后同会话即时回显缩略图、文件卡片或已上传状态。
- 上传失败时错误展示在控件附近，弹窗保持打开，可重试或取消。
