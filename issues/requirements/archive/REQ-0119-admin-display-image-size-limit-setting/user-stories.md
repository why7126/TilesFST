# 用户故事

## US-001 后台管理员配置详情展示图体积目标

作为后台系统管理员，我希望在「系统设置 - 媒体与存储」中配置详情展示图体积目标上限，以便在不改代码的情况下调整详情展示图的清晰度与流量平衡。

验收要点：

- [ ] 管理端媒体设置页展示详情展示图体积目标字段，默认值为 `768KB`。
- [ ] 字段单位为 KB，并有明确的目标上限说明。
- [ ] 保存后再次进入页面可以看到 effective 值。
- [ ] 恢复默认后该字段回到 `768`。

## US-002 运营人员区分缩略图与详情展示图策略

作为后台运营人员，我希望缩略图和详情展示图使用独立体积策略，以便列表图可以更轻量，而详情图仍保持足够清晰。

验收要点：

- [ ] 修改缩略图体积目标不改变详情展示图体积目标。
- [ ] 修改详情展示图体积目标不改变缩略图体积目标。
- [ ] UI 帮助文案说明该字段控制 `.display` 或详情展示图，不控制 `.thumb` 缩略图。

## US-003 新上传图片按 display 配置生成派生图

作为上传图片的后台用户，我希望保存配置后新上传图片自动使用新的 display 图体积目标，以便新内容尽快获得新的展示策略。

验收要点：

- [ ] 新上传图片生成 `.display` 图时读取最新 effective 配置。
- [ ] 生成失败或无法达标时不阻断原图上传和业务保存。
- [ ] 未达标结果具备 warning、任务链路摘要或维护任务失败原因。

## US-004 运维安全处理历史 display 图

作为运维或 QA，我希望历史 `.display` 图不会在保存系统设置时被自动重建，以便避免线上对象存储 I/O、缓存和展示抖动。

验收要点：

- [ ] 保存系统设置不会扫描对象存储或覆盖历史 `.display` 对象。
- [ ] 历史对象如需应用新策略，需通过受控维护任务 dry-run / apply。
- [ ] 维护任务输出包含成功、失败、跳过、重试候选和失败原因摘要。

## US-005 开发与测试验证配置契约

作为开发和测试人员，我希望 display 图体积目标配置有清晰的 API、默认值、文档和测试契约，以便后续 OpenSpec 实现阶段可以可靠落地。

验收要点：

- [ ] 系统设置 API 支持 GET / PATCH / reset 该字段。
- [ ] OpenAPI / Orval 与前端类型同步。
- [ ] 后端生成逻辑、管理端设置页、维护任务和文档均有对应测试或验证证据。
