# REQ-0128 用户故事

## US-001 首页快速搜索

作为装修客户，我希望在小程序首页首屏清楚看到搜索入口，以便快速搜索瓷砖名称、编号、品牌或规格。

验收要点：

- 首页搜索入口视觉权重高于普通快捷入口。
- 点击入口进入完整搜索页。
- 搜索页能识别来源为首页。
- 入口不遮挡首页 Banner、快捷入口和商品推荐。

## US-002 跨页面进入全局搜索

作为设计师，我希望首页和商品列表能进入完整搜索页，品牌、证书和收藏列表能直接在当前页过滤，以便不用反复返回首页；在全部分类页则保留清晰的分类层级浏览。

验收要点：

- 首页、商品列表等搜索相关页面具备完整搜索入口或等价入口；品牌、证书和收藏列表页搜索保留在当前列表布局内。
- 全部分类页不展示搜索入口，保持分类双栏浏览。
- 跳转搜索页时携带 `sourcePage` 和 `scope` 等上下文；品牌和证书列表页过滤请求携带 `keyword`。
- 搜索页继续承接搜索首页、联想、结果、筛选和无结果态。
- 搜索历史、热门词和结果点击逻辑不因多页面入口接入而漂移。

## US-003 当前列表内搜索

作为门店导购，我希望在商品、品牌、证书等列表中按当前场景快速搜索，以便演示时直接定位客户提到的资料。

验收要点：

- 商品列表支持结合分类、品牌、section 或已有关键词上下文搜索。
- 品牌列表支持按品牌名称、品牌简称和品牌英文名在当前页过滤，搜索态隐藏 Banner 轮播，清空后恢复完整列表。
- 证书列表支持证书名称、品牌名称、证书类型枚举或中文类型标签当前页查找。
- 收藏列表支持当前收藏范围内查找，不跳完整搜索结果页。
- 空结果时提示当前搜索范围，并提供调整关键词、清空当前搜索或进入全局搜索的适用路径。

## US-004 管理端列表搜索一致

作为企业管理人员，我希望管理端主要列表的关键词搜索和筛选体验一致，以便在不同模块中不用重新学习操作方式。

验收要点：

- 品牌、类目、SKU、规格、Banner、证书、用户、日志等主要列表遵守统一搜索区和筛选区规则。
- 搜索、筛选、重置后分页回到合理页码。
- 搜索空态、错误态和加载态清晰。
- 管理端搜索只返回当前用户有权查看的数据。

## US-005 搜索效果可观测

作为产品与运营人员，我希望能看到搜索入口、提交、结果曝光和无结果等行为数据，以便判断搜索体验优化是否有效。

验收要点：

- 搜索入口点击、搜索提交、联想曝光、结果曝光、结果点击、无结果、列表筛选和重置有稳定事件名。
- 行为事件与接口请求具备可关联的链路字段。
- 关键词按规范脱敏或截断，不记录敏感原文。
- 普通搜索默认不接入 Task Trace；复杂查询若接入需说明触发原因。

## US-006 验收人员按统一清单回归

作为 QA，我希望本需求有明确页面清单、API 影响、埋点口径和横切 AC，以便后续实现后能稳定回归。

验收要点：

- 小程序、管理端、API、Orval、数据库、Docker Compose 的影响边界已声明。
- 管理端列表页横切 AC 已纳入验收。
- 小程序页面入口、搜索请求和结果曝光有端上证据。
- Workflow Sync、AI Usage 和后续 OpenSpec 校验不替代产品验收。
