# 业务流程

## 1. 主流程

```text
运营人员
  |
  | 在管理端 SKU 维护入口配置
  | - 召回排序值：正整数，默认 9999
  | - 生效开始时间 / 生效结束时间
  v
SKU 召回置顶配置持久化
  |
  v
小程序请求商品列表或搜索 SKU 结果
  |
  v
后端过滤公开条件与当前筛选条件
  |
  v
判断是否为普通列表
  |-----------------------------|
  | 是                          | 否：新品榜 / 热销榜
  v                             v
应用召回排序值优先排序          保持榜单原排序
  |
  v
分页返回
  |
  v
小程序按接口顺序展示，不显示置顶标识
```

## 2. 排序规则

```text
普通商品列表 / 搜索 SKU 结果：

1. 先过滤公开条件：
   - SKU 已上架
   - 品牌启用
   - 类目启用
   - 规格可用或为空

2. 再过滤当前请求条件：
   - 关键词
   - 品牌
   - 类目
   - 规格
   - 价格区间

3. 再计算召回置顶资格：
   - 召回排序值为正整数
   - 当前时间处于运营配置有效期内
   - 默认值 9999 视为普通排序
   - 生效置顶商品少于 5 个

4. 最后排序并分页：
   - 生效召回商品按排序值升序
   - 同排序值使用稳定兜底
   - 非召回商品保持原列表排序
```

## 3. 榜单例外流程

```text
请求 section=new 或 section=hot
  |
  v
跳过召回置顶排序
  |
  v
沿用新品榜 / 热销榜既有排序
  |
  v
分页返回
```

## 4. 与父需求差异

| 需求 | 关系 | 差异 |
|---|---|---|
| REQ-0006-tile-sku-management | 父需求 | 定义 SKU 管理基础能力；本需求在 SKU 维护中新增召回排序配置，并影响小程序公开列表排序。 |
| REQ-0087-admin-sku-list-sort-optimization | 相关需求 | 该需求优化管理端 SKU 列表默认排序；本需求不改变管理端列表排序，仅在管理端维护字段并影响小程序公开商品列表。 |
| docs/knowledge-base/best-practices/miniapp-product-list-sorting.md | 最佳实践 | 强调后端作为分页排序事实源、小程序端不得跨页重排，以及新品榜 / 热销榜等分支不受影响。 |

## 5. 风险与控制点

| 风险 | 控制点 |
|---|---|
| 小程序端二次排序导致分页重复或跳动 | 明确后端排序事实源，验收小程序无本地跨页重排。 |
| 召回商品越过筛选条件强插 | 后端先过滤公开条件和请求筛选，再计算置顶资格。 |
| 置顶覆盖新品榜 / 热销榜 | 对 `section=new`、`section=hot` 增加回归测试。 |
| 运营输入异常 | 管理端字段只允许正整数，默认值 `9999`，时间字段明确校验。 |
| 置顶数量过多影响列表自然排序 | 生效置顶商品默认少于 5 个，超过上限按排序值和稳定兜底裁定。 |
