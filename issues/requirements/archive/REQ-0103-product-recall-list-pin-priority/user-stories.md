# 用户故事

## US-001 运营配置少量召回置顶商品

作为运营人员，我希望在管理端 SKU 维护入口为少量商品配置召回排序值和有效期，以便在小程序普通商品列表或搜索结果中优先展示重点商品。

验收要点：

- [ ] SKU 召回排序字段只允许正整数。
- [ ] 未配置时默认值为 `9999`。
- [ ] 排序值越低，小程序普通商品列表和搜索 SKU 结果中越靠前。
- [ ] 有效期未开始或已结束时，该商品不参与召回置顶。
- [ ] 生效置顶商品默认少于 5 个。

## US-002 小程序访客优先看到召回商品

作为小程序访客，我希望在普通商品列表和搜索结果中优先看到与当前场景匹配的重点商品，以减少翻页寻找的成本。

验收要点：

- [ ] 召回置顶只影响普通商品列表和搜索 SKU 结果。
- [ ] 商品仍满足关键词、品牌、类目、规格、价格等当前筛选条件。
- [ ] 商品仍满足公开展示条件，未上架或不可公开商品不会被展示。
- [ ] 小程序商品卡片不展示置顶、推荐或召回标识。

## US-003 产品负责人保护榜单语义

作为产品负责人，我希望新品榜和热销榜保持自身排序逻辑，不被召回置顶覆盖，以便榜单结果仍符合用户对“新品”和“热销”的理解。

验收要点：

- [ ] 新品榜 `section=new` 不应用召回置顶排序。
- [ ] 热销榜 `section=hot` 不应用召回置顶排序。
- [ ] 榜单例外不影响普通商品列表和搜索 SKU 结果的召回置顶。

## US-004 开发与测试验证分页稳定性

作为开发 / 测试人员，我希望召回置顶排序在后端分页前统一生效，以便加载更多、刷新和多入口列表顺序稳定。

验收要点：

- [ ] 后端公开 SKU 查询是排序事实源，小程序端不做跨页重排。
- [ ] 多页合并后无重复、漏项或已加载顺序跳动。
- [ ] 排序值相同、默认值、有效期边界和超过上限均有测试覆盖。
