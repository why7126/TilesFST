# 一句话

商品在被召回或重点推荐时，需要支持少量商品在列表排序中置顶展示。

# 原始描述

有少量几个商品在被召回的时候，需要在列表中排序置顶。

# 背景与关联

- 关联需求：`REQ-0006-tile-sku-management`
- 涉及端与模块：商品 / SKU 列表、商品召回排序、管理端配置能力、可能涉及店主 Web 展示端与微信小程序商品列表
- 业务价值：当运营或召回策略命中特定商品时，能够把少量重点商品优先展示，提升重点商品曝光与业务转化。
- 预期后续：明确“召回”来源、置顶配置方式、影响列表范围与同级排序规则后，生成 PRD 并进入评审。

# 待澄清

- [ ] “被召回”是指搜索 / 推荐召回算法命中，还是运营手动选择的重点商品。
- [ ] 置顶能力影响哪些列表：管理端 SKU 列表、店主 Web 商品列表、微信小程序商品列表、搜索结果页或推荐列表。
- [ ] 少量商品的数量上限是多少，是否需要配置生效时间、失效时间或优先级。
- [ ] 多个置顶商品之间如何排序：手动排序、权重值、更新时间或原列表排序。
- [ ] 置顶商品是否仍需满足上架状态、类目、品牌、库存或筛选条件。

# 建议验收要点

- [ ] 支持标记少量商品为置顶或召回优先，并能在目标商品列表顶部展示。
- [ ] 多个置顶商品之间排序稳定、可解释，且不影响非置顶商品的既有排序逻辑。
- [ ] 置顶商品仍遵守列表筛选条件与权限边界，不展示不应展示的下架或无权限商品。
- [ ] 管理端或配置入口能查看、设置、取消置顶状态，并有必要的校验提示。
- [ ] API 响应能表达置顶状态或排序结果；若影响前端 SDK，需同步 OpenAPI / Orval。
