# REQ-0103 商品召回列表支持少量商品排序置顶

## 1. 需求背景

小程序商品列表承载首页瀑布流、分类商品、品牌商品、搜索结果等公开浏览链路。当前列表排序主要按默认时间、热度、新品或价格等规则展示；当搜索或推荐算法召回少量重点商品时，系统缺少统一的“召回优先”排序层，导致这些商品可能散落在列表后部，无法在用户进入列表时获得足够曝光。

本需求要求在小程序商品列表中引入少量召回商品置顶能力：当搜索 / 推荐算法明确召回若干商品时，在符合当前筛选条件的前提下，将这些商品稳定排在目标列表顶部；但新品榜、热销榜不允许被召回置顶覆盖原排序，避免破坏榜单语义。

## 2. 目标用户

| 用户 | 核心诉求 |
|---|---|
| 小程序访客 | 在搜索、分类或推荐列表中优先看到与当前场景更匹配的重点商品。 |
| 运营人员 | 通过算法召回结果提升少量重点商品曝光，不需要小程序额外展示标识。 |
| 产品 / 业务负责人 | 明确召回置顶的适用列表、排序边界和榜单例外规则。 |
| 开发 / 测试人员 | 明确排序注入位置、分页一致性、筛选约束和 API / DB 影响。 |

## 3. 需求目标

- 小程序所有普通商品列表支持搜索 / 推荐算法召回商品优先排序。
- 召回置顶只调整商品排列顺序，不在小程序卡片上展示“置顶”“推荐”等 UI 标识。
- 召回置顶必须在后端排序层统一生效，确保分页前全量有序。
- 召回商品仍必须满足当前列表筛选条件和公开展示条件。
- 新品榜、热销榜保持原有榜单排序，不允许召回置顶覆盖。
- 排序能力由管理端运营维护 SKU 排序字段驱动，并为后续算法策略接入保留清晰扩展点。

## 4. 范围

### 4.1 本期包含

| 范围 | 说明 |
|---|---|
| 小程序普通商品列表 | 覆盖 `/api/v1/miniapp/products` 下的全部商品、分类商品、品牌商品、关键词商品等普通商品列表。 |
| 小程序搜索商品结果 | 覆盖 `/api/v1/miniapp/search` 中 SKU 商品结果列表，确保搜索召回商品可优先展示。 |
| 后端统一排序策略 | 在后端查询排序层合并召回优先级，避免小程序端本地二次排序。 |
| 公开展示条件 | 召回商品仍需满足 SKU 已上架、品牌启用、类目启用、规格可用等既有公开过滤条件。 |
| 筛选条件约束 | 召回商品必须匹配当前关键词、品牌、类目、规格、价格等筛选条件，不能越过用户筛选范围强插。 |
| 分页一致性 | 召回排序必须先于分页生效，翻页、刷新和加载更多结果稳定且不重复。 |
| API / DB / 测试同步 | 如新增字段、表或排序参数，必须同步 Schema、OpenAPI、Orval、数据库文档和测试。 |
| 管理端运营配置 | 瓷砖 SKU 新增召回置顶排序字段，运营可在 SKU 维护入口配置正整数排序值、有效期开始时间和有效期结束时间。 |

### 4.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 新品榜召回置顶 | `section=new` 的新品榜不允许召回置顶覆盖原排序。 |
| 热销榜召回置顶 | `section=hot` 的热销榜不允许召回置顶覆盖原排序。 |
| 小程序 UI 标识 | 不展示“置顶”“推荐”“召回”等卡片角标或文字说明。 |
| 小程序本地排序 | 不在小程序端对接口结果进行置顶重排。 |
| 管理端 SKU 列表置顶 | 不调整管理端 SKU 列表排序。 |
| 店主 Web 商品列表 | 不调整店主 Web 展示端商品列表排序。 |
| 收藏列表排序 | 收藏列表保持用户收藏时间等既有本地排序，不纳入算法召回置顶。 |
| 搜索实时联想置顶 | 搜索建议 / suggestion 不纳入本期置顶排序，除非后续单独提出需求。 |

## 5. 核心概念

### 5.1 搜索 / 推荐算法召回

“召回”指搜索或推荐算法在当前用户请求、关键词、类目、品牌或推荐场景下识别出的少量候选商品。召回结果可来自现有规则、后续算法服务、配置化权重或离线策略，但对小程序列表的输出统一表现为排序优先级。

### 5.2 召回置顶商品

召回置顶商品指在当前列表候选集中，被召回策略标记为需要优先展示的 SKU。它不是新的展示状态，也不改变 SKU 上下架状态、是否新品、是否热销等业务字段。

### 5.3 召回排序值

召回排序值是瓷砖 SKU 新增的运营配置字段，只允许正整数，默认值为 `9999`。数值越低排序越靠前；当排序值为默认值或配置不在有效期内时，该 SKU 视为普通商品，按原列表排序。

### 5.4 普通商品列表

普通商品列表指不带新品榜或热销榜语义的商品浏览结果，包括全部商品、分类商品、品牌商品、关键词商品和搜索结果 SKU 列表。普通列表允许召回置顶参与排序。

### 5.5 榜单列表

榜单列表指新品榜和热销榜。榜单列表已有明确业务排序语义，本期不允许召回置顶覆盖其原始排序。

## 6. 功能要求

### FR-001 召回置顶适用范围

- 小程序普通商品列表 MUST 支持召回商品优先排序。
- 小程序搜索结果中的 SKU 商品列表 MUST 支持召回商品优先排序。
- 新品榜和热销榜 MUST 保持原有排序，不得应用召回置顶。
- 收藏列表、搜索实时联想、管理端 SKU 列表和店主 Web 商品列表 MUST NOT 因本需求改变排序。

### FR-002 后端统一排序

- 召回置顶排序 MUST 在后端商品查询排序层生效。
- 系统 MUST 在完整结果集排序后再分页，避免仅当前页内置顶。
- 小程序端 MUST 直接渲染接口返回顺序，不得额外实现置顶重排。
- 后端排序逻辑 MUST 对 `/api/v1/miniapp/products` 与 `/api/v1/miniapp/search` 的商品结果保持一致的召回优先原则。

### FR-003 筛选与公开条件

- 召回置顶商品 MUST 满足当前列表已有公开条件：SKU 已上架、品牌启用、类目启用、规格可用。
- 召回置顶商品 MUST 满足当前请求的关键词、品牌、类目、规格、价格区间等筛选条件。
- 若召回商品不匹配当前筛选条件，系统 MUST 排除该商品，不得强行插入列表顶部。
- 排序策略不得绕过权限、状态或公开字段过滤。

### FR-004 置顶数量与同级排序

- 系统 MUST 支持少量召回置顶商品，默认上限为少于 5 个生效置顶商品。
- 召回置顶排序 MUST 使用 SKU 召回排序值，且排序值只能为正整数，默认值为 `9999`。
- 召回排序值越低，商品在普通商品列表和搜索 SKU 结果中越靠前。
- 召回排序值相同的商品 MUST 使用稳定兜底排序，例如既有列表排序字段、更新时间或 SKU ID。
- 非召回商品 MUST 保持当前列表对应的既有排序规则。
- 召回置顶商品数量达到上限时，系统 MUST 仅让排序值最靠前且处于有效期内的少量商品参与置顶，其余商品按普通商品排序。

### FR-005 运营配置与有效期

- 管理端 SKU 维护入口 MUST 支持维护召回排序值。
- 召回排序值输入 MUST 只允许正整数；为空或未配置时按默认值 `9999` 处理。
- 管理端 MUST 支持配置召回置顶生效开始时间和结束时间。
- 当前时间不在运营配置有效期内时，该 SKU MUST 不参与召回置顶排序。
- 有效期配置为空时的语义 MUST 在 OpenSpec 阶段明确，并通过测试覆盖。

### FR-006 榜单例外

- 当请求为新品榜时，系统 MUST 使用新品榜原有排序，不得加入召回置顶优先级。
- 当请求为热销榜时，系统 MUST 使用热销榜原有排序，不得加入召回置顶优先级。
- 榜单例外规则 MUST 覆盖首页快捷入口进入的新品榜、热销榜，以及任何通过 `section=new` 或 `section=hot` 派生的商品列表。
- 榜单例外不得影响普通商品列表的召回置顶能力。

### FR-007 小程序展示约束

- 小程序商品卡片 MUST NOT 展示“置顶”“推荐”“召回”等额外 UI 标识。
- 小程序商品卡片布局、图片、标题、价格、品牌、类目和标签展示保持现有体验。
- 小程序埋点可记录商品曝光位置，但不得依赖 UI 标识判断召回状态。
- 排序变化不得造成列表加载、下拉刷新、加载更多、分享封面或空状态异常。

### FR-008 API 与数据模型

- 持久化召回置顶配置 MUST 明确 SQLite / MySQL 表结构、索引、有效期、排序值和状态字段。
- 如需要在 API 响应中返回召回状态或排序解释字段，MUST 同步 Pydantic Schema、OpenAPI、Orval 和接口文档。
- 若 API 响应不展示召回状态，排序仍需可通过测试数据和查询结果验证。
- 排序参数、分页字段、错误码和现有响应结构不得发生不兼容变化。
- 查询实现 MUST 使用参数化查询、ORM 表达式或等价安全方式，禁止拼接不可信输入到 SQL。

### FR-009 可观测与测试

- 测试 MUST 覆盖普通商品列表中召回商品位于非召回商品之前。
- 测试 MUST 覆盖搜索结果 SKU 列表中召回商品位于顶部。
- 测试 MUST 覆盖召回商品不满足品牌、类目、价格或状态过滤时不会展示。
- 测试 MUST 覆盖新品榜、热销榜不应用召回置顶。
- 测试 MUST 覆盖分页前排序与加载更多不重复。
- 测试 MUST 覆盖排序字段只允许正整数、默认值 `9999`、排序值相同、有效期未开始、有效期已结束和超过置顶上限等边界。

## 7. UI 约束

- 小程序不新增可见置顶标识、推荐角标、说明文案或排序控件。
- 商品卡片继续复用现有小程序商品卡片结构。
- 首页瀑布流、商品列表页、搜索结果页只体现顺序变化。
- 不新增页面教学、弹窗、提示卡片或营销式说明区域。
- 若后续实现需要调试字段，应限制在后端日志、测试或开发工具，不进入小程序公开 UI。

## 8. 数据与接口影响

| 范围 | 影响 |
|---|---|
| SQLite/MySQL | 瓷砖 SKU 需要新增召回排序值与有效期字段，需同步 schema、migration 和数据库文档。 |
| Pydantic Schema | 若响应需要携带召回状态或排序解释字段，需同步 `MiniappProductCard` 或相关响应 Schema。 |
| OpenAPI/Orval | API 请求或响应发生变化时必须同步 OpenAPI 与 Orval。 |
| 后端 API | 影响 `/api/v1/miniapp/products` 与 `/api/v1/miniapp/search` 的商品结果排序。 |
| 小程序 | 只消费接口返回顺序，不新增 UI 标识。 |
| 管理端 | SKU 维护入口需支持运营配置召回排序值与有效期；不改变管理端 SKU 列表默认排序。 |
| 店主 Web | 本期不涉及。 |
| 测试 | 需覆盖普通列表、搜索结果、筛选约束、榜单例外和分页稳定性。 |
