# 原型策略

## 1. UI 范围

本需求不要求小程序展示新增 UI 标识；小程序商品卡片、列表结构、搜索结果结构保持现状，只通过接口返回顺序体现召回置顶。

管理端需要在 SKU 维护入口增加运营配置字段：

- 召回排序值：正整数，默认 `9999`，数值越低越靠前。
- 生效开始时间：运营配置的开始时间。
- 生效结束时间：运营配置的结束时间。

## 2. 管理端布局策略

优先复用现有 SKU 新建 / 编辑弹窗的表单结构，在商品基础信息或运营配置区域加入字段组：

```text
运营配置
├── 召回排序值 [InputNumber]
├── 生效开始时间 [DateTimePicker]
└── 生效结束时间 [DateTimePicker]
```

字段级提示：

- 召回排序值仅允许正整数。
- 默认值为 9999。
- 数值越低，在小程序普通商品列表越靠前。
- 新品榜、热销榜不受此字段影响。

## 3. 小程序布局策略

小程序无需新增视觉稿：

- 不新增角标。
- 不新增排序说明文案。
- 不新增列表控件。
- 商品卡片继续复用现有组件，仅按后端顺序展示。

## 4. 验收策略

- 管理端以字段可编辑、字段校验、保存回显、弹窗宽度和 toast/confirm 作为 UI 验收重点。
- 小程序以 API 返回顺序、分页稳定性和无新增 UI 标识作为验收重点。
- 若实现阶段确认新增独立运营配置页，再补充 HTML prototype 或截图基准。
