# 验收标准

## 1. 管理端弹窗与字段校验

- [ ] **AC-001** 新增类目弹窗中，类目名称字段允许输入并保存 15 个用户可见字符。
- [ ] **AC-002** 编辑类目弹窗中，类目名称字段允许输入并保存 15 个用户可见字符。
- [ ] **AC-003** 类目名称 trim 后为空时，前端阻止保存并提示「类目名称不能为空」或等价文案。
- [ ] **AC-004** 类目名称达到 16 个用户可见字符时，前端阻止保存并提示「类目名称最多 15 个字符」或等价文案。
- [ ] **AC-005** 中文、英文、数字均按 1 个用户可见字符计数，15 个中文、15 个英文、15 个数字和中英文数字混排样例均可通过长度校验。
- [ ] **AC-006** 类目名称字符集仍沿用既有规则，仅允许中文、英文、数字；空格、标点、emoji、下划线、连字符、斜杠等特殊字符仍被拒绝。
- [ ] **AC-007** 同层级类目名称唯一规则不变，15 字符合规名称如与同层级既有名称重复仍被拒绝。

## 2. 后端 API 与错误响应

- [ ] **AC-008** `POST /api/v1/admin/tile-categories` 接受 1-15 字符类目名称，并继续执行字符集、同层级唯一、层级和排序权重校验。
- [ ] **AC-009** `PUT /api/v1/admin/tile-categories/{id}` 接受 1-15 字符类目名称，并继续不允许修改编码和上级类目等既有边界。
- [ ] **AC-010** 创建类目时，16 字符名称被后端拒绝，并返回统一 response envelope。
- [ ] **AC-011** 更新类目时，16 字符名称被后端拒绝，并返回统一 response envelope。
- [ ] **AC-012** 如果沿用既有名称非法错误码，测试必须断言 message 已表达 15 字符上限；如果新增错误码，必须同步 `docs/standards/error-codes.md`。
- [ ] **AC-013** 后端不得暴露 FastAPI / Pydantic 默认 `detail` 作为唯一错误结构。

## 3. 数据库、OpenAPI 与 Orval

- [ ] **AC-014** `tile_categories.name` 或等价字段确认支持至少 15 个用户可见字符；若无需迁移，OpenSpec design 中记录原因。
- [ ] **AC-015** 若 SQLite schema、MySQL migration、索引或约束存在 10 字符限制，后续 Change 必须包含迁移和回滚说明。
- [ ] **AC-016** OpenAPI schema 中类目名称字段的 `maxLength` 或等价约束更新为 15。
- [ ] **AC-017** Orval 生成客户端与 OpenAPI 保持一致，前端不得手写重复接口类型。
- [ ] **AC-018** 测试夹具、helper 和最小合法 payload 中不再保留“最多 10 字符”的有效约束假设。

## 4. 展示兼容性

- [ ] **AC-019** 管理端类目列表名称列展示 15 字符名称时，不与编码副行、状态列、操作列或分页区域重叠。
- [ ] **AC-020** 管理端左侧类目树展示 15 字符名称时，不破坏层级缩进、SKU 数量徽标和当前节点激活态。
- [ ] **AC-021** 小程序分类页或分类入口使用 15 字符类目名称样例回归，不出现文字重叠、容器横向撑破或关键操作被遮挡。
- [ ] **AC-022** Web 展示端分类筛选入口或商品列表入口使用 15 字符类目名称样例回归，不出现文字重叠、容器横向撑破或关键操作被遮挡。
- [ ] **AC-023** 前台端如空间不足可沿用合理截断 / tooltip / 换行策略，但不得在数据层拒绝保存合法 15 字符名称。

## 5. 测试与回归

- [ ] **AC-024** 后端测试覆盖：15 字符名称可创建，16 字符名称创建失败。
- [ ] **AC-025** 后端测试覆盖：15 字符名称可更新，16 字符名称更新失败。
- [ ] **AC-026** 前端表单测试覆盖：15 字符名称不显示超长错误，16 字符名称显示「类目名称最多 15 个字符」。
- [ ] **AC-027** 前端回归测试覆盖：非法字符、空名称、同层级重复名称规则不因长度调整而放松。
- [ ] **AC-028** 管理端回归类目树、列表、筛选、分页、启停、删除和保存刷新行为不受影响。
- [ ] **AC-029** 小程序或 Web 展示端如已有分类页测试，补充 15 字符名称样例；如暂无自动化，需在验收记录中给出手工截图或说明。

## 横切 AC（knowledge-base）

> 来源：`docs/knowledge-base/best-practices/admin-list-page-consistency.md`、`docs/knowledge-base/best-practices/admin-modal-width-css-cascade.md` — 预防 Sprint 002/003 复发类缺陷。

- [ ] **AC-XCUT-001** 管理端类目列表分页 DOM 继续对齐用户管理基准：左侧 `page-summary`，右侧 `page-right` 页码与每页条数，15 字符名称回归不得重写分页结构。
- [ ] **AC-XCUT-002** 管理端类目列表操作成功 / 失败反馈使用 fixed toast，不得使用会推挤页面或表格纵向位移的文档流 notice。
- [ ] **AC-XCUT-003** 类目启停、删除等状态或危险操作继续使用 Design System confirm modal；本需求不得引入 `window.confirm`。
- [ ] **AC-XCUT-004** 管理端摘要指标卡如被触达，DOM 仍使用 `.metric-label` / `.metric-value` / `.metric-desc`，不得退化为裸 `strong` / `span` 结构。
- [ ] **AC-XCUT-005** `CategoryFormModal` 或后续专属弹窗 TSX 不得同时挂载通用 `modal-card` 与专属类；应使用单一专属类承载宽度样式。
- [ ] **AC-XCUT-006** 在 1440px 视口下验收类目弹窗 computed width 与设计批准宽度一致；本 REQ 默认沿用类目弹窗既有宽度，若 Change 调整宽度必须在 design/tasks 中写明。
- [ ] **AC-XCUT-007** Web 测试或等价 CSS 栈校验需覆盖可能冲突的 admin CSS，确认类目弹窗宽度未被 `.modal-card`、用户管理或系统设置样式覆盖。
- [ ] **AC-XCUT-008** 矮视口下弹窗 body 可滚动，底部操作区不遮挡上级类目、类目名称、排序权重、描述或状态字段。
