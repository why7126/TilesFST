# 用户故事

## US-001 创建用户时维护联系信息

作为后台管理员，我希望在添加用户时填写联系邮箱和手机号码，以便新账号创建后即可保留线下联系信息。

验收要点：

- 添加用户弹窗包含「联系邮箱」「手机号码」字段。
- 两个字段允许为空；非空时按规则校验。
- 保存成功后列表或再次编辑时能看到已保存的联系信息。

## US-002 编辑用户时更新或清空联系信息

作为后台管理员，我希望在编辑用户时修改或清空联系邮箱和手机号码，以便用户联系信息变化后能及时更新。

验收要点：

- 编辑弹窗回填当前邮箱和手机号。
- 修改后保存，后端返回的新值与页面展示一致。
- 清空字段后保存，后端保存为空值，不保留旧数据。

## US-003 通过联系信息检索用户

作为后台管理员，我希望能用邮箱或手机号片段搜索用户，以便在只知道联系方式时快速定位账号。

验收要点：

- 关键词搜索匹配用户名、昵称、邮箱和手机号。
- 搜索 placeholder 或帮助文案体现新的匹配范围。
- 搜索不会改变角色、状态、登录情况筛选的既有语义。

## US-004 联系信息不参与身份与权限判断

作为系统管理员，我希望邮箱和手机号只是联系信息，不影响登录和权限，以避免引入未评审的账号体系变化。

验收要点：

- 邮箱和手机号不要求唯一。
- 邮箱和手机号不可用于登录、重置密码或权限判断。
- 受保护账号、已删除用户、非管理员访问等既有约束保持不变。
