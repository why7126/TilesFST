# REQ-0086 微信小程序品牌列表页 UI 与交互体验优化

## 1. 需求背景

微信小程序品牌列表页已具备品牌浏览、品牌详情入口及品牌下商品类目汇总能力，但当前页面的 UI 层级和交互反馈仍不够顺畅。用户在浏览品牌时，需要更明确地识别页面主题、品牌矩阵、品牌卡片入口和类目入口，避免品牌详情跳转与类目商品列表跳转混淆。

本需求基于已重新设计的品牌列表页视觉稿，优化小程序品牌列表页的整体视觉、信息层级和触控体验。新版页面采用暗色旗舰风与金色品牌强调色，顶部保留自定义导航与微信胶囊避让，中部使用品牌氛围 Hero 区，下方以“品牌矩阵”承载单品牌卡片，并通过上行品牌入口与下行类目标签入口形成清晰的操作分区。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 装修业主 | 快速理解品牌页内容，按品牌和类目筛选感兴趣的瓷砖商品。 |
| 室内设计师 | 在移动端向客户展示品牌阵列与主营类目时，页面更高级、信息更好扫读。 |
| 门店销售 | 在小程序端演示品牌和商品范围时，能稳定点击品牌详情或指定类目商品列表，减少误触。 |

## 3. 范围

### 3.1 本期包含

| 范围 | 说明 |
|---|---|
| 品牌列表页整体视觉优化 | 按新版设计稿优化暗色页面、金色强调、间距、圆角、边框、文字层级与底部安全区。 |
| 顶部导航与页面标题 | 保留小程序自定义导航结构，标题展示“品牌”，左侧返回按钮、右侧微信胶囊区域需安全避让。 |
| 品牌氛围 Hero 区 | 在列表上方展示品牌主题 Banner，包含英文弱标签、主标题与辅助描述。 |
| 品牌矩阵区 | 品牌列表标题展示“品牌矩阵”，不展示“按类目快速识别”等辅助提示。 |
| 单品牌卡片 | 每张卡片展示一个品牌，上行展示品牌标识、品牌名称、商品数量和进入指示。 |
| 类目汇总交互 | 卡片下行直接展示完整类目胶囊标签，不展示额外类目说明文案；类目标签支持独立点击进入品牌下对应类目的商品列表。 |
| 状态与边界体验 | 覆盖加载、空态、无 Logo、长品牌名、类目较多、弱网和不同手机宽度下的视觉与交互兜底。 |

### 3.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 管理端品牌维护改造 | 不新增品牌后台字段、排序配置、推荐配置或权限能力。 |
| 品牌详情页结构改造 | 不调整品牌详情页内部模块、证书、商品 Tab 或详情布局。 |
| 商品列表页视觉重构 | 类目标签可跳转到商品列表页，但商品列表页自身 UI 不在本需求范围。 |
| 类目管理规则改造 | 不调整类目层级、命名规则、绑定逻辑或后台排序规则。 |
| 新增搜索/筛选体系 | 不新增品牌搜索、首字母索引、多条件筛选或热门品牌运营位。 |
| Web 展示端与管理端调整 | 本需求仅针对微信小程序品牌列表页。 |

## 4. 功能要求

### FR-001 顶部导航与页面标题

- 品牌列表页 MUST 使用小程序现有自定义导航能力，页面标题 MUST 展示为“品牌”。
- 左侧返回按钮 MUST 保留明确点击热区和按压反馈。
- 右侧 MUST 避让微信原生胶囊区域，不得出现标题、按钮或内容遮挡胶囊。
- 导航区域的背景、文字和按钮样式 SHOULD 与新版暗色旗舰风保持一致。

### FR-002 品牌氛围 Hero 区

- 页面顶部内容区 SHOULD 展示品牌氛围 Hero 卡片，用于强化品牌页定位。
- Hero 区 SHOULD 包含英文弱标签，例如“BRAND GALLERY”。
- Hero 主标题 SHOULD 表达品牌价值，例如“全球严选瓷砖品牌”。
- Hero 辅助文案 SHOULD 简短说明品牌筛选价值，例如“轮播图保持现有品牌页能力”或实现阶段确认后的正式文案。
- Hero 区 MUST 不影响既有品牌轮播数据与点击能力；若复用现有轮播容器，用户可感知的数据来源和跳转规则 MUST 保持兼容。

### FR-003 品牌矩阵标题区

- 品牌列表区域标题 MUST 展示为“品牌矩阵”。
- 标题右侧 MUST NOT 展示“按类目快速识别”等弱提示文案。
- 标题区 MUST 与 Hero 区、品牌卡片区保持稳定纵向间距，不得与卡片边框或内容粘连。

### FR-004 单品牌卡片上行信息

- 品牌列表 MUST 每张卡片展示一个品牌。
- 卡片上行 MUST 展示品牌标识、品牌名称、商品数量和进入指示。
- 品牌 Logo 缺失或加载失败时，MUST 使用品牌首字母、品牌缩写或项目现有占位策略兜底，不得出现破图。
- 品牌名称过长时 MUST 限制行数或截断，商品数量和进入指示仍需可见。
- 商品数量 MUST 表达该品牌下小程序公开可见商品数量，文案 SHOULD 使用“128 款商品”一类短句。
- 卡片上行品牌信息区域 MUST 作为独立点击入口，点击后进入对应品牌详情页。

### FR-005 卡片下行类目汇总

- 卡片下行 MUST 与上行品牌信息通过分隔线、间距或视觉层级分开。
- 下行 MUST NOT 展示“全部类目 · 点击查看该品牌下的类目商品”等说明文案。
- 下行 MUST 展示该品牌公开商品对应的末级类目集合。
- 同一品牌下重复的末级类目 MUST 去重展示。
- 每个类目 MUST 以独立胶囊标签展示，标签文字 MUST 尽量完整显示。
- 类目胶囊标签字号 SHOULD 比品牌名称字号小 2rpx，避免扫读时显得过弱。
- 类目数量较多时 MUST 自动换行并由卡片高度自然承载，不得用“等 N 类”替代完整集合。
- 每个类目标签 MUST 是独立点击入口，点击后携带 `brandId` 与 `categoryId` 进入该品牌下对应类目的商品列表页。
- 点击类目标签 MUST NOT 同时触发品牌详情页跳转。

### FR-006 数据与接口边界

- 小程序端 MUST 通过后端公开接口获取品牌列表数据，不得直连管理端私有接口或未授权对象存储。
- 品牌列表项 SHOULD 至少包含品牌 ID、品牌名称、Logo URL、公开商品数量和末级类目集合。
- 类目集合中的每一项 SHOULD 包含 `categoryId` 与 `categoryName`，以支持类目标签精确跳转。
- 商品数量与类目集合 MUST 使用一致的数据口径，优先统计小程序公开可见商品。
- 若现有接口无法满足类目标签跳转所需字段，后续 OpenSpec Change MUST 同步 API、OpenAPI、Orval、小程序调用类型、文档和测试。

### FR-007 状态反馈与边界场景

- 页面加载中 MUST 有明确状态，不得白屏。
- 品牌为空时 MUST 展示与暗色视觉一致的空态文案或组件。
- 接口失败时 MUST 展示可理解的错误提示，并保留重试入口或下拉刷新能力。
- 无 Logo、无商品、无类目、长品牌名、长类目名和类目数量较多时，页面 MUST 不重叠、不横向溢出、不遮挡底部 TabBar。
- 品牌卡片、品牌入口和类目标签 SHOULD 提供小程序端可感知的按压反馈。

## 5. UI / UE 约束

- 页面视觉 MUST 以新版设计稿为目标，延续“工业石材 · 暗色旗舰风”，主背景使用深色，品牌强调使用金色或金色系语义色。
- 页面 MUST 避让状态栏、导航栏、微信胶囊和底部 TabBar / Safe Area。
- 不得使用会破坏品牌质感的高饱和大面积色块；卡片边框、分隔线和辅助文案 SHOULD 保持低对比但可读。
- 品牌卡片 SHOULD 使用 16px 左右的圆角、细金色边框或项目 Design System 可接受的等价语义样式。
- 品牌标识区域 SHOULD 使用圆形 Logo / 首字母容器；首字母占位需与品牌金色强调一致。
- 类目标签 SHOULD 使用低对比胶囊形态，保持足够点击间距。
- 在 320、375、390、430 pt 常见小程序视口下，主标题、品牌名称、商品数量、类目标签和底部导航文字 MUST 不重叠、不溢出。
- 底部 TabBar 中“品牌”项 MUST 呈现选中态，且页面滚动内容不得被 TabBar 遮挡。

## 6. 数据字段建议

品牌列表项 SHOULD 映射以下字段；实际命名在 OpenSpec 与接口实现阶段按项目约定确认。

| 字段 | 用途 | 首期要求 |
|---|---|---|
| `brandId` | 品牌详情跳转、类目商品列表筛选和埋点 | 必需 |
| `brandName` | 品牌名称展示 | 必需 |
| `brandInitials` | Logo 缺失时展示品牌缩写或首字母 | 建议 |
| `logoUrl` | 品牌 Logo 展示 | 必需或需有占位兜底 |
| `productCount` | 品牌公开商品数量 | 必需 |
| `leafCategories[].categoryId` | 类目标签点击跳转参数 | 必需 |
| `leafCategories[].categoryName` | 类目标签展示名称 | 必需 |
| `sortOrder` | 品牌列表排序 | 建议 |
| `isPublic` | 是否可公开展示 | 必需 |

## 8. 风险与待确认

| 风险 / 待确认 | 说明 |
|---|---|
| 设计稿与现有轮播关系 | 需确认新版 Hero 区是替换现有品牌轮播视觉，还是仅作为轮播的一帧/样式表达；PRD 约束为不破坏既有轮播能力。 |
| 类目点击参数 | 若当前接口只返回类目名称，不返回 `categoryId`，需要在后续 Change 中扩展接口。 |
| 类目过多导致卡片过高 | 需求要求完整展示类目集合，品牌类目特别多时页面会变长，需要通过自然滚动承载。 |
| 暗色视觉可读性 | 金色、灰色辅助文案和卡片边框需在真机上验证对比度与可读性。 |
| 误触风险 | 品牌上行与类目标签均可点击，实现时需阻止事件冒泡，避免类目点击触发品牌详情跳转。 |
| 视觉资源落地 | 若后续需要固定 Hero 背景图或品牌氛围图，需要确认资源来源、尺寸、压缩和小程序包体影响。 |
