# REQ-0109 用户故事

## US-001 后台用户在用户菜单中切换主题

作为后台管理员或运营人员，我希望在用户菜单中完成主题切换，而不是在侧边栏导航区寻找主题选择器，以便账号相关偏好集中在同一入口中。

### 验收要点

- 用户菜单展开层内存在主题切换按钮。
- 侧边栏底部不再展示独立主题选择器。
- 主题切换不会影响个人资料、密码修改、退出登录等用户菜单操作。

## US-002 后台用户只面对两种主题模式

作为后台用户，我希望主题选择只保留暗色旗舰与跟随系统两种模式，以便快速理解当前主题策略，减少多选项选择负担。

### 验收要点

- 可见主题模式仅为 `dark_flagship` 与 `system`。
- 不再暴露 `comfort_dark` 与独立 `light` 选项。
- 选择 `system` 时，实际亮暗主题跟随操作系统偏好变化。

## US-003 已有偏好用户平滑过渡

作为曾经保存过浅色或舒适暗色偏好的用户，我希望升级后页面仍能稳定展示主题，不会因为旧值导致界面异常或偏好同步失败。

### 验收要点

- 历史 `light` 可归一为 `system`。
- 历史 `comfort_dark` 可归一为 `dark_flagship`。
- 本地存储、账号资料、API 校验与前端类型保持一致。

## US-004 QA 验证主题入口与状态同步

作为 QA，我希望有明确的入口、状态、兼容和同步验收清单，以便验证主题按钮、系统偏好监听、API contract 与 Orval 类型都已闭环。

### 验收要点

- 可验证本机主题即时生效。
- 可验证账号级主题同步成功和失败反馈。
- 可验证 OpenAPI / Orval 类型不再暴露已移除主题模式。
