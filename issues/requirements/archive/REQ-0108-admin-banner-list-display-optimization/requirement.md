# REQ-0108 Web 管理后台 Banner 列表显示内容优化

## 1. 需求背景

Web 管理后台 Banner 管理页用于维护小程序首页轮播和品牌列表页轮播的 Banner 图片、投放位置、跳转、状态、排序与有效期。随着 Banner 标题逐步降级为内部兼容字段，列表中继续展示内部标题或把识别重点放在标题上，会增加运营理解成本。

用户反馈希望 Banner 列表更贴近实际运营判断：Banner 本身以主图为核心识别对象；跳转目标需要展示可读名称，避免运营只能看到跳转类型和对象 ID 后还要进入编辑弹窗确认。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 后台管理员 / 运营 | 在 Banner 列表中快速确认主图和跳转对象，不被内部标题等非运营信息干扰。 |
| 开发 / 测试 | 在不改变 Banner 基础配置能力的前提下，明确列表新增字段、API 返回字段和测试边界。 |

## 3. 需求目标

1. Banner 列仅展示主图或缩略图，不展示标题、内部识别、展示位置、状态、排序等其他文字信息。
2. 保留当前列表已有的展示位置、展示端、跳转类型、状态、有效期、排序、更新时间和操作列。
3. 新增独立“跳转对象”列，按跳转类型展示可读对象名称、链接地址或 `-`。
4. 管理端列表无需进入编辑弹窗即可判断 Banner 图片对应的跳转目标。
5. 维持现有 Banner 创建、编辑、上线、下线、删除、搜索、筛选和分页能力稳定。

## 4. 范围

### 4.1 本期包含

| 范围 | 说明 |
|---|---|
| Banner 列内容瘦身 | Banner 列只显示主图/缩略图；不再显示内部标题、内部识别或其他文本。 |
| 跳转对象独立列 | 在 Banner 列表中新增独立“跳转对象”列。 |
| 跳转对象展示规则 | 品牌详情显示品牌名称，SKU 显示 SKU 名称，专题页显示专题名称，外部链接显示链接地址，无跳转显示 `-`。 |
| API 只读字段 | 管理端 Banner 列表接口补充跳转对象展示字段，供前端直接渲染。 |
| 现有列保留 | 展示位置、展示端、跳转类型、状态、有效期、排序、更新时间、操作等未提及修改的列继续保留。 |
| 测试覆盖 | 覆盖列表列结构、Banner 列只显示图片、跳转对象字段和 API/Orval 同步。 |

### 4.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 修改 Banner 表单 | 不改变新增/编辑 Banner 的字段、校验和保存流程。 |
| 修改小程序前台展示 | 不改变小程序首页或品牌列表页 Banner 渲染。 |
| 修改跳转规则 | 不新增跳转类型，不改变品牌、SKU、专题、外部链接或无跳转的点击行为。 |
| 展示 SKU 编码 | SKU 跳转对象只显示 SKU 名称，不显示 SKU 编码。 |
| 删除 Banner 标题字段 | 不要求移除数据库、API 或历史数据中的 `title` 字段。 |
| 大规模列表重构 | 不重做筛选、分页、批量操作或页面整体布局。 |

## 5. 功能要求

### FR-001 Banner 列只显示主图

- Banner 列 MUST 只展示 Banner 主图或缩略图。
- Banner 列 MUST 不展示标题、内部识别、展示位置、状态、排序、跳转类型、更新时间等文字内容。
- 图片加载失败时 SHOULD 沿用现有列表图片 fallback 能力。
- Banner 图片展示尺寸 SHOULD 保持列表可扫描性，不因只显示图片导致行高异常膨胀。

### FR-002 保留既有列表列

- 展示位置列 MUST 保留，并继续显示 Banner 投放位置。
- 展示端列 MUST 保留，并继续显示当前展示端。
- 跳转类型列 MUST 保留，并继续显示跳转类型标签。
- 状态、有效期、排序、更新时间和操作列 MUST 保留。
- 本需求未提及的筛选、搜索、分页、上线、下线、删除与编辑入口 SHOULD 保持既有行为。

### FR-003 新增跳转对象列

- Banner 列表 MUST 新增独立“跳转对象”列。
- 当跳转类型为品牌详情时，跳转对象列 MUST 显示品牌名称。
- 当跳转类型为 SKU 详情时，跳转对象列 MUST 显示 SKU 名称，不显示 SKU 编码。
- 当跳转类型为专题页时，跳转对象列 MUST 显示专题名称。
- 当跳转类型为外部链接时，跳转对象列 MUST 显示链接地址。
- 当跳转类型为无跳转时，跳转对象列 MUST 显示 `-`。

### FR-004 跳转对象字段来源

- 管理端 Banner 列表接口 SHOULD 返回只读展示字段，例如 `jump_target_label`。
- `jump_target_label` SHOULD 由后端根据 `jump_type` 和关联对象一次性计算，前端不应为每条 Banner 额外请求品牌、SKU 或专题接口。
- 外部链接类型可直接复用已配置的 `external_url` 作为展示值。
- 无跳转类型应返回空值或 `-`，前端最终展示为 `-`。
- 如果关联对象不存在、不可用或名称为空，实现阶段 MUST 明确兜底文案，避免列表空白或报错。

### FR-005 搜索与筛选兼容

- 现有展示端、状态、时间状态筛选 MUST 不受新增列影响。
- 现有关键词搜索 MUST 至少保持当前能力不回退。
- 跳转对象列是否纳入关键词搜索可在实现阶段确定；如纳入，品牌名、SKU 名、专题名和外部链接 SHOULD 按统一关键词规则匹配。
- 搜索占位文案 SHOULD 与列表可见字段保持一致，避免强调已隐藏或不可见的内部标题。

### FR-006 API 与 Orval 同步

- 如新增 `jump_target_label` 或等价响应字段，MUST 同步 Pydantic Schema、OpenAPI、Orval 生成类型和前端 API 类型引用。
- 新增字段 SHOULD 为只读响应字段，不应要求创建或更新 Banner 时由前端提交。
- API 错误码和现有创建/编辑请求体不应因本需求改变。
- 数据库表结构 SHOULD 保持不变，优先通过查询关联现有品牌、SKU、专题表获得展示名称。

## 6. UI / UE 约束

- 管理端继续遵守现有“工业石材 · 暗色旗舰风”和 Banner 管理页表格风格。
- Banner 列只显示图片后，表格仍需保持横向扫描效率；新增“跳转对象”列不应导致操作列被挤压或遮挡。
- 跳转对象文本较长时 SHOULD 使用单行截断、title tooltip 或等价可访问方式展示完整信息。
- 外部链接可能较长，列表中 SHOULD 避免撑宽整表。
- 图片列、跳转类型列、跳转对象列之间的视觉层级应清晰：图片用于识别素材，跳转类型用于识别行为，跳转对象用于识别目标。

## 7. 权限与安全

- Banner 管理权限沿用现有规则，未授权角色不得访问管理端 Banner 列表或 API。
- 跳转对象字段只展示已允许管理端查看的品牌、SKU、专题名称或运营已配置的外部链接。
- 新增响应字段不得暴露数据库内部表名、对象 key、密钥、访问令牌或管理端备注。
- 外部链接展示应来自已保存且通过现有校验的链接地址，不新增前端直连外部服务行为。

## 9. 风险与待确认

| 风险 / 待确认 | 说明 |
|---|---|
| 关联对象不可用展示 | 品牌、SKU、专题被禁用、删除或名称为空时，需要确定显示 `-`、对象不可用，还是其他兜底文案。 |
| 搜索范围 | 跳转对象列是否参与关键词搜索仍需确认；纳入搜索会增加后端查询复杂度。 |
| 表格宽度 | 新增一列后需要控制列宽和横向滚动，避免操作列或分页布局回归。 |
| API 生成物 | 新增响应字段需要同步 OpenAPI 和 Orval，否则前端类型与后端响应会漂移。 |
