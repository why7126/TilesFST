# 一句话

完善图片上传、视频上传、文件上传的链路日志与单次上传追踪能力，让一次上传在前端、后端、对象存储、数据库记录、后处理等节点的耗时和结果可被串联分析。

# 原始描述

完善图片上传、视频上传、文件上传的日志，能够解决 BUG-0085 的耗时分析，能够追踪用户一次上传在各个节点的日志。

# 背景与关联

- 关联缺陷：`BUG-0085-admin-video-upload-stuck-at-99`
- 涉及范围：管理端上传入口、后端 media 模块、对象存储适配层、数据库媒体记录、视频/文件上传后处理状态反馈。
- 业务价值：当用户反馈上传卡住、上传慢、上传失败或进度停留在 99% 时，研发和运维可以基于同一个上传追踪标识定位耗时节点，而不是只能凭浏览器进度条和零散服务日志判断。
- 技术价值：建立上传链路耗时事实源，支持后续对图片、视频、文件上传 SLA、超时配置、对象存储写入、响应返回、重试策略进行持续优化。

# 影响范围

- 图片上传：品牌 Logo、Banner 图片、SKU 图片等管理端图片素材上传。
- 视频上传：SKU 视频、品牌/商品相关视频素材上传。
- 文件上传：证书、附件、文档类文件上传。
- 日志链路：前端上传开始/进度/完成/失败，后端接收/校验/存储/落库/响应，对象存储 put/stat/presign，视频或文件后处理。
- 安全与隐私：日志不得记录真实密钥、Authorization、原始对象存储凭证、敏感用户数据；文件名、路径、错误堆栈需要脱敏或最小化。

# 初步需求要点

- 为每一次上传生成可贯穿端到端的 `upload_trace_id` 或等价追踪标识，并在前端、后端和对象存储相关日志中一致携带。
- 按节点记录时间戳、耗时、结果、错误码、文件类型、文件大小、媒体类型、用户/租户上下文、请求 ID、对象 key 前缀等必要诊断字段。
- 能区分“请求体上传完成”“后端校验中”“对象存储写入中”“数据库记录中”“后处理/转码/封面生成中”“响应返回完成”等阶段。
- 对 BUG-0085 这类“进度卡 99%”场景，必须能从日志中判断卡顿发生在前端进度事件、后端处理、对象存储写入、数据库落库、后处理还是响应返回阶段。
- 日志查询或排查方式应支持按 `upload_trace_id`、用户、媒体类型、时间范围、错误码筛选，至少满足研发/运维命令行或管理端内部排查视图使用。
- 失败日志必须映射到统一错误码，不暴露内部路径、密钥、存储桶私密信息或完整敏感堆栈。

# 待澄清

- [ ] 上传追踪事实源优先落在结构化应用日志、数据库审计表、对象存储元数据，还是组合方式。
- [ ] 是否需要管理端日志查询页面，还是先提供后端结构化日志和排查脚本。
- [ ] `upload_trace_id` 是否由前端生成、后端生成，或沿用 request_id 并增加 upload-specific span。
- [ ] 视频后处理是否纳入本期，若涉及转码/封面生成增强，需要单独遵守视频增强能力 OpenSpec 门禁。
- [ ] 日志保留周期、采样策略、慢上传阈值和告警阈值。

# 建议验收要点

- [ ] 上传一张图片、一个视频、一个文件后，能通过同一个追踪标识串联前端、后端、对象存储和数据库记录的关键日志。
- [ ] 对一个模拟慢对象存储或慢后处理场景，日志能清楚展示各节点耗时，并标识最慢节点。
- [ ] 对 BUG-0085 的 99% 停留场景，能统计从前端上传完成到后端响应完成之间的耗时拆解。
- [ ] 上传失败时，日志包含统一错误码、失败节点、耗时、可关联请求 ID，且不泄露密钥、内部绝对路径或 Authorization。
- [ ] 图片、视频、文件三类上传均覆盖相同的最小日志字段，并允许按媒体类型扩展专属字段。

# 分类说明（/capture）

该条目描述的是跨上传类型的可观测性增强能力，用于支撑 BUG-0085 和后续上传性能排查；当前没有明确现有日志能力基线可判定为单一偏差，因此判定为 REQ。
