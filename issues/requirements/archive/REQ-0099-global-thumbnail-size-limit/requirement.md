# REQ-0099 全局缩略图生成支持可配置体积上限

## 1. 需求背景

当前系统已经具备图片上传后生成同目录 `.thumb` 缩略图的能力，SKU、品牌 Logo、Banner 图片和品牌证书图片等资源可以在列表、卡片、小程序页面等小图场景中复用缩略图，降低原图加载成本。

现有缩略图生成策略主要基于最大宽高和固定质量输出，不限制最终文件体积。对于小程序、管理端图片密集列表和公开展示卡片等高频小图场景，缩略图如果仍然偏大，会继续增加首屏加载时间、移动端流量和对象存储读取成本。管理员也缺少一个全局入口来按业务环境调整缩略图体积策略。

本需求要求新增全局缩略图体积目标上限配置，并在管理后台“系统设置 - 媒体与存储”中维护。该配置默认不限制，保持当前生成行为；开启后对后端后续新生成或维护任务重生成的图片缩略图生效，同时保持现有 `.thumb` Key / URL 推导约定不变。

## 2. 目标用户

| 角色 | 核心诉求 |
|---|---|
| 后台系统管理员 | 在不改代码的情况下全局调整缩略图体积目标，控制图片流量和存储读取成本。 |
| 后台运营人员 | 在 SKU、品牌、Banner、证书等图片密集页面获得更轻量、更稳定的缩略图加载体验。 |
| 小程序用户 / 公开访客 | 在品牌、证书、商品卡片等场景中更快看到小图资源，减少移动端流量消耗。 |
| 运维 / QA | 能明确配置变更的增量生效边界、历史重生成方式和失败回退策略。 |
| 前后端开发 | 有统一的全局媒体策略契约，避免按业务模块重复实现缩略图体积控制。 |

## 3. 需求目标

- 新增全局缩略图体积目标上限配置，默认不限制。
- 管理后台“系统设置 - 媒体与存储”提供该配置的查看、保存和重置入口。
- 配置对所有后端生成的图片缩略图统一生效，包括 SKU 图片、品牌 Logo、Banner 图片与品牌证书图片。
- 配置只影响缩略图生成内容，不改变 `.thumb` Key / URL 推导规则。
- 管理后台保存配置后默认仅对增量新生成缩略图生效，不自动批量重建历史缩略图。
- 历史缩略图如需应用新策略，必须通过受控维护任务扫描并重生成。
- 无法达到目标体积时不得阻断原图上传或业务保存，应提供 warning 或可观测记录。

| 不包含 | 说明 |
|---|---|

| 公开端配置入口 | 店主 Web 和小程序不提供配置入口，仅消费后端生成后的缩略图资源。 |

## 5. 功能要求

### FR-001 全局缩略图体积目标配置

系统 MUST 新增全局缩略图体积目标上限配置。该配置 SHOULD 使用 KB 作为单位，并支持“不限制”状态。

建议配置语义：

```text
thumbnail_max_size_kb = 0    表示不限制，保持当前生成模式
thumbnail_max_size_kb = 20   表示生成缩略图时尽量控制在 20KB 以内
```

配置值 MUST 有后端校验。建议允许范围为 `0-1024 KB`，其中 `0` 表示不限制；若后续采用 `null` 表示不限制，API、管理后台和环境默认值 MUST 保持一致语义。

### FR-002 管理后台媒体与存储配置入口

管理后台“系统设置 - 媒体与存储”MUST 提供缩略图体积目标上限配置入口。该入口 SHOULD 放在“上传限制”或等价媒体策略区域，与图片最大尺寸、视频最大尺寸、支持 MIME 类型等媒体配置保持同组。

UI 文案 MUST 避免承诺绝对必达，推荐使用“目标上限”“尽量不超过”等表达，并明确：

- `0` 或空值表示不限制。
- 保存后仅对新生成缩略图生效。
- 历史缩略图需要通过维护任务重生成。

### FR-003 配置对所有图片缩略图生成场景生效

系统 MUST 将该配置作为全局媒体策略应用于所有后端生成的图片缩略图场景，包括但不限于：

- SKU 图片上传生成缩略图。
- SKU 临时图片正式化时复制或补生成缩略图。
- 品牌 Logo 上传生成缩略图。
- Banner 图片上传生成缩略图。
- 品牌证书图片上传生成缩略图。
- 品牌、证书或其他图片缩略图维护任务重生成。

不同业务模块不得各自维护互相冲突的缩略图体积上限。若后续某类资源确需差异化，应另行提出需求或在 OpenSpec Change 中明确豁免原因。

### FR-004 缩略图 Key 与 URL 规则保持稳定

本需求 MUST 保持现有同目录 `.thumb` 缩略图 Key / URL 推导规则稳定。配置变更只影响缩略图对象的内容、编码质量、像素尺寸和最终体积，不影响资源寻址。

示例：

```text
images/default/tiles/1/main.webp
  -> images/default/tiles/1/main.thumb.webp
```

前端、小程序和后端服务仍可基于现有 `same_directory_thumbnail_object_key()` 或后端返回字段消费缩略图。系统不得要求本需求同步新增业务表 `thumbnail_key` 字段或迁移历史媒体引用模型。

### FR-005 增量生效与历史处理边界

管理员保存缩略图体积上限后，系统 MUST 默认只对后续新生成的缩略图生效，包括新上传、新正式化和后续维护任务重生成。

系统 MUST NOT 在保存设置时自动批量读取原图、覆盖历史 `.thumb` 对象或重建历史缩略图。该限制用于避免不可预期的对象存储 I/O、CPU 消耗、缓存变化和线上展示抖动。

历史缩略图如需应用新策略，MUST 通过受控维护任务处理。维护任务 SHOULD 支持 dry-run 预览影响数量、跳过原因、失败原因和预计写入对象数量；apply 执行时 SHOULD 记录成功、失败、跳过与重试候选。

### FR-006 生成策略与未达标处理

当配置了目标体积上限时，系统 SHOULD 采用渐进式压缩策略生成缩略图，例如：

1. 按当前最大宽高与默认质量生成缩略图。
2. 若超过目标上限，对 JPEG / WebP 递减质量。
3. 若仍超过目标上限，可按比例降低最大宽高后重新生成。
4. 对 PNG、透明图和复杂纹理图片，应优先保证可用性与透明度处理正确，再尽量控制体积。

若最终仍无法达到目标上限，系统 MUST 不阻断原图上传、业务保存或维护任务整体执行。系统 SHOULD 记录 warning、任务链路信息或维护任务失败原因，便于后续排查。

### FR-007 默认行为与向后兼容

默认配置 MUST 保持当前行为，不限制缩略图最终体积，避免升级后影响现有上传效果、缩略图画质和测试基线。

新增设置字段 MUST 向后兼容：

- 不移除现有媒体设置字段。
- 不改变现有上传接口返回的 `thumbnail_key`、`thumbnail_url` 语义。
- 不改变已有原图 URL 字段语义。
- 不要求历史客户端更新后才能继续读取 `.thumb` 缩略图。

### FR-008 可观测与测试要求

后续实现 MUST 对以下情况提供测试或可验证证据：

- 默认不限制时生成行为保持现状。
- 配置目标上限后，JPEG / WebP 示例缩略图能按策略压缩到目标附近或低于目标。
- 复杂图片无法达标时上传不失败，并能记录 warning 或维护任务失败原因。
- 系统设置保存、读取、重置和校验行为正确。
- SKU、品牌、Banner、证书图片生成路径均使用同一全局配置。
- 历史缩略图不会在保存配置时自动重建。

## 6. UI 约束

- 管理后台入口应复用现有“系统设置 - 媒体与存储”页面结构，不新增独立页面。
- 控件应使用现有设置页表单样式、数字输入或选择控件，保持暗色旗舰风与 Design System 语义 token。
- 字段名称建议为“缩略图大小目标 (KB)”或“缩略图体积上限 (KB)”。
- 帮助文案应明确“0 表示不限制”“仅对新生成缩略图生效”“历史需通过维护任务重生成”。
- 不应在页面内展示过长技术说明、对象 Key 细节或压缩算法流程。
- 保存、重置、校验错误和只读对象存储策略区域应沿用现有系统设置交互。

## 7. 数据与接口影响

| 范围 | 影响 |
|---|---|
| SQLite/MySQL | 若系统设置已使用通用 key-value 表存储，则不要求新增业务表；如配置枚举或默认值表有约束，需同步。 |
| Pydantic Schema | `MediaSettingsPatch`、`MediaSettingsData` 或等价系统设置 Schema 需要新增缩略图体积上限字段。 |
| OpenAPI/Orval | 系统设置响应与 PATCH payload 字段变化，需要同步 OpenAPI 与 Orval 生成物。 |
| 管理端 Web | 系统设置媒体页需要新增字段展示、编辑、保存、重置和测试。 |
| 小程序 | 不改接口和页面；通过后续生成的轻量缩略图间接受益。 |
| 店主 Web | 不改接口和页面；通过后续生成的轻量缩略图间接受益。 |
| 媒体上传 / 对象存储 | 缩略图生成内容会受配置影响；对象 Key、URL、鉴权读取链路不变。 |
| 维护任务 | 历史缩略图重生成任务应读取同一配置，并支持 dry-run / apply 边界。 |
| 测试 | 需要补充后端缩略图生成、系统设置 API、管理端设置页和维护任务相关测试。 |
