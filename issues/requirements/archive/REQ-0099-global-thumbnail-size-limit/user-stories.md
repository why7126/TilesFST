# 用户故事

## US-001 管理员配置缩略图体积目标

作为后台系统管理员，我希望在“系统设置 - 媒体与存储”中配置缩略图体积目标上限，以便在不改代码的情况下控制后续缩略图的流量成本。

验收要点：

- 管理员可以查看当前缩略图体积目标上限。
- 管理员可以设置 `0` 表示不限制。
- 管理员可以设置有效 KB 数值，例如 `20`。
- 设置保存成功后有固定 toast 反馈。
- 设置恢复默认时使用 DS 确认弹窗，不使用原生确认框。

## US-002 运营人员获得更轻量的小图加载体验

作为后台运营人员，我希望 SKU、品牌、Banner 和证书等图片资源的新缩略图按统一体积策略生成，以便图片密集页面加载更轻、更稳定。

验收要点：

- SKU 图片新上传或正式化生成缩略图时使用全局策略。
- 品牌 Logo、Banner 图片和品牌证书图片新上传生成缩略图时使用同一策略。
- 缩略图 Key 和 URL 规则保持不变。
- 缩略图生成失败或未达标不阻断原图上传。

## US-003 运维人员受控处理历史缩略图

作为运维人员，我希望历史缩略图不会在管理员保存设置时被自动重建，而是通过维护任务 dry-run 预览并受控执行，以便避免生产环境出现不可预期的对象存储写入和缓存变化。

验收要点：

- 保存系统设置不会自动批量扫描或覆盖历史 `.thumb` 对象。
- 历史重生成任务支持 dry-run，输出影响数量、跳过原因和失败原因。
- apply 执行可记录成功、失败、跳过和重试候选。
- 输出不得包含真实密钥、真实客户数据或本机敏感路径。

## US-004 QA 验证默认兼容与配置生效

作为 QA，我希望能分别验证默认不限制、设置上限、新增缩略图、历史不自动重建和未达标回退，以便确认需求不会破坏现有上传与展示链路。

验收要点：

- 默认配置下现有缩略图生成行为保持不变。
- 设置目标上限后，新生成 JPEG / WebP 缩略图能压缩到目标附近或低于目标。
- 复杂图片无法达标时有 warning 或维护任务原因。
- 系统设置 API、管理后台保存和重置均可验证。
