# REQ-0106 Banner 标题隐藏与小程序前台标题遮罩移除

## 1. 需求背景

管理后台 Banner 管理已支持小程序首页轮播和品牌列表页轮播配置。当前新增/编辑 Banner 时，“Banner 标题”作为运营必填字段展示，且小程序首页与品牌列表页会把该标题叠加在 Banner 图片上展示。

用户反馈 Banner 标题属于多余信息，运营配置时没有实际价值；同时前台 Banner 通常已由图片本身承载主视觉和文案，额外标题遮罩会干扰运营图表达。因此需要把 Banner 从“标题驱动”调整为“图片驱动”：运营不再感知和填写标题，小程序前台也不再展示标题遮罩。

本需求优先采用兼容实现：不要求立即删除数据库和 API 中的 `title` 字段，而是在前后台体验上隐藏该字段，并通过自动生成或后端兼容策略满足现有唯一性与历史数据约束。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 后台管理员 / 运营 | 创建和编辑 Banner 时只关注图片、展示位置、跳转、排序和有效期，不再填写无业务价值的标题。 |
| 小程序访客 | 查看首页和品牌列表页 Banner 时以运营图为主，不被额外标题遮罩干扰。 |
| 开发 / 运维 | 在不破坏历史数据和现有 Banner API 的前提下完成体验优化。 |

## 3. 需求目标

1. Web 管理后台新增/编辑 Banner 时不再展示“Banner 标题”字段。
2. 运营保存 Banner 时不再因为未填写标题而被阻断。
3. 小程序首页轮播与品牌列表页轮播不再展示 Banner 标题遮罩文字。
4. 后台列表仍能识别 Banner 记录，不能因为隐藏标题导致运营无法区分不同 Banner。
5. 保持现有 Banner 数据、状态、跳转、排序、上传和有效期能力稳定。

## 4. 范围

### 4.1 本期包含

| 范围 | 说明 |
|---|---|
| 管理端表单隐藏标题 | 新增/编辑 Banner 弹窗不展示标题输入项，不要求运营填写标题。 |
| 管理端保存兼容 | 创建/更新请求仍需满足现有 API 和数据库约束时，由前端或后端自动生成内部标题。 |
| 管理端列表识别优化 | 列表第一列不应只依赖人工标题；需以缩略图、展示位置、跳转目标或内部识别名帮助运营识别。 |
| 小程序首页 Banner 去文案遮罩 | 首页轮播有图片时不展示 Banner 标题文字；图片本身成为主视觉。 |
| 小程序品牌列表页 Banner 去文案遮罩 | 品牌列表页轮播有图片时不展示 Banner 标题文字。 |
| 历史数据兼容 | 旧 Banner 的 `title` 可继续保留为内部字段或列表辅助信息，但不再作为前台主展示内容。 |
| 测试覆盖 | 覆盖管理端表单无标题字段、保存不阻断、小程序前台不渲染标题遮罩。 |

### 4.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 立即删除 `title` 字段 | 不要求本期移除数据库列、Pydantic 字段或 OpenAPI 响应字段。 |
| 大规模数据迁移 | 不批量重写历史 Banner 标题；历史值可保留。 |
| 新增 Banner 点击统计 | 不新增曝光、点击或转化统计。 |
| 轮播视觉大改版 | 不重做小程序 Banner 轮播样式、尺寸、动效或跳转规则。 |
| 后台拖拽排序 | 继续沿用现有排序字段。 |

## 5. 功能要求

### FR-001 管理端新增/编辑弹窗隐藏标题字段

- 新增 Banner 弹窗 MUST 不展示“Banner 标题”输入框。
- 编辑 Banner 弹窗 MUST 不展示“Banner 标题”输入框。
- 表单内 MUST 不出现“Banner 标题不能为空”“同一展示端 + 展示位置下标题不可重复”等面向运营的标题校验提示。
- 隐藏标题后，展示端、展示位置、图片、跳转类型、跳转目标、排序、有效期、运营备注等字段继续按既有规则展示和校验。

### FR-002 Banner 保存不再依赖运营填写标题

- 运营不填写标题时，点击保存 MUST 能正常进入创建或更新流程。
- 如果后端仍要求 `title` 非空，系统 MUST 自动提供内部标题，避免保存失败。
- 自动标题 SHOULD 具备稳定唯一性，例如基于展示位置、跳转类型、时间戳或 Banner ID 生成。
- 自动标题不得作为小程序前台展示文案。
- 自动标题冲突时，系统 MUST 兜底生成新的唯一值，而不是要求运营手动修改。

### FR-003 管理端列表识别 Banner

- Banner 列表第一列 SHOULD 以缩略图作为主要视觉识别信息。
- 列表 MUST 提供足够上下文帮助运营区分 Banner，包括展示位置、跳转类型、跳转目标、排序或更新时间。
- 如继续展示标题，标题 MUST 作为内部识别信息降级展示，不得表达为运营必须维护的前台标题。
- 关键词搜索若仍支持标题匹配，可保留为内部兼容能力；但搜索占位文案 SHOULD 不再强调“标题”。

### FR-004 小程序首页轮播移除标题遮罩展示

- 小程序首页存在在线有效 Banner 图片时，轮播 MUST 不展示 Banner `title` 文本。
- 首页轮播 SHOULD 保留图片、轮播指示器和点击跳转能力。
- 如当前轮播存在遮罩层、描述、按钮等与标题绑定的文案组件，实现阶段 MUST 明确处理策略，避免残留无意义空容器。
- 无 Banner 数据时，首页原有兜底 Hero 文案可继续展示，不受本需求影响。

### FR-005 小程序品牌列表页轮播移除标题遮罩展示

- 小程序品牌列表页存在在线有效 Banner 图片时，轮播 MUST 不展示 Banner `title` 文本。
- 品牌列表页轮播 SHOULD 保留图片、轮播指示器和点击跳转能力。
- 无品牌列表页 Banner 数据时，品牌列表页原有兜底 Hero 可继续展示，不受本需求影响。

### FR-006 API 与数据兼容

- 若本期保留 API 请求体 `title` 字段，管理端 SHOULD 以系统生成值填充，不暴露给运营。
- 若实现阶段选择后端自动生成标题，则 API 请求体可允许缺省标题，但 MUST 同步 OpenAPI、Orval 和测试。
- 公开小程序接口 MAY 继续返回 `title` 字段用于兼容旧客户端，但当前小程序页面不得把该字段渲染为 Banner 主标题。
- 任何 API 请求/响应结构变化 MUST 同步 OpenAPI、Orval、接口文档和相关测试。

### FR-007 错误提示与文案

- 管理端保存失败时，不得向运营展示“Banner 标题不能为空”作为主要错误。
- 标题唯一性冲突如仍可能发生，系统 SHOULD 自动重试或转换为内部错误提示，不要求运营填写标题。
- 后台页面说明文案 SHOULD 聚焦“图片、排序、跳转与生效时间”，避免强调标题。

## 6. UI / UE 约束

- 管理端遵守现有“工业石材 · 暗色旗舰风”和 Banner 管理页布局。
- 表单隐藏标题后，字段网格应自然收拢，不留下空白行或异常间距。
- 小程序 Banner 有图场景应突出运营图，不叠加无必要标题文字。
- 若移除标题后遮罩层仅用于提升文字可读性，则 SHOULD 一并弱化或移除；若遮罩仍用于保证轮播指示器可见，需保持视觉克制。
- 小程序首页和品牌列表页的无 Banner 兜底 Hero 不属于本次“去标题遮罩”范围，可继续保留品牌默认文案。

## 7. 权限与安全

- Banner 管理权限沿用现有规则：`admin` 与 `employee` 可维护，`store_owner` 不可访问管理端 Banner 页面和 API。
- Banner 图片上传仍必须走后端鉴权、文件类型/大小校验和对象存储适配层。
- 自动生成的内部标题不得包含真实客户数据、密钥、访问令牌或用户隐私信息。
- 小程序公开接口不得因为前台隐藏标题而暴露管理端备注、对象 key 或未授权字段。

## 9. 风险与待确认

| 风险 / 待确认 | 说明 |
|---|---|
| 自动标题生成位置 | 可由前端填充以减少 API 改动，也可由后端生成以统一约束；OpenSpec 阶段需确定。 |
| 列表识别方式 | 隐藏标题后，列表第一列需要选择“缩略图 + 跳转目标”或“内部识别名”等识别策略。 |
| 遮罩处理范围 | 用户明确移除标题遮罩展示；实现阶段需确认是否同时移除副标题和按钮文案。 |
| API/DB 兼容 | 若选择彻底字段语义迁移，成本会扩大到 DB migration、OpenAPI、Orval 和更多回归测试。 |
