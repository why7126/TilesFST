# Business Flow

## 1. 后台新增 Banner

```text
运营进入 /admin/banners
  ↓
点击“新增 Banner”
  ↓
弹窗展示图片、展示位置、跳转、排序、有效期、备注等字段
  ↓
不展示 Banner 标题字段
  ↓
运营完成其他必填项并保存
  ↓
系统生成或补齐内部 title
  ↓
后端保存 Banner
  ↓
列表刷新，展示缩略图与投放上下文
```

## 2. 后台编辑 Banner

```text
运营在列表点击“编辑”
  ↓
弹窗回填现有图片、位置、跳转、排序、有效期、备注
  ↓
不展示历史 title 输入项
  ↓
运营修改投放配置并保存
  ↓
系统保留或重新生成内部 title
  ↓
列表刷新，前台展示不受 title 影响
```

## 3. 小程序首页 / 品牌列表页展示

```text
小程序请求公开 Banner 数据
  ↓
后端返回在线且有效的 Banner
  ↓
页面渲染轮播图片
  ↓
不渲染 item.title 作为 Banner 主标题
  ↓
用户点击 Banner
  ↓
沿用既有跳转逻辑进入 SKU / 品牌 / 搜索 / 门店 / 无跳转
```

## 4. 与父需求差异

| 项 | REQ-0016 原始 Banner 管理 | REQ-0106 本需求 |
|---|---|---|
| 标题字段 | 运营必填，用于唯一性和展示 | 运营不可见，内部兼容使用 |
| 前台 Banner | 可叠加标题文案 | 有图 Banner 不展示标题遮罩 |
| 数据模型 | `title` 为核心业务字段 | 本期不删除 `title`，但降低为内部兼容字段 |
| 列表识别 | 第一列可直接展示标题 | 第一列需依赖缩略图和投放上下文 |

## 5. 影响面

| 影响面 | 说明 |
|---|---|
| Web 管理端 | Banner 列表、筛选文案、新增/编辑弹窗、表单校验。 |
| 小程序 | 首页轮播、品牌列表页轮播。 |
| 后端/API | 取决于实现策略；前端自动生成标题时 API 可不变，后端生成标题时需变更请求 schema。 |
| 数据库 | MVP 不变；彻底语义迁移时才需要 DB migration。 |
| Orval | API schema 不变则不需要；请求字段变更则必须生成。 |
