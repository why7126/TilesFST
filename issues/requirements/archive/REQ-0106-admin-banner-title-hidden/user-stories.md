# User Stories

## US-001 后台运营隐藏 Banner 标题字段

作为后台运营，我希望新增或编辑 Banner 时不再填写 Banner 标题，以便只维护真正影响投放效果的图片、位置、跳转、排序和有效期。

验收要点：

- 新增 Banner 弹窗不展示标题输入框。
- 编辑 Banner 弹窗不展示标题输入框。
- 保存时不因标题为空阻断。
- 表单错误提示不再出现“Banner 标题不能为空”。

## US-002 后台运营仍能识别 Banner 记录

作为后台运营，我希望隐藏标题后仍能在 Banner 列表里区分不同记录，以便进行编辑、上下线、排序和删除。

验收要点：

- 列表以缩略图、展示位置、跳转类型、跳转目标、排序或更新时间提供识别上下文。
- 标题如保留展示，应降级为内部识别信息，不再表达为运营必填前台文案。
- 关键词搜索文案不再强调“标题”。

## US-003 小程序访客看到图片驱动的 Banner

作为小程序访客，我希望首页和品牌列表页 Banner 以图片为主视觉，以便运营图上的内容不被额外标题遮罩干扰。

验收要点：

- 小程序首页有 Banner 图时不渲染 Banner 标题文字。
- 小程序品牌列表页有 Banner 图时不渲染 Banner 标题文字。
- 点击跳转、轮播指示器、无 Banner 兜底不回归。

## US-004 开发保持兼容交付

作为开发人员，我希望在不立即删除 `title` 字段的情况下完成体验优化，以便降低 API、DB 和历史数据迁移风险。

验收要点：

- 若 API/DB 仍要求 `title`，系统自动生成内部标题。
- 自动标题不作为小程序前台展示文案。
- 如最终修改 API schema，必须同步 OpenAPI、Orval、文档和测试。
