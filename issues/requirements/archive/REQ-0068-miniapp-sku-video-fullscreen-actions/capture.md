# 一句话

微信小程序商品详情页的视频媒体应提供明确的全屏播放按钮，并在全屏播放时支持长按唤起类似图片全屏预览的操作菜单，包括转发给朋友、保存视频和取消。

# 原始描述

微信小程序商品详情页，视频可以有全屏播放的按钮，全屏播放时，长按可以有【转发给朋友】、【保存视频】【取消】等交互，类型图片全屏时长按的交互。

# 背景与关联

- 父需求：`REQ-0044-miniapp-sku-detail-page`
- 涉及端：微信小程序
- 涉及页面：`pages/tile-detail/index`
- 涉及对象：商品详情页视频媒体、全屏播放入口、全屏态长按操作菜单、微信分享与保存视频交互
- 当前诉求：现有商品详情页视频依赖微信原生播放器控制条，尚未把“视频全屏播放按钮”和“全屏态长按菜单”作为明确产品能力和验收项。
- 业务价值：让用户在浏览商品视频时更容易进入沉浸式查看，并能像图片全屏预览一样进行转发、保存或取消操作，提升素材传播和客户演示体验。

# 建议验收要点

- [ ] 商品详情页视频媒体展示明确可感知的全屏播放入口；入口不得遮挡视频播放、轮播切换或媒体计数信息。
- [ ] 用户点击全屏入口后，视频进入微信小程序支持的全屏播放态。
- [ ] 全屏播放期间，长按视频可唤起操作菜单或等价交互，至少包含“转发给朋友”“保存视频”“取消”。
- [ ] “转发给朋友”应复用商品详情页分享能力，分享路径回到对应 SKU 商品详情页。
- [ ] “保存视频”应遵守微信小程序权限、临时文件和远程视频保存限制；保存失败时展示明确提示，不阻断播放。
- [ ] “取消”关闭菜单后应回到当前全屏播放态或安全退出菜单，不影响视频继续播放。
- [ ] 图片全屏预览的既有长按交互不得回归；视频全屏交互与图片全屏交互在可行范围内保持一致。
- [ ] 页面隐藏、锁屏、跳转、退出全屏或切换媒体时，视频暂停策略不回归。
- [ ] 若微信原生 `video` 组件不支持完全自定义长按菜单，应在 PRD / OpenSpec 阶段明确平台限制和可替代方案。

# 待澄清

- [ ] 全屏入口是使用微信原生控制条按钮即可，还是需要额外提供自定义按钮。
- [ ] 长按菜单是否必须在视频全屏态由自定义弹层呈现，还是接受微信原生菜单能力。
- [ ] 保存视频是否要求直接保存远程视频，还是允许先下载到临时文件后调用保存能力。
- [ ] 保存视频是否需要权限引导、失败重试、或仅对可公开视频开放。
- [ ] 转发内容是否使用当前商品详情页既有分享文案、封面和路径，还是需要视频专属分享内容。
