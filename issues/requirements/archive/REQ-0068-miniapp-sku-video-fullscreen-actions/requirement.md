# REQ-0068 小程序商品详情页视频全屏播放与长按操作菜单

## 1. 需求背景

微信小程序商品详情页已经支持图片与视频混合媒体浏览，图片可进入全屏预览，视频可由用户主动播放。当前视频能力更多依赖微信原生 `<video>` 控件默认控制条，尚未把“明确的全屏播放入口”和“全屏态长按操作菜单”沉淀为商品详情页的产品契约。

装修客户、设计师和门店导购在查看瓷砖视频纹理、空间效果或工艺展示时，需要更容易进入全屏播放，并在全屏态像图片预览一样完成转发、保存或取消操作。该需求用于补齐 SKU 详情页视频沉浸浏览和素材传播能力。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 装修客户 | 全屏查看商品视频细节，并可将视频或商品转发给家人朋友一起确认。 |
| 设计师 | 在全屏态向客户展示瓷砖效果视频，必要时保存素材用于方案沟通。 |
| 门店导购 | 快速全屏播放商品视频并转发商品详情，提升线下讲解和微信沟通效率。 |
| 被分享用户 | 从微信分享进入对应 SKU 详情页后，可继续查看商品视频和资料。 |
| 开发 / 测试人员 | 明确视频全屏、长按菜单、保存视频和分享复用的验收边界。 |

## 3. 需求目标

- 商品详情页视频媒体 MUST 提供明确可感知的全屏播放入口。
- 用户触发全屏入口后，视频 MUST 进入微信小程序支持的全屏播放态。
- 视频全屏播放态 SHOULD 支持长按唤起操作菜单或平台允许的等价交互。
- 长按操作菜单 SHOULD 至少包含“转发给朋友”“保存视频”“取消”。
- 视频转发 MUST 复用商品详情页分享契约，分享路径回到对应 SKU 详情页。
- 保存视频 MUST 遵守微信小程序权限、下载、临时文件和相册保存限制。
- 若微信原生能力不支持完全自定义长按菜单，实现阶段 MUST 明确降级方案和验收说明。

## 4. 范围

### 4.1 本期包含

| 范围 | 说明 |
|---|---|
| 视频全屏入口 | 商品详情页视频媒体提供可感知入口，可使用微信原生控制条或项目自定义按钮。 |
| 全屏播放 | 点击入口后进入微信小程序支持的视频全屏态，保持用户主动播放和页面隐藏暂停策略。 |
| 长按菜单 | 全屏态长按视频时唤起“转发给朋友 / 保存视频 / 取消”或微信平台允许的等价操作。 |
| 转发给朋友 | 复用商品详情页现有分享标题、路径、封面和 `skuId` 参数，不新增独立分享系统。 |
| 保存视频 | 在权限允许、视频 URL 可下载且微信能力支持时保存到相册；失败时给出明确提示。 |
| 降级策略 | 对微信平台限制、远程视频保存失败、权限拒绝等情况提供可理解反馈。 |
| 既有能力保护 | 图片全屏预览、视频播放、轮播暂停、页面隐藏暂停、商品分享不回归。 |

### 4.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 视频转码 / 压缩 | 不新增视频转码、压缩、多清晰度、HLS / DASH 或 CDN 播放能力。 |
| 视频海报 | 不生成视频专属分享海报、营销海报或朋友圈图片海报。 |
| 后台配置 | 不新增管理端配置长按菜单、保存权限、视频分享文案或按钮开关。 |
| 新增媒体字段 | 默认不新增 API 字段、数据库字段或 Orval 类型；优先使用现有视频 URL 和商品分享数据。 |
| 外部下载链路 | 不绕过后端受控媒体 URL，不直连未授权对象存储地址。 |
| 强制保存所有视频 | 对平台不允许保存、跨域不可下载、视频格式不支持或权限拒绝的场景允许失败提示。 |

## 5. 功能要求

### FR-001 视频全屏入口

- 商品详情页视频媒体 MUST 展示明确可感知的全屏播放入口。
- 全屏入口 MAY 使用微信原生视频控制条的全屏按钮；若原生入口不够明显，SHOULD 提供项目自定义入口。
- 自定义入口不得遮挡视频播放控制、媒体计数、轮播滑动手势或错误提示。
- 无视频媒体时不得展示视频全屏入口。
- 视频加载失败时，全屏入口 SHOULD 禁用或触发可理解错误提示。

### FR-002 进入与退出全屏播放

- 用户点击全屏入口后，视频 MUST 进入微信小程序支持的视频全屏态。
- 视频全屏播放 MUST 保持用户主动触发，不得默认自动全屏或默认自动播放。
- 全屏态应保留微信平台允许的视频播放控制，例如播放、暂停、进度、退出全屏等。
- 用户退出全屏后，页面 MUST 回到商品详情页当前媒体上下文，不应重置到首张图片或丢失 SKU 数据。
- 页面隐藏、锁屏、跳转、切换媒体或返回上一页时，现有视频暂停策略 MUST 不回归。

### FR-003 全屏态长按操作菜单

- 视频全屏态 SHOULD 支持长按视频唤起操作菜单。
- 操作菜单 SHOULD 至少包含“转发给朋友”“保存视频”“取消”。
- 菜单文案 MUST 使用中文，且与图片全屏预览长按交互的用户理解保持一致。
- “取消”被点击后，MUST 关闭菜单，不应误触转发、保存或退出商品详情页。
- 若微信原生 `video` 全屏态不支持拦截长按或自定义菜单，实现阶段 MUST 使用平台允许的等价方案，例如全屏外自定义操作入口、全屏前操作菜单或原生菜单能力，并在验收中说明差异。

### FR-004 转发给朋友

- 用户选择“转发给朋友”时，MUST 复用商品详情页既有微信分享能力。
- 分享路径 MUST 指向当前 SKU 商品详情页，并保留 `skuId` 与 `source=share` 或等价来源参数。
- 分享标题 SHOULD 使用当前 SKU 名称与品牌名称；分享图 SHOULD 使用商品分享图、主图或安全兜底图。
- 转发操作不得要求新增后台分享配置。
- 分享埋点 SHOULD 能区分视频全屏态触发，埋点失败 MUST NOT 阻断分享。

### FR-005 保存视频

- 用户选择“保存视频”时，系统 SHOULD 尝试将当前视频保存到用户相册。
- 保存视频 MUST 遵守微信小程序授权、临时文件、远程文件下载和相册保存限制。
- 视频 URL MUST 来自详情接口返回的安全可播放 URL，不得使用原始 object key 拼接对象存储地址。
- 若需要下载远程视频到临时文件，下载过程 SHOULD 有加载提示或防重复触发状态。
- 保存成功后 SHOULD 展示明确成功提示。
- 保存失败时 MUST 展示明确失败提示，例如权限未开启、视频暂不可保存、网络异常或平台不支持，不得阻断继续播放和浏览商品详情。
- 权限被拒绝时 SHOULD 引导用户按微信平台允许方式开启权限，但不得无限弹窗打扰。

### FR-006 平台限制与降级

- PRD / OpenSpec 阶段 MUST 明确微信 `video` 组件全屏、长按、菜单和保存视频能力的实际边界。
- 若平台不支持在全屏视频上完全模拟图片长按菜单，系统 SHOULD 保留可被用户发现的替代操作入口。
- 降级方案 MUST 保持“转发给朋友”“保存视频”“取消”三个意图可达或明确说明不可达原因。
- 平台限制说明不得暴露技术细节给普通用户；用户侧只展示简洁可理解的结果或失败提示。

### FR-007 既有交互不回归

- 图片全屏预览的缩放、拖动、左右切换和长按能力不得回归。
- 视频播放、暂停、错误提示和轮播暂停能力不得回归。
- 商品详情页底部收藏、分享、推荐跳转和品牌入口不得受视频全屏改造影响。
- 分享直达商品详情页后，视频全屏入口和保存 / 转发交互在视频存在时仍应可用。

### FR-008 埋点与验收证据

- 视频全屏入口点击 SHOULD 记录埋点，事件可命名为 `sku_video_fullscreen_click` 或等价事件。
- 视频全屏态长按菜单点击 SHOULD 记录菜单动作，至少区分 `share`、`save`、`cancel`。
- 保存视频成功 / 失败 SHOULD 记录结果，用于判断素材传播链路质量。
- 埋点失败 MUST NOT 阻断全屏、分享、保存或取消操作。
- 后续验收 SHOULD 包含微信开发者工具与至少一台真机证据，覆盖全屏入口、全屏态操作菜单、转发、保存成功或失败提示、退出全屏和回到详情页。

## 6. UI / UE 约束

- 视频全屏入口必须清晰可见，但不得破坏商品详情页顶部媒体区的沉浸感。
- 自定义按钮如存在，应使用小程序当前深色企业轻奢风格，不新增突兀色彩主题。
- 入口点击目标应满足小程序常见移动端可点尺寸，不小于 44x44px 或等价触达面积。
- 全屏态菜单文案固定为“转发给朋友”“保存视频”“取消”或微信平台原生等价文案。
- 保存视频时的加载、成功和失败提示应简短明确，不覆盖过久，不影响用户继续浏览。
- 权限引导应遵循微信小程序平台交互，不自绘仿系统授权弹窗。
- 若使用自定义全屏按钮，应避免与视频原生控制条重复造成用户困惑。

## 8. 技术与实现影响预判

| 领域 | 影响预判 |
|---|---|
| 小程序 | 预计影响 `src/miniapp/pages/tile-detail/index.*`，包括视频组件属性、VideoContext 全屏控制、长按菜单、保存视频和埋点。 |
| API | 默认不新增 API；若保存视频需要签名下载 URL 或额外媒体权限字段，需在 OpenSpec 阶段评审。 |
| 数据库 | 默认不新增表或字段。 |
| Web 管理端 | 不涉及；不新增视频后台配置。 |
| Web 展示端 | 不涉及。 |
| Orval | 默认不需要；如新增接口字段或 API contract，再同步 Orval。 |
| Docker Compose | 不涉及。 |
| 对象存储 / 媒体 | 必须继续使用后端安全媒体 URL；不得放宽 MinIO 权限或暴露 object key。 |
| 测试 | 后续需补充小程序静态测试、真机验收 checklist，必要时补充保存视频降级用例。 |
