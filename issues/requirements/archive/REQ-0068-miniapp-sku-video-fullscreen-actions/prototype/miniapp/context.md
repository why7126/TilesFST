# 小程序原型策略

## 目标

本需求属于微信小程序原生视频交互增强。由于全屏视频态、长按菜单、保存视频和微信分享能力依赖微信小程序运行环境，HTML 原型无法真实模拟最终交互。本阶段提供小程序原型上下文与验收矩阵，后续 OpenSpec / apply 阶段以微信开发者工具和真机 evidence 为准。

## 页面与状态

页面：`pages/tile-detail/index`

需要覆盖的状态：

- 视频媒体正常加载，展示封面、播放控件和全屏入口。
- 视频媒体加载失败，全屏入口禁用或展示错误提示。
- 视频全屏播放态，用户可退出全屏回到详情页。
- 长按菜单可用态：转发给朋友、保存视频、取消。
- 平台降级态：原生全屏态不允许自定义长按菜单时，展示等价入口或记录 N/A。
- 保存视频成功、权限拒绝、网络失败、平台不支持。

## 布局约束

- 全屏入口应位于视频媒体区域内或原生控制条中，不能遮挡媒体计数。
- 自定义入口如存在，触控面积不小于 44x44pt。
- 入口不占用微信右上角原生胶囊区域，不自绘伪系统分享 / 关闭按钮。
- 全屏退出后页面主体 offset、商品信息和底部操作栏保持稳定。

## 交互矩阵

| 场景 | 期望 |
|---|---|
| 点击全屏入口 | 当前视频进入微信支持的全屏态。 |
| 退出全屏 | 返回当前 SKU 详情页，不丢失媒体上下文。 |
| 全屏长按 | 展示操作菜单或平台允许的等价入口。 |
| 转发给朋友 | 复用商品详情页分享路径，保留 `skuId`。 |
| 保存视频 | 成功保存或展示明确失败提示。 |
| 取消 | 关闭菜单，不触发其他动作。 |

## Evidence 策略

后续验收必须区分：

- `static_test`：检查 WXML / JS / TS 运行入口和关键属性。
- `devtools`：记录 320 / 375 / 430pt 视口下入口布局和操作结果。
- `real_device`：至少一台真机验证全屏、长按菜单或降级、转发、保存提示。
- `follow_up` / `blocked`：真机不可用或平台能力不可测时使用，不得写成通过。

## 待产物

- PNG / 录屏：待 OpenSpec apply 阶段通过微信开发者工具或真机导出。
- 若实现选择自定义按钮，需在 Change design 中补充按钮位置、图标、触控面积和与原生控制条的关系。
