# 用户故事

## US-001 后台运营优先处理未上架 SKU

作为后台运营，我希望进入管理端 SKU 列表后优先看到未上架 SKU，以便先处理待完善、待发布或已下架后需要复核的商品。

验收要点：

- SKU 列表默认先展示未上架 SKU，再展示已上架 SKU。
- 未上架 SKU 不需要运营额外筛选即可优先出现。
- 未上架 SKU 分组内按创建时间降序展示。
- 新建 SKU 后刷新列表，该 SKU 能按创建时间进入未上架分组的正确位置。

## US-002 后台管理员查看最新发布 SKU

作为后台管理员，我希望已上架 SKU 按发布时间倒序展示，以便快速查看最近发布的商品，并复核发布结果。

验收要点：

- 已上架 SKU 排在未上架 SKU 之后。
- 已上架 SKU 分组内按发布时间降序展示。
- 发布时间较新的已上架 SKU 排在发布时间较旧的 SKU 前面。
- 发布时间为空或异常时有稳定兜底顺序，不导致列表报错或随机跳动。

## US-003 测试人员验证排序稳定性

作为测试人员，我希望排序规则明确到状态分组、主排序字段和次级排序字段，以便编写稳定的回归测试。

验收要点：

- 测试能覆盖未上架优先于已上架。
- 测试能覆盖未上架按创建时间降序。
- 测试能覆盖已上架按发布时间降序。
- 测试能覆盖时间相同或时间缺失时的稳定排序。
- 测试能覆盖搜索、筛选、分页后仍按完整结果集排序。

## US-004 开发人员确认实现层级

作为开发人员，我希望明确排序应在后端分页前或前端分页前完成，以便避免只对当前页排序造成跨页错乱。

验收要点：

- 若列表由后端分页接口提供，排序优先在后端完成。
- 若前端持有完整结果集再分页，前端必须在分页前排序。
- 若接口契约变化，必须同步 Pydantic Schema、OpenAPI、Orval、接口文档和测试。
- 不改变既有鉴权、筛选参数、分页结构和错误响应。

## US-005 产品负责人确认管理端列表一致性

作为产品负责人，我希望排序优化不引入新的视觉或交互偏差，以便 SKU 列表仍与管理端其他列表页保持一致。

验收要点：

- 本需求不新增显式排序控件、说明卡片或额外筛选项。
- 分页 DOM 与管理端用户管理基准保持一致。
- 筛选下拉继续使用统一组件或共享样式，不回退为页面级临时弹层。
- 操作反馈使用 fixed toast，不造成页面布局位移。
- 不新增 `window.confirm`；若后续触及上架/下架等危险操作，必须使用 DS confirm modal。
