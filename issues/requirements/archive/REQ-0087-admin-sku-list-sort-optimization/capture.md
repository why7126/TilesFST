# 一句话

管理端 SKU 列表页按上架状态与对应时间字段优化默认排序，让未上架 SKU 优先展示并按创建时间倒序，已上架 SKU 按发布时间倒序。

# 原始描述

管理端，SKU列表页排序优化
1. 先按是否上架排序，优先排未上架
2. 未上架的，再根据创建时间降序
3. 已上架的，再根据发布时间降序

# 背景与关联

- 父需求：`REQ-0006-tile-sku-management`
- 相关需求：`REQ-0079-admin-sku-list-published-at`
- 相关缺陷：`BUG-0090-admin-sku-list-publish-sort-order`
- 涉及端：企业内部 Web 管理端
- 涉及页面：瓷砖 SKU 列表页
- 业务价值：帮助运营优先处理尚未上架的 SKU，同时让已上架商品按最新发布时间排列，减少人工筛选和查找成本。
- 类型判断：该输入是对管理端 SKU 列表默认排序策略的新增/细化要求，不直接指向已交付能力的可复现偏差，因此按 REQ 记录，不按 BUG 处理。

# 待澄清

- [ ] “未上架”是否包含草稿、已下架、待发布等全部非上架状态，还是仅指从未发布的 SKU。
- [ ] 未上架 SKU 的创建时间字段是否使用 `created_at`；若数据缺失，是否回退到更新时间或置底。
- [ ] 已上架 SKU 的发布时间字段是否使用 `published_at`；若历史数据为空，是否回退到创建时间、更新时间或置底。
- [ ] 该排序是列表默认排序，还是也需要作为显式排序选项展示在 UI 中。
- [ ] 用户手动选择其他排序、筛选或分页时，是否覆盖默认排序规则。
- [ ] 后端接口是否需要统一排序输出，还是仅管理端前端本地排序即可。

# 建议验收要点

- [ ] SKU 列表默认先展示未上架 SKU，再展示已上架 SKU。
- [ ] 未上架 SKU 分组内按创建时间降序排列，最新创建的排在前面。
- [ ] 已上架 SKU 分组内按发布时间降序排列，最新发布的排在前面。
- [ ] 排序规则在分页、筛选、搜索后仍保持一致，避免跨页顺序错乱。
- [ ] 发布时间或创建时间为空的异常数据有明确兜底顺序，不导致列表报错或顺序不稳定。
- [ ] 如涉及列表接口排序参数或响应字段变化，需同步 OpenAPI、Orval、接口文档和相关测试。
