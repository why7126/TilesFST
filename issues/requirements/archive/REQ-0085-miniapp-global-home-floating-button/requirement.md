# REQ-0085 小程序非首页页面新增返回首页全局悬浮按钮

## 1. 需求背景

微信小程序用户在搜索结果、分类商品列表、品牌详情、商品详情等深层页面浏览时，若想回到首页，通常需要依赖顶部返回、底部 TabBar 或重新进入页面路径。深层浏览链路较长时，用户回到首页的路径不够直接，容易增加跳转成本。

本需求在小程序首页以外的业务页面提供一个全局返回首页悬浮按钮。用户在非首页页面浏览商品、品牌、类目或搜索结果后，可通过固定入口快速回到首页，提升跨页面导航效率。首页本身不展示该按钮，避免重复入口和视觉干扰。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 装修业主 | 在浏览商品详情、搜索结果或分类列表后，可以快速回到首页重新选择入口。 |
| 室内设计师 | 在多品牌、多类目间切换时，减少逐级返回和重新进入首页的操作成本。 |
| 门店销售 | 向客户演示小程序时，可从任意深层页面快速回到首页继续介绍其他内容。 |

## 3. 范围

### 3.1 本期包含

| 范围 | 说明 |
|---|---|
| 非首页页面全局悬浮按钮 | 在小程序首页以外的主要业务页面展示返回首页悬浮按钮。 |
| 首页展示例外 | 小程序首页不展示该悬浮按钮。 |
| 快速返回首页 | 点击悬浮按钮后，用户可直接回到小程序首页。 |
| 页面覆盖策略 | 明确搜索结果、分类列表、品牌详情、商品详情等深层页面的默认覆盖口径。 |
| 安全区与遮挡规避 | 按钮位置需避开底部安全区、TabBar、固定操作区和页面核心内容。 |
| 小程序端交互适配 | 按钮点击、滚动、分享、筛选、加载更多等既有交互不受影响。 |

### 3.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 首页视觉改造 | 不调整首页布局、首页入口或首页内容结构。 |
| 底部 TabBar 改造 | 不新增、删除或重排底部 TabBar。 |
| Web 展示端改造 | 本需求仅针对微信小程序，不影响 Web 店主展示端。 |
| 管理端配置能力 | 不新增后台开关、页面级配置或运营配置入口。 |
| 登录/授权链路改造 | 不改变登录、授权、会话恢复和权限判断规则。 |
| 埋点与数据分析 | 不新增点击埋点、转化统计或运营报表。 |
| 全屏媒体体验改造 | 视频全屏、图片预览等原生全屏能力的交互例外在后续阶段确认，不在本 PRD 中展开实现方案。 |

## 4. 功能要求

### FR-001 首页不展示返回首页悬浮按钮

- 小程序首页 MUST 不展示返回首页悬浮按钮。
- 若用户已位于首页，页面中不得出现语义重复的“返回首页”固定入口。
- 首页现有导航、轮播、分类、品牌和商品入口不因本需求发生变化。

### FR-002 非首页主要业务页面展示悬浮按钮

- 小程序非首页主要业务页面 SHOULD 默认展示返回首页悬浮按钮。
- 首期默认覆盖页面 SHOULD 包含搜索结果页、分类商品列表页、品牌详情页、商品详情页等深层浏览页面。
- 若页面属于登录页、授权页、错误页、全屏视频页、图片预览页或其他特殊流程页，是否展示悬浮按钮需在 `/req-complete` 阶段进一步确认。
- 悬浮按钮组件 SHOULD 采用统一实现，避免在多个页面复制不一致的样式和跳转逻辑。

### FR-003 点击后快速返回小程序首页

- 用户点击悬浮按钮后，MUST 快速回到小程序首页。
- 返回首页过程 MUST 不产生空白页、死循环跳转或重复堆叠多个首页实例。
- 返回策略 SHOULD 结合小程序路由形态选择 `switchTab`、`reLaunch` 或等价导航方式，并在后续 OpenSpec 阶段明确。
- 返回首页后，首页 SHOULD 保持可正常浏览、刷新和继续跳转到其他业务页面。

### FR-004 不影响页面原有交互

- 悬浮按钮 MUST 不影响页面滚动、下拉刷新、筛选、加载更多、分享、收藏、商品查看等既有交互。
- 悬浮按钮 MUST 不遮挡页面主要内容、底部操作区、系统安全区域和关键按钮。
- 商品详情页如存在底部购买、咨询、收藏或分享等固定操作区，悬浮按钮 MUST 与这些元素保持可用间距。
- 列表页如存在筛选栏、分页加载或空态按钮，悬浮按钮不得覆盖用户必须点击的核心控件。

### FR-005 视觉与状态一致

- 悬浮按钮视觉 SHOULD 延续小程序现有视觉规范，使用清晰的首页语义图标或短文案。
- 按钮尺寸 MUST 适合触控操作，点击热区不应过小。
- 按钮默认态、按压态和禁用/不可用兜底态 SHOULD 与现有小程序组件风格一致。
- 在 320 到 430 pt 常见微信小程序手机宽度下，按钮 MUST 不导致页面内容重叠、横向滚动或安全区冲突。
- 如图标、文案、位置或阴影样式与现有设计系统存在差异，需在 `/req-complete` 阶段收敛为可实施约束。

### FR-006 异常与边界处理

- 当首页路径不可达或导航 API 返回失败时，页面 SHOULD 保持在当前页，并提供不破坏体验的失败兜底。
- 若用户连续点击悬浮按钮，系统 SHOULD 避免重复触发导致多次跳转或异常状态。
- 页面加载中、接口失败、空态、无网络等状态下，悬浮按钮展示策略 SHOULD 与页面可交互状态保持一致。
- 若页面本身是首页的子状态或首页 Tab 内页面，是否展示按钮需在实现前明确判断规则。

## 5. UI / UE 约束

- 悬浮按钮 SHOULD 放置在页面右下侧或符合小程序现有布局习惯的位置，最终位置需避开底部安全区和固定操作区。
- 按钮内容 SHOULD 优先使用“首页”语义明确的图标；如配文案，文案应短且不挤占页面内容。
- 按钮视觉层级应足以被用户发现，但不得压过商品图片、商品价格、主按钮等核心业务信息。
- 页面滚动时按钮 SHOULD 保持固定位置；如页面存在特殊沉浸式头图或全屏内容，可在后续阶段确认隐藏或偏移策略。
- 不同页面的按钮位置、尺寸、圆角、阴影、图标和点击反馈 SHOULD 保持一致。
- 悬浮按钮不得遮挡微信小程序系统胶囊、导航栏、TabBar、安全区或已有客服/分享类悬浮入口。

## 7. 风险与待确认

| 风险 / 待确认 | 说明 |
|---|---|
| 小程序路由策略 | 需确认首页是否为 TabBar 页面，并据此选择 `switchTab`、`reLaunch` 或其他导航方式。 |
| 页面例外清单 | 登录、授权、错误、全屏视频、图片预览等特殊页面是否展示按钮仍需确认。 |
| 悬浮入口冲突 | 需核对是否已有客服、分享、咨询或商品操作类悬浮入口，避免互相遮挡。 |
| 视觉样式口径 | 图标、文案、位置、尺寸和按压反馈需在需求完善阶段收敛。 |
| 页面栈影响 | 返回首页后是否保留原页面栈、是否影响用户再次返回深层页面，需要在实现方案中明确。 |
