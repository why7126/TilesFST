# 用户故事

## US-001 从深层页面快速回到首页

作为小程序用户，我希望在商品详情、品牌详情、分类列表或搜索结果等非首页页面看到清晰的返回首页入口，以便不用逐级返回也能重新开始浏览。

验收要点：

- 首页不展示返回首页悬浮按钮。
- 主要非首页业务页面展示统一的返回首页悬浮按钮。
- 点击后直接进入首页，不出现空白页、重复首页或无响应。

## US-002 浏览过程中不被悬浮按钮打扰

作为正在浏览商品、品牌或类目的用户，我希望悬浮按钮不遮挡图片、筛选、底部操作区和安全区，以便继续完成当前页面操作。

验收要点：

- 悬浮按钮避开底部 TabBar、固定操作区、客服入口和系统安全区。
- 页面滚动、筛选、分享、收藏、加载更多等原有交互不受影响。
- 320/375/430 pt 常见视口下，按钮与页面文字、图片和主操作不重叠。

## US-003 从异常或分享直达页面安全返回首页

作为从分享、收藏或外部入口进入深层页面的用户，我希望即使没有上一页页面栈，也能通过悬浮按钮安全回到首页。

验收要点：

- 分享直达商品详情、品牌详情或列表结果页时，悬浮按钮可用。
- 当前页面处于加载、空态、错误态或网络失败时，按钮展示策略清晰且不会导致异常跳转。
- 首页路径不可达或导航 API 失败时，当前页面保留可恢复状态。

## US-004 识别稳定统一的首页入口

作为门店销售或设计师，我希望不同非首页页面的返回首页按钮样式和位置保持一致，以便向客户演示时不需要重新解释入口。

验收要点：

- 按钮图标、尺寸、位置、触控热区和按压反馈在覆盖页面中保持一致。
- 图标或文案具有明确“首页”语义。
- 按钮视觉层级清晰，但不抢占商品图片、价格或主 CTA。

## US-005 识别页面例外和后续实现边界

作为产品和研发人员，我希望在实现前明确哪些页面展示按钮、哪些页面豁免，以便减少上线后页面遮挡和导航冲突问题。

验收要点：

- `/req-opsx` 阶段必须产出页面覆盖清单和例外清单。
- 登录页、授权页、错误页、全屏视频页、图片预览页等特殊页面必须有展示或豁免理由。
- 若发现已有客服、分享、咨询等悬浮入口，必须明确避让或合并策略。
