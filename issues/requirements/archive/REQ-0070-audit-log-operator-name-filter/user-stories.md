# 用户故事

## US-001 系统管理员按名称筛选操作者

作为系统管理员，我希望在日志审计页面通过用户名称搜索并选择操作者，以便快速定位某个人产生的请求日志、行为事件和审计操作。

验收要点：

- 操作者筛选为单选可搜索下拉，而不是 User ID 输入框。
- 输入用户名称或账号关键字后，能看到匹配的用户候选项。
- 选择用户后，日志列表按对应 `actor_user_id` 精确过滤。
- 清空筛选后，日志列表恢复为全部操作者。

## US-002 审计负责人避免同名误选

作为安全 / 审计负责人，我希望下拉候选项在用户同名或名称缺失时展示账号和用户名称两行，以便避免选错操作者。

验收要点：

- 候选项第一行展示账号 `username`，第二行展示用户名称 `display_name || username`。
- 同名用户必须能通过账号区分。
- 已选态展示可读名称，不展示裸 User ID。

## US-003 运维保持日志查询语义稳定

作为开发 / 运维人员，我希望界面按名称选择，但后端仍按稳定的用户 ID 查询日志，以便避免名称变更或同名导致历史日志筛选不准确。

验收要点：

- 日志查询参数仍使用 `actor_user_id`。
- 前端不得把用户名称作为 `actor_user_id` 传给日志列表接口。
- 用户改名后，历史日志仍能通过该用户 ID 被准确筛选。

## US-004 管理员处理候选加载异常

作为系统管理员，我希望用户候选列表加载失败、无结果或仍在加载时，页面有清晰反馈，以便判断是用户候选不可用还是日志列表本身无数据。

验收要点：

- 候选搜索加载中有可感知状态。
- 无匹配结果展示空态提示。
- 候选接口失败时，不影响其他筛选条件和日志列表按全部操作者查询。
- 候选接口错误反馈与日志列表错误反馈可区分。

## US-005 产品负责人确认管理端列表一致性

作为产品负责人，我希望日志审计页面在新增可搜索下拉后仍保持管理端列表页一致性，以便避免分页、指标卡、toast 和移动端布局回归。

验收要点：

- 分页 DOM 与用户管理页基准一致。
- 操作反馈使用 fixed toast 或等价固定反馈，不引起布局位移。
- 页面不新增 `window.confirm`。
- 1440x1024 与移动端视口下筛选区和表格不溢出、不遮挡。
- 时间范围固定为最近5分钟至最近7天的常用窗口，不提供全部时间。
