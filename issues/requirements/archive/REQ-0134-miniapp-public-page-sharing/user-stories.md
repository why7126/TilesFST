# 公开页面分享用户故事

范围与规则以 [需求说明](requirement.md) 为准；编号用于回扣 [验收清单](acceptance.md)。

| 编号 | 用户故事 | 功能要求 | 验收要点 |
|---|---|---|---|
| US-001 | 作为客户，我希望把当前公开页面发给朋友或朋友圈，让接收者直接打开。 | FR-001 | AC-001 至 AC-011：11 页双渠道覆盖。 |
| US-002 | 作为销售，我希望分享指定商品、品牌或证书，避免接收者再次查找。 | FR-002 | AC-002、005、007、016：对象一致，失效对象安全降级。 |
| US-003 | 作为设计师，我希望分享有效筛选或搜索结果，让客户沿同一条件选砖。 | FR-003 | AC-003、004、006、009、010、012：恢复条件并从第一页读取最新数据。 |
| US-004 | 作为用户，我希望只分享公开内容，不把历史搜索或收藏暴露给他人。 | FR-004、005 | AC-013、014、015：白名单、容错、安全卡片与无历史泄露。 |
| US-005 | 作为接收者，我希望从找砖页进入搜索，并在没有页面栈时仍能继续使用。 | FR-006、007 | AC-011、016、017；AC-XCUT-001 至 003。 |
| US-006 | 作为运营人员，我希望区分分享触发与分享接收，不把触发次数解释成完成次数。 | FR-008 | AC-018 至 AC-021：事件语义、去重、脱敏和链路边界。 |

列表完整筛选恢复和发现页 JS 同步已纳入批准范围，结论见 [review.md](review.md)；实现仍遵循 Sprint 与 OpenSpec 流程。
