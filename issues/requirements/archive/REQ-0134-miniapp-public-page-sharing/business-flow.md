# 公开页面分享业务流程

## 1. 主流程

```text
发送者进入公开页面
  → 读取当前已生效的对象或筛选条件
  → 用户触发朋友 / 朋友圈分享
  → 按页面白名单构造参数、公开标题与轻量图片
  → 记录分享触发（上报失败不阻断）
  → 微信承载分享操作（不能推定实际完成）
  → 接收者打开分享入口
  → 解析并校验参数，建立接收端独立行为链路
  → 详情：读取同一公开对象
    列表：恢复有效条件、第一页查询
    搜索首页：仅公开入口，不传播个人历史
    分类：有效分享分类优先于本机旧选择
    普通入口：加载当前公开页面
  → 显示最新数据与安全图片 / 明确空态或错误态
  → 继续浏览、重试或返回首页
```

## 2. 异常分支

| 条件 | 处理 |
|---|---|
| 未知参数或非法枚举 | 忽略非法值并恢复有效默认状态；不得原样拼接请求。 |
| 对象 ID 缺失、非法或对象不可见 | 展示不可用状态，保留可用返回路径，不借用其他对象伪装同一详情。 |
| query 超限 | 先移除仅用于显示的冗余名称；仍超限则分享该页公开默认入口并使用默认入口标题，不保留部分筛选造成语义误导。具体项目上限由实现设计核对目标平台后固定。 |
| 网络失败或数据为空 | 使用明确错误 / 空态，允许重试或返回；不以发送者缓存代替授权查询。 |
| 图片缺失或不可读 | 使用包内公开 Logo，搜索首页禁止以个人历史截图兜底。 |
| 接收方存在旧搜索或分类缓存 | 不导入发送者历史；分享搜索不写接收方历史，分类分享参数优先。 |
| 无页面栈或返回失败 | 普通模式走统一首页兜底；单页模式按客户端可用能力提供进入小程序路径。 |
| 采集失败 | 分享和公开内容加载继续；不得无限重试或弹出阻断提示。 |

## 3. 参数与恢复契约

逐页对象与标题矩阵见 requirement.md §3.1。商品列表扩展到有效规格、价格区间和排序；品牌/证书列表保留已生效关键词；搜索保留已提交关键词、有效 scope/tab。分页和滚动不传播。详情进入默认 Tab，不恢复媒体轮播位置。

实现设计须从当前接口与页面枚举生成明确白名单，固定关键词及编码后 query 的边界值，并提供边界上下各一组样例。外部输入不作为权限或身份依据。

## 4. 与已有需求的差异及原型策略

无父需求。关联 REQ-0064 的四页分享为回归基线，本需求扩展到 11 页并补齐上下文与安全契约。收藏清单、海报、短链及分享激励不纳入。

原型策略为沿用原生菜单与现有页面结构，无新增视觉布局，不创建 prototype/web 或模拟系统分享界面。导航、原生胶囊与错误态通过验收截图回归；若评审增加独立面板或布局改动，重新制定原型策略。
