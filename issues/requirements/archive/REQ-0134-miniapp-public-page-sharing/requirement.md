# REQ-0134 小程序公开内容页朋友及朋友圈分享

## 1. 背景与目标

装修客户、设计师和门店销售需要将公开商品、品牌、证书及检索结果分享给微信朋友或朋友圈，让接收者直接查看对应内容。页面分享应形成一致的标题、图片、安全参数、直达恢复和失败处理契约。

需求来源见 [capture.md](capture.md)。已归档的 [REQ-0064](../../archive/REQ-0064-miniapp-wechat-share-pages/requirement.md) 覆盖首页、商品详情、商品列表和品牌详情的双渠道分享。本需求作为独立增量交付，补齐其余公开内容页，并对已有页面统一回归；不反向修改归档需求。

源码基线：`src/miniapp/app.json` 注册 12 个页面，其中 11 个为本需求范围，收藏页排除。首页、商品详情、商品列表、品牌详情、证书详情具有双渠道回调；品牌列表和证书列表只有朋友回调；发现页朋友回调为空模板；搜索、门店信息和分类没有分享回调。该基线仅证明源码状态，不证明客户端可分享或接收成功。

## 2. 目标用户

| 用户 | 目标 |
|---|---|
| 装修客户 | 将公开商品和检索结果发给家人朋友共同选砖。 |
| 设计师与门店销售 | 分享商品、品牌、证书和门店资料，减少接收者重复查找。 |
| 接收者 | 从分享入口直达内容，并可继续浏览、搜索或返回首页。 |
| 产品与测试人员 | 按逐页、逐渠道矩阵验证参数、安全、异常和接收效果。 |

## 3. 范围

### 3.1 包含

以下页面均覆盖微信朋友与朋友圈，朋友分享与朋友圈入口使用同一业务上下文。路径均位于 `src/miniapp/pages/`。

| 页面 | 页面目录 | 分享上下文 | 标题与图片策略 |
|---|---|---|---|
| 首页 | `index` | 公开首页与固定分享来源 | 门店或产品名称；公开品牌图或本地产品 Logo。 |
| 商品详情 | `tile-detail` | 当前 `skuId` | 公开分享标题或商品名；公开轻量分享图或商品缩略图。 |
| 商品列表 | `product-list` | 分类、品牌、关键词、榜单、有效规格、价格区间与排序 | 当前筛选语义；公开结果缩略图或产品 Logo。 |
| 品牌列表 | `brand-list` | 当前已生效关键词 | 品牌列表及有效关键词；公开品牌素材或产品 Logo。 |
| 品牌详情 | `brand-detail` | 当前 `brandId`，进入默认内容 Tab | 品牌名称；公开轻量品牌图或产品 Logo。 |
| 证书列表 | `certificates` | 当前已生效关键词 | 证书列表及有效关键词；公开证书缩略图或产品 Logo。 |
| 证书详情 | `certificate-detail` | 当前 `certificateId` | 证书名称或公开分享标题；公开缩略图或产品 Logo。 |
| 门店信息 | `store-info` | 当前应用的公开门店入口 | 门店名称；公开门店素材或产品 Logo。 |
| 分类 | `category` | 当前有效一级分类 ID | 分类名称或全部分类；产品 Logo。 |
| 搜索 | `search` | 首页无关键词；结果页保留已提交关键词、有效范围和结果 Tab | 搜索入口或结果语义；固定公开产品图，禁止使用个人历史截图。 |
| 发现/找砖 | `find` | 公开找砖入口 | 找砖入口与产品名称；产品 Logo。 |

列表完整筛选恢复、发现页现有搜索按钮 JS 同步纳入已批准范围，评审结论与后续交付检查点见 [review.md](review.md)。实现前仍需纳入 Sprint 并创建 OpenSpec Change。

### 3.2 不包含

- 个人收藏清单分享、公开选品清单、收藏同步或用户身份共享。
- 分享海报、短链、H5 中转、后台分享素材配置。
- 邀请奖励、分享排行、分销、交易或分享完成率统计平台。
- 新建发现页业务模块、重新设计页面、增加全局分享面板。
- 固化分享时商品库存、价格、排序结果或分页数据的历史快照。
- 新增后端 API、数据库结构或修改对象存储访问权限。

## 4. 功能要求

### FR-001 逐页双渠道覆盖

11 个范围内页面均须提供有效的朋友分享与朋友圈分享配置，包括明确标题、落地上下文和安全图片兜底。回调存在但无有效内容不视为完成。已有分享按钮及原生菜单语义保持一致，不强制在每页增加按钮。

### FR-002 公开对象直达

商品、品牌和证书详情须直达同一公开对象。分享参数只用于定位，不作为权限或公开状态依据；接收者重新使用现有公开接口获取数据。对象不存在、下架、不可见或 ID 无效时展示可理解的不可用状态，并提供可用的首页返回路径，不展示缓存的非公开对象。

### FR-003 列表与搜索结果恢复

- 商品列表保留有效分类 ID/层级、品牌、已提交关键词、榜单、规格、价格区间与排序。恢复后第一页重新加载；不恢复页码、已加载数组或滚动位置。
- 品牌和证书列表保留已生效关键词，接收后使用对应列表查询，不跳全局搜索。
- 搜索结果保留已提交关键词、有效 `scope` 与 `tab`；正在输入但未提交的联想文本不分享。搜索首页不传关键词或历史记录。
- 分类页优先恢复有效分享分类，再应用普通页面默认策略；分享参数不得被接收方旧本地分类状态覆盖。分类失效时回到可浏览默认分类。
- 显示名称仅用于展示；查询以合法 ID 和既有接口枚举为准。接收后结果反映最新公开数据，可与发送时数量不同。
- 分享打开搜索结果仅执行恢复查询，不应当作主动提交搜索写入接收方最近搜索或重复上报 `search_submit`；用户再次主动搜索沿用既有逻辑。

### FR-004 参数白名单与容错

按页面构建白名单，不整体复制页面 query、data 或 storage。详情只传对应对象 ID 和固定来源；普通入口只传固定来源；列表与搜索只传 FR-003 的有效上下文。各参数最终名称与枚举复用现有页面和接口契约。

中文、空格、百分号、连接符等须安全编码和解析，避免重复解码。未知参数忽略；非法 ID、超长关键词、畸形编码或不支持枚举不得造成白屏。关键词长度沿用现有搜索限制；完整 query 的项目上限在实现设计中按目标平台固定；超限先移除冗余显示名称，仍超限则分享该页公开默认入口并使用默认标题，不保留部分条件造成语义误导。

不得携带个人历史、收藏数据、会话标识、鉴权信息、内部对象 key、后台备注或本机路径。分享来源字段固定生成，不透传任意外部输入。发送者链路 ID 不经公开链接传播，接收端创建自己的行为链路。

### FR-005 标题与图片兜底

标题使用已加载的公开对象名称或页面语义；数据未加载、空值或请求失败时使用稳定公开标题，不出现 `undefined`、`null` 或内部编号文案。

图片优先使用已存在的公开轻量分享图、缩略图，再使用包内产品 Logo。不得为分享加载原始大图、生成海报或放宽存储权限。无法保证安全内容的页面不得依赖当前页面截图兜底，尤其是展示最近搜索的搜索首页。素材地址不可读、失效、加载未完成时仍有安全卡片内容；朋友圈与朋友渠道分别验证实际图片表现。

### FR-006 发现页最小可用性

发现页限定为现有找砖入口：分享直达当前页后，“开始搜索”可进入公开搜索首页。实现阶段同步已有 `index.ts` 中的搜索跳转到实际运行 `index.js`，补齐双渠道回调；不扩展找砖业务。TS/JS 同步验证不得仅检查类型源码。

### FR-007 冷启动、返回与异常

分享接收不能依赖发送者 storage、前置页面栈或内存列表。冷启动、热启动、无页面栈返回、网络失败、空结果及对象失效均须有明确处理。普通直达复用现有导航返回首页兜底；朋友圈单页入口按客户端实际能力验证浏览和进入小程序路径，不假定所有导航 API 可用。非关键采集、缓存和媒体失败不得阻断公开内容读取。

### FR-008 分享行为采集

沿用既有 `track()`、事件字典及请求封装，记录页面、渠道、公开对象 ID 或脱敏上下文摘要。已有分享事件保持可追溯，新覆盖页面补入稳定事件映射。

分享回调仅表达分享触发，不代表实际发送、发布或接收成功；没有可验证结果时不得记录分享完成成功。接收访问与分享触发分开统计，普通访问不误标分享访问。同一次触发避免按钮和生命周期双重上报。上报失败不得阻断分享。

事件不得原样保存完整分享 URL、用户输入或本地数据；仅记录白名单摘要并遵守现有脱敏、截断及服务端过滤。客户端来源字段只用于归因，不作为可信身份或授权证据。

## 5. UI 约束

沿用现有页面结构、原生分享菜单、产品 Logo 和既有导航组件。本需求不新增页面视觉方案，因此不生成 prototype；若后续增加独立面板或调整布局，应重新明确原型与视觉验收范围。任何必要样式调整遵循 `rules/ui-design.md` 与已有 semantic token，禁止新增裸 Hex。

分享文案面向用户，不展示参数名、接口名或内部实现。保留首页添加引导、商品详情已有分享交互和证书详情原生分享方式。
