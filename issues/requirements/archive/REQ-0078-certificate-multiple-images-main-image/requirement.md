# REQ-0078 证书支持多图上传与主图设置需求文档

- 版本：v1
- 状态：approved
- 产品：菲尚特瓷砖信息管理平台
- 范围：Web 管理端品牌证书新增/编辑弹窗与证书列表缩略图
- 更新日期：2026-07-28

## 1. 背景

`REQ-0038-brand-certificate-management` 已交付管理后台品牌证书管理能力，当前证书文件以单文件方式维护，支持图片或 PDF 上传、预览和列表缩略图展示。实际运营中，一个证书资料可能包含封面、内页、检测明细页、附页或补充说明页，仅用单张图片无法完整表达证书内容。

本需求将证书图片从单图维护升级为多图维护，并允许运营指定其中一张作为主图。主图用于管理端列表缩略图、证书卡片首图和默认预览入口；多图用于在证书编辑、预览和后续公开展示中保留完整材料。PDF/文档类证书是否继续复用现有单文件形态，需在后续补齐阶段明确。

## 2. 产品目标

1. 支持运营为同一证书上传多张图片，覆盖证书多页、附页和细节图场景。
2. 支持运营设置唯一主图，让证书列表与卡片展示有稳定缩略图。
3. 明确主图默认、切换、删除后的兜底规则，避免证书有图片但缺少主图。
4. 保持证书上传链路的后端鉴权、文件校验和对象存储安全边界。
5. 为后续小程序或店主端证书公开展示提供可复用的数据结构和展示顺序。

## 3. 目标用户

| 用户 | 核心诉求 |
|---|---|
| 后台运营 | 上传证书多页图片，并选择最能代表证书的主图 |
| 后台管理员 | 维护证书资料完整性，减少单图无法表达完整证书内容的问题 |
| 产品/验收人员 | 验收多图数量、主图唯一性、删除兜底、列表回显和上传安全规则 |

## 4. 范围

### 4.1 本期包含

- 管理端品牌证书新增/编辑弹窗支持上传多张证书图片。
- 每张证书图片支持缩略图回显、上传状态、失败提示、删除和设置主图。
- 同一证书有多张图片时，只允许一张图片为主图。
- 未手动设置主图时，默认第一张成功上传图片为主图。
- 设置主图后，主图在视觉和保存顺序上默认排到第一位。
- 删除当前主图后自动选择兜底主图；删除非主图不影响当前主图。
- 管理端证书列表、证书卡片和默认预览入口使用主图作为缩略图。
- 保存后再次进入编辑弹窗，图片顺序、主图标记、图片数量和缩略图回显一致。

### 4.2 本期不包含

- 不新增证书审批流、OCR 识别、电子签章、真伪校验。
- 不新增证书与 SKU 单独绑定能力。
- 不新增批量上传、批量删除或批量设置主图能力。
- 不做对象存储物理文件删除；删除图片仅解除证书与图片的业务关联。
- 不调整 SKU 图片、品牌 Logo、Banner 等其他媒体场景的主图规则。
- 不直接实现店主 Web 或微信小程序证书详情多图展示，除非后续 OpenSpec 明确纳入。

## 5. 产品决策

1. 证书多图能力首期以图片为主；PDF/文档类证书沿用既有单文件占位，是否允许与图片并存需在 OpenSpec 设计阶段最终确认。
2. 同一证书图片列表中必须保持唯一主图，保存 payload 和后端返回均不得出现多个 `is_main=true`。
3. 第一张成功上传图片默认成为主图，降低运营首次维护成本。
4. 用户手动设置主图后，新主图应移动到图片列表第一个位置，强化“首图即主图”的理解。
5. 删除当前主图时，优先选择当前主图后一张图片作为新主图；若不存在后一张但仍有图片，则选择删除后列表第一张。
6. 当全部图片被删除后，允许证书处于无图片状态；是否允许保存、发布或前台展示由后续证书完整度与展示策略确认。

## 6. 功能要求

### FR-001 多图上传

- 新增/编辑证书弹窗中的证书文件区域应支持上传多张图片。
- 已上传图片应以稳定缩略图卡片展示，展示文件名、上传状态和主图标记。
- 上传中、上传成功、上传失败和取消上传状态应和现有证书上传链路保持一致。
- 图片上传必须继续经过后端鉴权、MIME Type、扩展名和大小校验。

### FR-002 主图默认规则

- 当证书还没有任何图片时，第一张成功上传图片应自动成为主图。
- 当证书已有主图时，继续新增图片不得自动覆盖当前主图。
- 当后端返回历史数据没有主图但存在图片时，前端或后端应按图片顺序兜底选择第一张作为主图，并在保存时修正为唯一主图。

### FR-003 设置主图

- 每张非主图图片应提供“设为主图”操作。
- 用户设置主图后，该图片立即成为唯一主图。
- 原主图应取消主图标记并保留在图片列表中。
- 新主图应移动到图片列表第一个位置，保存时 `sort_order` 与展示顺序一致。

### FR-004 删除图片与主图兜底

- 用户可删除任意已添加图片。
- 删除非主图图片时，当前主图保持不变，剩余图片顺序稳定。
- 删除当前主图且仍有其他图片时，应自动选择新主图，并在弹窗中即时可见。
- 删除最后一张图片后，弹窗进入空图片状态，不显示主图标记。
- 被删除图片不应出现在保存 payload 中，但本需求不要求立即物理删除对象存储文件。

### FR-005 列表缩略图与默认预览

- 管理端证书列表的缩略图应优先展示主图。
- 证书卡片、弹窗文件摘要和默认预览入口应以主图作为首图。
- 当主图加载失败时，应显示证书图片占位或文件类型占位，不显示破图。
- 当证书无图片但仍有 PDF/文档文件时，沿用既有 PDF 或文件占位规则。

### FR-006 保存与回填一致性

- 保存证书时，图片数组应包含稳定的文件引用、展示 URL、主图标记和排序信息。
- 保存 payload 中主图必须唯一；有图片时应至少有一张主图。
- 后端保存后再次查询证书详情，返回的图片列表顺序、主图标记和数量应与保存结果一致。
- 编辑弹窗重新打开时，不得丢失主图标记、图片顺序或已上传图片回显。

### FR-007 公开端展示边界

- 本期不直接实现公开端多图浏览，但数据结构应支持后续小程序或店主 Web 按主图和图片顺序展示。
- 如公开证书列表已使用证书缩略图，应优先消费后端返回的主图字段或主图 URL。
- 公开端不得直接访问未授权对象存储 Key，仍应使用后端控制的可读 URL 或签名 URL。

## 7. UI 约束

- 证书图片区域应保持管理端暗色旗舰风、品牌金主图标记、低圆角和语义化 token。
- 图片卡片尺寸应稳定，上传进度、失败提示、主图标记和删除入口不得造成布局跳动。
- 主图标记与“设为主图”操作应区分清楚，避免运营误点。
- 删除入口不得遮挡证书图片主体内容；需要有可访问名称。
- 空图片状态继续保留上传入口和必要状态提示，不使用大段功能说明文案。
- 多图较多时，图片区域应支持换行或局部滚动，不能撑破弹窗宽度或遮挡底部按钮。

## 8. 数据与接口影响

| 范围 | 影响 |
|---|---|
| 管理端 Web | 需要调整品牌证书新增/编辑弹窗的图片数组、主图状态、删除和回显逻辑 |
| 后端 API | 预计需要从单文件字段扩展或兼容到证书图片数组，并返回主图信息 |
| SQLite/MySQL | 可能需要新增证书图片关联表或扩展现有证书文件字段，具体由后续设计确认 |
| Pydantic Schema | 需要表达图片列表、`is_main`、`sort_order`、文件引用和展示 URL |
| OpenAPI/Orval | 若 API 请求/响应结构变化，则必须同步 OpenAPI 并重新生成 Orval 客户端 |
| MinIO/对象存储 | 继续沿用后端鉴权上传与对象存储适配层；不做前端直连未授权对象存储 |
| 测试 | 需要覆盖多图上传、设置主图、删除主图兜底、保存回填、上传校验和兼容旧数据 |
