# User Stories

## US-001 上传证书多页图片

作为后台运营，我希望在新增或编辑证书时上传多张图片，以便完整维护证书封面、内页、检测明细页和附页。

验收要点：

- 证书图片区域支持一次或多次添加图片。
- 上传成功后图片卡片即时回显，不需要关闭弹窗或刷新页面。
- 图片上传失败时，失败原因显示在对应图片或上传控件内。
- 图片数量达到上限后，继续添加入口进入禁用或提示状态。

## US-002 设置证书主图

作为后台运营，我希望从多张证书图片中选择一张主图，以便证书列表和卡片展示时优先使用最具代表性的图片。

验收要点：

- 第一张成功上传图片自动成为主图。
- 非主图图片可设置为主图。
- 同一证书同时只能存在一张主图。
- 设置主图后，该图片移动到列表第一位。

## US-003 删除图片并保持主图兜底

作为后台运营，我希望删除错误或过期的证书图片，同时系统能自动保持主图规则，以便避免保存后证书有图片但没有主图。

验收要点：

- 删除非主图图片不影响当前主图。
- 删除当前主图后，系统自动选择下一张或第一张剩余图片作为新主图。
- 删除最后一张图片后，图片区进入空状态，不显示主图标记。
- 删除图片只解除业务关联，不要求立即物理删除对象存储文件。

## US-004 保存后稳定回填

作为后台管理员，我希望保存证书后再次打开编辑弹窗时，图片顺序和主图标记保持一致，以便确认运营维护结果没有丢失。

验收要点：

- 保存请求中的图片数组包含文件引用、展示 URL、`is_main` 和 `sort_order`。
- 后端返回的图片列表顺序与保存前一致。
- 再次打开编辑弹窗时，主图仍在第一位并有明确标记。
- 旧单文件证书数据在迁移或兼容后可正常展示。

## US-005 使用主图作为列表缩略图

作为后台运营，我希望证书列表优先展示主图缩略图，以便快速识别证书内容并减少误操作。

验收要点：

- 证书列表的缩略图优先使用主图。
- 主图加载失败时显示稳定占位，不显示破图。
- 无图片但存在 PDF 或文档文件时，沿用既有 PDF/文件占位规则。
- 预览入口默认从主图开始查看。

## US-006 保障上传安全与边界

作为系统管理员，我希望多图上传继续遵守后端鉴权、大小限制、类型校验和对象存储策略，以便新增能力不引入未授权上传或文件回显问题。

验收要点：

- 上传仍走后端鉴权与媒体适配层。
- 前端不得直连未授权对象存储 Key。
- 超限、非法类型和上传失败均返回可识别错误。
- Docker Web 入口下完成合法小图和超限图片边界验收。
