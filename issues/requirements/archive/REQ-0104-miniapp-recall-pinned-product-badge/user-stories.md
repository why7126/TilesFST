# 用户故事

## US-001 小程序访客识别置顶商品

作为小程序访客，我希望在普通商品列表中看到被置顶展示的商品带有“置顶”标识，以便理解它为什么排在列表前面。

验收要点：

- 普通商品列表中实际生效的召回置顶商品展示“置顶”。
- 非置顶商品不展示“置顶”。
- 标识不遮挡商品图片、名称、品牌、规格和参考价格。

## US-002 搜索用户识别置顶 SKU

作为通过搜索查找商品的小程序用户，我希望搜索 SKU 结果中的置顶商品也展示“置顶”标识，以便快速识别重点商品。

验收要点：

- 搜索 SKU 结果中实际生效的召回置顶商品展示“置顶”。
- 搜索实时联想不展示“置顶”。
- 小程序不根据列表位置自行推断标识状态。

## US-003 运营人员确认置顶前台效果

作为运营人员，我希望配置召回置顶后，小程序前台能清晰展示“置顶”标识，以便确认重点商品曝光策略已被用户感知。

验收要点：

- 置顶配置失效、取消或未进入置顶数量上限时，商品不展示“置顶”。
- 新品商品列表和热销商品列表不应用置顶逻辑，因此不展示“置顶”。
- 标识状态与接口返回保持一致。

## US-004 开发测试人员验证兼容边界

作为开发或测试人员，我希望有明确字段、范围和回归分支，以便实现时不破坏现有排序和榜单语义。

验收要点：

- API 响应字段表达“当前列表实际生效的召回置顶展示状态”。
- 缺少该字段时，小程序默认不展示“置顶”。
- 普通列表、搜索 SKU 结果、新品榜、热销榜均有测试覆盖。
