# REQ-0104 小程序召回置顶商品展示“置顶”标识

## 1. 需求背景

`REQ-0103` 已定义小程序普通商品列表与搜索 SKU 结果中的召回置顶排序能力：当少量商品满足召回置顶条件时，系统在后端排序层将这些商品优先排列，但新品榜与热销榜不应用置顶逻辑。

当前小程序商品卡片只能通过列表顺序体现置顶结果，用户无法识别哪些商品是被业务策略置顶展示的。为提升列表解释性和运营信息传达，本需求要求在小程序中对实际生效的召回置顶商品展示“置顶”标识。

## 2. 目标用户

| 用户 | 核心诉求 |
|---|---|
| 小程序访客 | 进入普通商品列表或搜索 SKU 结果时，可以明确识别被优先展示的置顶商品。 |
| 运营人员 | 配置召回置顶后，小程序前台能同步展示“置顶”标识，增强重点商品曝光解释性。 |
| 产品 / 业务负责人 | 明确置顶标识只跟随实际生效的置顶逻辑，不误伤新品榜、热销榜等榜单语义。 |
| 开发 / 测试人员 | 明确 API 字段、卡片标识优先级、适用列表和不适用列表。 |

## 3. 需求目标

- 小程序普通商品列表中实际生效的召回置顶商品展示“置顶”标识。
- 小程序搜索 SKU 结果中实际生效的召回置顶商品展示“置顶”标识。
- 新品商品列表和热销商品列表没有置顶逻辑，因此不得展示“置顶”标识。
- “置顶”标识必须来源于后端返回的明确状态字段，避免小程序端根据排序位置猜测。
- 标识展示不得改变既有列表排序、分页、点击、加载更多和商品卡片主要信息展示。

## 4. 范围

### 4.1 本期包含

| 范围 | 说明 |
|---|---|
| 小程序普通商品列表 | 覆盖全部商品、分类商品、品牌商品、关键词商品等应用召回置顶排序的普通列表。 |
| 小程序搜索 SKU 结果 | 覆盖搜索页中 SKU 商品结果，实际生效的召回置顶商品需展示“置顶”标识。 |
| 商品卡片标识 | 在小程序商品卡片中展示固定文案“置顶”，展示位置与视觉样式需不遮挡商品关键信息。 |
| 后端状态字段 | API 响应需能表达商品是否为当前列表中实际生效的召回置顶商品。 |
| API / Orval / 小程序同步 | 若新增响应字段，需同步 Pydantic Schema、OpenAPI、Orval 与小程序类型定义。 |
| 测试覆盖 | 覆盖置顶商品展示、非置顶商品不展示、新品榜和热销榜不展示等关键路径。 |

### 4.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 新品商品列表置顶标识 | 新品商品列表没有置顶逻辑，不展示“置顶”标识。 |
| 热销商品列表置顶标识 | 热销商品列表没有置顶逻辑，不展示“置顶”标识。 |
| 收藏列表置顶标识 | 收藏列表保持用户收藏时间等既有排序，不展示召回置顶标识。 |
| 搜索实时联想标识 | 搜索建议 / suggestion 不纳入本期置顶标识。 |
| 店主 Web 商品列表 | 不调整店主 Web 展示端商品列表或卡片。 |
| 管理端 SKU 列表标识 | 不在管理端列表中新增前台“置顶”角标展示。 |
| 小程序端本地排序 | 小程序端不根据“置顶”标识重新排序。 |
| 多种置顶文案 | 本期不区分运营置顶、召回置顶、推荐置顶，统一展示“置顶”。 |

## 5. 核心概念

### 5.1 实际生效的召回置顶商品

实际生效的召回置顶商品指在当前请求列表中满足 `REQ-0103` 召回置顶规则，并且真正参与当前列表置顶排序的 SKU。仅配置了召回排序值但当前列表未应用置顶逻辑，或未处于有效期、未进入置顶数量上限、未满足筛选条件的商品，不应被视为实际生效的召回置顶商品。

### 5.2 “置顶”标识

“置顶”标识是小程序商品卡片上的前台展示文案，用于解释当前商品被优先展示。它不是新的 SKU 状态，不改变商品上下架、是否新品、是否热销、库存或价格等业务字段。

### 5.3 榜单列表

榜单列表指新品商品列表和热销商品列表。此类列表没有召回置顶逻辑，也不展示“置顶”标识，避免破坏榜单原有排序语义。

## 6. 功能要求

### FR-001 标识展示范围

- 小程序普通商品列表中，实际生效的召回置顶商品 MUST 展示“置顶”标识。
- 小程序搜索 SKU 结果中，实际生效的召回置顶商品 MUST 展示“置顶”标识。
- 非置顶商品 MUST NOT 展示“置顶”标识。
- 仅配置召回排序值但当前请求未应用置顶逻辑的商品 MUST NOT 展示“置顶”标识。

### FR-002 新品榜与热销榜例外

- 新品商品列表没有置顶逻辑，MUST NOT 展示“置顶”标识。
- 热销商品列表没有置顶逻辑，MUST NOT 展示“置顶”标识。
- 通过首页快捷入口、商品列表参数或其他入口进入新品榜 / 热销榜时，均 MUST 遵守不展示“置顶”标识的规则。
- 新品榜和热销榜中原有“新品”“热销”展示语义不得被“置顶”覆盖。

### FR-003 后端状态字段

- API 响应 MUST 提供明确字段表达商品是否为当前列表中实际生效的召回置顶商品。
- 该字段 MUST 基于后端排序层的置顶生效判断生成，不得由小程序端根据列表位置或排序值自行推断。
- 当请求为新品榜、热销榜或其他不应用置顶逻辑的列表时，该字段 MUST 为 false 或不触发展示。
- 字段命名、默认值、兼容策略和 OpenAPI 表达需在 OpenSpec 阶段明确。

### FR-004 小程序商品卡片展示

- 小程序商品卡片 MUST 在收到置顶生效字段为 true 时展示固定文案“置顶”。
- 标识位置 SHOULD 复用现有商品卡片角标区域，避免新增复杂布局。
- 标识不得遮挡商品主图核心内容、商品名称、品牌、规格和参考价格。
- 标识展示不得影响整卡点击进入商品详情页、图片加载失败兜底和曝光 / 点击埋点。

### FR-005 标识优先级

- 当商品同时满足置顶与新品 / 热销展示条件时，普通商品列表和搜索 SKU 结果中 SHOULD 优先展示“置顶”标识。
- 新品商品列表和热销商品列表不应用置顶逻辑，因此 MUST 保留榜单自身语义，不展示“置顶”标识。
- 若后续需要同时展示多个标签，需另行提出需求，不在本期扩展。

### FR-006 刷新与状态一致性

- 当商品置顶配置取消、失效或超过置顶数量上限后，小程序列表刷新后 MUST 不再展示“置顶”标识。
- 下拉刷新、加载更多、筛选切换和搜索关键词切换后，标识状态 MUST 与接口返回保持一致。
- 分页加载时已展示商品不得因端侧合并逻辑错误出现重复、错位或遗留“置顶”标识。

### FR-007 API 与兼容

- 如新增 `MiniappProductCard` 响应字段，MUST 同步 Pydantic Schema、OpenAPI、Orval 和小程序类型定义。
- 新字段 MUST 保持向后兼容，不破坏既有列表响应结构、分页字段和错误码。
- 若前端遇到旧接口缺少该字段，MUST 默认不展示“置顶”标识。
- 相关接口文档需说明字段含义为“当前列表中实际生效的召回置顶展示状态”，而不是后台配置状态。

### FR-008 测试要求

- 测试 MUST 覆盖普通商品列表中置顶商品展示“置顶”标识。
- 测试 MUST 覆盖搜索 SKU 结果中置顶商品展示“置顶”标识。
- 测试 MUST 覆盖非置顶商品不展示“置顶”标识。
- 测试 MUST 覆盖新品商品列表不展示“置顶”标识。
- 测试 MUST 覆盖热销商品列表不展示“置顶”标识。
- 测试 MUST 覆盖接口缺少置顶字段时小程序默认不展示。

## 7. UI 约束

- 商品卡片标识文案固定为“置顶”。
- 优先复用现有商品卡片角标视觉，不新增弹窗、说明卡片、排序控件或教学文案。
- 标识需要在列表密度、紧凑卡片和搜索结果卡片中保持可读。
- 标识颜色、边框和字号应与小程序既有深色商品卡片风格一致。
- 标识不得造成卡片高度跳动、文本溢出或遮挡商品核心信息。

## 8. 数据与接口影响

| 范围 | 影响 |
|---|---|
| SQLite/MySQL | 不新增独立业务表；复用 `REQ-0103` 已有召回置顶配置与生效判断。 |
| Pydantic Schema | 预计需要在 `MiniappProductCard` 增加置顶生效展示字段。 |
| OpenAPI/Orval | 响应字段新增时必须同步 OpenAPI 与 Orval。 |
| 后端 API | 影响 `/api/v1/miniapp/products` 与 `/api/v1/miniapp/search` 的 SKU 商品结果响应。 |
| 小程序 | 商品卡片根据后端字段展示“置顶”标识；不进行端侧排序。 |
| 管理端 | 不新增管理端配置入口，继续复用 `REQ-0103` 的召回置顶配置。 |
| 店主 Web | 不涉及。 |
| 测试 | 需覆盖接口字段、普通列表、搜索结果、新品榜、热销榜和兼容缺省字段。 |
