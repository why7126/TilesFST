# REQ-0083 小程序品牌列表页按品牌单行展示类目汇总

## 1. 需求背景

微信小程序品牌列表页已具备顶部品牌轮播和下方品牌列表能力。当前品牌列表更偏品牌卡片浏览，用户需要进入品牌详情页后才能进一步判断该品牌覆盖哪些商品类目，浏览效率不够直观。

本需求在保持品牌列表页上半部轮播图不变的前提下，调整下半部品牌列表的信息结构：每行展示一个品牌，左侧展示品牌基础信息，右侧展示该品牌下所有商品对应的末级类目名称。用户可在品牌列表页直接判断品牌商品覆盖范围，再决定是否进入品牌主页或商品列表。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 装修业主 | 在浏览品牌时快速判断品牌覆盖的瓷砖类目，减少反复进入详情页的试探成本。 |
| 室内设计师 | 按品牌快速识别可推荐的商品品类，便于选材沟通。 |
| 门店销售 | 在向客户展示品牌矩阵时，同时说明品牌商品覆盖类目和商品数量。 |

## 3. 范围

### 3.1 本期包含

| 范围 | 说明 |
|---|---|
| 品牌列表页下半部布局调整 | 下半部品牌列表由现有卡片展示调整为每行一个品牌的信息行。 |
| 品牌行左侧信息 | 展示品牌 Logo、品牌名称、商品数量。 |
| 品牌行右侧信息 | 展示该品牌下所有商品对应类目的最后一层级类目名称。 |
| 末级类目去重 | 同一品牌下多个商品命中同一末级类目时，类目名称只展示一次。 |
| 移动端适配 | 在常见微信小程序手机宽度下，品牌名称、数量和类目名称可读且不重叠。 |
| 数据边界确认 | 明确商品数量、末级类目集合、空态和异常态所需字段。 |

### 3.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 顶部轮播图改造 | 品牌列表页上半部轮播图的视觉、数据和交互保持不变。 |
| 品牌详情页改造 | 单品牌主页/详情页的结构、Tab、商品列表和证书列表不在本需求中调整。 |
| 管理端品牌维护改造 | 不新增品牌管理字段、品牌排序后台或权限能力。 |
| 类目管理规则改造 | 不调整类目层级、类目命名、类目排序和商品绑定类目的管理规则。 |
| 品牌筛选/搜索 | 不新增品牌搜索、类目筛选、首字母筛选或多条件过滤。 |
| Web 展示端调整 | 本需求仅针对微信小程序品牌列表页。 |

## 4. 功能要求

### FR-001 保持顶部品牌轮播不变

- 品牌列表页上半部轮播图 MUST 保持现有视觉、布局、数据来源和交互行为不变。
- 本需求的实现范围 MUST 仅作用于轮播图下方的品牌列表区域。
- 若后续实现需要改动轮播区域以适配整体页面间距，MUST 保持用户可感知的轮播内容、图片比例、指示器和点击行为不变。

### FR-002 品牌列表每行展示一个品牌

- 品牌列表下半部 MUST 改为每行显示一个品牌。
- 每个品牌行 MUST 分为左侧品牌信息区和右侧类目汇总区。
- 品牌行整体 SHOULD 保持可点击，点击后沿用现有品牌列表页进入品牌主页/详情页或品牌关联商品列表的跳转规则。
- 品牌行之间 MUST 有稳定间距或分隔，便于用户纵向浏览。
- 列表加载、分页、下拉刷新、错误态和空态 SHOULD 复用现有品牌列表页能力。

### FR-003 左侧展示品牌基础信息

- 左侧品牌信息区 MUST 展示品牌 Logo。
- 左侧品牌信息区 MUST 展示品牌名称。
- 左侧品牌信息区 MUST 展示该品牌下的商品数量。
- 商品数量文案 SHOULD 使用清晰短句，例如“12 款商品”或实现阶段按小程序现有文案规范确认。
- 品牌 Logo 缺失或加载失败时 MUST 使用品牌占位图、品牌名称首字或现有品牌占位策略，不得出现破图。
- 品牌名称过长时 MUST 限制行数或截断，不得挤压商品数量和右侧类目汇总区。

### FR-004 右侧展示品牌商品末级类目

- 右侧类目汇总区 MUST 展示该品牌下所有商品对应类目的最后一层级类目名称。
- 若商品绑定的是多级类目路径，展示值 MUST 取该路径的最后一层级名称。
- 若商品只绑定一级或二级类目，展示值 MUST 取该商品实际绑定路径中的最后一层名称。
- 同一品牌下重复的末级类目名称 MUST 去重展示。
- 类目名称展示顺序 SHOULD 优先使用类目后台排序；如接口无法提供排序依据，则在后续 OpenSpec 阶段明确稳定兜底排序。
- 类目数量较多时 MUST 有移动端可读的溢出策略，例如自动换行、限制行数后省略，或展示“等 N 类”；具体策略在 `/req-complete` 阶段确认。

### FR-005 商品数量统计口径

- 商品数量 MUST 表达该品牌下可在小程序公开展示的商品数量。
- 已下架、禁用或不应公开展示的商品 SHOULD 不计入小程序品牌列表页商品数量。
- 商品数量与右侧类目汇总 SHOULD 使用一致的商品集合口径，避免出现“数量为 0 但仍展示类目”或“有数量但无类目且无说明”的矛盾。
- 若品牌无公开商品，商品数量 MUST 显示为空态友好的值，例如“0 款商品”，右侧类目区 MUST 使用空态文案或隐藏策略。

### FR-006 数据与接口边界

- 小程序端 MUST 通过后端公开接口获取品牌列表信息，不得直连未授权对象存储或管理端私有接口。
- 品牌列表数据 SHOULD 至少包含品牌 ID、品牌 Logo URL、品牌名称、商品数量和末级类目名称集合。
- 若现有品牌列表接口不能返回商品数量或末级类目集合，后续 OpenSpec Change MUST 明确接口扩展、响应 Schema、错误码、OpenAPI、Orval 或小程序 API 类型同步范围。
- API 响应 MUST 只返回小程序可公开展示的数据，不得暴露管理端内部备注、未公开品牌、未公开商品或对象存储内部 key。

## 5. UI / UE 约束

- 页面视觉 MUST 延续微信小程序现有暗色旗舰风和品牌列表页视觉基调。
- 顶部轮播图 MUST 保持不变，下方列表调整后不得遮挡轮播、导航栏或底部安全区。
- 品牌行 SHOULD 采用左右分区布局，左侧优先保证 Logo、品牌名称和商品数量可读，右侧用于展示类目标签或文本集合。
- 在 320 到 430 pt 常见小程序手机宽度下，品牌行 MUST 不出现文字重叠、横向滚动、Logo 拉伸或内容溢出容器。
- 类目名称较长时 MUST 限制行数、换行或省略，不得覆盖品牌基础信息。
- 品牌行点击区域 SHOULD 不小于 44px 高度，并保留小程序原生按压反馈。
- 无 Logo、无商品、无类目、接口失败和加载中状态 MUST 有清晰视觉反馈，不得白屏或展示破损图片。

## 6. 数据字段建议

品牌列表项 SHOULD 映射以下字段；字段命名在后续 API / 小程序实现阶段按项目约定确认：

| 字段 | 用途 | 首期要求 |
|---|---|---|
| `brandId` | 品牌跳转和埋点 | 必需 |
| `brandName` | 品牌名称 | 必需 |
| `logoUrl` | 品牌 Logo 展示 | 必需或需有占位兜底 |
| `productCount` | 品牌公开商品数量 | 必需 |
| `leafCategoryNames` | 品牌下公开商品对应末级类目名称集合 | 必需 |
| `sortOrder` | 品牌列表排序 | 建议 |
| `isPublic` | 是否可公开展示 | 必需 |

## 8. 风险与待确认

| 风险 / 待确认 | 说明 |
|---|---|
| 接口字段是否齐全 | 当前品牌列表接口可能尚未返回商品数量和末级类目集合；实现前需确认是否扩展 API。 |
| 商品统计口径 | 需确认仅统计公开已上架商品，还是包含其他状态商品；PRD 建议以小程序公开可见商品为准。 |
| 类目排序口径 | 需确认末级类目按后台排序、商品关联顺序、热度还是名称排序。 |
| 右侧内容溢出 | 类目较多时需要确定折行、省略或“等 N 类”的最终交互。 |
| 空态策略 | 品牌无商品、商品无类目、Logo 缺失时需要统一兜底文案和视觉。 |
