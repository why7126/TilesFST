# User Stories

## US-001 新增类目时允许特殊字符

作为后台管理员，我希望在新增瓷砖类目时可以输入包含特殊字符的类目名称，以便按真实业务语义维护分类。

验收要点：

- 输入 `岩板-大规格`、`仿古砖/客厅`、`600x1200(亮面)` 等合法名称时可以保存。
- 名称最多 15 个用户可见字符，超过 15 个字符时保存被阻止。
- 名称 trim 后为空时保存被阻止。
- 字段级错误显示在类目名称字段下方。

## US-002 编辑类目时保留特殊字符

作为运营人员，我希望编辑已有瓷砖类目时可以把名称调整为包含特殊字符的表达，以减少不自然缩写。

验收要点：

- 编辑弹窗与新增弹窗使用同一套名称校验口径。
- 合法特殊字符名称保存成功后，列表、类目树和选择器展示为保存后的名称。
- 保存失败时弹窗保持打开，后端字段级错误映射到名称字段。

## US-003 服务端统一兜底

作为系统维护人员，我希望后端对类目名称特殊字符规则做统一兜底，避免前后端校验不一致。

验收要点：

- 创建 / 更新 API 接受合法特殊字符名称。
- 创建 / 更新 API 拒绝空名称、超过 15 字符名称、换行、制表符和不可见控制字符。
- 响应结构继续遵守统一 response envelope。
- OpenAPI / Orval / API 文档 / 测试与最终规则一致。

## US-004 展示与查询兼容

作为前台消费方用户，我希望类目名称包含特殊字符时，分类页、筛选入口和商品列表仍能正常展示和查询。

验收要点：

- 管理端类目列表、类目树、SKU 类目选择器展示不重叠、不破版。
- 小程序或 Web 展示端如展示类目名称，特殊字符不导致布局异常。
- 搜索、筛选和选择流程对合法特殊字符名称保持可用。
