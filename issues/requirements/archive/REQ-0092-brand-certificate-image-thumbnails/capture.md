# 一句话

品牌图片和证书图片也需要支持类似商品图片的真实缩略图生成与使用，避免列表、卡片和预览场景继续加载原图资源。

# 原始描述

目前新上传的商品，确实原图与缩略图大小不一样了，缩略图比原图小了很多了。但是品牌以及证书的图片也需要实现类似商品的缩略图功能，将该 BUG 调整成 REQ。

# 背景

BUG-0100 已为 SKU 商品图片补齐真实同目录 `.thumb` 缩略图生成能力，用户复核后确认新上传商品图的缩略图已明显小于原图。品牌图片、证书图片当前仍需要类似的缩略图能力，以降低管理端、小程序和公开展示端在列表、卡片、证书展示等场景的图片加载成本。

# 影响范围

- 品牌图片上传、存储、列表展示、详情展示和小程序品牌相关页面。
- 证书图片上传、主图、列表缩略图、证书卡片、证书详情和预览入口。
- 后端 media 模块、对象存储 key 规则、图片读取回退策略和历史对象重生成策略。
- 管理端、微信小程序、店主 Web 展示端中消费品牌图或证书图的页面性能。

# 待澄清

- [ ] 品牌图片缩略图是否沿用商品同目录 `.thumb` 命名规则，或需要区分 Logo、品牌封面、Banner 等图片类型。
- [ ] 证书图片缩略图是否覆盖证书主图、多图列表和历史单文件图片 fallback。
- [ ] 品牌和证书缩略图目标最大宽高、质量、格式策略是否完全复用 SKU 图片规则。
- [ ] 存量品牌图、证书图是否需要提供 dry-run / apply 重生成脚本。
- [ ] 前端接口是否需要新增 thumbnail URL 字段，还是通过后端返回现有图片 URL 时切换为 `.thumb` 受控读取。

# 建议验收要点

- [ ] 新上传品牌图片生成真实缩略图，缩略图像素尺寸或文件体积明显低于原图，且不是原图 bytes 复制品。
- [ ] 新上传证书图片生成真实缩略图，并在证书列表、卡片和默认主图展示中可使用。
- [ ] 品牌和证书图片的小图、横图、竖图、PNG 透明图、WebP、异常图片输入均有明确处理策略。
- [ ] 缩略图生成失败时不影响原图上传成功，展示端可安全回退原图或占位。
- [ ] 存量品牌图与证书图具备可审计、可重入的缩略图补齐或重生成方案。
- [ ] 管理端、小程序和店主 Web 展示端不直连对象存储，继续走后端受控 `/media/{object_key}` 或等价受控读取链路。
