# REQ-0092 品牌图片与证书图片真实缩略图生成与使用

## 1. 需求背景

BUG-0100 已为 SKU 商品图片补齐真实同目录 `.thumb` 缩略图生成能力，用户复核后确认新上传商品图的缩略图已明显小于原图，不再是原图 bytes 复制品。品牌图片与证书图片当前仍缺少同等缩略图能力，列表、卡片、品牌详情、证书展示和预览入口仍可能直接加载原图资源。

品牌 Logo、品牌封面、证书图片通常出现在管理端列表、小程序页面和店主 Web 展示端的高频浏览场景。如果这些场景持续使用原图，会增加页面首屏加载、滚动列表渲染、移动端流量和对象存储读取成本，也会让 SKU 图片缩略图优化在整体体验上不完整。

本需求将商品图片已验证的真实缩略图能力扩展到品牌图片和证书图片，并明确生成、存储、读取、回退、历史对象处理与跨端使用边界。

## 2. 目标用户

| 角色 | 诉求 |
|---|---|
| 企业内部运营人员 | 在管理端维护品牌和证书时，列表与卡片图片加载更快，上传失败或缩略图缺失时有稳定回退。 |
| 店主 / 客户 / 公开访客 | 在小程序和店主 Web 查看品牌与证书时，页面加载更轻、更稳定。 |
| 管理员 / 运维人员 | 能确认品牌与证书图片是否生成真实缩略图，并具备可审计、可重入的存量补齐方案。 |
| 开发 / 测试 | 能复用 SKU 图片缩略图治理经验，对品牌图和证书图建立一致的生成、读取和回归验证口径。 |

## 3. 范围

### 3.1 本期包含

- 新上传品牌图片生成真实缩略图。
- 新上传证书图片生成真实缩略图。
- 品牌图片与证书图片缩略图遵循后端受控媒体读取链路，不由前端直连未授权对象存储。
- 品牌列表、品牌详情、证书列表、证书卡片、证书默认主图等适合小图展示的场景优先使用缩略图。
- 原图预览、下载、放大查看等需要高质量资源的场景继续使用原图。
- 缩略图生成失败时不阻断原图上传和业务保存，并提供可控回退。
- 存量品牌图片和证书图片提供 dry-run / apply 形式的缩略图补齐或重生成方案。
- 明确小图、横图、竖图、PNG 透明图、WebP 和异常图片输入的处理策略。

### 3.2 本期不包含

- 不改变 SKU 商品图片已完成的缩略图能力，除非后续实现需要复用公共逻辑。
- 不新增视频缩略图、PDF 首页渲染缩略图或 OCR 识别能力。
- 不改变品牌、证书的业务字段、权限模型、启停删除规则和审核流程。
- 不允许前端绕过后端鉴权直接读取对象存储。
- 不在 PRD 阶段直接实现 API、数据库、脚本、前端组件或 OpenSpec Change。
- 不要求立即物理清理历史原图或历史无效缩略图对象。

## 4. 功能要求

### FR-001 品牌图片缩略图生成

系统 MUST 在新上传品牌图片时生成真实缩略图。缩略图 SHOULD 复用 SKU 商品图片已验证的尺寸、质量、格式和同目录 `.thumb` 命名策略；若品牌 Logo、品牌封面、Banner 等类型确需差异化，应在后续 OpenSpec Change 中明确对象 key 与生成策略。

缩略图文件 MUST 与原图存在可追溯关系，且缩略图像素尺寸或文件体积应明显低于原图。系统 MUST 避免把原图 bytes 直接复制为缩略图。

### FR-002 证书图片缩略图生成

系统 MUST 在新上传证书图片时生成真实缩略图，覆盖证书主图、单图证书文件和多图列表中作为图片展示的证书资源。

对于非图片证书文件，系统 MAY 继续使用文件类型占位或既有 PDF 占位策略；PDF 首页渲染为图片缩略图不属于本需求范围。

### FR-003 缩略图读取与回退

系统 MUST 在品牌与证书的小图展示场景优先返回或使用缩略图资源。缩略图不存在、生成失败、读取失败或对象损坏时，系统 MUST 安全回退到原图或占位图，并记录可定位的失败信息。

前端不得拼接未授权对象存储地址。管理端、小程序和店主 Web 展示端 MUST 继续通过后端受控 `/media/{object_key}` 或等价受控读取链路访问图片。

### FR-004 跨端展示场景

系统 MUST 明确以下场景的图片资源选择：

| 场景 | 资源策略 |
|---|---|
| 管理端品牌列表 Logo | 优先缩略图，缺失时回退原图或首字母占位。 |
| 管理端品牌编辑 / 详情预览 | 小预览优先缩略图，放大预览使用原图。 |
| 管理端证书列表 / 卡片 | 图片证书优先缩略图，PDF 或异常文件显示文件类型占位。 |
| 管理端证书预览 | 点击预览使用原图或原文件。 |
| 小程序品牌与证书展示 | 列表、卡片、默认主图优先缩略图；大图预览使用原图。 |
| 店主 Web 品牌与证书展示 | 列表、卡片、默认主图优先缩略图；大图预览使用原图。 |

### FR-005 存量对象补齐

系统 SHOULD 提供可审计、可重入的存量品牌图片和证书图片缩略图补齐方案。补齐方案 MUST 支持 dry-run 统计受影响对象、预计生成数量、跳过原因和风险提示；apply 执行时 MUST 记录成功、失败、跳过和重试结果。

存量补齐不得依赖真实客户数据进入仓库，不得提交运行时对象或数据库文件。

### FR-006 异常与边界处理

系统 MUST 对以下输入给出明确处理策略：

- 小图原图：可跳过生成或生成轻量缩略图，但必须记录策略。
- 横图 / 竖图：保持比例，不应拉伸变形。
- PNG 透明图：透明背景处理不得产生明显黑底、白底误差，除非后续明确转码策略。
- WebP：应支持读取与生成；不支持时必须回退并报告。
- 损坏图片、超大图片、非允许 MIME：按上传校验或缩略图失败回退策略处理。

## 5. UI 约束

- 管理端品牌列表、证书列表和卡片展示 MUST 复用既有暗色旗舰风与 Design System 组件，不因缩略图能力新增大面积视觉改版。
- 缩略图加载失败不得显示浏览器破图，应展示品牌首字母占位、文件类型占位或既有空状态。
- 图片预览入口语义保持不变：小图用于快速浏览，大图或原文件用于详情查看。
- 小程序和店主 Web 展示端应优先减少列表图片加载成本，不新增额外操作负担。
- UI 变更如涉及新字段、新状态或新提示文案，后续实现 MUST 遵守 semantic token 与端侧组件边界。
