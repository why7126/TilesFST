# 用户故事

## US-001 产品负责人查看真实加载体验

作为产品负责人，我希望看到小程序和 Web 关键页面的真实用户加载耗时，以便判断哪些页面需要优先优化。

验收要点：

- [ ] 能按端类型、页面和时间范围查看样本量、平均耗时、P75、P95 和 P99。
- [ ] 能识别样本不足的页面，避免将低样本波动误判为真实体验问题。
- [ ] 能对比不同版本的关键页面加载指标。

## US-002 研发定位慢页面和慢接口

作为研发人员，我希望从慢页面排行下钻到页面关键指标和接口耗时，以便定位首屏慢是来自接口、资源还是端侧渲染。

验收要点：

- [ ] 慢页面排行能展示端类型、页面标识、版本、样本量和分位耗时。
- [ ] 关键接口耗时能与页面加载指标关联展示。
- [ ] 性能事件字段经过脱敏，不包含 Authorization、Cookie、签名 URL 或完整请求体。

## US-003 测试验证发布性能回归

作为测试人员，我希望在发布前后查看关键页面性能趋势，以便发现版本发布引入的加载性能回归。

验收要点：

- [ ] 能按版本筛选或对比页面性能指标。
- [ ] 能识别超过慢页面阈值的指标。
- [ ] 小程序真实环境或体验版验证结果可作为发布验收证据补充。

## US-004 系统管理员查看管理端性能概览

作为系统管理员，我希望在管理端查看性能摘要和慢页面列表，以便辅助处理用户反馈和内部系统卡顿问题。

验收要点：

- [ ] 管理端性能观测入口受权限控制。
- [ ] 页面具备空数据、加载失败、样本不足和权限不足状态。
- [ ] 普通公开端用户和小程序用户不会看到内部性能上报失败细节。

## US-005 端侧用户不被监控影响主流程

作为店主或管理端用户，我希望性能监控不会影响页面加载、搜索、列表、详情或管理操作，以便监控失败时主业务仍然稳定可用。

验收要点：

- [ ] RUM 上报失败、超时或被限流不阻断主业务。
- [ ] 端侧支持采样、批量上报或节流策略。
- [ ] 上报逻辑异常时有受控降级，不产生用户可见的内部错误。
