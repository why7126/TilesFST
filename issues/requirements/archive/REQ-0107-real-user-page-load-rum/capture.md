# 一句话

微信小程序和 Web 页面需要接入轻量自建 RUM，采集真实用户页面加载耗时并支持后续按端、页面、版本、网络和设备维度分析。

# 原始描述

采集微信小程序和 Web 页面真实用户加载耗时监控能力。

补充决策：做轻量自建 RUM。

# 背景与关联

- 涉及端与模块：微信小程序、Web 展示端、管理端性能观测、后端 telemetry 接口与数据聚合
- 业务价值：从真实用户视角发现慢页面、慢接口和版本性能波动，为页面体验优化、发布回归和线上问题定位提供量化依据
- 方案倾向：自建轻量 RUM，优先采集页面进入、首屏关键接口完成、首屏可用、完整加载、资源或接口耗时等核心指标
- 预期后续：明确采样与隐私策略，设计前端/小程序埋点、后端上报接口、数据存储与管理端性能看板范围

# 待澄清

- [ ] Web 端首期覆盖店主展示端、管理端，还是二者都覆盖
- [ ] 小程序首期覆盖首页、品牌列表、商品列表、商品详情等哪些关键页面
- [ ] 主指标采用“首屏可用耗时”，还是同时把“完整加载耗时”作为发布门禁指标
- [ ] 是否需要按版本、页面、网络类型、设备类型、登录态或公开/管理权限边界聚合
- [ ] 性能数据采样率、保留周期、脱敏规则和异常上报阈值如何设定
- [ ] 管理端是否首期提供性能看板，还是先只提供 API 与日志/数据查询能力

# 建议验收要点

- [ ] Web 页面可采集真实用户导航加载、首屏可用、接口耗时和关键资源耗时，并能区分页面路径、端类型和版本。
- [ ] 微信小程序页面可采集页面进入、首个关键接口完成、首屏渲染就绪和页面可交互耗时，并能区分页面、网络和版本。
- [ ] 后端提供受控的性能上报接口，校验请求体并避免采集手机号、openid、Authorization、Cookie、签名 URL 等敏感信息。
- [ ] 性能数据可按页面和端类型聚合 P50/P75/P95/P99，并支持定位慢页面和版本性能波动。
- [ ] 首期实现说明 API、数据库、Orval、Web、小程序、管理端和 Docker/环境变量是否受影响。
