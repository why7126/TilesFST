# 小程序有效价格统一红色展示

## 1. 背景与目标

小程序面向店主、选购客户及协助选型人员提供瓷砖资料浏览。用户希望在浏览和比较商品时更快识别价格，并将金额与品牌、按钮等金色元素区分。

当前共享商品卡片、商品详情主价格与推荐价格、收藏价格沿用金色。需求目标是统一有效金额的红色展示和无价状态的中性色展示，保持价格内容、业务含义与页面结构稳定。本需求属于跨页面视觉增强，建议优先级 P2，最终由评审确定。

事实依据：`src/miniapp/components/product-card/index.wxml`、`src/miniapp/pages/tile-detail/index.wxml`、`src/miniapp/pages/favorites/index.wxml` 及其 WXSS。代码静态检查不代表体验版或真机已验证。

## 2. 目标用户

- 店主：向客户展示商品并比较参考价格。
- 选购客户及协助选型人员：浏览商品列表、详情或收藏，快速识别金额与无价状态。

## 3. 范围

### 3.1 包含范围

| 展示区域 | 覆盖要求 |
|---|---|
| 首页新品、热门、全部产品 | 共享商品卡片各密度的价格展示 |
| 商品列表、品牌详情商品列表 | 列表及双列卡片中的价格 |
| 搜索最佳匹配及 SKU 结果 | 实际展示 SKU 的共享商品卡片 |
| 商品详情 | 主价格、同系列推荐与同品牌推荐价格 |
| 收藏列表 | 有效商品价格、无价和失效商品文案的视觉区分 |
| 价格语义与规范 | 独立价格 token、小程序样式引用及现有价格用色规范的适用范围说明 |

### 3.2 不包含范围

- Web 店主端、管理端用色或全产品主题重设计。
- 价格计算、币种转换、折扣、促销、库存或后端价格格式化规则调整。
- 分享能力、个人收藏清单发布、收藏交互或数据存储改造。
- 新增 API、DB 字段、管理端配置、行为事件、请求封装或 Task Trace。
- 商品卡片图片比例、布局、字体体系、导航与页面信息架构调整。

## 4. 功能要求

### FR-001 有效金额统一红色

- 纳入范围的有效价格应使用同一价格语义红色，货币符号与金额保持一致。
- 金额继续消费既有 `price_display`，不改写精度、分隔符或业务计算规则。
- 有效金额指符合现有价格展示契约、能够识别为正数金额且商品可公开查看的价格；不得仅按非空字符串判断。

### FR-002 非金额状态使用中性色

- 空值、未维护、零价、非正或无法识别为有效金额的输入不得使用价格红色；展示文案沿用既有无价处理，不扩展价格业务规则。
- “暂无”、既有兼容无价文案、“暂不可查看”及失效状态采用中性色，不模拟有效报价。
- “参考价格”、单位说明及“实际价格以门店最终确认为准”等辅助信息使用辅助文字色。
- 商品不可查看状态优先于缓存金额，失效收藏项不得因为保留历史金额而呈现有效报价。

### FR-003 跨入口与状态一致

- 共享商品卡片的默认、compact、grid 等实际使用密度均遵循同一规则。
- 独立实现的详情主价格、推荐价格和收藏价格应采用同一展示状态口径。
- 异步加载、切换商品、收藏刷新或无价数据变化后，颜色应随当前数据更新，不残留上一条有效价格样式。

### FR-004 价格语义独立

- 在现有设计系统中定义独立价格语义 token，并为小程序建立统一引用方式；不得在页面重复散落红色色值。
- 不通过替换品牌金 token 或借用错误色 token 实现价格用色。
- 品牌、按钮、激活态、热销标识和错误提示维持各自语义；共享 token 改动不得改变 Web、管理端现有视觉。
- 实施阶段同步 `rules/ui-design.md` 中价格用色的端侧适用说明，沿用项目 token 同步与预览要求。

### FR-005 视觉层次与可读性

- 最终采用 `#F87171`；代表页面 DevTools 取证及实际背景对比度见归档 Change 的 implementation/evidence.md，不代表真机验收。
- 有效金额与其实际渲染背景的对比度目标不低于 4.5:1，需覆盖页面、卡片和不同密度背景及实际透明度。
- 保持原字号、布局和卡片尺寸，长金额、小字号推荐区及常见手机宽度不应新增截断、遮挡或横向溢出。
- 保留参考价格说明；不新增折扣、特价或促销暗示文案。

## 5. UI 与技术约束

当前三种背景上的静态对比度计算如下；数值只证明不透明候选色与指定底色的计算关系，不替代渲染或真机证据。

| 候选色 | 页面背景 `#18160F` | 卡片背景 `#211E16` | 紧凑卡片背景 `#252116` |
|---|---|---|---|
| `#F87171` | 6.54:1 | 6.02:1 | 5.81:1 |
| `#EF4444` | 4.81:1 | 4.42:1 | 4.27:1 |

本需求不要求完整页面重设计。后续以商品卡片、详情页、收藏页为代表进行视觉验证；若采用 `prototype/`，须遵循项目 UI Contract 和视觉证据要求。局部原型见 `prototype/miniapp/price-states.html`，边界见同目录 `context.md`。

实现应优先复用现有组件和统一展示状态逻辑。若涉及小程序逻辑，保持 `.ts` 与实际加载的 `.js` 同步。不得以全局查找替换颜色代替对实际价格节点和状态的识别。

## 6. 验证要求

- 用例覆盖有效金额、空值、零价、非正值、旧无价文案、失效收藏及金额状态切换，证明仅有效金额使用价格红色。
- 覆盖共享组件全部实际密度和独立详情／推荐／收藏入口，检查辅助文案、金额及货币符号的样式。
- 记录代表页面实际样式和背景，校验对比度；在常见手机宽度检查长金额及小字号价格。
- 若修改展示逻辑，补充聚焦状态分支测试，运行 `tests/test_miniapp_static.py` 对应检查；不新增价格计算测试或后端业务测试。
- 视觉证据区分静态计算、微信 DevTools、体验版及真机来源，未执行环境不得标为通过。

## 8. 风险与后续设计事项

- 价格容器同时承载金额和占位文案，直接换色会造成无价状态误强调。
- 收藏或异步列表可能保留历史金额，状态判断需避免失效内容呈现有效报价。
- 共享 token 容易扩大影响，验收需确认 Web、管理端及非价格品牌元素未被改变。
- 最终红色色值由视觉验收确定；在满足有效金额红色和对比度目标的前提下可微调，不阻塞 PRD 生成。
