# REQ-0129 小程序商品详情页底部收藏按钮与操作栏紧凑化

## 1. 需求背景

微信小程序商品详情页底部固定操作栏承载 SKU 收藏和“分享给客户”两个高频动作。其中分享是门店销售、设计师和客户沟通时的主操作，收藏是辅助用户后续找回商品的次级动作。

当前详情页收藏按钮采用心形图标加“收藏 / 已收藏”文字的纵向结构，固定操作栏高度随之偏高。该文字主要用于解释图标语义，但收藏状态已经可以通过空心 / 实心心形、激活颜色、成功 / 失败 toast 和收藏列表结果表达。为减少底部固定区域占高、降低视觉噪音，需要将收藏按钮收敛为更紧凑的图标状态，并同步调整返回首页悬浮按钮在 actionbar 场景下的位置。

## 2. 目标用户

| 用户 | 诉求 |
|---|---|
| 装修客户 | 在详情页查看更多商品图片、参数和推荐内容时，减少底部固定栏对内容区域的占用。 |
| 室内设计师 | 快速收藏备选 SKU，同时保持商品图片和分享按钮的视觉焦点清晰。 |
| 门店销售 | 向客户展示商品时，底部“分享给客户”入口保持突出，辅助收藏动作不抢主操作层级。 |

## 3. 范围

### 3.1 本期包含

| 范围 | 说明 |
|---|---|
| 收藏按钮视觉精简 | 商品详情页底部收藏按钮去掉下方“收藏 / 已收藏”文字，仅保留心形图标状态。 |
| 收藏状态表达 | 未收藏、已收藏、请求中、保存失败等状态仍需有清晰反馈。 |
| 底部操作栏高度压缩 | 在满足触控热区和安全区适配前提下，压缩底部固定操作栏整体高度。 |
| 分享按钮优先级保持 | “分享给客户”主按钮仍保持清晰、稳定、易点击。 |
| 首页悬浮按钮 offset 调整 | 商品详情页 actionbar 场景下的返回首页悬浮按钮位置需随底部栏高度同步调整。 |
| 小程序视觉验收 | 覆盖常见手机视口，确认底部栏、收藏按钮、分享按钮和首页悬浮按钮无重叠、无裁切。 |

### 3.2 本期不包含

| 不包含 | 说明 |
|---|---|
| 收藏接口改造 | 不新增、不删除、不调整 SKU 收藏 API 契约。 |
| 收藏数据模型改造 | 不调整收藏粒度、存储表、客户端本地收藏结构或同步策略。 |
| 收藏列表页面改造 | 不改收藏列表的信息架构、卡片布局或删除收藏按钮样式。 |
| 分享能力改造 | 不改变微信分享标题、路径、分享图或分享埋点规则。 |
| 商品详情信息架构重排 | 不调整媒体区、商品参数、品牌卡、推荐区等页面主体结构。 |
| 新增后台配置 | 不新增管理端开关、运营配置或主题配置项。 |
| 新增行为埋点 | 不新增、重命名或删除收藏、分享、返回首页相关行为事件。 |

## 4. 功能要求

### FR-001 收藏按钮去除下方文字

- 商品详情页底部收藏按钮 MUST 不再显示“收藏 / 已收藏”下方文字。
- 收藏按钮 SHOULD 仅通过心形图标表达操作入口，通过空心 / 实心或等价视觉状态表达当前收藏状态。
- 已收藏状态 SHOULD 使用现有激活颜色或同等强度的品牌强调色，未收藏状态保持次级操作视觉层级。
- 去掉文字后，收藏按钮仍 MUST 保留足够可点击热区，避免仅图标区域可点。

### FR-002 收藏交互与反馈保持不变

- 用户点击收藏按钮后，MUST 继续调用既有 SKU 收藏 / 取消收藏逻辑。
- 收藏请求中 SHOULD 保持防重复点击能力，避免连续点击导致状态抖动。
- 收藏成功、取消收藏成功和保存失败仍 MUST 有 toast 或等价反馈。
- 收藏失败时，MUST 保持状态回滚能力，避免页面显示状态与实际保存状态不一致。

### FR-003 底部操作栏高度压缩

- 底部固定操作栏 MUST 在满足安全区和触控热区的前提下压缩整体高度。
- 操作栏高度调整后，页面底部内容留白 SHOULD 同步匹配，避免出现过大空白或内容被固定栏遮挡。
- 在 320 到 430 pt 常见微信小程序手机宽度下，底部操作栏 MUST 不导致横向滚动、按钮挤压或视觉重叠。
- 操作栏背景、边线和按钮间距 SHOULD 延续当前小程序深色视觉风格。

### FR-004 分享主按钮保持核心操作优先级

- “分享给客户”按钮 MUST 保持底部操作栏中的主视觉权重。
- 收藏按钮精简后，不得削弱分享按钮的可识别性、可点击范围或微信 `open-type="share"` 能力。
- 分享按钮文案 SHOULD 保持当前语义，除非后续评审确认需要统一更短文案。

### FR-005 返回首页悬浮按钮 offset 同步调整

- 商品详情页存在底部操作栏时，返回首页悬浮按钮 MUST 避开操作栏和底部安全区。
- 底部操作栏压缩后，`actionbar` 场景 offset SHOULD 同步下调或重算，避免悬浮按钮离底栏过远。
- 首页悬浮按钮 MUST 不遮挡商品详情页推荐卡片、分享按钮、收藏按钮和系统安全区。
- 本需求不改变返回首页悬浮按钮的跳转语义和其他页面 offset 策略。

### FR-006 可访问性与语义兜底

- 去掉可见文字后，收藏按钮 SHOULD 保留可被语义识别的按钮说明，例如 `aria-label`、同等小程序属性或实现层可用的辅助说明。
- 无障碍语义 SHOULD 能区分未收藏和已收藏状态，避免仅依赖颜色。
- 若小程序平台对按钮语义支持有限，实现阶段 SHOULD 至少通过稳定图标状态和 toast 文案保证用户理解。

## 5. UI / UE 约束

- 收藏按钮是次级动作，视觉权重低于“分享给客户”主按钮。
- 收藏图标尺寸需清晰可辨，但不得因过大导致底部栏高度回升。
- 底部操作栏应保持紧凑、稳定，不随收藏状态文字或 loading 状态发生高度跳变。
- 安全区适配必须覆盖带底部手势条的设备。
- 不得新增裸露解释性文案来替代被移除的“收藏 / 已收藏”文字。
- 若保留无障碍说明，该说明不得成为可见的第二行文字。

## 7. 风险与待确认

| 风险 / 待确认 | 说明 |
|---|---|
| 触控热区压缩过度 | 若只追求视觉高度，可能降低收藏按钮和分享按钮点击舒适度；实现需保留有效点击区域。 |
| 状态识别依赖图标 | 去掉文字后，需确认空心 / 实心心形和颜色对目标用户足够明确。 |
| loading 态视觉 | 小程序 button 的 loading 表现可能影响图标居中和操作栏高度，需要实现阶段验证。 |
| 首页悬浮按钮联动 | actionbar offset 需要和新底部栏高度一致，否则可能出现悬浮按钮过高或贴底问题。 |
| 无障碍语义 | 可见文字移除后，需确认实现方式是否能保留按钮语义说明。 |
