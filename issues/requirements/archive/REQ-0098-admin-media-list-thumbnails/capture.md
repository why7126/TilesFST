# 一句话

管理端图片密集列表应优先展示缩略图，降低 SKU、品牌、证书与 Banner 列表的图片加载耗时，同时保留详情、编辑和预览场景使用原图。

# 原始描述

管理端图片密集列表使用缩略图展示

- SKU 列表响应增加 `main_image_thumbnail_url`
- Banner 列表响应增加 `image_thumbnail_url`
- 前端列表页优先使用 thumbnail 字段，失败或缺失时 fallback 到原图
- 保持详情/编辑/预览仍可使用原图
- 同步 OpenAPI / Orval / 测试

# 背景与关联

- 背景：管理后台 SKU 列表页、品牌列表页、证书列表页、Banner 列表页包含图片卡片或图片单元格，当前部分列表仍直接加载原图，列表首屏和翻页体感较慢。
- 现状线索：品牌与证书列表已有缩略图优先策略；SKU 与 Banner 列表仍需补齐列表响应字段和前端优先级。
- 涉及端：Web 管理端。
- 涉及能力：媒体缩略图、SKU 管理、Banner 管理、品牌与证书列表展示一致性。
- 业务价值：提升管理后台图片密集列表加载速度，减少无必要原图带宽消耗，保持列表浏览与详情编辑的清晰度边界。

# 待澄清

- [ ] SKU 与 Banner 缩略图字段是否仅用于列表响应，详情响应是否保持原字段不变
- [ ] 缩略图不存在或生成失败时，前端是否统一 fallback 到原图并记录可观测日志
- [ ] 品牌与证书列表是否只需验收现有缩略图优先策略，还是需要统一字段命名与测试覆盖
- [ ] 是否需要为历史媒体补齐缩略图维护任务，还是沿用访问时/上传时已有生成机制
- [ ] 验收是否需要覆盖低网速或大图样例下的列表加载体验
