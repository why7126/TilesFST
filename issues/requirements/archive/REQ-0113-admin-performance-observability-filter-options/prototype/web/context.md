# Web 管理端原型策略

## 1. 页面范围

本需求属于现有管理端性能观测页增强，不新建独立视觉页面。后续实现应在现有 `/admin/performance` 与 `/admin/performance/samples` 上调整筛选控件、字段顺序和样本上下文。

## 2. UI Contract

### 性能观测页筛选区

筛选区控件顺序固定为：

```text
时间范围 > 端类型 > 版本号 > 页面 > 网络 > 指标
```

控件策略：

- 时间范围：前端固定选项。
- 端类型：后端固定候选值。
- 版本号、页面、网络：后端基于时间范围返回并在筛选区展示；设备候选值由接口返回但不作为本期筛选控件展示。
- 指标：后端固定候选值。
- 每个维度都提供“全部”选项。

### 聚合列表

字段顺序固定为：

```text
页面 > 版本号 > 端类型 > 设备 > 网络 > 指标 > 样本 > P50 > P75 > P95 > P99 > 状态 > 操作
```

### 样本页上下文

字段顺序固定为：

```text
页面 > 版本号 > 端类型 > 设备 > 网络 > 指标
```

### 样本列表

字段顺序固定为：

```text
页面 > 版本号 > 端类型 > 设备 > 网络 > 指标 > 耗时 > 事件时间 > 接收时间 > request_id
```

## 3. 视觉与交互约束

- 延续管理端“工业石材 · 暗色旗舰风”。
- 筛选控件优先复用 `AdminFilterSelect`、`SearchableSelect` 或等价 shared wrapper。
- 表格、分页、操作列与用户管理基准保持一致。
- 长文本字段必须受控截断，不撑破表格。
- 不新增解释性卡片、营销式 hero 或与管理端工具页无关的视觉装饰。

## 4. 视觉验收建议

后续 `/opsx-apply` 时建议补充：

- 1440x1024 性能观测页截图，验证筛选顺序、表格字段顺序和分页 DOM。
- 窄屏或横向滚动截图，验证 sticky 操作列可达且不遮挡筛选弹层。
- 样本页截图，验证上下文顺序、样本字段顺序和 request_id 截断/复制入口。
- 候选值空态或加载失败状态截图。

## 5. Mock/API 边界

- 原型阶段不引入 mock 数据文件。
- 实现阶段以 `GET /api/v1/admin/performance-events/filter-options` 作为候选值事实源。
- 若候选值接口失败，前端必须区分“候选值加载失败”和“性能样本为空”。
