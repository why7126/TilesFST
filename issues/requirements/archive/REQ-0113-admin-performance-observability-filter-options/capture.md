# 一句话

管理端性能观测需要提供筛选维度候选值接口，并统一筛选区、聚合列表和样本页字段展示顺序，减少前端纯文本输入和字段顺序不一致。

# 原始描述

标题：管理端性能观测提供筛选维度候选值接口

背景：性能观测页需要将页面、版本号、端类型、网络、设备、指标作为筛选项，其中版本号、页面、设备、网络需要后端提供可选值，避免前端纯文本输入。

影响范围：后端管理端性能观测 API、OpenAPI/Orval、Web 管理端性能观测页、相关测试与文档。

建议验收要点：新增候选值接口返回 6 大维度可选项；管理端筛选区顺序为“时间范围 > 端类型 > 版本号 > 页面 > 设备 > 网络 > 指标”；聚合列表和样本页字段顺序按用户指定展示。

# 背景与关联

- 父级需求：`REQ-0107-real-user-page-load-rum`
- 涉及端与模块：后端管理端性能观测 API、OpenAPI/Orval、Web 管理端性能观测页、测试与文档
- 业务价值：通过后端候选值约束筛选输入，提升性能观测数据筛选的准确性、可发现性和前后端展示一致性
- 预期后续：在 PRD 阶段明确候选值来源、空数据策略、权限边界、缓存策略、字段顺序和 Orval 生成要求

# 待澄清

- [ ] “6 大维度可选项”中端类型和指标是否由后端接口一并返回固定枚举，还是继续由前端静态维护
- [ ] 版本号、页面、设备、网络候选值的时间范围口径是否跟随当前筛选时间范围
- [ ] 候选值排序规则是否需要固定，例如最近活跃优先、字母序、指标预定义顺序或数据量倒序
- [ ] 聚合列表和样本页“按用户指定展示”的完整字段顺序清单
- [ ] 候选值接口空数据、权限不足和参数非法时的错误码与前端降级展示

# 建议验收要点

- [ ] 新增管理端性能观测候选值接口，返回页面、版本号、端类型、网络、设备、指标 6 大筛选维度的可选项。
- [ ] 版本号、页面、设备、网络候选值由后端基于性能观测数据提供，避免前端纯文本输入。
- [ ] 管理端性能观测筛选区顺序固定为：时间范围 > 端类型 > 版本号 > 页面 > 设备 > 网络 > 指标。
- [ ] 聚合列表字段顺序与样本页字段顺序按用户指定清单展示，并补充对应前端测试或视觉验证证据。
- [ ] API 变更同步 OpenAPI、Orval 客户端、接口文档和后端/前端相关测试。
