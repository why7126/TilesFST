# 用户故事

## US-001 系统管理员选择性能观测筛选项

作为系统管理员，我希望性能观测页的端类型、版本号、页面、网络和指标都能通过下拉候选项选择，以便快速筛选真实存在的数据维度，避免手工输入 key。

验收要点：

- 筛选区顺序为时间范围 > 端类型 > 版本号 > 页面 > 网络 > 指标。
- 时间范围变化后，候选值接口按新的时间范围重新请求。
- 版本号、页面、设备、网络候选值来自后端性能事件数据。
- 端类型和指标候选值来自后端受控枚举及 label。
- 每个筛选维度保留“全部”选项。

## US-002 研发按版本与页面定位慢页面

作为研发人员，我希望在性能观测页按版本号和页面选择候选值后查看聚合列表，以便判断某个版本或页面是否出现性能回退。

验收要点：

- 聚合查询参数正确携带所选端类型、版本号、页面、网络、指标和时间范围。
- 任一筛选项变化后，聚合列表分页回到第一页。
- 候选值仅按时间范围返回，不随其他筛选项级联收敛。
- 候选值为空时不阻断聚合列表查询。

## US-003 测试验证聚合列表字段顺序

作为测试人员，我希望聚合列表字段顺序稳定，以便按同一口径验证页面、版本、端、设备、网络、指标和分位耗时。

验收要点：

- 聚合列表字段顺序为页面 > 版本号 > 端类型 > 设备 > 网络 > 指标 > 样本 > P50 > P75 > P95 > P99 > 状态 > 操作。
- 空版本号、空设备和空网络分别展示版本未知、设备未知、网络未知。
- 页面等长文本不会撑破表格或遮挡操作列。
- 操作列的查看样本入口在横向滚动与窄屏下仍可达。

## US-004 研发查看样本页上下文与样本列表

作为研发人员，我希望从聚合列表进入样本页后，样本上下文和样本表字段顺序与聚合维度一致，以便直接核对样本细节。

验收要点：

- 样本上下文顺序为页面 > 版本号 > 端类型 > 设备 > 网络 > 指标。
- 样本列表字段顺序为页面 > 版本号 > 端类型 > 设备 > 网络 > 指标 > 耗时 > 事件时间 > 接收时间 > request_id。
- 样本页不展示完整 URL、Header、Cookie、签名 URL、Authorization 或原始 payload。
- `request_id` 保持受控截断和复制交互。

## US-005 后端维护候选值 API 口径

作为后端开发人员，我希望候选值接口的 Schema、排序、权限和空数据行为明确，以便稳定同步 OpenAPI、Orval 和测试。

验收要点：

- 候选值接口仅系统管理员可访问。
- 接口支持 `start_time`、`end_time`。
- 动态候选值按最近出现优先、样本数倒序、value 升序稳定排序。
- API 文档、OpenAPI、Orval、后端测试和前端测试同步更新。
