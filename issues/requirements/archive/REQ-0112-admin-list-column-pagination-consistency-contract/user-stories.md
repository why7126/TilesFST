# User Stories

## US-001 运营扫描管理端列表

作为后台运营，我希望 Banner、日志审计、用户管理等列表页的表头和普通字段默认单行展示，以便在横向扫描时不被随机换行、行高抖动或列宽变化打断。

验收要点：
- 表头不换行。
- 普通文本字段默认单行截断。
- 长文本不撑宽整表，不挤压操作列。

## US-002 运营识别有效期

作为后台运营，我希望有效期、投放周期等复合时间字段可以清晰展示起止时间，以便判断记录是否在有效期内，同时不破坏列表行高和分页布局。

验收要点：
- 有效期列允许双行展示。
- 普通更新时间、创建时间等单时间字段保持单行。
- 有效期例外不得泛化到名称、备注、链接等长文本字段。

## US-003 管理员执行行内操作

作为后台管理员，我希望列表操作列在横向滚动和窄屏下仍可见、可点击且不遮挡其他内容，以便稳定执行编辑、冻结、上线、删除等操作。

验收要点：
- 操作列在横向滚动时保持可达。
- sticky 操作列不遮挡筛选弹层、确认弹窗、toast 或分页。
- 危险操作使用 Design System confirm modal，不使用 `window.confirm`。

## US-004 QA 验证分页一致性

作为 QA，我希望管理端列表分页 DOM、总数、页码和每页条数有统一契约，以便通过固定测试阻止分页样式和行为回退。

验收要点：
- 分页 DOM 包含 `page-summary` 和 `page-right`。
- 总数来自后端真实总数。
- 搜索、筛选、排序后页码恢复策略明确。

## US-005 前端开发复用列表契约

作为前端开发，我希望后续管理端列表改造能引用共享契约、模板或 class，而不是在页面内重复写临时样式，以便降低返修和跨页面漂移。

验收要点：
- OpenSpec design 引用 knowledge-base 和本 REQ。
- 共享 class、模板 prop 或组件策略在实现阶段明确。
- 前端测试覆盖代表页面。
