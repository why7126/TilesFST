# 用户故事

## US-001 产品负责人确认跨端图片规格口径

作为产品负责人，我希望有一份统一矩阵说明 Web 与小程序每个页面位置应使用 `thumbnail`、`display` 还是 `original`，以便需求评审时不用在代码、spec 和历史验收中反复查证。

验收要点：

- 矩阵字段包含页面、位置、图对象、是否缩略图、是否 display 图、是否原图、优化方案。
- 店主 Web 展示端当前被标注为预留规范，不被误认为已完成真实页面验收。
- 每个位置只表达一个主消费规格；普通展示和点击预览必须拆行。

## US-002 测试人员按矩阵验收媒体展示

作为测试人员，我希望矩阵明确每个场景的目标规格和不允许的 fallback，以便验证列表、详情、预览和下载时能准确判断是否通过。

验收要点：

- 列表、卡片、推荐位、小 Logo 等场景目标规格为 `thumbnail`。
- 详情普通展示、图册浏览、表单大预览等场景目标规格为 `display`。
- 高清预览、下载、保真查看等场景目标规格为 `original`。
- 非原图目标场景不得 fallback 到原图；缺规格时必须标记优化或使用安全占位。

## US-003 Web 管理端开发定位现状偏离

作为 Web 管理端开发，我希望矩阵记录当前 SKU、Banner、品牌、证书、头像等媒体位置的目标规格和优化方案，以便后续 Change 能按范围逐项修正。

验收要点：

- SKU 列表、Banner 列表、品牌列表、证书列表等图片密集区域均有矩阵行。
- 表单弹窗中的普通预览与原图查看边界被拆分表达。
- 已知原图 fallback 或只有单一 `url` 字段的位置被标记为优化项，而不是默认通过。

## US-004 小程序开发保持列表性能与详情清晰度

作为小程序开发，我希望首页、商品列表、商品详情、品牌、证书和收藏等页面有统一取图规则，以便同时保护列表性能、详情清晰度和高清预览体验。

验收要点：

- 首页、商品列表、搜索结果、推荐商品和收藏商品使用 `thumbnail`。
- 商品详情 Banner 普通展示使用 `display`。
- 商品详情图片预览使用 `original`。
- 品牌 Logo、证书普通展示和证书预览的目标规格与优化项写清楚。

## US-005 后端和媒体服务开发维护字段契约

作为后端和媒体服务开发，我希望矩阵能反向说明 API 字段语义和缺失规格的处理要求，以便后续新增字段或修正 fallback 时不会破坏客户端消费规则。

验收要点：

- 矩阵能关联 `thumbnail_url`、`display_url`、`original_url` 或等价字段语义。
- 缺少目标规格时不能静默返回原图作为通过结果。
- 后续若需要 API 字段变更，必须在对应 Change 中同步 OpenAPI、Orval、文档和测试。
