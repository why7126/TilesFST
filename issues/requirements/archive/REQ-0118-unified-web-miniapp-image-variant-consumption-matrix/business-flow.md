# 业务流程

## 1. 三规格消费决策流程

```text
页面位置需要展示图片
        |
        v
判断用户意图
        |
        +--> 快速识别 / 多图扫描 / 小尺寸 Logo
        |       |
        |       v
        |   使用 thumbnail
        |
        +--> 普通查看 / 详情展示 / 图册浏览 / 表单大预览
        |       |
        |       v
        |   使用 display
        |
        +--> 放大预览 / 下载 / 审核保真 / 原文件查看
                |
                v
            使用 original
```

## 2. 目标规格缺失处理流程

```text
客户端按矩阵选择目标规格
        |
        v
目标规格 URL 是否存在且可读？
        |
   +----+----+
   |         |
  是        否
   |         |
   v         v
展示目标图   不 fallback 到 original
             |
             +--> 使用安全占位
             +--> 标记需补齐派生图或字段
             +--> 必要时阻断发布/验收
```

## 3. 跨端矩阵沉淀流程

```text
REQ-0115 三规格能力
        |
        v
整理当前端侧消费点
        |
        +--> 微信小程序真实页面
        +--> Web 管理端真实页面
        +--> 店主 Web 预留规范
        |
        v
形成消费矩阵
        |
        +--> 页面 / 位置 / 图对象
        +--> thumbnail / display / original
        +--> 优化方案
        |
        v
后续 Change 引用矩阵
        |
        +--> 规范落点
        +--> 实现偏离修正
        +--> 媒体验收模板
```

## 4. 与父需求差异

| 对象 | 关系 | 差异 |
|---|---|---|
| `REQ-0115-media-multi-variant-images` | 父需求 | 定义三规格生成、API 字段和对象存储能力。 |
| `REQ-0118-unified-web-miniapp-image-variant-consumption-matrix` | 本需求 | 定义 Web 与小程序在页面、位置、图对象上的消费矩阵和禁止 fallback 到原图的治理口径。 |

## 5. 与后续实现分流

| 分流类型 | 处理方式 |
|---|---|
| 只需规范沉淀 | 在 OpenSpec Change 中更新媒体规范、对象存储规范、验收模板或 README。 |
| 发现实现偏离但不需要 API 字段 | 后续可用单独 Change 修正客户端取图优先级和占位策略。 |
| 发现实现偏离且需要 API 字段 | 后续 Change 必须同步后端 Schema、OpenAPI、Orval、文档和测试。 |
| 历史图片缺失派生图 | 不纳入本需求，必要时另行走维护任务或新 REQ。 |

## 6. 异常与边界

| 场景 | 处理 |
|---|---|
| 非原图目标场景只有原图字段 | 矩阵优化方案标记“补齐目标规格字段或改用安全占位”，不得视为符合规范。 |
| 当前页面没有业务图片 | 矩阵可标注“不涉及业务图片”。 |
| 店主 Web 未接入真实业务页面 | 仅写“预留规范”，不得写“已满足”。 |
| PDF 或视频不具备完整三规格 | 按图对象注明“证书文件查看使用 original”“视频封面使用 thumbnail”，缺派生能力进入优化方案。 |
