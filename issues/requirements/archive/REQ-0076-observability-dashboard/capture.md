# 一句话

日志审计页需要升级为链路观测仪表，输出请求、行为、审计与 Task Trace 的关键指标和追踪视图。

# 原始描述

采纳优化建议：仪表页升级为“日志审计 + 链路观测”，增加任务成功率、慢任务、最慢 span、失败原因分布、客户端分布、接口错误率、`request_id`/`task_trace_id` 一键追踪。

# 背景与关联

- 当前日志审计页已有列表、详情、Task Trace 时间线和基础指标。
- 当前指标包括今日总量、API 错误、慢请求、审计操作。
- 排查链路问题时仍缺少按任务类型、span、客户端、接口路径聚合的仪表化输出。

# 影响范围

- 后端：日志聚合查询、Task Trace 聚合指标接口。
- Web 管理端：日志审计页或独立观测页的信息架构、筛选、图表和详情跳转。
- API：可能新增指标接口或扩展日志列表 summary。
- 测试：聚合指标、筛选、空态和权限测试。

# 初步需求要点

- 提供任务成功率、任务耗时分布、慢任务排行和最慢 span 排行。
- 提供接口错误率、慢请求排行、失败原因分布和客户端分布。
- 支持通过 request_id、task_trace_id 一键追踪到详情。
- 仪表应遵守管理端 Design System，避免只做静态卡片，需支持排障工作流。

# 待澄清

- [ ] 仪表是扩展现有日志审计页还是新增独立链路观测页。
- [ ] 指标时间范围默认值和可选范围。
- [ ] 是否需要图表库，或先用表格/指标卡完成 MVP。
- [ ] P95/P99 等分位指标是否需要数据库层支持。

# 建议验收要点

- [ ] 管理员能查看请求、行为、审计、Task Trace 的统一观测摘要。
- [ ] 能按时间范围、客户端、日志类型、任务类型筛选指标。
- [ ] 慢任务、失败任务、最慢 span 可跳转到具体日志详情。
- [ ] 空数据、加载失败和权限不足有清晰反馈。
- [ ] 仪表数据与日志列表筛选口径一致。
