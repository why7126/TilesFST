# 用户故事

## US-001 管理员查看统一观测摘要

作为系统管理员，我希望在日志审计入口看到请求、行为、审计和 Task Trace 的统一摘要，以便快速判断平台当前是否存在错误率升高、慢请求或任务失败。

验收要点：

- 默认进入页面时展示统一摘要指标。
- 摘要指标与当前筛选条件一致。
- 空数据时显示零值和空态，不显示异常占位。

## US-002 运维人员定位慢任务和最慢 span

作为研发 / 运维人员，我希望查看慢任务排行和最慢 span 排行，以便定位上传、日志写入、对象存储或后端任务中的耗时瓶颈。

验收要点：

- 慢任务排行展示任务类型、状态、耗时、触发来源和 `task_trace_id`。
- 最慢 span 排行展示 span 名称、任务类型、耗时、结果和关联 `task_trace_id`。
- 点击排行项可进入对应 Task Trace 时间线或日志详情。

## US-003 运维人员追踪接口错误

作为研发 / 运维人员，我希望按接口路径、状态码和错误原因查看错误分布，以便快速判断是单个接口异常、客户端异常还是系统性失败。

验收要点：

- 支持展示接口错误率、失败原因分布和慢请求排行。
- 慢请求和错误请求必须包含可追踪的 `request_id`。
- 点击 `request_id` 或错误项可打开对应日志详情。

## US-004 管理员按追踪 ID 一键定位链路

作为系统管理员，我希望输入 `request_id` 或 `task_trace_id` 后直接定位相关日志和任务链路，以便减少跨列表搜索和人工复制排查。

验收要点：

- 支持 `request_id` 与 `task_trace_id` 精确查询。
- 命中单条时可直接打开详情；命中多条时展示相关记录集合。
- 未命中时展示清晰空态，不误报系统错误。

## US-005 产品负责人观察客户端与行为分布

作为产品负责人，我希望看到不同客户端和行为事件的分布，以便识别管理端、店主端、小程序或后端任务中的异常趋势。

验收要点：

- 客户端分布覆盖 `web_admin`、`web_catalog`、`miniapp`、`backend` 和未识别客户端。
- 行为分布优先展示事件类型、模块、结果和失败原因。
- 行为事件与请求日志有关联时，可沿 `request_id` 查看同链路记录。
