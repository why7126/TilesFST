# 用户故事

## US-001 后台运营识别列表对象

作为后台运营，我希望品牌、证书、SKU、Banner 等列表中的图片、名称和缺失信息展示口径一致，以便我能快速判断对象是否正确、完整、可继续操作。

验收要点：

- 列表检查表覆盖图片、名称和兜底字段。
- 无图、图片加载失败、名称为空、关联对象缺失时有明确展示规则。
- 检查表能说明哪些列表适用、哪些列表不适用。

## US-002 产品和设计沉淀展示口径

作为产品或设计负责人，我希望管理端列表字段展示有固定 adapter 检查表，以便后续新增或调整列表时不再重复讨论图片、名称和兜底文案。

验收要点：

- 检查表包含 image adapter、name adapter、fallback adapter 三个部分。
- 检查表明确强制项、推荐项和不适用项。
- 后续 OpenSpec design 可直接引用检查表。

## US-003 前端开发复用展示规则

作为前端开发，我希望检查表能标出现有 helper、页面内判断和待统一逻辑，以便后续实现时决定复用、抽象或保留局部逻辑。

验收要点：

- 首批列表的现状盘点包含品牌、证书、SKU、Banner。
- 检查表不强制立即重构所有列表。
- 若后续抽公共 adapter，需要在 OpenSpec design 中说明边界。

## US-004 QA 按清单回归边界场景

作为 QA，我希望验收清单明确可测试场景，以便覆盖无图、空名称、关联缺失、未知枚举值和布局稳定性。

验收要点：

- 验收标准包含可勾选的功能 AC 与横切 AC。
- 手工验证场景需说明样例数据和判定标准。
- 管理端列表分页、toast、confirm 等横切要求不被本需求遗漏。
