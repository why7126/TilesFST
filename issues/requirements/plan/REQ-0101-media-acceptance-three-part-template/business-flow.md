# 业务流程

## 1. 触发判断

```text
REQ / BUG / Change / Sprint 验收
        |
        v
是否涉及媒体 URL、对象 key、缩略图、上传、对象存储、
列表图片展示、历史资源维护？
        |
   +----+----+
   |         |
  是        否
   |         |
   v         v
启用三段   使用普通验收模板；
验收模板   必要时引用五联/四联
```

## 2. 三段证据组织

```text
媒体类条目验收
        |
        +--> A. 列表展示字段
        |       - API 响应字段
        |       - Orval 类型
        |       - admin web 字段选择与 fallback
        |       - 截图、接口样例或测试断言
        |
        +--> B. 生成策略
        |       - 触发时机
        |       - 尺寸、体积、格式、质量策略
        |       - 失败降级与日志
        |       - 增量或存量影响
        |
        +--> C. 历史对象维护或重生成
                - dry-run / apply
                - 扫描范围与权限
                - 幂等性
                - 对象存储 key/prefix
                - 成功、失败、跳过统计
```

## 3. 影响矩阵流程

```text
每段证据
  |
  +--> API：是 / 否 / 待确认 + 证据
  +--> Orval：是 / 否 / 待确认 + 证据
  +--> DB：是 / 否 / 待确认 + 证据
  +--> 对象存储：是 / 否 / 待确认 + 证据
  +--> admin web 列表：是 / 否 / 待确认 + 证据
```

## 4. 与既有模板关系

```text
REQ-0090 媒体五联
  key / object / URL / thumbnail benefit / miniapp render
        ^
        |
REQ-0101 三段模板
  用三段组织证据，并在每段内引用五联检查项
        |
        v
REQ-0091 BUG 四联
  原 BUG 场景 / key / object / URL / render / 修复对照
```

## 5. 与父 REQ 或历史需求差异

| 对象 | 差异 |
|---|---|
| `REQ-0090` | 横向检查媒体链路五个维度；REQ-0101 纵向拆分列表、生成、历史维护三类证据。 |
| `REQ-0091` | 聚焦 BUG 修复闭环；REQ-0101 同时适用于 REQ 与 BUG，并强调影响矩阵。 |
| `REQ-0098` | 是列表缩略图字段案例；REQ-0101 不重新实现该能力，只沉淀模板。 |
| `REQ-0099` | 是生成策略和历史重生成案例；REQ-0101 不新增配置或维护任务。 |

## 6. 异常与后续分流

| 状态 | 处理 |
|---|---|
| `fail` | 记录实际结果、期望结果、影响范围和复现入口，可转 `/bug-capture`。 |
| `blocked` | 记录阻塞原因和补证责任，例如环境、对象样例、体验版或接口未合并。 |
| `n/a` | 必须说明不涉及原因，不得留空或删除段落。 |
| `待确认` | 进入评审问题或 OpenSpec design 决策，不得在验收中默认通过。 |
