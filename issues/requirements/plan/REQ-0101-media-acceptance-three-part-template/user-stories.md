# 用户故事

## US-001 产品负责人验收媒体需求

作为产品负责人，我希望媒体类需求的验收证据按列表展示字段、生成策略、历史对象维护或重生成三段组织，以便快速判断用户可见展示、后台生成逻辑和存量对象治理是否分别闭环。

验收要点：

- 能看出本需求是否影响 admin web 列表字段、API、Orval、DB 和对象存储。
- 能看出缩略图、派生对象或历史对象维护是否只影响增量，还是影响存量。
- 能识别每段证据的 `pass`、`fail`、`n/a` 或 `blocked` 状态。

## US-002 测试人员执行媒体回归

作为测试人员，我希望模板提供固定检查项和证据字段，以便在媒体类 REQ/BUG 验收时不遗漏字段、生成、对象维护、fallback 和失败态。

验收要点：

- 列表展示字段段能指导我验证字段来源、页面展示和 fallback。
- 生成策略段能指导我验证触发时机、尺寸体积策略、失败降级和日志。
- 历史对象维护段能指导我验证 dry-run、apply、幂等性和失败统计。

## US-003 后端和对象存储开发补证

作为后端或对象存储开发，我希望模板清楚要求 key/prefix、object、URL、DB 记录和维护任务证据，以便提交验收时能证明媒体对象链路可追踪且没有绕过后端适配层。

验收要点：

- 对象存储影响必须说明 key/prefix、对象写入、访问 URL 和权限边界。
- DB 不涉及时必须写明“不改表”或“不改业务记录”。
- 历史维护任务必须记录扫描、成功、失败、跳过和重试信息。

## US-004 管理端开发补齐列表字段证据

作为 Web 管理端开发，我希望模板要求列出接口字段、Orval 类型、前端取图优先级和截图或测试证据，以便列表缩略图、原图 fallback 和占位状态可以被稳定验收。

验收要点：

- API 字段变化必须同步 OpenAPI / Orval 证据。
- 列表页面必须说明优先字段、fallback 字段和空态。
- 如不涉及列表展示，必须写明 `n/a` 原因。

## US-005 Sprint 或发布负责人复核范围

作为 Sprint 或发布负责人，我希望媒体类条目的影响矩阵能被复制到 Sprint 验收报告或 release note，以便发布前知道哪些端、接口、数据和对象存储范围需要复核。

验收要点：

- 影响矩阵每项不得留空。
- `blocked` 项必须有明确补证或后续 capture 建议。
- 已归档 Sprint 可作为经验来源，但不得被本需求重新修改范围。
