# 设计说明

## 根因分析

品牌链路媒体性能慢不是单一接口响应问题，而是小程序端渲染、后端媒体 URL 语义、对象存储缩略图质量和 `/media` 读取链路共同造成的闭环缺口：

1. 后端和小程序虽然倾向使用 `.thumb` URL，但缺少真实 object、bytes、像素和 resolved key 的验收。
2. `media.thumbnail_max_size_kb` 可能未设置有效体积目标，导致新生成或历史缩略图仍偏大。
3. 品牌列表 Banner、品牌 Logo、品牌详情 Logo、证书图片和品牌过滤商品列表的懒加载覆盖不完整，首屏可能一次性发起过多图片请求。
4. `/media/{object_key}` 受控读取若缺少缓存头、网关缓存或 CDN 验证，多图页面会反复穿透后端与对象存储。

## 修复方案

1. 品牌列表页媒体策略：
   - 品牌轮播图片优先使用后端返回的缩略图 URL 或等价轻量展示 URL。
   - 品牌 Logo 使用真实轻量缩略图，加载失败时回退原图、品牌首字或统一占位。
   - 非首屏品牌卡片图片启用小程序 `lazy-load` 或等价延迟加载策略，首屏关键图保持可预期展示。
2. 品牌详情页媒体策略：
   - 品牌 Logo 小图优先使用缩略图，分享图、预览图或高清查看入口保留原图或安全高清 URL。
   - 商品 Tab 复用商品卡片缩略图优先解析策略。
   - 证书 Tab 图片小图优先使用缩略图，证书预览或详情保留原图、原文件或受控高清 URL。
3. 品牌分类商品列表页媒体策略：
   - `brandId + categoryId` 查询场景继续使用商品列表公开接口的缩略图优先字段。
   - 商品卡片组件不得因入口参数不同而改读原图字段。
4. 后端媒体与对象治理：
   - 复核品牌列表、品牌详情、商品列表和证书接口返回字段，确保展示字段、预览字段和受控 URL 语义一致。
   - 维护任务或脚本至少提供 dry-run 审计，覆盖品牌 Logo、Banner、SKU 主图和图片类品牌证书。
   - 对 `.thumb` 缺失、0 字节、疑似复制原图、体积无收益、MIME 不匹配、对象不可读等情况输出摘要。
5. `/media` 缓存与观测：
   - 媒体读取日志或等价观测应能区分请求 key、实际 resolved key、content length、MIME 和耗时。
   - 生产环境应验证 `/media` 图片响应的缓存头、Nginx/网关缓存或 CDN 策略；若暂不启用缓存，必须记录原因和剩余风险。

## 风险与约束

- `.thumb` URL 可访问不等于性能通过，验收必须对比原图和缩略图的 bytes、像素或 MIME。
- 缩略图缺失回退原图可以避免破图，但必须作为性能风险记录。
- 小程序懒加载不能破坏图片点击、商品跳转、证书预览、分享和失败态。
- 历史对象回填涉及对象存储写入时必须先备份，并提供 dry-run、apply、二次审计和幂等摘要。
- 本 Change 可能涉及公开小程序接口字段语义和 API 文档；如 OpenAPI 发生变化，需要同步 Orval；若仅复用既有字段语义，小程序不直接使用 Orval。

## 验证计划

- 运行品牌列表、品牌详情、商品列表接口相关后端 pytest。
- 运行小程序静态测试，覆盖 `brand-list`、`brand-detail`、`product-list` 和 `product-card` 图片绑定及懒加载。
- 运行媒体对象审计 dry-run，记录脱敏摘要。
- 运行 OpenSpec 校验与语言校验。
- 使用微信 DevTools、真机或体验版 Network 记录品牌链路图片 URL、资源大小、耗时、resolved key 和渲染 evidence。
