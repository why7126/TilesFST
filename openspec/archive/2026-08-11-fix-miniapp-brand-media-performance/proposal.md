# 修复小程序品牌链路媒体加载性能

## 背景

`BUG-0126-miniapp-brand-media-slow-load` 已确认用户在微信小程序品牌列表页、从品牌列表页进入的分类商品列表页、品牌详情页感知图片加载速度慢。该问题主要影响品牌 Logo、品牌轮播 Banner、品牌详情 Logo、品牌下商品卡片图和品牌证书图片。

现有能力已经要求品牌链路优先使用后端受控缩略图，但实际性能收益还依赖缩略图对象真实存在、体积明显小于原图、小程序非首屏图片启用懒加载，以及生产 `/media/{object_key}` 读取链路具备缓存或可观测回退证据。当前这些条件尚未形成闭环，可能出现 URL 看起来是 `.thumb`，但对象缺失、回退原图、缩略图过大或多图首屏穿透后端与对象存储的退化。

## 变更内容

- 修复品牌列表页图片加载策略，使品牌轮播、品牌 Logo 和非首屏品牌卡片图片优先使用真实轻量缩略图并启用小程序懒加载。
- 修复品牌详情页图片加载策略，使品牌 Logo、商品 Tab 商品卡片图和证书 Tab 图片优先使用真实轻量缩略图，预览或详情入口保留原图或安全高清 URL。
- 修复从品牌列表页进入的品牌分类商品列表页，确保品牌过滤与分类过滤叠加场景继续复用商品卡片缩略图优先策略。
- 补齐后端媒体读取、缩略图体积目标和历史对象审计/回填验收要求，明确 `.thumb` 缺失回退原图不得视为性能通过。
- 补齐 `/media/{object_key}` 缓存策略验证、媒体四联验收、小程序 DevTools/真机 evidence、后端测试和小程序静态测试。

## 不做范围

- 不新增对象存储 Bucket，不改变 MinIO 单桶和标准前缀策略。
- 不让小程序或前端直连未授权对象存储。
- 不实现视频转码、多清晰度图片服务或独立图片 CDN 产品能力；若生产使用 CDN 或网关缓存，仅在修复中验证和记录缓存策略。
- 不把所有历史媒体对象强制迁移为同步阻断项；本 Change 至少要求 dry-run 审计，写入式回填需具备备份、幂等和失败摘要。
- 不修改品牌信息、商品排序、证书业务展示规则本身。

## 回滚方案

- 若缩略图 URL 在生产环境不可访问，可临时回退对应页面展示原图或统一占位，但必须保留 BUG-0126 验收阻塞记录。
- 若懒加载导致首屏关键图延迟过度，可仅保留首屏关键图立即加载，非首屏图片继续延迟加载。
- 若 `/media` 缓存配置引入错误响应或过期资源，可回退缓存头或网关缓存配置，同时保留媒体读取日志与缩略图对象审计。
- 回滚后必须重新评估缩略图对象存在性、体积收益和历史回填计划，不能仅以页面不破图作为完成标准。
