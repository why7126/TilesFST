## 上下文

REQ-0099 已评审通过，目标是在不改变现有 `.thumb` 缩略图寻址模型的前提下，为所有图片缩略图生成增加一个全局体积目标上限，并把配置放入管理后台“系统设置 - 媒体与存储”。当前系统已有 `media.max_image_size_mb`、`media.allowed_image_types` 等 effective 设置，也已有同目录缩略图生成、SKU 图片正式化和媒体维护任务。

影响范围横跨系统设置 API、Web 管理端设置页、媒体上传链路、对象存储缩略图生成和生产媒体维护任务，因此需要设计文档明确默认值、生效范围、历史处理和 UI 策略。

## 目标 / 非目标

**目标：**

- 使用全局配置控制后续新生成缩略图的目标体积。
- 默认不限制，保持当前生成行为。
- 配置覆盖 SKU、品牌 Logo、Banner、品牌证书图片和维护任务重生成。
- 保持同目录 `.thumb` Key / URL 规则稳定。
- 保存配置不自动重建历史缩略图。
- 后续历史重生成通过维护任务 dry-run、apply 和二次审计处理。
- 管理后台设置页遵守 admin-form 和 media-upload 知识库横切 AC。

**非目标：**

- 不新增业务表 `thumbnail_key` 字段。
- 不改变前端、小程序、后端既有缩略图 URL 推导或返回字段语义。
- 不实现视频缩略图、PDF 首页缩略图或公开端配置入口。
- 不在保存系统设置时执行历史对象扫描或覆盖。

## 决策

### D1 配置字段与默认语义

采用 `media.thumbnail_max_size_kb` 作为系统设置 key，后端配置和 API 字段使用 `thumbnail_max_size_kb`。默认值为 `0`，表示不限制，保持现有生成模式。

理由：

- `0` 比 `null` 更适合当前系统设置 key-value 与前端数字控件。
- 可以与图片、视频、文件大小限制同属 media 分组，并保持 reset 后返回可显示数字。
- 不需要用缺失字段表达状态，降低 Orval 和表单比较逻辑复杂度。

校验范围建议为 `0-1024 KB`。`0` 为关闭上限，`1-1024` 表示目标上限。

### D2 缩略图生成策略

`generate_image_thumbnail()` 或等价内部 helper 增加目标体积参数。生成过程按渐进策略执行：

```text
默认生成
  -> 若未配置上限，直接返回
  -> 若超过目标，对 JPEG / WebP 递减质量
  -> 仍超过目标时按比例缩小最大宽高
  -> 仍未达标时返回当前最佳结果并记录 warning
```

PNG 默认保持原格式和透明度优先，不在本 Change 中强制转 WebP。若后续希望为 PNG 转 WebP 建立更强达标能力，应作为单独需求或在后续设计中明确兼容风险。

### D3 全局生效范围

所有后端生成图片缩略图的入口读取同一 effective 设置：

- 图片上传保存时生成缩略图。
- SKU 暂存图片正式化时补生成缩略图。
- 品牌 Logo、Banner 图片和品牌证书图片上传缩略图。
- 历史缩略图维护任务重生成。

不同业务模块不得各自维护不同体积上限。

### D4 历史资源处理

保存系统设置只影响后续新生成缩略图，不触发历史 `.thumb` 对象扫描、读取或覆盖。历史重生成继续由维护任务负责，并读取当前 effective `thumbnail_max_size_kb`。

维护任务必须支持：

- dry-run 不写数据库或对象存储。
- apply 显式触发。
- 输出成功、失败、跳过、重试候选和失败原因统计。
- 二次审计覆盖 key、object、URL、thumbnail benefit、render 或 N/A / blocked 原因。
- 输出脱敏，不泄露密钥、真实客户数据、`.env` 或本机敏感路径。

### D5 UI 策略与原型冲突处理

采用 DS 增量策略，不做完整 CSS Port。原因是 REQ-0099 的 HTML 原型只说明字段位置与文案，不是新的视觉源；现有 `SystemSettingsPage` 已是权威实现基底。

冲突优先级处理：

```text
prototype HTML > prototype context.md > acceptance.md > ui-design.md > openspec/specs
```

结论：

- 字段放在“上传限制”区域。
- 对象存储策略区域保持只读，不加入压缩算法细节。
- 全页仍只有一个保存 CTA。
- 恢复默认和 dirty Tab 切换继续使用 DS modal。
- 成功反馈继续使用 fixed toast，不插入文档流提示块。

## 风险 / 权衡

- 复杂 PNG 或透明图可能无法达到目标体积 → 保持可用性优先，记录 warning，不阻断上传。
- 过低目标值可能导致画质明显下降 → 后端限制 `1-1024 KB` 且 UI 文案表达“目标上限 / 尽量不超过”。
- 历史重生成可能消耗大量 I/O → 不在保存设置时自动执行，必须通过维护任务 dry-run/apply。
- API 字段变化可能造成前端类型漂移 → 必须同步 OpenAPI / Orval 与前端测试。
- 当前已有 `optimize-admin-media-list-thumbnails` active Change → 本 Change 不修改管理端列表字段，只提供后续更轻量缩略图内容策略，避免范围重叠。

## 迁移计划

1. 增加配置默认值和 system settings media 分组字段。
2. 实现缩略图体积目标生成策略并保持默认不限制行为。
3. 让上传、SKU 图片正式化和维护任务读取同一 effective 配置。
4. 更新管理后台媒体设置页字段与测试。
5. 同步 OpenAPI / Orval。
6. 运行后端、前端、OpenSpec 语言与目录校验。

回滚策略：

- 将 `thumbnail_max_size_kb` 恢复为 `0` 即可回到当前不限制模式。
- 若缩略图生成策略出现问题，上传原图仍应成功；可临时关闭上限并通过维护任务重生成受影响缩略图。

## 待确认事项

- 第一版是否需要在管理后台提供历史重生成触发入口。当前设计默认仅提供受控维护任务。
- 未达标 warning 最终写入后端日志、Task Trace 还是维护任务摘要。当前设计要求至少可定位，不强制新审计字段。
