## 背景

当前系统已具备同目录 `.thumb` 缩略图生成能力，但缩略图只按最大宽高与固定质量输出，无法通过后台配置控制最终体积。小程序、管理端图片密集列表和公开展示卡片需要更稳定的轻量缩略图策略，同时管理员保存配置时不能不可预期地批量重建历史媒体对象。

## 变更内容

- 在系统设置 `media` 分组新增全局缩略图体积目标上限配置，默认不限制。
- 在管理后台“系统设置 - 媒体与存储”的上传限制区域展示、保存和重置该配置。
- 将该配置应用到所有后端图片缩略图生成场景，包括 SKU 图片、SKU 暂存图片正式化、品牌 Logo、Banner 图片和品牌证书图片。
- 保持现有同目录 `.thumb` Key / URL 推导规则，不新增业务表 `thumbnail_key` 字段。
- 保存设置仅影响后续新生成缩略图，不自动重建历史缩略图。
- 历史缩略图如需应用新策略，通过受控维护任务 dry-run、apply 和二次审计执行。
- 同步 OpenAPI、Orval、系统设置测试、媒体生成测试、管理端设置页测试和维护任务验收。

## 能力范围

### 新增能力

- 无。

### 修改能力

- `system-settings`: media 分组新增缩略图体积目标上限字段和管理后台设置入口。
- `object-storage`: 图片缩略图生成读取全局体积目标策略，并保持 `.thumb` Key / URL 稳定。
- `prod-media-maintenance-jobs`: 历史缩略图重生成维护任务读取当前全局策略，并保留 dry-run/apply/二次审计边界。

## 影响

- 后端：配置、effective settings、上传保存、缩略图生成、SKU 图片正式化、媒体维护任务。
- API：系统设置 `GET/PATCH/reset` 字段变化，需要 OpenAPI / Orval 同步。
- Web 管理端：系统设置媒体 Tab 新增字段、校验、保存、重置和横切 UI 验收。
- 存储：缩略图对象内容可能更小，但对象 Key、URL、鉴权读取链路不变。
- 数据库：不新增业务表字段；若系统设置使用 key-value 存储，仅新增配置 key/default。
- 小程序与店主 Web：不新增配置入口，通过后续更轻量缩略图间接受益。
- 测试：后端单元/集成测试、前端 Vitest、OpenAPI/Orval 生成物、必要的 Docker Web 边界验证说明。
