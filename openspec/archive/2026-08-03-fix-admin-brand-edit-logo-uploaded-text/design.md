## 背景

品牌管理能力已要求编辑品牌时可回显 Logo，并且弹窗小预览优先展示缩略图。`BUG-0106` 暴露的问题不在上传、存储或回显链路，而在 Web UI 对 Logo 上传组件成功态的展示规则：已有 Logo 或上传成功后的稳定状态旁出现 `已上传Logo` 文案，与图片预览和控件状态重复。

## 缺陷分析报告

- 现象：管理后台品牌编辑弹窗 Logo 区域旁显示冗余 `已上传Logo` 文案。
- 复现：登录管理后台，进入品牌列表，打开任一已上传 Logo 的品牌编辑弹窗，查看 Logo 区域旁提示。
- 影响：品牌编辑弹窗视觉噪音增加；不阻断 Logo 预览、替换、删除、重新上传或品牌保存。
- 严重等级：`low`，属于管理后台 UI 展示偏差。
- 关联 BUG：`BUG-0106-admin-brand-edit-logo-uploaded-text`。
- 关联需求：无。

## 根因分析

品牌编辑表单中的 Logo 上传区域可能复用了通用上传成功态文案，未针对“编辑已有图片并展示预览”的稳定场景收敛展示规则。当前 UI 把“已存在图片”和“上传成功提示”同时渲染，使辅助文案进入常驻状态。

## Decisions

- D1：已有 Logo 回显和上传成功后的稳定预览状态不展示 `已上传Logo` 或等价冗余成功态文案。
- D2：不得通过隐藏整个上传组件来解决该问题；必须保留图片预览、替换、删除或重新上传入口。
- D3：上传中、上传失败、格式不支持等必要反馈仍必须可见，避免把错误/处理中状态与冗余成功态一并删除。
- D4：该修复不改变后端品牌 API、媒体上传 API、对象存储 key 或数据库字段。

## 风险

- 若直接移除通用上传组件所有状态文案，可能误删上传失败或格式不支持提示。
- 若只用 CSS 隐藏整块提示区域，可能影响可访问反馈或布局稳定性。

## 验证

- 打开已有 Logo 的品牌编辑弹窗，确认 Logo 区域不显示 `已上传Logo`。
- 确认 Logo 图片仍正常预览，布局不因文案移除而错位。
- 执行替换、删除或重新上传 Logo，确认交互保持正常。
- 上传非法格式或模拟失败，确认必要错误提示仍可见。
- 运行相关前端测试或补充 focused 测试覆盖上述场景。
