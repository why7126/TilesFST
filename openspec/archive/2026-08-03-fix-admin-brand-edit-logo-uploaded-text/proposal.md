## 背景与原因

`BUG-0106-admin-brand-edit-logo-uploaded-text` 已评审通过。管理后台品牌编辑弹窗中，已有 Logo 的品牌在 Logo 区域旁稳定展示 `已上传Logo` 文案。该文案与图片预览、上传或替换控件表达的信息重复，造成界面噪音，并与品牌编辑弹窗当前预期不一致。

## 变更内容

- 收敛品牌编辑弹窗 Logo 上传/预览区域的成功态展示规则：已有 Logo 或上传成功后的稳定状态不再显示 `已上传Logo` 冗余文案。
- 保留 Logo 图片预览、替换、删除或重新上传交互。
- 保留上传中、上传失败、格式不支持等必要状态反馈，避免误删真实错误提示。
- 补充回归验证，覆盖已有 Logo 回显、重新上传、错误提示与布局不跳动。

## 能力影响

### 新增能力

- 无。

### 修改能力

- `brand-management`: 管理端品牌编辑弹窗 Logo 回显与上传控件必须避免展示冗余成功态文案，同时保留必要操作和错误反馈。

## 影响范围

- 影响范围：管理后台 Web UI 的品牌编辑弹窗 Logo 上传/预览区域。
- 不影响 API 响应结构、错误码、数据库表结构、MinIO 对象存储策略或小程序。
- 不需要 Orval。
- 不需要 Docker Compose 验证。
- 需要补充或更新前端回归测试，覆盖 `BUG-0106` 的验收标准。

## 回滚方案

- 若修复导致 Logo 预览、替换或错误提示异常，回退本次 UI 展示逻辑调整。
- 回退后必须保留已有 Logo 上传、预览和品牌保存流程的原有行为，并重新评估是否需要用更精细的状态字段区分成功态与错误态。
