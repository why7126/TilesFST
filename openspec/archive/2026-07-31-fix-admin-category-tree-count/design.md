## Background

BUG-0095 关联 `REQ-0005-tile-category-management`。管理端类目树用于帮助后台运营理解类目层级，并与右侧类目列表联动。当前树节点右侧数字显示为商品数量，和用户确认的“下一层级类目数量”口径不一致。

## Root Cause

- 直接原因：管理端类目树节点右侧计数绑定到了商品数量计数字段，而不是直接子类目数量字段。
- 根本原因：正式 spec 和前端展示约束未清晰区分 `sku_count` 与直接子类目数量，导致同一个计数位置被商品数量占用。
- 分类：`ui-contract / data-mapping / count-semantics`，属于管理端 UI 与接口字段语义偏差。

## Fix Approach

1. 确认 `GET /api/v1/admin/tile-categories/tree` 的节点响应中存在直接子类目数量字段；若 OpenAPI/Orval 未暴露，补齐稳定字段 `children_count`。
2. 保留 `sku_count` 的既有含义：含子级汇总的 SKU 数，继续用于删除规则、列表统计或商品数量提示，不用于类目树节点右侧的下级类目数量。
3. 调整管理端类目树组件计数绑定：
   - 普通类目节点右侧显示 `children_count`。
   - 叶子类目显示 `0`。
   - “全部类目”入口显示顶层类目数量。
   - “全部类目”入口保留完整按钮边框，使选中态边框包住文字和数值；右侧计数列视觉对齐，文字左边线与类目树标题对齐，不使用会让文字溢出边框的负向偏移。
4. 如页面需要商品数量提示，使用独立位置、标签或文案展示，避免与类目数量混淆。
5. 不改变类目树点击筛选、展开收起、权限、删除规则、排序规则和类目层级限制。

## Test Strategy

- 前端组件测试：一级类目显示直接子类目数量，不显示商品数量。
- 前端组件测试：叶子类目显示 `0`。
- 前端页面测试：全部类目入口显示顶层类目数量。
- 前端回归测试：展开/折叠和点击筛选行为不回归。
- 后端接口测试：若补齐 `children_count` OpenAPI/Pydantic 契约，验证 tree 响应持续返回直接子类目数量，且 `sku_count` 语义不变。
- Orval 验证：若 API 契约变化，运行 `./scripts/generate-openapi-client.sh` 并更新生成类型。

## Risks

- 若实现误用 `children.length` 而接口只返回部分层级，可能导致计数不可靠；优先使用后端返回的直接子类目数量字段。
- 若修复过程中改动 `sku_count` 聚合语义，可能影响删除门禁或商品统计；本 Change 明确禁止改变 `sku_count` 既有业务含义。
- 若“全部类目”入口被当作商品汇总入口复用，需要同时调整 UI 文案或位置，避免口径继续混淆。
