# 设计说明

## 根因摘要

根因状态为 `probable`。后台 Banner 表单会生成 `internal-*` 内部标题并保存到 `title` 字段；后端小程序公开 Banner item 当前会将 `record.title` 原样写入公开 `title` 字段。当前仓库的小程序首页 WXML 不直接渲染 `item.title`，因此实现阶段仍需补齐接口响应、当前小程序包或图片对象证据，确认标题最终进入画面的具体路径。

## 修复方案

1. 后端公开 Banner DTO 净化
   - 对小程序首页和品牌列表页公开 Banner 数据统一识别内部标题。
   - `internal-*`、包含 `MINIAPP_HOME` / `NO_JUMP` 等内部枚举和时间戳模式的标题不得作为公开展示标题下发。
   - 如公开 schema 仍保留 `title` 字段，应返回空字符串、安全展示名或仅供公开搜索语义的字段，不得返回后台内部识别值。

2. 小程序端防御
   - 首页轮播和品牌列表页轮播继续只以 `image_url` 渲染图片，不渲染后台标题遮罩。
   - 首页首屏存在有效 Banner 图片时，不叠加从左深到右浅的渐变遮罩，图片不设置透明化，确保运营上传素材按原始视觉渲染。
   - 无跳转首页 Banner 点击保持静默，不显示“内容建设中”或任何包含内部标题的提示；搜索兜底、分享文案和埋点展示摘要不得使用内部标题。
   - 若接口仍带空标题，端侧应安全降级，不出现空白遮罩或布局跳动。

3. 后台管理兼容
   - 管理端可继续自动生成内部标题用于唯一键和列表搜索兼容。
   - 管理端列表、编辑、上线、下线、排序和跳转类型配置不得因公开端净化回退。

4. 存量数据与媒体对象
   - 若内部标题已写入 Banner 图片像素，应通过运营替换、重新上传或受控清理解决。
   - 若只是公开 DTO 或端侧渲染暴露，修复不需要对象迁移。

## 测试策略

- 后端测试覆盖 `NO_JUMP` 且 `title=internal-*` 的首页 Banner 和品牌列表页 Banner，断言公开接口不暴露内部标题。
- 小程序静态测试继续断言首页轮播和品牌列表页轮播不渲染 `item.title`。
- 小程序静态测试断言首页轮播不包含 `hero-shade` 渐变遮罩，并避免恢复图片透明化。
- 小程序交互/静态测试覆盖无跳转首页 Banner 点击静默，以及 search fallback 不使用内部标题。
- 媒体四联验收覆盖 key、object、URL、render，并记录 DevTools、真机或体验版证据状态。

## 风险

- 若已有存量图片对象本身带字，仅净化 DTO 无法消除画面文字，需要运营替换素材。
- 若第三方或旧小程序包仍使用标题遮罩、渐变遮罩或透明化样式，需要确认体验版/线上包版本并发布新包。
- 若公开 API 字段语义变更影响小程序端类型或测试，需要同步 OpenAPI、Orval、API 文档和回归测试。
