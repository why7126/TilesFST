## Why

BUG-0096 指出管理后台瓷砖 SKU 页「类目」筛选只能选择一级类目，无法按二级、三级或更深层级类目筛选 SKU。当前 SKU 页使用只保留一级类目的选项构造逻辑，后端 `category_id` 过滤也是精确匹配；这与已确认的产品口径不一致：SKU 页类目筛选应使用级联选择控件，选择父类目时应包含所有子孙类目 SKU。

## What Changes

- 管理后台 SKU 页类目筛选改为级联选择控件。
- 类目筛选可选择当前类目树中的任意层级节点。
- 选择父类目时，SKU 列表必须包含该父类目下所有子孙类目的 SKU。
- 保留「全部类目」和重置能力。
- 保持关键词、品牌、类目、状态、素材完整度、分页和默认排序组合行为不回归。
- 补充前后端测试，覆盖级联选择、子树过滤和组合筛选。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `tile-sku-management`: 管理端 SKU 列表类目筛选必须支持级联选择各层级类目；父类目筛选必须包含所有子孙类目 SKU。

## Impact

- 影响范围：管理后台 Web 的瓷砖 SKU 列表筛选区；后端管理端 SKU 列表类目过滤语义。
- 可能影响 API 契约：若继续使用 `category_id`，需将其语义调整为“类目子树过滤”；若新增筛选参数，必须同步 OpenAPI、Orval、API 文档和测试。
- 不影响数据库结构、MinIO 上传、小程序或店主端展示。
- 需要补充或更新前端 Vitest/Testing Library 测试与后端 pytest。
- 不需要 Docker Compose 验证，除非实现阶段发现接口联调必须通过 compose 环境验证。

## Rollback Plan

如修复导致 SKU 列表筛选结果异常、级联控件不可用或组合筛选回归，可回退本 Change 的前端筛选控件和后端类目过滤逻辑，恢复原一级类目精确筛选行为。回退后必须保留 BUG-0096 文档，重新评估父类目子树过滤的接口设计，并不得修改 SKU 数据归属或类目层级数据来规避问题。
