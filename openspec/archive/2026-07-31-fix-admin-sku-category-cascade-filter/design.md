## Background

BUG-0096 关联 `REQ-0006-tile-sku-management`。管理后台 SKU 页已经提供类目筛选，但当前只展示一级类目，无法按细分类目定位商品。产品已确认：

- 父类目筛选语义：包含所有子孙类目 SKU。
- UI 形态：级联选择控件。

## Root Cause

- 直接原因：`TileSkuManagementPage` 使用 `buildParentOptions(tree).filter((o) => o.id != null)` 构造筛选项，而 `buildParentOptions` 跳过 `level >= 2`，导致 SKU 列表筛选只展示一级类目。
- 根本原因：SKU 列表筛选复用了“类目父级选择”口径，而不是“SKU 归属类目筛选”口径。
- 后端现状：管理端 SKU 列表接口接收单个 `category_id`，Repository 过滤条件为 `t.category_id = :category_id`，属于精确匹配，不包含子孙类目。
- 分类：`ui-behavior / filtering-contract / admin-usability`。

## Fix Approach

1. 前端筛选控件
   - 将 SKU 页「类目」筛选从普通下拉改为级联选择控件。
   - 控件形态采用单个下拉触发框；筛选区不并排展示多个类目筛选框。
   - 打开下拉后先展示当前层级，点击有下级类目的节点时，在同一下拉层右侧展开下级类目面板；点击节点本身即可选中该层级作为筛选条件。
   - 当前选择路径只展示在下拉触发框内，不在筛选项下方额外展示“当前：xxx”文案。
   - 下拉层定位在筛选控件下方，并通过筛选卡片层级确保不被 SKU 列表或 sticky 操作列遮挡。
   - 品牌、类目、状态筛选统一使用同一套触发框、下拉菜单、选项和选中态样式；类目在统一菜单基础上额外支持右侧子级面板。
   - 数据源使用完整 `fetchCategoryTree()` 结果。
   - 控件支持选择任意层级节点。
   - 保留「全部类目」或清空入口。

2. 后端过滤语义
   - 对父类目筛选解析子树范围，返回该父类目及所有子孙类目的 SKU。
   - 对叶子类目筛选返回该叶子类目 SKU。
   - 保持关键词、品牌、状态、素材完整度和分页排序条件可组合。
   - 实现可选择：
     - 继续使用 `category_id` 参数，并将其语义调整为“类目子树过滤”；或
     - 新增更明确的参数（例如 `category_scope_id` / `category_id` + scope），但必须同步 OpenAPI、Orval 和文档。

3. 回归与兼容
   - SKU 新增/编辑弹窗已有全层级类目选择能力，修复不得破坏该弹窗。
   - 默认排序、分页、加载态、空态、失败态和行操作不得回归。
   - 不修改数据库结构和现有 SKU 类目归属数据。

## Test Strategy

- 前端测试：SKU 页类目级联控件仅保留一个下拉触发框，点击父级后在右侧面板展示子级，并可选择一级、二级、三级类目。
- 前端测试：选择子类目、父类目、清空类目后，调用列表接口参数正确。
- 前端测试：品牌、类目、状态筛选下拉触发框和菜单使用一致样式类。
- 后端测试：父类目筛选返回自身及所有子孙类目的 SKU。
- 后端测试：子类目筛选只返回对应子树内 SKU。
- 后端测试：类目筛选与关键词、品牌、状态、素材完整度、分页和默认排序组合不回归。
- 契约测试：如 API 参数或响应契约变化，更新 OpenAPI、Orval、docs/03-api-index.md 和相关测试。

## Risks

- 若直接改变 `category_id` 语义为子树过滤，历史调用方对“精确类目匹配”的隐含依赖可能变化。当前该接口主要服务管理端 SKU 页，仍需通过测试确认无其他调用方受影响。
- 级联控件在窄屏或筛选区空间有限时可能影响布局，需要视觉检查。
- 子树过滤若通过递归查询实现，需确认 SQLite 与 MySQL 兼容性；可采用应用层收集子孙类目 ID 后使用参数化 `IN` 查询规避方言差异。
