# 持续执行设计

## 决策

详细契约归属 docs/standards/command-execution-order.md，两个 apply 入口引用并在实施循环及收尾执行。规则入口只保留摘要。

已采纳持续执行与阻塞分类，因为普通实现细节和可恢复错误属于当前授权范围。未采纳忽略所有错误或自动归档，因为必要人工确认与交付边界仍成立。

## 状态与调度

通过前置门禁后持续选择未完成且依赖满足的任务。测试失败先定位修复；修复超出范围或需要缺失资源时记录证据、阻塞项和恢复条件，继续独立任务。用户明确停止则停止全部工作。

分组完成、上下文压缩和进度汇报不构成命令完成。每项验证通过再勾选；部分完成保留未勾选任务，不能无条件要求 applied。使用现有 Workflow Sync 派生状态并 dry-run 复核，不新增状态枚举或伪造完成。

## 边界

Sprint 纳入、UI Skeleton 首轮确认、权限与不可逆动作的必要授权继续有效。已回答决策沿用。当前 apply 不自动触发 archive、发布、下一 Change 或 follow-up。

## 验证责任

治理执行者运行静态校验与临时夹具回退验证，覆盖连续任务、自修复、局部阻塞、人工确认、上下文恢复、部分完成与完成收尾；这些证明规范覆盖与检查器检出能力，不证明未来每次 Agent 会话必然一次完成。
