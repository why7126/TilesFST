## 背景

`REQ-0115` 已定义 `thumbnail`、`display`、`original` 三类图片规格，但 Web 与微信小程序的页面级消费规则仍分散在 spec、README、组件实现和历史验收口径中。`REQ-0118` 要把这些规则收敛成统一矩阵，避免列表加载原图、详情展示缩略图、预览误用展示图，或把原图 fallback 当作性能通过。

## 变更内容

- 更新 `media-multi-variant-images` 能力，新增跨端图片三规格消费矩阵要求。
- 明确矩阵字段：页面、位置、图对象、是否缩略图、是否 display 图、是否原图、优化方案。
- 明确微信小程序真实页面、Web 管理端真实媒体位置和店主 Web 预留规范的覆盖边界。
- 明确非原图目标场景不得 fallback 到 `original`；缺少目标规格时必须使用安全占位、补齐派生图或标记优化。
- 将现有偏离点只记录为优化方案，不在本 Change 中修改 Web、小程序、后端、API、数据库或对象存储实现。

## 能力范围

### 新增能力

- 无。

### 修改能力

- `media-multi-variant-images`：补充跨端消费矩阵、页面级目标规格、店主 Web 预留规则、禁止原图 fallback 和验收矩阵落点。

## 影响

- 后端：不修改。
- API：不修改；后续若基于矩阵修正偏离点需要新增字段，必须在独立 Change 中同步 OpenAPI、Orval、文档和测试。
- 数据库：不修改。
- 对象存储：不修改 key、prefix、bucket 或签名 URL 策略。
- Web 管理端：只沉淀真实媒体消费位置和优化方案，不改代码。
- 店主 Web：只沉淀预留规范，不做真实页面验收。
- 微信小程序：只沉淀页面级消费矩阵和优化方案，不改代码。
- 测试与文档：需要补充规范矩阵和验收证据，后续实现偏离点时引用该矩阵。
