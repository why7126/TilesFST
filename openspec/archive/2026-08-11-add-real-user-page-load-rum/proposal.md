## 背景

微信小程序和 Web 页面目前缺少真实用户加载耗时的统一采集口径，线上慢页面、慢接口和版本性能波动主要依赖人工复现、调试工具或零散反馈定位。随着商品列表、详情、品牌、搜索和管理端页面逐步成为核心路径，项目需要轻量自建 RUM 能力，把真实用户首屏可用、完整加载和关键接口耗时沉淀为可聚合、可脱敏、可回归的事实数据。

## 变更内容

- 新增真实用户性能观测能力，定义 Web 与微信小程序 RUM 采集、上报、聚合和隐私边界。
- 新增后端性能上报接口与聚合查询能力，支持 SQLite demo 与生产 MySQL。
- 扩展 Web 客户端约束，要求管理端和店主展示端采集页面加载指标并在管理端提供性能观测入口或查询预留。
- 扩展产品使用行为日志规范，将性能事件与既有日志/行为事件边界区分。
- 扩展 API 治理和数据库规范，明确 OpenAPI、Orval、错误码、schema、migration 和文档同步门禁。
- 明确小程序真实环境或体验版网络证据要求，避免仅用开发工具单次调试结果替代线上体验指标。

## 能力范围

### 新增能力

- `real-user-performance-monitoring`：覆盖真实用户页面加载耗时采集、性能事件模型、匿名上报、聚合查询、管理端观测和隐私降级策略。

### 修改能力

- `product-usage-logging`：补充性能事件与既有使用行为事件、请求日志的边界和存储保留要求。
- `web-client`：补充 Web RUM 采集、管理端性能观测入口和 UI 验收约束。
- `api-governance`：补充性能上报与聚合查询 API 的 OpenAPI、Orval、错误码和敏感字段约束。
- `database`：补充性能事件表、索引、保留周期和 SQLite/MySQL 兼容要求。

## 影响范围

- 后端：新增 telemetry/performance 模块或等价分层、Pydantic Schema、Service、Repository、聚合查询和鉴权边界。
- API：新增性能事件上报接口和管理端聚合查询接口，需同步 OpenAPI、Orval 和 API 文档。
- 数据库：新增性能事件存储表、索引、迁移和保留策略，需同步 SQLite 与 MySQL schema。
- Web：新增 RUM 采集工具、请求上报封装和管理端性能观测入口或查询预留。
- 微信小程序：新增页面生命周期与关键接口耗时采集、采样、批量或节流上报、失败降级。
- 管理端：若首期包含页面，需要新增或扩展观测入口，遵守 Design System semantic token。
- 测试：需补充后端 API/聚合测试、前端采集单测或 smoke、小程序静态/真实环境证据。
