## Why

小程序体验版首页和多个商品列表场景存在商品卡片图片长时间加载不完整的问题，已记录为 [BUG-0092](../../../issues/bugs/archive/BUG-0092-miniapp-card-images-slow-load/bug.md)。探索证据显示，首页会并发拉取 Banner、`new_products`、`hot_products` 与 `all_products`，商品卡片图片通过后端 `/media/{object_key}` 读取原对象，卡片组件未声明懒加载，且缺少面向列表卡片的缩略图、缓存响应头和媒体请求观测。该问题会直接影响小程序首屏可用性和选材浏览效率，属于异常体验。

## What Changes

- 为小程序商品卡片图片建立加载性能契约：列表卡片优先使用轻量缩略图或等价优化图片，非首屏图片延迟加载，并保留统一占位与失败降级。
- 调整首页商品推荐/瀑布流的首屏图片加载策略，降低 `new_products`、`hot_products`、`all_products` 同时触发的图片请求压力。
- 强化后端受控媒体读取能力，为列表图片提供缓存响应头、缩略图读取路径或缩略图 URL，并补充媒体请求耗时与失败观测。
- 增加对象引用一致性校验与回归测试，避免公开 SKU 主图指向不存在对象或缺少可展示图片时表现为长时间加载。
- 保持小程序不得直连未授权对象存储、不暴露 MinIO 原始 object key、不影响详情页高清图与视频 Range 支持。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `miniapp-product-list-page`: 修改商品卡片图片加载要求，补充缩略图、懒加载、占位、失败降级、跨首页/搜索/品牌详情复用卡片的一致体验。
- `miniapp-home`: 修改首页商品推荐与瀑布流要求，约束首屏图片并发、列表懒加载和分区回退。
- `object-storage`: 修改受控媒体读取要求，补充图片缓存、缩略图读取、媒体观测和对象引用一致性校验。

## Impact

- `miniapp`: 影响首页、商品列表、搜索结果、品牌详情商品 Tab 等复用商品卡片的图片加载策略和失败降级。
- `api`: 可能影响小程序公开 SKU 列表响应中的图片 URL 字段或新增等价缩略图字段；如契约变更需同步 OpenAPI、Orval 或小程序 API 类型。
- `backend`: 影响公开 SKU 查询、媒体 URL 生成、`/media/{object_key}` 图片响应缓存与媒体请求观测。
- `database`: 可能新增或回填缩略图对象键字段；若实现阶段选择派生缩略图路径且无需持久化，则数据库结构不变。
- `storage`: 影响 MinIO 中 `thumbnails/` 前缀的写入、读取和对象一致性校验，仍遵守单 Bucket + 前缀策略。
- `admin`: 可能影响管理端上传商品主图后的缩略图生成或回填，但不改变管理端权限边界。
- `web`: 不计划影响 Web 展示端；若复用后端媒体缓存头，不得造成 Web 图片展示回退。
- `tests`: 需要覆盖后端媒体/公开 SKU 契约、小程序卡片懒加载/失败降级、对象引用校验和体验版 evidence。

## Rollback Plan

实现阶段应保留原始图片对象和详情页高清图读取能力。若缩略图生成或新图片字段导致阻断，可临时回退为原 `cover_image` 输出并保留懒加载、占位和失败降级；若媒体缓存策略异常，可撤回新增缓存头配置但保留安全鉴权和对象 key 过滤。回滚不得让小程序直连未授权对象存储，也不得删除已存在的原图对象。
