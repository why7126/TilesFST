## Context

`BUG-0092-miniapp-card-images-slow-load` 指向小程序体验版商品卡片图片加载慢。当前卡片能力来自 `REQ-0049-miniapp-product-card-component`，并被首页、商品列表、搜索结果、品牌详情商品 Tab 等入口复用。探索中发现的主要风险包括：

- 首屏会同时渲染多组商品卡片，触发较多图片请求。
- 小程序商品卡片图片缺少懒加载或视口优先级控制。
- 列表卡片使用后端 `/media/{object_key}` 受控读取，后端倾向读取原对象并返回，缺少列表缩略图和图片缓存响应头。
- `/media/` 请求日志被排除，缺少体验版图片加载耗时、失败率和对象不存在的证据链。
- 本地样例中存在公开 SKU 主图对象缺失或 SKU 无主图的情况，体验版需要继续核验是否存在同类对象引用漂移。

## Goals / Non-Goals

**Goals:**

- 降低小程序商品卡片首屏图片加载耗时和失败率。
- 让商品卡片优先加载轻量缩略图或等价优化图片，详情页仍可使用高清图。
- 为非首屏卡片启用懒加载或等价延迟加载策略。
- 为受控媒体读取补齐图片缓存、媒体请求观测和对象引用一致性校验。
- 确保缺图、对象不存在和网络慢时页面有稳定占位，不出现长时间空白或布局跳动。

**Non-Goals:**

- 不引入小程序直连未授权对象存储。
- 不改变管理端、店主端或小程序的权限边界。
- 不重做商品卡片视觉体系、筛选逻辑、分页逻辑或详情页媒体播放能力。
- 不将视频转码、多清晰度视频或 CDN 接入作为本次修复的必选项。
- 不把 DevTools evidence 表述为真机通过。

## Decisions

### D1. 商品卡片使用缩略图优先

小程序列表卡片需要优先使用 `thumbnails/` 前缀下的缩略图或后端生成的等价轻量图片 URL。实现阶段可以选择新增 `thumbnail_image`/`thumbnail_url` 字段，也可以让现有 `cover_image` 在列表接口中解析为优化后的缩略图 URL；若 API 字段发生变化，必须同步 OpenAPI、Orval 或小程序 API 类型、接口文档和测试。

详情页、预览图和其他需要高清展示的场景不应被迫使用列表缩略图。

### D2. 小程序端降低非首屏图片并发

商品卡片组件应使用小程序原生懒加载能力或等价视口触发策略，优先展示首屏可见图片。首页 `new_products`、`hot_products`、`all_products` 同时存在时，非首屏和后续瀑布流图片应延迟加载，避免一次性压满体验版网络请求。

### D3. 后端 `/media` 图片响应补齐缓存与观测

受控媒体读取继续由后端代理，保持安全过滤和单 Bucket 策略。图片响应应补充合理的 `Cache-Control`、`ETag` 或 `Last-Modified` 等缓存能力，并记录媒体读取耗时、状态码、对象缺失和尺寸/类型相关信息。观测日志不得记录 Authorization header、Cookie 或真实客户敏感信息。

### D4. 对象引用一致性纳入修复闭环

公开 SKU 主图、缩略图和对象存储对象必须可被校验。实现阶段应提供脚本、测试或管理端补偿流程，覆盖“公开 SKU 引用对象不存在”“无主图 SKU 降级”“缩略图缺失时回退原图或占位”的场景，避免用户误以为所有慢加载都是网络问题。

### D5. 验收以体验版证据为准

本 BUG 的结论来自体验版现象，修复验收必须包含体验版或等价生产环境的证据：首屏商品卡片图片加载完成时间、媒体请求失败率、对象缺失清单和至少 320/375/430 pt 视口截图或录屏。若无法取得真机/体验版数据，验收记录必须标记 blocked 或 follow_up。

## Risks / Trade-offs

- [Risk] 缩略图生成需要处理历史数据 → Mitigation: 先实现按需生成或回填脚本，并允许缩略图缺失时安全回退。
- [Risk] 图片字段契约变更影响小程序和 Web 调用方 → Mitigation: 优先保持 `cover_image` 兼容；新增字段时同步类型、文档和测试。
- [Risk] 缓存头配置错误导致图片更新不及时 → Mitigation: 使用对象版本、ETag 或带版本的 URL；上传替换图片时刷新引用或版本参数。
- [Risk] 日志恢复 `/media` 观测后噪声过大 → Mitigation: 仅记录结构化摘要、慢请求和失败请求，避免记录大对象内容或敏感 header。

## Migration Plan

1. 采集体验版基线：小程序 Network 面板、媒体请求耗时、失败率和首屏图片完成时间。
2. 审计公开 SKU 图片对象引用，区分缺图、对象不存在、原图过大、网络慢和缓存缺失。
3. 实现列表缩略图生成/读取策略，并同步公开 SKU 列表图片 URL 契约。
4. 调整小程序商品卡片懒加载、占位、失败降级和首页分区图片加载优先级。
5. 为 `/media` 图片响应补充缓存头和失败/慢请求观测。
6. 运行回归测试和体验版 evidence，确认图片加载速度、失败降级和安全边界。

回滚策略：保留原图 URL 与旧字段兼容；缩略图策略异常时回退原 `cover_image` 读取，同时保留小程序懒加载和占位降级；缓存头异常时撤回缓存配置但继续通过后端安全代理读取。

## Open Questions

- 列表缩略图目标尺寸和质量参数是否采用统一默认值，还是按不同卡片尺寸区分。
- 体验版当前慢加载是否主要由对象缺失、原图体积、后端代理耗时、微信域名链路或并发请求数造成，需要基线数据最终确认权重。
