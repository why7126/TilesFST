## Context

`REQ-0068-miniapp-sku-video-fullscreen-actions` 已评审通过，来源于微信小程序商品详情页视频体验增强诉求。当前 SKU 详情页已经支持图片与视频混合轮播、视频用户主动播放、封面兜底、页面隐藏暂停和商品详情分享，但视频全屏入口、全屏态长按操作菜单、保存视频和平台降级尚未形成 OpenSpec 契约。

本 Change 只创建实现前的 OpenSpec 设计和规格，不写 `src/`。后续实现预计主要影响 `src/miniapp/pages/tile-detail/index.*`，并需要小程序静态测试、DevTools evidence 和真机 evidence。

关键约束：

- 微信小程序 `video` 组件的全屏态、长按、自定义菜单和保存视频能力存在平台限制，不能在设计阶段假定完全可自定义。
- 项目要求小程序上传、视频播放和图片预览必须考虑平台限制。
- 视频 URL 必须来自详情接口返回的安全可播放 URL，不得拼接 raw object key 或直连未授权对象存储。
- 小程序运行事实源存在 `.ts` 源与 `.js` 运行入口漂移风险，后续实现必须同步两者并补静态测试。
- 真机能力不可由静态测试或 DevTools 自动替代，验收记录必须区分 `static_test`、`devtools`、`real_device`、`blocked` 和 `follow_up`。

## Goals / Non-Goals

**Goals:**

- 为 SKU 详情页视频媒体补充明确全屏入口要求。
- 支持进入微信小程序视频全屏播放态，并在退出后保持当前 SKU 与媒体上下文。
- 设计全屏态长按操作菜单或平台允许的等价交互，覆盖“转发给朋友”“保存视频”“取消”三个用户意图。
- 复用商品详情页既有分享契约，确保转发路径保留 `skuId` 和分享来源参数。
- 约束保存视频必须遵守微信权限、下载、临时文件、相册保存和平台限制。
- 明确降级策略、静态测试、DevTools / 真机 evidence 和运行入口同步要求。

**Non-Goals:**

- 不实现视频转码、压缩、多清晰度、HLS / DASH 或 CDN 播放。
- 不新增视频海报、营销海报或朋友圈图片海报。
- 不新增管理端菜单配置、保存权限配置、分享文案配置或按钮开关。
- 默认不新增 API、数据库字段或 Orval 类型；仅当实现期确认保存视频必须依赖签名下载 URL 或额外媒体字段时再同步扩展。
- 不放宽 MinIO 权限，不暴露 bucket、endpoint、object key 或密钥。

## Decisions

1. **优先使用微信原生视频能力，必要时补可发现的等价入口。**

   - 方案：先确认原生 `video` 控制条是否可满足全屏入口；若原生入口不够明显或验收不可感知，再增加自定义全屏入口调用 VideoContext。
   - 原因：原生控件更符合微信平台全屏和播放控制行为，减少自绘控制条和平台兼容风险。
   - 替代方案：完全自定义视频控制层。暂不采用，因为全屏态、进度、系统手势和长按菜单都受平台限制，复杂度高且容易与原生控件冲突。

2. **全屏态长按菜单采用“能力确认 + 等价降级”策略。**

   - 方案：实现前先确认微信原生全屏态是否允许拦截长按或自定义菜单。若支持，展示包含“转发给朋友”“保存视频”“取消”的菜单；若不支持，提供平台允许的等价入口，并在验收记录中说明差异。
   - 原因：用户诉求是三个操作意图可达，而不是必须突破平台限制自绘系统菜单。
   - 替代方案：强制宣称长按自定义菜单必达。拒绝该方案，因为可能与微信小程序真实能力不一致。

3. **转发给朋友复用现有 SKU 详情页分享契约。**

   - 方案：菜单“转发给朋友”触发商品详情页既有分享对象或等价分享路径构造，保留当前 `skuId` 和 `source=share`。
   - 原因：REQ-0064 已建立小程序页面分享路径、参数保留和埋点不阻断规则，复用可以降低路径漂移。
   - 替代方案：为视频全屏态创建独立分享接口或后台配置。暂不采用，超出当前范围。

4. **保存视频默认基于现有安全媒体 URL，失败可提示。**

   - 方案：优先尝试使用详情接口返回的安全视频 URL 完成下载到临时文件与保存相册；如果平台、跨域、权限或视频格式不允许保存，展示明确失败提示。
   - 原因：当前需求不要求所有视频强制保存成功；保存能力必须服从微信与安全媒体链路边界。
   - 替代方案：新增签名下载 URL 或公开对象存储直链。签名 URL 仅作为实现期确认后的条件分支；公开对象存储直链不采用。

5. **验收以静态测试 + DevTools + 真机 evidence 分层。**

   - 方案：静态测试覆盖 WXML/JS/TS 运行入口和关键逻辑；DevTools 覆盖 320/375/430 pt 布局；真机覆盖全屏、菜单或降级、转发、保存提示。
   - 原因：视频全屏、相册保存和微信分享属于平台行为，不能只靠静态测试宣称通过。
   - 替代方案：只跑静态测试。拒绝，因为历史复盘已明确小程序真机能力不可自动化替代。

## Risks / Trade-offs

- **微信全屏态不支持自定义长按菜单** → 在 tasks 中设置平台能力确认项；若不可行，采用等价入口并在验收中记录 N/A / 降级原因。
- **远程视频无法直接保存到相册** → 使用下载临时文件 + 保存相册路径；失败时提示“视频暂不可保存”或权限相关文案，不阻断播放。
- **新增签名下载 URL 会扩大 API 范围** → 默认不新增；若必须新增，补 API、OpenAPI、Orval、docs 和 tests，并在验收记录写明。
- **自定义按钮遮挡媒体计数或原生胶囊** → 按小程序 prototype/context 与 miniapp-custom-navigation best practice 做 320/375/430 pt evidence。
- **`.ts` / `.js` 运行入口漂移** → 实现时同步 `index.ts` 与 `index.js`，并补小程序静态测试。

## Migration Plan

1. OpenSpec apply 阶段先确认微信 `video` 全屏、长按、自定义菜单、保存视频 API 和权限边界。
2. 在小程序 SKU 详情页实现全屏入口和全屏状态处理。
3. 根据平台能力实现长按菜单或等价入口，接入分享、保存和取消。
4. 补充小程序静态测试、运行入口同步检查、DevTools evidence 和真机 evidence。
5. 若没有 API/DB/Orval 变化，在验收记录中写明 N/A；若有签名下载 URL 等契约变化，同步相关文档与测试。

回滚策略：关闭或隐藏自定义全屏入口 / 菜单入口，保留原生视频播放能力；若保存视频异常，可仅保留转发入口并记录 follow-up。

## Open Questions

- 微信原生 `video` 全屏态是否允许自定义长按菜单或拦截长按事件。
- 保存视频对当前生产安全媒体 URL、域名、文件大小、格式和临时文件策略的限制。
- 自定义全屏入口是否必要，还是原生控制条已足够满足“明确可感知”。
- 保存视频失败文案是否需要区分权限拒绝、网络异常、格式不支持和平台限制。
