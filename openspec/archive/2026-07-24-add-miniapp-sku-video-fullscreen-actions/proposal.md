## Why

微信小程序商品详情页已经支持视频播放，但“视频全屏入口”和“全屏态长按操作菜单”尚未成为明确产品契约。补齐该能力可以让装修客户、设计师和门店导购更沉浸地查看商品视频，并在微信场景中完成转发、保存或取消等素材传播操作。

## What Changes

- 在 SKU 详情页视频媒体上明确全屏播放入口，可使用微信原生控制条或项目自定义入口。
- 支持用户主动进入微信小程序视频全屏播放态，并在退出后回到当前 SKU 与当前媒体上下文。
- 在全屏播放态提供长按操作菜单或平台允许的等价交互，覆盖“转发给朋友”“保存视频”“取消”。
- “转发给朋友”复用商品详情页既有分享路径、标题、封面与 `skuId` 参数。
- “保存视频”遵守微信权限、下载、临时文件、相册保存和平台限制；失败时给出可理解提示。
- 明确微信原生 `video` 全屏态自定义长按菜单能力需要在实现期确认，若不可行必须记录降级方案。
- 补充小程序静态测试、DevTools evidence、真机 evidence、运行入口同步和埋点不阻断验收。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `miniapp-sku-detail-page`: 增强 SKU 详情页视频媒体浏览能力，新增视频全屏入口、全屏态操作菜单、转发 / 保存 / 取消交互、平台降级和验收证据要求。

## Impact

- 小程序：预计影响 `src/miniapp/pages/tile-detail/index.*` 的 `video` 组件属性、VideoContext 全屏控制、长按菜单或等价入口、分享触发、保存视频、提示和埋点。
- API：默认不新增 API；如实现期确认保存远程视频必须依赖签名下载 URL 或额外媒体字段，必须同步 OpenAPI / Orval / docs / tests。
- 数据库：默认不新增表或字段。
- 对象存储 / 媒体：继续使用后端安全媒体 URL，不放宽 MinIO 权限，不暴露 object key、bucket、endpoint 或密钥。
- 测试与验收：需要小程序静态测试、`.ts` / `.js` 运行入口同步检查、DevTools 320/375/430 pt evidence、至少一台真机 evidence 或明确 blocked / follow_up。
