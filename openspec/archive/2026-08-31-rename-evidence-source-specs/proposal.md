# 提案：收敛证据来源声明规格命名

## 背景

前序治理已将环境分层 evidence 从默认 workflow 门禁降级为手动证据来源诊断工具，但正式 OpenSpec 中仍存在“环境分层”“生产证据后置”“强脚本门禁”等旧标题或旧语义。它们容易让后续命令误以为项目仍采用发布目标分层或生产专属门禁。

## 变更内容

- 将 agent workflow 中旧“环境分层 evidence 门禁”重命名并收敛为“证据来源声明边界”。
- 将 agent workflow 中旧“环境证据强脚本门禁”重命名为“证据来源诊断工具”。
- 将 testing 中旧“环境证据脚本测试覆盖”重命名为“证据来源诊断测试覆盖”。
- 将 media 与 miniapp 规格中的旧环境分层 requirement 收敛为“证据来源声明”语义。
- 保留 `production_only_pending` 仅作为历史兼容字段，不作为新记录推荐分类。

## 非目标

- 不修改业务 `src/` 代码。
- 不移除手动诊断脚本能力。
- 不恢复 development / production 发布目标分层。
- 不直接修改 `openspec/specs/` 正式规格；正式规格合并由归档流程完成。
