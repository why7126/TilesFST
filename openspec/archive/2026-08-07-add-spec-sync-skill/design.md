## 设计目标

`/spec-sync` 面向“学习其他项目 Harness 工程并迁移治理经验”的场景。它不是普通文件复制命令，而是一个分阶段治理同步工作流：

1. 读取学习对象的治理结构。
2. 生成候选学习清单。
3. 等待用户确认。
4. 在 active OpenSpec Change 与 Sprint scope 约束下应用到本项目。
5. 输出学习报告和更新清单。

## 输入模型

- 学习对象：本地项目路径或 GitHub 项目 URL。
- 学习模式：
  - 自动学习：未指定时默认，综合识别可复用的规范、技能、脚本、部署治理和文档索引。
  - 指定学习内容：用户可指定技能、UI 设计系统、API 治理、测试治理、部署治理等主题。

## 学习范围

学习某个主题时仍必须横向检查相关模块，避免只读取单一目录导致结论片面：

- 项目入口：`AGENTS.md`、`project.yaml`、`DOCUMENT_METADATA_INDEX.md`。
- 全局规范：`rules/`、`docs/`。
- Agent 能力：`.agents/`、`.cursor/`、`.codex/`、`.kiro/`、`.opencode/`、`.claude/` 等。
- 自动化脚本：`scripts/`。
- 部署与环境：`docker-compose*.yml`、`.env.example`、`deploy/`。

## 安全边界

- 对 GitHub URL 的学习必须先获取只读快照；如需网络或 clone，应按权限策略请求用户批准。
- 学习对象必须被视为外部只读输入；无论本地路径还是 GitHub 快照，`/spec-sync` 都不得修改学习对象中的代码、文档、配置、依赖锁文件、Git 状态、缓存、生成物或运行时数据。
- `/spec-sync` 不得在学习对象路径下运行会写入文件或改变仓库状态的命令，包括安装依赖、格式化、迁移、生成、测试修复、提交、分支、reset、clean 或 push。
- 学习对象中的密钥、`.env`、真实客户数据、运行时数据库、构建产物和依赖目录不得复制到本项目。
- 应用阶段禁止修改 `src/`。
- 不直接恢复本项目明确不维护的 `.cursor/`、`.codex/`、`.claude/`、`.opencode/`、`.kiro/` 入口；如确需引入，必须通过 OpenSpec Change 先更新目录边界与 AGENTS。

## 输出设计

学习阶段输出：

- 学习对象和模式。
- 读取到的 Harness 模块摘要。
- 建议应用的内容、理由、风险、目标文件。
- 明确等待用户确认，默认不落盘应用。

应用阶段输出：

- 应用到本项目的具体内容。
- 修改文件清单和原因。
- 未采纳内容及原因。
- 学习报告路径。
- 学习对象只读保护结果。
- API、数据库、Web、小程序、管理端、Orval、Docker、测试影响说明。
