## Background

BUG-0097 关联 `REQ-0006-tile-sku-management`。管理后台 SKU 列表需要帮助运营快速判断图片与视频素材完整度，但当前素材列把已有图片的正常状态也渲染成「主图已设」标签。

## Root Cause

- 直接原因：管理端 SKU 列表素材列使用 `has_main_image` 渲染「主图已设 / 缺主图」标签。
- 根本原因：素材列展示策略没有与“有图片即有主图兜底”的业务规则对齐，导致正常状态被当作需要强调的标签展示。
- 分类：`design`，属于管理端 UI 信息层级缺陷。

## Fix Approach

1. 调整管理端 SKU 列表素材列渲染。
2. 素材列不再展示主图状态标签，包括「主图已设」和「缺主图」。
3. 保留 `image_count` 与 `video_count` 展示，并将其作为素材列唯一展示内容。
4. 删除管理端 SKU 列表中的素材完整度条件筛选，常规列表请求不再提交 `material_completeness`。
5. 对缺图、缺视频或素材不完整状态，继续依赖图片数量与视频数量识别。
6. 不修改后端 API、Pydantic Schema、OpenAPI、Orval 生成物或数据库结构。

## Test Strategy

- 前端组件/页面测试：验证已有图片 SKU 的素材列不出现「主图已设」或「缺主图」。
- 前端组件/页面测试：验证图片数量与视频数量仍展示。
- 前端回归测试：验证缺主图 SKU 的素材列也只展示图片/视频数量，且页面不展示素材完整度筛选控件、不提交 `material_completeness` 请求参数。
- 手工或 E2E 验收：检查 SKU 列表行高、列宽、状态列和操作列无遮挡或布局抖动。

## Risks

- 移除标签与筛选后，运营需要通过素材数量判断素材状态。该风险通过保留图片/视频数量展示缓解。
- 若实现误删数量展示，可能降低异常素材识别能力；测试必须覆盖缺失状态仍可通过数量识别。
