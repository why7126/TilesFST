## 上下文

`BUG-0135` 的根因状态为 `probable`：代码定位显示品牌详情页证书卡图片 `src` 使用 `item.thumbnail_url || item.file_url`，后端 `get_brand_certificates()` 同时返回 `file_url` 与 `thumbnail_url`。当图片证书缺缩略图、缩略图对象不可读或字段为空时，卡片展示会直接请求证书原文件。

同类证书列表页已有更安全策略：只有图片证书且存在 `thumbnail_url` 且未加载失败时才渲染图片，否则展示 PDF 或证书占位。本 Change 将品牌详情证书卡与证书列表卡片策略对齐，并为其他证书卡片摘要入口建立验收约束。

## 目标与非目标

**目标：**

- 小程序证书卡有缩略图时优先使用 `thumbnail_url`。
- 小程序证书卡缺缩略图、缩略图不可读或图片加载失败时展示占位或受控失败态，不请求 `file_url` 原文件。
- 图片证书和 PDF/文档证书的对象前缀、端侧展示、预览/打开动作分流清晰。
- API、OpenAPI、Orval、测试、媒体四联和小程序 Network evidence 同步闭环。

**非目标：**

- 不新增通用媒体规格生成平台。
- 不替代 `fix-miniapp-certificate-detail-display-url` 的证书详情顶部 `display_url` 修复。
- 不引入生产 CDN 正式接入。
- 不自动执行生产历史对象写入维护任务。
- 不改变管理端品牌证书上传权限、MinIO 单桶策略或证书详情预览能力。

## 设计决策

### 决策 1：卡片展示从原文件 fallback 改为占位 fallback

品牌详情证书 Tab、证书列表和关联证书摘要入口的图片节点应只使用 `thumbnail_url`、卡片专用小图 URL 或静态占位资源。`file_url`、`original_url`、`preview_url` 仅可用于详情、预览、打开或下载动作，不得作为卡片图片 `src` 的默认兜底。

### 决策 2：端侧显式记录图片加载失败态

小程序端应在缩略图加载失败后标记当前证书卡的失败状态，并展示统一占位。失败态不得重新尝试原文件 URL，以避免把网络错误或缩略图缺失转化为原图下载。

### 决策 3：后端字段语义保持可兼容但需明确用途

如品牌证书摘要接口继续返回 `file_url`，该字段必须被实现和文档标注为详情、预览或打开动作使用。卡片展示可新增或复用 `thumbnail_url` / `card_image_url` 等轻量字段，但普通卡片渲染不得消费原文件字段。

### 决策 4：图片和文档证书按前缀与行为分流

JPG、JPEG、PNG、WebP 证书图片使用 `images/default/brand-certificates/` 或等价图片前缀，并验证缩略图对象存在性或占位 fallback。PDF 或其他文档证书使用 `files/default/brand-certificates/`，卡片展示文件类型占位，预览或打开动作由详情页或文件打开能力处理。

### 决策 5：证据以媒体四联和小程序 Network 为准

实现完成后必须覆盖 key、object、URL、render 四联：记录脱敏 key 前缀、对象存在性、卡片 URL 类型、HTTP 状态、资源大小、耗时、缓存状态和页面 render 结果。静态测试可以作为回归门禁，但不能替代 DevTools、真机或体验版 Network evidence。

## 风险与取舍

- 缺缩略图时卡片会从“可能显示原图”变为“显示占位”：这是有意取舍，用稳定性能和访问边界换取卡片缩略图缺失时的视觉降级。
- 老数据可能缺少缩略图对象：实现阶段可通过 dry-run 审计识别，但不得默认写生产对象存储。
- 老客户端可能仍读取 `file_url`：后端可保留兼容字段，但新小程序卡片必须停止将其作为图片 `src` fallback。
- 该 Change 与 BUG-0134 都涉及品牌证书图片规格，实施时可共享 helper 和测试夹具，但验收证据必须分别回填到各自 BUG。

## 迁移与回滚

- 先修小程序卡片绑定和失败态，再按需补后端字段说明或卡片字段，最后补测试与文档。
- 如涉及历史对象或缩略图补齐，只能先 dry-run 输出脱敏统计，再由人工确认 apply；apply 后记录幂等摘要。
- 回滚时保留对象存储数据，不删除历史对象；仅回退端侧卡片绑定或接口字段映射，并记录卡片可能重新请求原文件的已知风险。
