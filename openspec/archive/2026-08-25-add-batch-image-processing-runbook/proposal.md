## 背景

`REQ-0122-batch-image-processing-runbook` 已确认：图片转换脚本、`thumbnail` / `display` 派生生成、缩略图专项重建、对象 key 迁移和生产媒体维护步骤已经分散在脚本、规则、经验文档与验收记录中，缺少一份可执行、可审计、可投影到版本使用文档的 Runbook。

本变更新增批量图片处理 Runbook 能力，统一说明生产执行、安全门禁、回滚边界和验收证据，降低后续媒体维护、升级交付和客户现场执行时的误操作风险。

## 变更内容

- 新增批量图片处理 Runbook，覆盖图片转换脚本、`thumb` / `display` 派生生成、缩略图专项重建、对象 key 迁移、生产执行步骤、安全门禁和验收证据模板。
- 明确 Runbook 长期事实源位于 `docs/`，并投影到 `releases/vX.Y.Z/usage-docs/` 作为版本交付快照。
- 明确脚本清单必须标注现有脚本、需修改脚本和新增脚本，不把尚未实现的脚本写成可直接执行。
- 明确所有生产 apply 类任务必须先 dry-run、备份确认和脱敏审计，且默认不得包含真实密钥、真实客户数据或未脱敏对象 key。
- 明确对象 key 迁移以数据库快照和 bucket / prefix 快照恢复为主，未验证反向脚本不得作为默认可靠回滚。

## 能力影响

### 新增能力

- `batch-image-processing-runbook`：定义批量图片处理 Runbook 的内容范围、双投影归属、脚本说明、安全门禁、对象 key 迁移回滚边界和验收证据要求。

### 修改能力

- 无。现有 `media-multi-variant-images`、`object-storage`、`prod-media-maintenance-jobs` 已提供媒体处理和维护作业行为底座；本变更新增 Runbook 文档化与投影契约，不改变既有运行时能力。

## 影响范围

- 文档：新增或更新长期 Runbook 事实源，并在版本使用文档快照中投影。
- 发布/交付：后续版本交付需要携带该 Runbook 快照和 manifest 证据。
- 运维：生产执行步骤、dry-run/apply 门禁、备份确认、脱敏输出和二次审计流程被明确。
- 后端/API/数据库/Web/小程序/管理端：本 Change 阶段不直接改业务代码、接口、Schema 或 UI；若实现阶段发现必须新增脚本或调整脚本行为，应在任务中同步测试和相关文档。
