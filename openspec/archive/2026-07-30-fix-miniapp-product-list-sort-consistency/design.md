## 背景

`BUG-0091` 指出小程序搜索商品结果页、分类商品列表页需要与品牌详情页商品列表保持一致排序。现有 `miniapp-brand-detail-home-page` 规格已要求品牌主页商品 Tab 按 `published_at` 升序、SKU ID 升序展示，历史数据 `published_at` 为空时使用 `created_at` 兜底。`miniapp-product-list-page` 规格对品牌过滤查询已有同等默认排序描述，但分类查询和普通搜索入口尚未明确使用该排序。

## 根因

直接原因是商品列表相关入口没有统一复用品牌详情页现行排序策略。根本原因是商品列表通用能力缺少跨入口排序契约，分类入口、搜索入口、品牌详情页之间缺少统一验收项；搜索结果页若存在相关性排序，也缺少与默认发布时间排序的优先级说明。

## 修复方案

1. 将商品列表页默认排序定义为：`published_at` 升序、SKU ID 升序；`published_at` 为空时使用 `created_at` 作为排序兜底。
2. 分类入口包括一级分类聚合查询和二级分类精确查询，未显式请求新品、热销、价格排序或搜索相关性排序时，均使用默认排序。
3. 搜索入口在普通关键词匹配场景下使用默认排序；若产品明确保留相关性排序，则必须在实现和验收材料中声明相关性优先，且不得破坏分页稳定性。
4. 后端查询排序应优先成为事实源，避免小程序端在分页后重新排序导致重复、漏项或顺序漂移。
5. 首页“全部产品”列表保持既有策略，不因本修复改变排序。

## 测试策略

- 后端测试：构造同一品牌、同一分类、关键词命中的多条公开 SKU，覆盖 `published_at` 不同、相同、为空的排序组合。
- 分页测试：覆盖第一页、加载更多、刷新后顺序稳定，确认无重复、漏项、跨页漂移。
- 小程序测试：覆盖品牌详情页商品 Tab、搜索商品结果页、一级分类商品列表、二级分类商品列表。
- 回归测试：确认首页“全部产品”列表排序不变；确认新品榜、热销榜、价格排序或明确的搜索相关性排序不被误改。

## 风险与边界

- API 请求/响应字段原则上不变；若实现需要新增排序参数或返回排序说明，必须同步 OpenAPI、Orval、docs 和测试。
- 不新增数据库字段；如实现阶段发现排序字段缺索引导致性能风险，应通过同一 Change 补充 schema、迁移和数据库文档。
- 不允许通过小程序端硬编码完整排序替代后端稳定分页排序。
