# 修复小程序 RUM 与性能观测展示口径

## 背景

BUG-0129 暴露出小程序 RUM 上报与管理后台性能观测展示之间的同源口径问题：小程序把运行环境名 `production` 作为 `app_version` 上报，性能样本缺少 `request_id`，小程序指标名直接显示内部枚举，空态样式不符合管理端列表体验，聚合列表又因为隐藏 `network_type`、`device_class` 分组维度而看起来存在重复项。

这些问题不影响业务主流程，但会降低性能观测的可信度、可读性和排障效率，应作为同一修复范围处理。

## 变更内容

- 规范小程序 RUM 版本号来源，使小程序与 Web 管理后台使用统一产品版本号口径，不再把 `production`、`development` 等环境名写入 `app_version`。
- 为小程序 RUM 性能事件补齐受控 `request_id`，接口耗时指标优先复用统一 API 封装生成的请求追踪标识。
- 在管理后台性能观测聚合页、样本页和指标筛选中补齐小程序指标中文标签。
- 优化性能观测聚合列表空态，使无数据时的字号、颜色、间距和表格内层级与管理端列表体验一致。
- 在聚合列表展示完整分组键，至少显示网络类型和设备类别，避免隐藏分组维度导致用户误判重复项。

## 影响范围

- 微信小程序 RUM 上报链路：版本号、`request_id`、启动与接口耗时指标。
- Web 管理后台性能观测页：聚合列表、样本明细、指标筛选、空态展示和查看样本上下文。
- 后端性能聚合接口既有字段展示口径：本 Change 不要求新增数据库字段，优先复用当前聚合结果中的 `network_type`、`device_class`、`request_id`。

## 回滚计划

- 若小程序上报调整出现异常，可回滚小程序端版本号与 `request_id` 生成逻辑，后端仍按可选字段兼容历史样本。
- 若管理端展示调整影响列表可用性，可回滚前端列展示、指标标签和空态样式变更，不影响后端数据写入。
- 历史已写入 `production` 或空 `request_id` 的样本不做强制迁移，管理端按历史事实展示或标记未知。
