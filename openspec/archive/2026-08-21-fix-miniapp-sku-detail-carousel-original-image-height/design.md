# 设计说明

## 根因摘要

根因状态为 `probable`。当前 SKU 详情接口图片媒体 `url` 优先返回同目录 `.thumb`，小程序详情页首屏 `<image>` 使用 `item.url` 渲染；`.thumb` 默认最大宽高较小，在详情页大图区域中被放大后导致纹理和文字细节不清晰。轮播容器高度固定为 `680rpx`，无法根据瓷砖详情展示和不同小程序视口做更合适的媒体区比例。

## 修复方案

1. 详情页展示 URL 语义
   - SKU 详情页图片媒体首屏展示源应使用原图或详情级高清展示图。
   - `preview_url` 继续指向原图或等价高清 URL。
   - 响应不得暴露原始 object key、对象存储 endpoint、bucket 名称、Authorization header、Cookie 或未授权素材路径。

2. 列表与推荐位性能边界
   - 商品列表、商品卡片、首页推荐、品牌商品列表和 Banner 保持 `.thumb` 或等价轻量图片 URL。
   - 修复不得把列表接口、卡片组件或推荐位展示源切到原图。
   - 测试必须覆盖详情页高清展示与列表缩略图策略的差异。

3. 小程序商品详情页布局
   - 轮播高度从固定 `680rpx` 调整为基于视口宽度、安全区和上限约束的媒体区。
   - 媒体区应更适合瓷砖竖图、横图和展板图查看。
   - 320 到 430px 逻辑宽度下，商品名称或关键商品信息仍应在首屏露出，不得被媒体区完全挤出。

4. 验收证据
   - 媒体四联验收覆盖 key、object、URL、render。
   - key/object 证据记录原图与 `.thumb` 的脱敏关系、像素尺寸、MIME 和 bytes 摘要。
   - URL 证据区分详情展示 URL、预览 URL、列表卡片 URL。
   - render 证据需要小程序 DevTools、真机或体验版截图，覆盖清晰度、高度和首屏信息露出。

## 测试策略

- 后端测试覆盖 SKU 详情图片媒体展示 URL 不再优先返回 `.thumb`，预览 URL 仍为高清 URL。
- 后端测试覆盖商品列表、商品卡片或推荐位仍返回 `.thumb`。
- 小程序静态测试覆盖详情页首屏图片绑定高清展示源，预览绑定高清预览源。
- 小程序样式测试或静态约束覆盖轮播高度公式、320/375/430px 视口和首屏商品信息露出要求。
- 媒体四联验收记录 key/object/URL/render，缺少真机或体验版证据时不得写作完全通过。

## 风险

- 原图体积过大可能影响详情页首屏加载，需要在实现中评估详情级展示图、懒加载或渐进加载策略。
- 存量原图若本身低清，仅切换 URL 不能改善视觉，需要记录为素材质量边界。
- 若现有测试或正式 spec 仍断言详情首屏使用 `.thumb`，必须同步更新，否则会把旧性能策略误判为正确行为。
