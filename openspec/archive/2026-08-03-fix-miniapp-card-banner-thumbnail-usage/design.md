## 背景

BUG-0110 要求核查并修复小程序商品卡片、品牌卡片、证书卡片和 Banner 未按缩略图处理的遗漏。现有 specs 已分别约束商品卡片、品牌列表和证书卡片的缩略图优先策略，但不同页面和组件仍可能独立读取原图字段，Banner 也缺少明确的轻量展示图约束。

## 缺陷分析报告

- 现象：小程序多个卡片和 Banner 场景应使用缩略图或轻量展示图，但当前尚未确认所有场景均按该策略处理。
- 复现：进入商品列表、品牌列表、证书列表和包含 Banner 的页面，检查图片请求或渲染字段是否为缩略图 URL。
- 影响：移动端首屏、列表滚动和 Banner 展示可能加载原图，造成性能回退；缩略图缺失时若无降级策略，可能出现空白、破图或布局跳动。
- 严重等级：`high`，覆盖多个高频展示场景，但未确认造成数据损坏或功能完全不可用。
- 关联：`BUG-0100-thumbnail-size-equals-original`。

## 根因分析

根因倾向于小程序展示层和公开响应字段使用口径不统一：

- 商品、品牌、证书和 Banner 分属不同页面/组件，容易各自选择 `image_url`、`logo_url`、`file_url`、`cover_image` 等字段。
- 卡片小图场景和详情/预览高清场景缺少统一命名和优先级约束。
- Banner 作为运营位可能沿用上传原图字段，未明确轻量展示图或尺寸/压缩策略。
- 缩略图缺失、空值、加载失败和原图回退的顺序可能在各场景不一致。

## 修复设计

1. 为小程序卡片类图片建立统一字段选择顺序：
   - 缩略图或轻量展示图 URL。
   - 可访问原图 URL。
   - 统一占位图或首字母占位。
2. 商品卡片继续以 `cover_image` 或等价字段承载小图展示 URL，但该字段必须解析为真实轻量资源；详情/预览使用原图字段。
3. 品牌列表卡片和品牌卡片组件优先使用品牌 Logo/图片缩略图；缩略图缺失时回退原图、品牌首字或占位。
4. 图片证书卡片优先使用证书缩略图；证书详情和图片预览继续使用原图/文件 URL。
5. 首页和品牌列表 Banner 使用后端提供的缩略图、展示图或符合性能策略的安全 URL；自定义上传 Banner 图片时必须同步生成同目录真实缩略图对象，避免公开接口只返回 `.thumb` URL 但媒体读取层因对象缺失回退原图。
6. 品牌列表接口只下发展示卡片所需的小图 URL；详情页、分享或预览所需的原图 URL 保留在详情接口，避免列表 payload 携带多个未使用图片 URL。小程序页面不再额外复制 `logo_display_url`，直接以缩略图字段驱动 `<image>` 渲染。
7. 保持所有 URL 来自后端授权、公开安全 URL 或对象存储适配层，不暴露原始 object key、内部 endpoint、Authorization header 或 Cookie。

## 测试策略

- 补充或更新小程序静态测试，检查商品卡片、品牌卡片、证书卡片和 Banner 的图片字段映射。
- 补充后端公开接口测试；若响应字段变化，覆盖商品列表、品牌列表、公开证书列表和首页聚合/Banner 响应。
- 覆盖缩略图缺失、空值和加载失败降级，不出现空白、破图或阻塞跳转。
- 在微信开发者工具或体验版手工验收商品、品牌、证书和 Banner 场景。
- 若 API 响应字段变化，运行 OpenAPI / Orval 生成与相关前端测试。

## 风险

- 某些历史媒体缺少缩略图对象，若降级顺序处理不当可能导致空白。
- Banner 图片比例和清晰度要求可能与缩略图尺寸冲突，需要区分 Banner 展示图和卡片缩略图。
- 若只修前端字段而后端未返回缩略图，可能无法闭环性能收益。
- 若上传运行环境缺少图片处理依赖或缩略图生成失败，媒体服务可能按既有策略回退原图；验收必须检查缩略图对象真实存在，而不能只看 URL 后缀。

## 非目标

- 不新增视频转码、多清晰度视频或复杂媒体处理能力。
- 不改变详情页、图片预览或证书文件打开的高清/原文件策略。
- 不新增运营报表、埋点分析或管理端上传交互能力，除非实现发现现有字段无法满足本 BUG 修复。
