## 背景与原因

BUG-0110 暴露出小程序商品卡片、品牌卡片、证书卡片和 Banner 可能未统一使用缩略图或轻量展示图的问题。该问题会让多个高频图片展示场景回退到原图直载，增加移动端首屏和列表滚动加载压力，并与 `BUG-0100-thumbnail-size-equals-original` 后续缩略图治理目标不一致。

## 变更内容

- 统一小程序商品卡片、品牌列表卡片、品牌卡片组件、证书卡片和首页 Banner 的图片字段选择策略。
- 卡片类小图场景必须优先使用后端受控缩略图或等价轻量优化图片 URL；缺失或加载失败时按明确顺序回退原图或占位。
- Banner 必须使用符合性能策略的展示图字段；若业务要求使用原图，必须有明确尺寸/压缩约束和降级策略。
- 保持详情页、图片预览和需要高清展示的场景继续使用原图或安全文件引用。
- 补充回归测试和小程序静态/手工验收，覆盖商品、品牌、证书、Banner、缩略图缺失和预览不回归。

## 回滚方案

- 若修复导致某一类卡片图片空白或加载失败，可回退该场景的字段选择改动，临时恢复原图读取，并保留占位降级。
- 若 Banner 展示图字段在部分数据上不可用，可先回退 Banner 到既有安全 URL 字段，同时记录数据补齐 follow-up。
- 回退不得影响详情页、图片预览、跳转或已有对象存储授权链路。

## 能力影响

### 新增能力

- 无。

### 修改能力

- `miniapp-product-list-page`: 商品卡片列表、搜索、首页推荐和品牌详情商品 Tab 必须优先使用真实缩略图或轻量图。
- `miniapp-brand-list-page`: 品牌列表卡片必须优先使用品牌 Logo/图片缩略图，并保持品牌详情原图入口。
- `miniapp-brand-card-component`: 复用品牌卡片组件时必须支持缩略图优先和 Logo 失败降级。
- `miniapp-certificate-list-page`: 图片证书卡片必须优先使用真实缩略图，详情/预览继续使用原图或文件引用。
- `miniapp-home`: 首页 Banner 和商品分区必须使用符合性能策略的展示图或已有商品缩略图策略。

## 影响范围

- 影响范围：微信小程序图片展示字段选择、公开接口响应字段使用、卡片/Banner 降级策略和回归测试。
- 可能影响公开 API 响应字段使用口径；若实现新增或调整响应字段，必须同步 OpenAPI / Orval / docs / tests。
- 不新增数据库表；若实现发现缺少缩略图字段来源，需在本 Change 内补充对应 schema、文档和测试。
- 来源 BUG：`BUG-0110-miniapp-card-banner-thumbnail-usage`。
