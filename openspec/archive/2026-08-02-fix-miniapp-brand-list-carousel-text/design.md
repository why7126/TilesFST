## Context

`REQ-0060-brand-list-page` 已交付并归档，正式能力 `miniapp-brand-list-page` 要求品牌列表页顶部提供品牌轮播区域，并与小程序首页轮播保持一致的基础交互体验。后续 `REQ-0086` 又补充新版品牌页首屏结构，允许 Hero 展示英文弱标签、主标题和辅助文案。

`BUG-0102` 的问题不在于是否允许页面存在设计文案，而在于轮播图区域残留了不应面向用户展示的开发/说明性文案：

- `BRAND GALLERY`
- `轮播图保持现有品牌页能力`

这些文案不是品牌轮播数据，也不是正式产品文案，展示后会干扰品牌列表页首屏视觉。

## Goals / Non-Goals

**Goals:**

- 移除品牌列表页轮播图区域中 `BRAND GALLERY` 与 `轮播图保持现有品牌页能力` 的用户可见展示。
- 保持品牌页轮播图现有图片加载、图片展示、轮播切换、点击或跳转能力。
- 保证文案移除后布局稳定，不出现空白占位、遮挡、错位、高度异常或内容重叠。
- 增加小程序静态测试或等价验证，防止类似说明文案再次进入品牌列表页。

**Non-Goals:**

- 不新增品牌轮播接口。
- 不修改后端品牌、Banner、SKU 或媒体数据模型。
- 不修改 Orval 生成客户端。
- 不重设计品牌列表页整体视觉、品牌卡片或类目胶囊交互。
- 不删除所有正式营销文案；只禁止本 BUG 指定的开发/说明性文案和同类调试提示进入轮播图区域。

## Decisions

### D1. 以展示层清理为默认修复路径

本 BUG 表现为固定文案残留，默认修复范围应在小程序品牌列表页 WXML/WXSS/TS/JS 或相关组件的展示层中处理。

如果文案来自页面模板或硬编码，应直接删除对应可见节点；如果来自临时 mock、占位字段或原型说明，应移除其渲染路径，而不是隐藏整个轮播图。

### D2. 保持轮播能力不变

修复不得通过删除轮播图容器、禁用轮播数据、移除点击处理或隐藏整个图片区块来规避问题。轮播图仍需满足现有 `miniapp-brand-list-page` 能力，包括图片展示、自动/循环播放、指示点以及有效项跳转。

### D3. 测试优先覆盖文案回归

后续实现应优先补充小程序静态测试或等价检查，断言品牌列表页模板和运行入口中不包含 `BRAND GALLERY` 与 `轮播图保持现有品牌页能力`。若测试框架已支持品牌列表页页面级断言，应同步覆盖轮播图容器仍存在、品牌列表页关键入口不回归。

## Risks / Trade-offs

- [Risk] 误删轮播图标题/副标题能力。Mitigation：只删除 BUG 指定的开发/说明性文案，保留数据驱动的正式标题、副标题或品牌内容。
- [Risk] 文案节点移除后布局留空。Mitigation：验收要求检查空白占位、错位、高度异常和内容重叠。
- [Risk] `.ts` 与 `.js` 运行入口不一致。Mitigation：实现时同步小程序实际加载的 `.js` 与源 `.ts`，或通过现有构建/同步流程保持一致。

## Verification Strategy

1. 静态检查品牌列表页 WXML/JS/TS/WXSS 中不再出现 `BRAND GALLERY` 与 `轮播图保持现有品牌页能力`。
2. 运行小程序静态测试或相关测试，确保品牌列表页关键模板未回归。
3. 使用微信开发者工具或真机查看品牌列表页，确认轮播图正常展示和切换，且两段多余文案不可见。
4. 确认变更范围不包含后端 API、数据库 schema、Orval 生成接口或 Docker Compose 配置。

## Open Questions

无阻塞问题。若产品后续希望保留某种正式品牌营销文案，应作为独立需求明确文案来源、展示位置和验收标准，不在本 BUG 修复中引入。
