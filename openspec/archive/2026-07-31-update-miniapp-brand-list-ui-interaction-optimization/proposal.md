## Why

REQ-0086 已确认微信小程序品牌列表页需要按新版设计稿优化 UI 与交互体验。现有品牌列表页已具备品牌入口、轮播、单品牌信息行、商品数量与末级类目汇总能力，但页面主题识别、品牌矩阵层级、品牌入口与类目入口的触控边界、底部 TabBar / Safe Area 以及 390pt 视觉稿一致性尚未形成 OpenSpec 契约。

本 Change 将新版品牌列表页体验沉淀为 `miniapp-brand-list-page` 的正式变更，使后续实现可以围绕既有能力做 UI/UE 更新，而不是重新发明品牌列表页。

## What Changes

- 按附件原型和截图明确品牌列表页新版视觉结构：自定义导航、品牌 Hero、品牌矩阵标题、单品牌卡片、类目胶囊和底部 TabBar 选中态。
- 明确品牌卡片上下分区交互：上行进入品牌详情，下行类目标签进入品牌 + 类目商品列表。
- 明确类目标签需要 `categoryId` 与 `categoryName` 支持精确跳转；若接口缺字段，需同步 API Schema、OpenAPI、Orval、小程序调用类型、文档和测试。
- 扩展小程序设备验收矩阵，覆盖 DevTools 320/375/390/430 pt、胶囊避让、TabBar 遮挡、加载/空/错态和真机 evidence 状态。
- 不改变品牌管理后台、品牌详情页结构、商品列表页整体视觉、类目管理规则、搜索筛选体系、数据库结构或对象存储策略。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `miniapp-brand-list-page`: 在既有品牌列表页能力上增加新版 UI/交互分区、类目胶囊独立点击、数据字段边界和设备验收要求。

## Impact

- 影响范围：
  - 小程序：`src/miniapp/pages/brand-list/**` 及可能复用的品牌卡片/导航/TabBar 样式。
  - API：如当前品牌列表公开接口未返回类目 ID 或品牌首字母/占位所需字段，需扩展响应 Schema。
  - OpenAPI / Orval：若 API 响应字段变化，必须同步生成与文档。
  - 测试：补充小程序静态测试、路由参数测试、事件冒泡/点击边界测试；API 字段变化时补充后端接口测试。
- 不影响：
  - 数据库结构。
  - 管理端品牌维护能力。
  - Web 展示端。
  - MinIO / 对象存储策略。
  - Docker Compose。

## Rollback Plan

如新版视觉或交互上线后出现严重问题，可回退小程序品牌列表页 UI 结构到当前已归档的 REQ-0083 单品牌卡片能力；接口新增字段需保持向后兼容，避免回退时破坏既有品牌列表数据消费。类目标签跳转若出现异常，可临时禁用类目点击入口并保留品牌详情入口，但不得把禁用状态作为长期验收结果。
