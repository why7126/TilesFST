# 提案：修复管理后台身份展示伪邮箱

## 背景

BUG-0128 已评审通过并纳入 `sprint-022`。当前管理后台在用户资料邮箱为空时，会在身份展示区域展示由前端拼接出的邮箱样式文本，例如 `username@tilesfst.com` 或 `admin@tilesfst.com`。该行为出现在左侧用户菜单触发区和个人资料页顶部身份栏，容易让用户误以为资料中存在真实邮箱。

历史个人资料需求曾允许侧栏邮箱为空时 fallback，但本次 BUG 已确认展示语义需要收敛：邮箱字段是可空的真实联系邮箱，前端不得创造伪邮箱。用户菜单栏只展示当前账号身份标识；个人资料页顶部身份栏只展示真实邮箱或省略邮箱片段。

## 变更目标

- 用户菜单栏只显示昵称；昵称为空时显示用户名。
- 用户菜单栏不显示邮箱、伪邮箱或任何副标题。
- 个人资料页顶部身份栏在邮箱为空时不拼接伪邮箱。
- 个人资料页顶部身份栏在邮箱非空时可以展示后端返回的真实邮箱。
- 个人资料编辑页“联系邮箱”输入框保留，且空邮箱保持为空。
- 更新前端测试，移除 `admin@tilesfst.com` 等伪邮箱兜底预期。

## 非目标

- 不新增用户管理页邮箱列或邮箱输入框。
- 不修改后端 API、数据库、Pydantic schema、OpenAPI 或 Orval 生成物。
- 不新增邮箱唯一性、邮箱登录、邮箱验证或发信能力。
- 不调整小程序或店主 Web。

## 能力范围

### 新增能力

无。

### 修改能力

- `web-client`：管理后台用户菜单与个人资料页身份展示语义。

## 影响范围

```yaml
impact:
  backend: false
  web: true
  miniapp: false
  admin: true
  database: false
  storage: false
  api: false
capabilities:
  new: []
  modified:
    - web-client
```

## 回滚计划

- 若修复造成用户菜单布局异常，可回滚 `AdminUserMenu` 的 JSX / CSS 调整和对应测试。
- 若个人资料页顶部身份栏展示不符合预期，可回滚 `ProfilePage` 顶部身份栏邮箱片段渲染逻辑。
- 回滚不得恢复前端拼接伪邮箱行为；如必须临时隐藏异常展示，应优先隐藏邮箱片段而不是重新生成 `username@tilesfst.com`。

## 风险

- 用户菜单移除副标题后，侧边栏底部垂直布局可能需要微调，避免头像、昵称和 chevron 对齐异常。
- 个人资料页顶部身份栏省略邮箱片段时，需要避免分隔符残留，例如 `角色 · · 最近登录`。
- 旧测试已断言伪邮箱兜底，需要同步更新，避免测试继续锁定错误行为。
