## 根因

`BUG-0148` 的 confirmed 根因为小程序商品卡片 grid 展示契约偏向铺满容器：图片使用填充裁切模式，图片框比例又偏矮，导致部分商品图无法完整显示主体。历史商品卡片需求强调双列稳定、轻量图片和防布局跳动，但没有明确“grid 列表优先完整显示整张商品图”的验收项。

## 修复方案

- 将 `density="grid"` 商品卡片图片从填充裁切展示调整为完整适配展示，确保图片主体不被上下或左右裁切。
- 将 grid 图片区域比例调高到更适合方形瓷砖图的区间，并让卡片整体高度稳定承载图片、名称、品牌/规格和价格信息。
- 为完整适配产生的空白区域设置与现有卡片视觉一致的背景或占位策略，避免透明空洞、破图或过强对比。
- 保留图片轻量字段策略，继续消费列表缩略图或等价轻量优化 URL，不引入原图字段回退。
- 保持 `compact` 与 `list` 密度现有布局不变，避免影响首页新品/热销横向卡片和搜索结果列表。

## UI Contract

| 项 | 内容 |
|---|---|
| 事实源优先级 | 用户参考截图、BUG acceptance、Change delta spec、现有小程序商品卡片实现、`rules/ui-design.md`。 |
| 页面与入口 | 小程序商品列表页、品牌详情商品 Tab、首页全部产品区域；均通过 `density="grid"` 复用 `components/product-card`。 |
| 信息架构 | 卡片仍由图片区域、商品名称、品牌/规格/价格等信息组成；本 Change 只调整 grid 图片区域和相关加载/占位状态。 |
| 视觉约束 | grid 图片区域应提高到接近方形瓷砖图展示所需比例，图片完整适配显示，留白由卡片背景自然承接，不改变 compact/list。 |
| 交互状态 | 点击卡片、懒加载、加载失败、无图占位和骨架屏保持可用；加载前后不得造成明显布局跳动。 |
| Mock/API 边界 | 不新增 Mock，不改 API；继续使用既有列表轻量图片 URL 字段。 |
| 权限规则 | 店主端公开浏览能力，不涉及管理端权限或内部维护入口。 |
| 一致性参照 | 320、375、430 pt 逻辑宽度双列 grid；商品列表页、品牌详情商品 Tab 和首页全部产品表现一致。 |

## Skeleton 计划

- 保持现有商品卡片 DOM 结构和双列 grid 容器不变，先调整图片容器比例和图片展示模式。
- 让无图占位、加载失败态和骨架屏跟随同一 grid 图片区域比例。
- 通过静态测试先锁定模式与比例契约；小程序 DevTools 或真机截图作为归档前 render evidence。

## 复用场景

- `src/miniapp/pages/product-list/`：全部商品、分类商品、品牌商品、首页推荐查看更多等入口进入的双列 grid 列表。
- `src/miniapp/pages/brand-detail/`：品牌详情商品 Tab 复用 grid 商品卡片。
- `src/miniapp/pages/index/`：首页全部产品区域复用 grid 商品卡片。

## 验证设计

- 更新小程序静态测试，确认 grid 商品图片不再使用填充裁切模式，且 grid 图片框比例与骨架屏比例一致。
- 静态检查 `compact` 和 `list` 相关契约未被本 Change 强制改动。
- 小程序 DevTools 或等价截图覆盖 320、375、430 pt 逻辑宽度，确认双列 grid 不横向溢出、不遮挡文本、图片完整适配。
- 媒体四联验收中 `key`、`object`、`URL` 为 n/a，`render` 以小程序截图或 DevTools evidence 为准。

## 风险与取舍

- 完整适配会在部分非方形图片上产生留白。该取舍符合本 BUG 的“优先完整显示整图”要求，需通过背景和比例控制降低突兀感。
- 提高图片区域比例会减少首屏可见商品数量。该变更只覆盖 grid 商品浏览场景，目标是提升瓷砖图片识别准确性。
- 不改变 URL 和缩略图策略，因此不会解决图片源质量不足、缩略图生成异常或对象缺失问题；这些问题应另行记录 BUG。
