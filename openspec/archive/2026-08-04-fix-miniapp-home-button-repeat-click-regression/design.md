## 问题分析

BUG-0115 指向小程序返回首页悬浮按钮的状态恢复回归。用户路径通常为：

1. 进入带 `home-floating-button` 的非首页页面。
2. 点击返回首页按钮并回到首页。
3. 再次进入同一页面或另一个带按钮页面。
4. 第二次点击返回首页按钮失效。

当前组件已经存在 `navigating` 状态锁、延迟解锁、页面 show 重置和 `reLaunch` 兜底，但真实运行环境仍可能出现锁未释放、生命周期未触发或运行包未同步导致的回归。

## 根因假设

- `wx.switchTab` 成功后，原页面组件可能没有在预期时机完成 `unlockNavigation()` 或 `pageLifetimes.show()` 重置。
- 不同页面类型的生命周期不同，TabBar 页面和非 TabBar 详情页在重复进入时可能产生不同的组件实例复用行为。
- 快速点击保护只在短时间内有价值，但若锁释放依赖不稳定回调，就可能把后续正常点击也拦截掉。
- 现有测试偏静态，不能证明状态机在连续点击序列中恢复。

## 修复方案

- 将返回首页悬浮按钮的导航锁释放设计为所有路径可恢复：
  - 成功路径释放；
  - 失败后兜底路径释放；
  - 兜底失败路径释放并提示；
  - 页面重新显示或组件重新挂载时释放；
  - 防重复窗口超时后释放。
- 如实现发现当前锁策略仍受小程序生命周期影响，优先改为“短窗口防重复 + 每次导航完成/超时强制解锁”的显式状态机。
- 保持首页路径 `/pages/index/index` 与 TabBar 首页跳转策略一致，不调整小程序页面范围。
- 检查 TypeScript 与运行时 JavaScript 是否同步，避免 DevTools 或体验版加载旧运行入口。

## 测试策略

- 增加状态流测试，直接模拟组件数据、`wx.switchTab` 成功、失败、`wx.reLaunch` 兜底和 timer 解锁。
- 测试同一组件实例连续两轮点击：第一轮成功后解锁，第二轮仍触发 `wx.switchTab`。
- 测试跨页面或重新 show：`pageLifetimes.show()` 调用后必须清理历史锁。
- 保留小程序静态覆盖测试，确认分类页、品牌列表页、搜索结果页、商品详情页等页面仍接入统一组件。
- 运行 `uv run pytest tests/test_miniapp_static.py` 或实现阶段新增的最小相关测试。

## 风险与边界

- 不修改后端 API、数据库、Orval、Web 或管理端。
- 不变更返回首页按钮视觉层级、尺寸和页面覆盖范围，除非修复确认必须调整触控状态。
- 微信开发者工具或体验版真机验证可能需要人工执行；无法执行时应在验收 evidence 中标记 blocked 或 follow_up。
