# 设计说明

## Bug Analysis Report

- 现象：管理后台 SKU 列表部分表头字段发生换行。
- 复现：登录管理后台，进入 SKU 列表，在常用桌面宽度下查看表头字段。
- 影响：表格扫描效率下降，用户可能误判表头与正文列的对应关系。
- 严重等级：`low`，不阻断 SKU 查看、筛选、分页或维护流程。
- 关联需求：`REQ-0006-tile-sku-management`。

## Root Cause

直接原因是表头单元格缺少稳定的单行显示约束。根本原因是 SKU 列表列数较多，表头文本、列宽、横向滚动容器之间缺少明确展示契约，布局收缩时优先发生文本折行。

## Fix Strategy

1. 在 SKU 列表表格层为表头字段增加单行显示约束，例如 `white-space: nowrap` 或等价组件样式。
2. 为较长表头列保留合理最小宽度，避免通过过度压缩正文列换取单行表头。
3. 保持或补齐表格横向滚动容器，使列数较多时能够完整查看所有列。
4. 验证排序、筛选、分页和操作列仍按既有行为工作。

## Testing

- 前端单元/组件测试：覆盖 SKU 列表表头 class/style 或 DOM 结构，确认表头单行约束存在。
- 前端回归测试：确认排序、筛选、分页和操作列关键交互仍可渲染或触发。
- 视觉验收：在常用桌面宽度下检查所有表头字段单行显示，并确认表头与正文列对齐。

## API / DB / Orval Impact

- API：无影响。
- 数据库：无影响。
- Orval：不需要。
