## 背景

小程序已经具备完整搜索页和 `components/search-entry` 入口组件，但首页、品牌、证书、商品列表和收藏等页面对搜索入口、来源参数和列表内搜索路径的承接仍不一致；底部 Tab「全部分类」页保持结构化分类浏览，不纳入搜索入口铺设范围。管理端主要列表已有不同程度的关键词和筛选能力，但入口位置、重置、分页、空态、权限边界和观测口径需要统一，避免用户在不同列表中反复学习不同搜索方式。

## 变更内容

- 强化小程序首页搜索入口，使搜索成为首页首屏高权重找砖入口。
- 统一小程序搜索入口契约，复用或增强 `components/search-entry`，并以 `/pages/search/index` 承接完整搜索首页、联想和结果页。
- 为小程序品牌、证书、商品列表和收藏补齐搜索入口或列表内搜索路径；品牌、证书和收藏采用当前页或当前收藏范围过滤，全部分类页不展示搜索入口。
- 调整与本需求冲突的既有小程序商品列表和证书列表规格，从“完全不展示搜索入口”收敛为“商品列表保留搜索路径、证书列表提供当前页关键词过滤”。
- 统一管理端主要列表的关键词搜索、筛选区、重置、分页、空结果和权限边界验收。
- 建立搜索行为事件和请求链路观测验收口径，关键词按规范脱敏或摘要化。
- 若实现阶段新增或调整 API 查询参数、响应字段、错误码、索引或请求封装，必须同步 OpenAPI、Orval、API 文档、数据库文档和测试；本 Change 不引入搜索引擎、搜索词运营后台或高级查询 DSL。

## 能力范围

### 新增能力

- 无。

### 修改能力

- `miniapp-search`: 统一搜索入口组件契约、多页面入口跳转参数、完整搜索页承接和搜索事件观测。
- `miniapp-home`: 强化首页搜索入口的首屏权重、位置、来源参数和移动端不遮挡验收。
- `miniapp-category-list-page`: 分类页保持底部 Tab 一级频道的分类浏览主体验，不展示搜索入口。
- `miniapp-brand-list-page`: 品牌列表支持品牌关键词当前页查找，不进入完整搜索页。
- `miniapp-certificate-list-page`: 证书列表从“无搜索”调整为支持证书关键词当前页查找，不进入完整搜索页。
- `miniapp-product-list-page`: 商品列表从“无二次搜索入口”调整为支持当前上下文搜索路径或返回完整搜索页调整关键词。
- `favorite-list-page`: 收藏列表收敛为当前收藏范围搜索。
- `xl-admin-page-acceptance-template`: 管理端主要列表统一搜索、筛选、重置、分页和横切 UI 验收 gate。
- `product-usage-logging`: 搜索入口、搜索提交、联想、结果曝光、列表筛选和重置事件纳入事件字典与请求链路验收。

## 影响

- 微信小程序：影响首页、搜索页、品牌页、证书页、商品列表页、收藏页的搜索入口、列表内过滤、跳转参数、空态和事件上报；全部分类页不展示搜索入口；实现阶段需同步 `.ts` 与 `.js` 运行入口。
- Web 管理端：影响品牌、类目、SKU、规格、Banner、证书、用户、日志等主要列表的关键词搜索和筛选一致性；必须复用 `AdminListPage` 或说明等价封装。
- 后端 API：可能新增或收敛小程序与管理端列表查询参数；必须校验关键词、scope、分页、筛选枚举和权限边界。
- 数据库：默认不新增表；如需要普通索引或检索字段，必须同步 SQLite/MySQL schema、迁移、数据库文档和测试。
- Orval：管理端或店主 Web API contract 变化时必须重新生成；纯小程序手写请求不触发 Orval，但后端 OpenAPI 仍需更新。
- 行为埋点与请求日志：适用。必须记录来源页面、搜索范围、关键词脱敏摘要、结果数量、筛选摘要和请求 ID。
- Task Trace：普通搜索默认不适用；若后续实现判定为长耗时复杂查询，需要按 Task Trace 覆盖规则补充声明与验收。
- Docker Compose / 对象存储：默认不涉及。
