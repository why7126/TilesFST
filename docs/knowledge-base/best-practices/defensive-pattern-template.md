# 防御性模式模板

> 使用时复制本模板结构到新的 best-practice 文档；不要在模板中记录具体项目事故。

## 缺陷类别

一句话说明这类问题会如何发生，以及通常影响哪个链路。

## 预防规则

用 MUST / SHOULD 写成可执行规则。规则应描述当前应如何做，不叙述“之前怎么错”。

## 适用范围

列出适用模块、命令、文档、接口、UI、部署或测试阶段。

## 验证方式

列出可以证明该规则生效的测试、脚本、截图、日志或人工验收要点。

## 例外与风险

说明什么情况下可以不适用，以及不适用时必须记录的理由。

## 关联事实源

列出仓库相对路径，例如 Issue、OpenSpec Change、测试文件、spec-log 或现有规则文档。
